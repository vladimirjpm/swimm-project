# Хендофф Клод-коду — таб «Start list», принятый дизайн «3a Ticket + Following»

Дата: 29.08.2026. Дизайн-макет: `Start List.dc.html`, секция **3a** (верхняя).
Входной хендофф дизайнеру: `uploads/design-handoff-start-list-tab.md` — все его правила
(раздел 5) остаются в силе. Ветка кода: `season-best-list-and-shared-filters`
(`…/components/start-list/`), коммит на момент дизайна `5277bd2`.

---

## 0. Что решено

Вместо трёх исходных вариантов принят объединённый: **пикер Following → единая карточка
плана («билет») → экран «протокол не опубликован»**. Секции 1c и 2a в макете ниже —
история итераций, не для реализации. Внутри 3a есть панель «4 варианта плотности строки»
(A/B/C/D/D1/D2/D3) — **принят D3**, остальные — отработанный материал.

Основной сценарий не изменился: родитель в зале с телефона, «когда и на какой дорожке
плывёт мой ребёнок». Ссылку на карточку шлют в родительский чат → работает без логина.

## 1. Экраны

### 1.1 Пикер «Following» (3a-S1)

Точка входа в персональный план. Открывается из «⭐ ▾» на карточке и из Edit-чипа плана.

- **FAVORITES** — чекбоксы, выбрать можно **несколько**. Строка: чекбокс · имя (иврит,
  RTL, primary — ⭐) · его дни («Sun 15 · Thu 19»). Выбранные — золотые
  (`--theme-personal-*`), счётчик «N selected» справа от заголовка.
- «+ Add a favorite by search…» → существующий поиск по имени.
- **FOLLOW A WHOLE CLUB** — тумблер на клуб: «все пловцы клуба попадают в план».
  Строка: аватар-буква · название (иврит) · «42 swimmers · 96 entries» · toggle.
  Данные — `GET /api/start-list/{orgCompId}/clubs/{id}` (сейчас нигде не используется).
  «All 61 clubs…» → полный список.
- CTA внизу: «Show my plan — 2 swimmers + מכבי חיפה» → карточка плана.
- Состав выбора хранится per-соревнование (localStorage гостя / профиль залогиненного).

### 1.2 Карточка плана — «билет» (3a-S2)

Один экран для «один выбран» и «несколько выбраны» — вид меняется данными, не разметкой.

Сверху вниз:

1. **Шапка**: «‹ Start list» и кнопка **Share link ↗** (cyan pill) — шарит текущий
   состав плана ссылкой (`?tab=startlist&swimmer=…` для одного; для состава —
   расширить URL-параметр, напр. `&plan=s1,s2,c5`).
2. **Дни-чипы** (маленькие): «Sun 15 ✓ · 10 swims». День **disabled (opacity .35),
   только если НИКТО из выбранных в него не плывёт**. Один выбран → его пустые дни гаснут.
3. **Чипы состава**: «⭐ אניה ✕» (золото) · «דניאל ✕» (золото) · «מכבי חיפה · 42 ✕»
   (cyan) · **Edit ▾** (заливной cyan) → пикер. Чипы `white-space:nowrap`.
   Один выбран → один чип «⭐ имя · год · клуб».
4. **Золотой билет** (`--theme-personal-bg/border`, перфорация dashed + полукруги):
   - Hero: «FIRST OF YOURS · SUN 15 FEB» (один выбран — «FIRST START»), время 44px
     Archivo Black с «≈»; справа плитка **ARRIVE BY** (см. §2).
   - Строка «Warm-up from 08:00 — arrival is 30 min before.» + чекбокс **I'm coming**.
   - Под перфорацией — заплывы выбранных, отсортированы по времени, строками D3 (§1.3).
5. Футер: «Times are approximate — heats run 20–40 min off schedule. Updated HH:MM · ↻
   Refresh» (автообновления нет — правило из исходного хендоффа).

### 1.3 Строка заплыва — формат D3 (принят)

Grid `74px | 1fr`, скругление 12px:

- **Плитка времени** слева, на всю высоту строки: «≈10:24» Archivo Black 16px,
  tabular-nums. Фон: золотой `badge-bg` у строки фаворита, нейтральный у клубной.
  Хита в плитке НЕТ.
- Правая колонка, первая строка: **`UI_SwimmStyleIcon`** (существующий UI-компонент —
  плитка стиля с красной дистанцией под пиктограммой, режим icon-len, ширина ~54px)
  + метка «Girls 9 · H3 · 1:24.90 PB» (12.5px, вмещается в 390px — слова Heat/seed
  сокращены до H№ и голого времени; PB — суффикс).
- Ниже — **имена столбиком**, по одному на строку: имя 15px (иврит, `dir="auto"`,
  фаворит 900 + ⭐, клубный — суффикс «· CLUB» cyan 10px; эстафета — «מכבי חיפה A · RELAY»,
  нога фаворита в метке «leg 2») · справа на уровне имени **дорожка** «L4» Archivo Black
  15px (золото у фаворита, cyan у клубного).
- **Несколько выбранных в одном заплыве = ОДНА строка**: плитка времени и стиль общие,
  имена столбиком каждый со своей дорожкой (пример ≈10:47 в макете).
- Один выбран → те же строки без строк имён (имя в чипе сверху); освободившееся место —
  ничем не заполнять.
- Статусы: `no-show` — строка opacity .45 + имя зачёркнуто + бейдж NO-SHOW;
  `swum` — бейдж «SWUM ✓» cyan (см. правило: после старта протокол = «кто не вышел»).
- Время отсутствует (полночь в источнике) → плитка «—», строка dashed, «not scheduled».

### 1.4 «Протокол не опубликован» (3a-S3)

Полноценный экран вместо серой строки: скелет-полосы, заголовок «Start list not published
yet», «Protocols usually appear a few days before the meet. Competition starts Sun 15 Feb.»,
кнопка «↻ Check again», **только залогиненному** — «⭐ Notify me when it's out»,
внизу «Last checked HH:MM».

## 2. ARRIVE BY — правила показа (важно)

1. **Время прибытия = начало разминки − 30 минут.** Время разминки **вытянуть из таканона
   соревнования** (регламент); в API его сейчас нет — нужно добавить в данные соревнования.
2. Блок ARRIVE BY (плитка в hero + строка warm-up + галочка) рендерится **только если
   выполнены все три условия**: соревнование — чемпионат ∧ юзер залогинен ∧ юзер отметил
   галочку «I'm coming». Гостю и без галочки — только первый старт, без ARRIVE BY.
3. Галочка «I'm coming» хранится **per-соревнование**.

## 3. Компоненты: переиспользовать, не рисовать заново

- **`UI_SwimmStyleIcon`** — плитка «стиль + дистанция» в строках D3 — это существующий
  UI-компонент (иконка стиля, дистанция красным). Использовать его, не картинку/копию.
  В макете PNG из `client/public/images/swimm-style-icon/` — только для эскиза.
- `UI_SwimTime` — все времена (tabular-nums, «≈»).
- `UI_SwimmerNameCell` — имя с эмблемой клуба в строках имён.
- `SwimRow` НЕ использовать (правило из исходного хендоффа, откат 28.08).
- Токены: всё «моё» — `--theme-personal-*`; cyan-акценты («мы», CTA, CLUB) — токены
  темы Deep (`design_handoff_competition_overview/deep-theme.css`). Хардкодов из макета
  (#8a6d1a, #0e7490 и т.д.) в коде быть не должно — только токены, light и dark.

## 4. Что уходит из текущего экрана

- Поиск по дисциплине в зуме 1 (дублирующее поле) — остаётся один поиск по имени.
- Смена смысла подтабов источников при открытой карточке — заменена днями-чипами
  внутри карточки плана.
- Одиночный «primary favorite» как единственный режим — теперь мульти-выбор + клуб.

## 5. Данные

Хватает существующего API (§4 исходного хендоффа) + два добавления:

1. Время разминки по дням — из таканона (для ARRIVE BY, §2).
2. Персистенс: состав плана (swimmers[], clubs[]) и галочка «I'm coming» —
   per-соревнование; гость — localStorage, залогиненный — профиль.

Правила из исходного хендоффа (раздел 5: seed ≠ результат, иврит в данных / английский
в UI, «≈» обязательно, полночь = not scheduled, без горизонтального скролла, мобайл
390px — основной вид) действуют без изменений.
