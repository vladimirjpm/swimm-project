# Design brief: страница «My media» (media.html) — v2

Бриф для проработки дизайна (claude.ai/design). Техническая база готова; здесь — что
страница должна уметь, какие данные есть, и что доделаем на сервере под новый дизайн.
**Все надписи UI — только English** (жёсткое правило проекта). Язык данных — иврит/EN
(имена пловцов, названия групп) — RTL-текст в карточках должен выглядеть аккуратно.

## 1. Кто пользуется и зачем (роли)

1. **Владелец медиа** (родитель/пловец) — 95% использования:
   видеть все свои ссылки по всем своим пловцам, находить нужную, привязывать к
   заплыву, делиться с группой, следить за статусами, удалять.
2. **Админ группы** (тренер; часто тот же человек) — модерация:
   видеть заявки на публикацию в СВОИ группы (кто подал, что, про какого пловца,
   какой заплыв), одобрять/отклонять, снимать опубликованное.
3. **Site admin** — расширение роли 2 на все группы + общий надзор (объём медиа юзеров).

Роли не переключатели: у одного человека может быть и то и другое → страница из двух
зон/табов: **My media** (всем) и **Moderation** (только если есть группы под управлением;
таб с бейджем количества pending).

## 2. Данные (что реально есть в системе)

Единица — «ссылка» (media): `{id, url, media_type: image|video, source_type: youtube|vimeo|other,
swimmer_id, swimmer_name, level: swimmer|competition|result, result_id?, result_label?
(например "breaststroke 50 · 16/02/2026"), competition_id?, created_at}`.
Превью: youtube/vimeo — реальный thumbnail; other — плейсхолдер-иконка.

Публикации ссылки: 0..N штук `{hub_group_name, level: members|public,
status: pending|approved|rejected, created_at, decided_at}`.

Для модерации: `{url, media_type, source_type, owner_email, swimmer_name, result_label,
level, status, created_at}` по каждой заявке.

Справочники для фильтров (сервер отдаст): список моих пловцов, сезоны, соревнования,
клубы — производные от моих медиа (фильтруем только по тому, что реально встречается).

## 3. Зона «My media»

### Раскладка
- **Заголовок + счётчик** (N links) + primary-кнопка **Add link** (см. ниже).
- **Панель фильтров** (одна строка, chips/dropdowns, сворачивается на мобиле в кнопку Filters):
  - **Swimmer** — самый главный фильтр (я/Сабина/второй ребёнок), chips с аватарками-инициалами;
  - **Season** (2026, 2025, …) — по дате соревнования заплыва;
  - **Competition** — dropdown с поиском (названия на иврите, RTL);
  - **Club** — клуб пловца в заплыве;
  - **Status** — All / Private / Pending / Published / Rejected;
  - **Date range** — необязательный, от/до (по дате заплыва; для непривязанных — по created_at).
  - Активные фильтры — chips с ×; кнопка Clear all.
- **Группировка**: по пловцу (секции с заголовком-именем), внутри — сетка карточек
  или список (переключатель grid/list — nice to have).

### Карточка медиа
- превью (thumbnail 16:9), клик → лайтбокс-плеер;
- бейдж заплыва: "50m breast · Feb 16, 2026 · <competition>" или "Not linked to a swim"
  (для level=swimmer) — тогда рядом действие **Link to a swim** (см. ниже);
- статус-строка публикаций: chips `<group> · pending / published / rejected`
  (published+public = глобус-иконка «visible to everyone»), у каждого × (withdraw);
- действия: **Share with a group** (если есть eligible-группы; иначе tooltip
  "The swimmer must be in the group's roster"), **Delete** (confirm).

### Add link (модал/панель)
Сейчас добавление живёт в карточке пловца; на странице нужен самостоятельный флоу:
1) вставить URL (автоопределение youtube/vimeo/other; для other — radio video/photo);
2) выбрать пловца (из «моих» — primary + favorites + те, у кого уже есть мои медиа);
3) опционально привязать к заплыву: выбор соревнования пловца → список его заплывов
   (дистанция/стиль/время/дата) → пикнуть один. Пропустить = «general link».
Серверу нужен новый endpoint «заплывы пловца для пикера» (см. §6).

### Пустые состояния
- вообще нет медиа: иллюстрация + "No media yet" + кнопка Add link + подсказка
  "You can also add videos from a swim row on the results page";
- фильтр ничего не нашёл: "Nothing matches the filters" + Clear all.

## 4. Зона «Moderation» (таб виден только админам групп / site admin)

- Бейдж на табе = число pending по всем моим группам.
- **Фильтры**: Group (мои группы), Status (Pending по умолчанию / Published / All),
  Swimmer, Level (members/public).
- **Список заявок** (строки, не сетка — решения принимаются быстро):
  превью-миниатюра | swimmer_name + result_label | владелец (email/имя) | группа |
  level-бейдж (Members / Public «visible to everyone» — public выделить, это выход
  на весь интернет) | дата подачи | кнопки **Publish** / **Reject** (для pending),
  **Unpublish** (для published).
- Клик по превью → лайтбокс (решение нельзя принимать не глядя видео).
- После решения строка анимированно уходит из Pending.
- Пусто: "No pending requests 🎉".

## 5. Мобильная версия

- Фильтры — bottom sheet по кнопке Filters (+ счётчик активных).
- Карточки — 2 колонки; список модерации — карточки со stacked-полями.
- Действия карточки — в meatball-меню (⋯), чтобы превью не были перегружены.

## 6. Серверные доделки под этот дизайн (моя часть, НЕ дизайн)

Уже есть: список медиа (+swimmer_name/result_label), публикации со статусами,
publish-targets (честный селектор групп), submit/withdraw/decide, per-group inbox.

Доделать:
1. **Фильтры**: расширить `GET /api/me/media` полями `competition_name, competition_date,
   season, club_name` (денормализация из заплыва) — фильтрацию можно делать на клиенте
   (объёмы маленькие), сервер просто отдаёт поля.
2. **Сводный inbox модерации**: `GET /api/me/moderation/media` — заявки по ВСЕМ группам,
   где я владелец/админ (сейчас inbox только per-group на странице группы); для site
   admin — по всем группам вообще.
3. **Пикер заплывов**: `GET /api/swimmers/{id}/results-brief?competitionId=` — краткий
   список заплывов пловца для привязки (дистанция, стиль, время, дата, result_id).
4. Опционально: `owner_name` вместо голого email в модерации.

## 7. Принципы

- Понятность важнее плотности: юзер — родитель, не оператор CRM.
- Статусы — только цвет+слово (не только цвет): pending (amber), published (green),
  rejected (red), private (gray).
- Public-уровень всегда явно маркировать «visible to everyone» — это публикация в интернет.
- Никаких сырых URL в iframe — только канонический embed (youtube-nocookie/vimeo player).
- Тема: светлая/тёмная через существующие var(--theme-mode-*) токены сайта.
