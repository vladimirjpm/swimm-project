# Архив источников справочника рекордов

Что именно скормили импорту в конкретный день — и что источник тогда говорил построчно.

Заведён 16.09.2026, когда короткая вода мастерсов откатила 18 израильских рекордов к более
медленным значениям, и выяснилось, что сверять новое с прежним **не с чем**: прежние данные
пришли из статики `normative-masters-records.js` (один коммит 04.04.2026), а из какого файла
федерации её тогда собрали — история не помнит (`docs/data-integrity.md`, И-21).

**Папка коммитится.** Файлы федерации и World Aquatics опубликованы публично, а архив, живущий
только на одной машине, исчезнет ровно в тот момент, когда понадобится (решение Влада
16.09.2026). Рост умеренный: файлы кладутся **только при новой контрольной сумме**, а источники
меняются редко — длинный мастерский PDF федерации стоит неизменным с апреля 2025.

## Кто пишет выгрузку

| прогон | чем | когда |
|---|---|---|
| `--records-refresh` (четыре источника Израиля и мира) | вручную: `--records-dump <источник> <файл.csv>` | после прогона, по шагам ниже |
| **боевой прогон по странам** (кнопка «Прогнать все страны») | **сам, без команды** | в конце прогона, до диффа и до Apply |

Прогон по странам выгружает себя сам не для удобства. Ручной `--records-dump` для него не
годится в принципе: он сходил бы в источник ЕЩЁ РАЗ, за теми же 430 файлами и ещё на час-два,
и принёс бы уже не то, что применили, а то, что источник отдаёт сейчас. Прогон же держит
разобранные строки в руках — выгрузка ему ничего не стоит. Путь к файлу показывается в админке
под прогрессом, чтобы файл не пришлось искать перед коммитом.

⚠ **Прогон ПОДМНОЖЕСТВОМ стран не архивируется.** Поле кодов подписано «повтор упавших или одна
страна для отладки»: складывать по файлу на каждую отладочную перетяжку значит засыпать мусором
ровно тот инструмент, ради которого архив заведён. Цена решения известна и принята: 17.09.2026
(И-22) пришлось доказывать косвенно, что дубль у Бермуд — ошибка источника, а не нашего парсера.

⚠ **PDF у прогона по странам нет.** Источник — 430 XLSX-отчётов API, а не публикуемый файл;
класть в архив по два файла на страну незачем. Доказательством остаётся сам CSV: он показывает,
что источник отдал в тот день построчно.

Выключается пустым `RecordsImport:SourceArchiveDir` в `appsettings.json` (относительный путь
считается от `server/Swimm.API`).

## Два артефакта на каждый прогон

| что | зачем |
|---|---|
| **PDF** — как отдал источник | **доказательство**. Когда спор «парсер врёт или источник», нужен оригинал, а не наш пересказ |
| **CSV** — разобранные строки | **рабочий инструмент**. `git diff` двух выгрузок отвечает на вопрос «что стояло в этой полосе раньше» — тот самый, на который 16.09 ответить было нечем |

CSV — наша интерпретация, PDF — первоисточник. Нужны оба: по CSV ищут, по PDF доказывают.

## Имена

```
<источник>-<бассейн>__source-<дата справочника>__fetched-<дата скачивания>.pdf
<источник>__fetched-<дата скачивания>.csv
```

- **источник** — ключ `IRecordSourceProvider`: `wa-masters`, `wa-junior`, `isrorg-masters`,
  `isrorg-age`, `worldrecords`. У `wa-junior` сырьё — JSON (`wa-junior-<пол>-<бассейн>`), даты
  справочника у источника нет, поэтому `__source-` в имени нет.
- **бассейн** — `lcm`/`50m` длинная, `scm`/`25m` короткая. У CSV его нет: провайдер тянет оба
  файла разом, и выгрузка у него одна на источник.
- **source** — дата САМОГО справочника, как её объявляет источник: «as of 01.09.2026» в подписи
  ссылки у World Aquatics, число в имени файла у федерации (`1_26` = январь 2026,
  `17_08_2026` = 17.08.2026). По ней видно, устарел ли файл.
- **fetched** — когда скачали мы. Расходится с `source` всегда: `source` — возраст данных,
  `fetched` — возраст нашей копии.

Так файлы одного источника выстраиваются по дате справочника, и «что изменилось между январём
и апрелем» — это `diff` двух соседних строк `ls`.

`SHA256SUMS.txt` — суммы по всем файлам: доказывают, что разобран именно этот файл, а не
перекачанный позже под тем же именем. Проверка:

```bash
cd !records-sources && sha256sum -c SHA256SUMS.txt
```

⚠ Сам файл сумм, README и CSV прибиты в `.gitattributes` к `eol=lf`. Без этого при
`core.autocrlf=true` они выезжают из гита с CRLF, и `sha256sum -c` спотыкается о `
` в конце
каждого ИМЕНИ — то есть проверка архива не работает ровно там, где нужна. Поймано 16.09.2026
сразу после первого коммита архива.

## Как пересобрать CSV

```bash
dotnet run --project server/Swimm.API -- --records-dump <источник> <путь к .csv>
```

Ходит в сеть за теми же файлами, что и импорт, и пишет строки, отсортированные по восьми осям.
Сортировка не косметика: без устойчивого порядка `git diff` показывал бы перестановки вместо
изменений, и смысл архива терялся бы.

| `wa-junior-{f,m}-{lcm,scm}` (`.json`) | JSON-эндпоинт страницы [worldaquatics.com/swimming/records](https://www.worldaquatics.com/swimming/records) (Record Type = World Junior): `api.worldaquatics.com/fina/records/SW?recordCode=WJ&gender=F\|M&pool=LCM\|SCM`. Сырые ответы, по файлу на пол×бассейн (J0, 21.09.2026). ⚠ XLSX-отчёт `/fina/records/report?recordCode=WJ` не годится — 504 |
| `isrorg-age-25m` / `isrorg-age-50m` | страница [«שיאי ישראל»](https://isr.org.il/data.asp?id=1013), ссылки «שיאי ישראל בוגרים ונוער» |

## После боевого прогона

1. Скачать файлы, которыми прогон питался, и сверить их суммы с `SHA256SUMS.txt`.
2. Положить сюда **только те, у которых сумма новая**; старые не перезаписывать — они и есть
   история.
3. Пересобрать CSV тех же источников (`--records-dump`) и обновить `SHA256SUMS.txt`.

## Если расхождение повторится

1. `git log` по CSV нужного источника → `git diff` двух выгрузок: видно построчно, что изменил
   источник.
2. Прежде чем объявлять источник виноватым, проверить три вещи:
   - **читает ли парсер верно** — найти спорное время в тексте самого PDF;
   - **есть ли значение в наших протоколах** — точное время + дистанция + стиль по `Results`.
     ⚠ Совпадение ВРЕМЕНИ ничего не значит, пока не сошёлся пловец: 16.09.2026 четыре таких
     «совпадения» оказались детьми 2010–2015 г.р. в 50-метровом бассейне;
   - **монотонность полос НЕ доказательство** — у мастерсов инверсии есть и в честных данных, и
     в самой таблице федерации (400 к/п ж: 65-69 — 08:16.61, а 70-74 — 07:27.04). Довод И-21
     держался на РАЗМЕРЕ разрыва (38 с), а не на факте инверсии.
3. Решение по данным — в `docs/data-integrity.md`, это их единственное место.
