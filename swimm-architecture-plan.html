Фундамент закрыт. Сервер расслоён (Domain / Application / Infrastructure / API), контроллеры инжектят только интерфейсы; БД на least-privilege ролях (swimm / swimm_rw / swimm_ro, два DbContext); auth полный (Google + локальный, SecurityStamp-ревокация, antiforgery, rate-limit); клиент переведён со статики на /api/results · /api/competitions · /api/categories · /api/club-points. Осталось в фазе 3: серверные агрегаты (3.4) и нагрузочный smoke k6 (3.5). Фазы 1 и 2 закрыты целиком, включая 2.6 — обновление рекордов с worldaquatics/isr.org.il с превью-диффом.

Масштаб и кэшСЕЙЧАС · 3.1–3.3 ✓
Готовность к миллионам записей: сервер отдаёт быстро, клиент не выкачивает всё.
  • 3.1: ETag + Cache-Control на всех публичных GET (общий CachedJson-хелпер; 304 на If-None-Match; глобальная токен-инвалидация)

  • 3.3: синтетика 3 млн строк (server/db/synthetic-results.sql) + EXPLAIN-профиль → индекс (CompetitionId, CompetitionDate DESC, Position): 335 мс → 0.5 мс
  • 3.4: серверные агрегаты — счётчики GetSources (~250 мс за кэшем), DISTINCT distance, серверные level_filter/recalc для paged
  • 3.5: нагрузочный smoke k6 (p95 < 300мс на промахе)

Структура БД (PostgreSQL · public) #db

Три роли (server/db/setup-roles.sql): владелец swimm — DDL/миграции · swimm_rw — runtime DML и все Sys_* · swimm_ro — SELECT только на публичных бизнес-таблицах (fail-closed: новая публичная таблица без гранта — публичный путь падает, это намеренно).
ГруппаТаблицыЗаметки
Результаты core · swimm_ro Results · Competitions · CompetitionEvents · Swimmers · Clubs · Styles · Countries · Relays · Galleries/GalleryItems Results: bigint PK, TimeMillisecond, InternationalPoints, CHECK ≥ 0. CompetitionEvent = родитель многодневных. Galleries — импортные медиа заплыва (НЕ путать с Sys_UserMedia).
Справочники core Categories · CategoryCompetitions · ClubPointsRules/Entries · CompetitionResultUrls Категории отдают name/badge клиенту через /api/categories; канонические ключи — client-only.
Рекорды фаза 2 ✓ · swimm_ro Records · NormativeStandards 3-осевая модель; 1719 + 6510 строк из сидера; UpdatedAt (2.6) — дата обновления записи, не путать с RecordDate.
Auth Sys_* · только swimm_rw Sys_AppUsers · Sys_AppRoles · Sys_AppUserRoles · Sys_UserExternalLogins · Sys_UserLocalCredentials · Sys_UserSecurityTokens · Sys_UserLoginHistory SecurityStamp на AppUser · пароли Argon2id · токены — SHA-256-хэши, single-use, TTL.
Пользовательское Sys_* Sys_UserFavorites · Sys_UserMedia · Sys_ImportHistory Single-primary через partial unique index. UserMedia создана, эндпоинты откроются в фазе 5.

Кэширование — три уровня #cache

УровеньМеханизмСтатус
1 · HTTP ETag + Cache-Control (общий CachedJson): records/standards — max-age=300; competitions/career/hints — max-age=60; If-None-Match → 304 без тела. 3.1 ✓
2 · Приложение ICacheService: ключ = нормализованный фильтр; InvalidateAllAsync() после импорта/CRUD (токен-инвалидация). работает (Memory)
3 · БД Индексы + SwimmReadDbContext NoTracking. Композит (CompetitionId, CompetitionDate DESC, Position) под paged-выдачу; все paged-запросы ≤ 4 мс на 3 млн строк. 3.3 ✓
Правило: авторизованные и персональные данные (/auth/*, favorites, user media) никогда не кэшируются на уровнях 1–2. Redis подключается заменой одной регистрации в DI — когда появится второй инстанс, не раньше.

AI extension points (future) #ai

Цель: заложить швы так, чтобы и простой LLM-вызов сейчас, и Microsoft Agent Framework потом внедрялись за один и тот же интерфейс — сменой реализации в Infrastructure, без правок контроллеров и домена. Реализация — после основного роадмапа; сейчас — только не мешать этим швам появиться.
ШовНазначение
ISwimmerProgressAnalyzerДетерминированная аналитика прогресса (без LLM). Она же — инструмент для агента.
ITrainingPlanGeneratorГенерация плана тренировок — один structured LLM-вызов.
IVirtualCoachРазговорный сценарий; контроллер зависит только от него — контракт не меняется при SDK→MAF.
IAgent · IAgentCatalog · IAgentRouterКаталог агентов: новый агент = класс + DI-регистрация. Примеры: VirtualCoach, ProgressAnalyst, RecordsWatcher, CompetitionScout…
Coach-tools — обычные C#-методы над данными заплывов (GetRecentResults, GetProgression, CompareSwimmers, SuggestTrainingFocus): в режиме прямого SDK — function-calling tools, в MAF — agent tools/MCP. Методы одни и те же, инвестиция не пропадает.

Как запустить локально #run

Backend

# Prerequisites: .NET 10 SDK, Docker Desktop, Node (для admin-CSS)
docker compose -f server/docker-compose.yml up -d # Postgres :5445
# миграции — явно (два контекста!):
dotnet ef database update --project server/Swimm.Infrastructure --startup-project server/Swimm.API --context SwimmDbContext
# или: dotnet run --project server/Swimm.API -- --migrate
dotnet run --project server/Swimm.API --urls http://localhost:5078
# → /api/results · /admin · /auth/login/google · home.html
# Tailwind админки: cd server/Swimm.API && npm run css:build

Frontend

npm --prefix client run dev # Vite :5173, proxy /api,/auth → :5078
# прод-сборка: npm --prefix client run build (build:azure — вырезает видео)
# страница результатов: results_main.html?category=…&competitionId=last
Footgun: MSB3027 «Swimm.API.dll is locked» = жив прошлый dotnet run — убить процесс перед пересборкой. Скиллы: /db-migrate, /smoke-test-api.
