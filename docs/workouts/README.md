# Занесение тренировок (workout) с листа тренера

Ранбук для агента: Влад присылает лист тренировки (картинка или текст на иврите) — его надо
занести на прод в занятие группы. Модель данных и редактор — `docs/plans/trainings-coach-flow-plan.md`
§5.5 (формат `Workout`) и §5.6 (что понимает «Paste»). Здесь — как это делать на практике и как
читать «диалект» листа, который разборщик сайта пока не понимает.

Папка:

- `sheets/<дата>-<HHmm>.txt` — лист как напечатан (переписан с картинки слово в слово);
- `sheets/<дата>-<HHmm>.json` — то, что занесено (документ `Workout`, ровно тело `PUT …/workout`);
- `tools/workout-check.mjs` — разбор листа настоящим разборщиком сайта и метры по уровням.

## Порядок

1. **Какое занятие.** Дату на листе обычно не пишут: это ближайшее занятие по расписанию (лист
   присылают в день тренировки). Ключ плана — `yyyy-MM-dd-HHmm`. Есть ли уже план:
   `node server/db/prod-sql.mjs read -c "SELECT \"Id\",\"Date\",\"Start\",\"Status\",length(\"Workout\") FROM \"Sys_LanePlans\" WHERE \"HubGroupId\"=17 ORDER BY \"Date\" DESC LIMIT 5"`.
   Сомневаешься в дате — спроси Влада. Занятия нет в расписании (лист «יום ה'», картинка
   приложения тренера с днём и временем) — завести разовое тем же запросом, что «+ New training»:
   `POST /api/hub-groups/17/sessions` с `{ date, start, title, pool_type: "25m", type: "swim",
   asks_rsvp: true }`; после этого у него есть ключ, RSVP и план (прецедент 26.11).
2. **Переписать лист** в `sheets/<ключ>.txt` слово в слово, строки и пустые строки как на листе.
3. **Прогнать разборщик:** `node docs/workouts/tools/workout-check.mjs parse sheets/<ключ>.txt`.
   Если всё понято правильно (времена по уровням, повторы, отдых) — можно заносить через «Paste»
   на сайте. Если нет — собрать JSON руками по правилам ниже.
4. **Собрать `sheets/<ключ>.json`** (образец — любой файл в `sheets/`) и сверить метры:
   `node docs/workouts/tools/workout-check.mjs totals sheets/<ключ>.json`. Сумма по уровням должна
   совпасть с объёмом внизу листа («2.3 – 2.7» → нижний уровень 2300, верхний 2700). Не сошлось —
   ошибка в повторах, ищи её, а не подгоняй.
5. **Занести на прод** — через сайт под аккаунтом Влада в панели браузера (Влад входит сам; пароль
   агент не вводит). Workout живёт при плане дорожек: у занятия нет плана — сначала «Create plan»
   в бассейне занятия (черновик, без рассылки), потом workout. Два пути:
   - «Workout → Paste» и правка ячеек в таблице — если разборщик справился;
   - из консоли страницы тем же запросом, что шлёт редактор:
     `GET /api/antiforgery/token` → `PUT /api/hub-groups/17/lane-plans/<ключ>/workout` с телом
     `{ "workout": <json> }` и заголовком `X-XSRF-TOKEN`. Так проходят все проверки сервера и
     лента событий, в отличие от SQL. **Писать workout SQL-ом в `Sys_LanePlans` нельзя.**
6. **Проверить глазами** занятие на сайте: превью уровня, «Workout · 2.3–2.7 km» в карточке.
7. **Публикация плана рассылает push участникам — только по «да» Влада.** Черновик плана с
   workout ничего не рассылает.
8. Строка в журнал внизу этого файла.

## Посещение и дорожки

Иногда Влад присылает картинку «кто придёт» из приложения тренера: имена с номером дорожки в кружке.
Берём **только имена**; дорожки раскладываем нашей логикой, номера с картинки не переносим (решение
Влада, 22.11.2026).

1. **Сопоставить имена с составом.** Список людей занятия — `GET /api/hub-groups/17/rsvp/<ключ>`
   (поле `people`: `swimmer_id`, `user_id`, имя). На картинке только имя; в составе бывает «фамилия
   имя» и другое написание («פטר» = «איזבקוב פיטר»). Два кандидата или ни одного — спросить Влада.
   «ולדימיר» — сам Влад: аккаунт 1, пловец 7180.
2. **«Going»** — `PUT /api/hub-groups/17/rsvp/<ключ>` с `{ "answer": "yes", "swimmer_id": <id> }` за
   каждого (тренер отвечает за пловца, Р73); за себя — без `swimmer_id`. Пуша нет.
3. **Раскладка.** Кнопка Auto-arrange в интерфейсе раскладывает всех из «Unassigned», а там после
   «Create plan» лежит весь состав — поэтому зовём ту же серверную раскладку только для идущих:
   `POST /api/hub-groups/17/lane-plans/auto-lanes` с `{ lane_count, max_per_lane, reserved_lanes,
   swimmer_ids: [идущие], pinned: [] }` (параметры — из плана), ответ (`lanes`, `swimmers`) сохранить
   `PUT /api/hub-groups/17/lane-plans/<ключ>` с теми же `lane_count/max_per_lane/reserved_lanes`,
   `note`. Не названные в `swimmers` уходят в «Not today». Workout этот PUT не трогает.
4. **Без уровня** раскладка не ставит на дорожку — остаются в Unassigned, публикация их не пропустит
   (решение 10). **Уровень берём по цвету плашки вокруг имени** на картинке (решение Влада,
   22.11.2026): `PUT /api/me/hub-groups/17/swimmer-levels/<id>`, `{ levelId, subLevel }`, потом
   разложить заново. Цвета приложения тренера НЕ совпадают с нашими цветами уровней — сверено по
   пловцам, у которых уровень уже был:

   | Цвет на картинке | Наш уровень | id | Подуровень |
   | --- | --- | --- | --- |
   | красный | Advanced | 37 | 1 |
   | оранжевый | Advanced | 37 | 2 |
   | синий / голубой | Intermediate | 38 | 1 |
   | жёлтый | Developing | 39 | 1 |
   | зелёный | Beginner | 36 | — |

   Если у пловца с уже известным уровнем цвет на картинке говорит другое — не менять молча,
   сказать Владу. Новый цвет, которого нет в таблице, — спросить.
5. Публикация — как выше, только по «да» Влада.

## Как читать лист (диалект тренера)

Общие правила разборщика — §5.6 плана; ниже то, что встречается на листах и как мы это заносим.
Принцип «ничего не теряется»: что не легло в поля, остаётся в `text` строки.

- **«100X4»** — 4 повтора по 100 (дистанция первой, кратна 25).
- **Название сета** — строка без дистанции, часто с двоеточием: «זומרס:», «כפות:» → `title`
  без двоеточия. У первого сета (разминка) названия обычно нет — `title: null`.
- **«2.3 – 2.7», «2.0», «2.4 או 2.2»** — объём в км (нижний уровень – верхний), не сет.
- **Повторы диапазоном «100X4-3», «50X4-6», «100X3-4»** — верхним уровням больше, нижним меньше.
  Advanced и Intermediate — большее число (это `reps` строки), Developing и Beginner — меньшее
  (`per_level.<id>.reps`). Проверка — сходится объём листа. Подсказки в скобках вроде «(מי ששוחה 3
  בלי פרפר)» («кто плывёт 3 — без баттерфляя») — в `text`.
- **Время выхода диапазоном «1:45-2:15», «35-45», «יציאה 30-40»** — края лесенки по уровням,
  сверху вниз. Середину делим поровну и округляем до 5 с: «1:45-2:15» → 1:45 / 1:55 / 2:05 / 2:15;
  «1:10-1:30» → 1:10 / 1:15 / 1:25 / 1:30; «30-40» → :30 / :35 / :35 / :40. Прецедент — лист 17.11,
  где тренер выписал «1:45 \ 1:55 \ 2:05 \ 2:15» явно.
- **Времена списком «1:45 \ 1:55 \ 2:05», «1:40 | 1:50», «יציאה: 50 \ 55 \ 1:00»** — по уровню на
  значение, сверху вниз; разборщик это понимает.
- **Отдых «10'» после строки, «'15», «מנוחה '15»** — отдых в секундах (апостроф = секунды), одно
  значение всем уровням: `send_off: "rest :10"`.
- **Интенсивность «2V», «3V», «2-3V»** → `intensity`. «הגברה 1-4, 4V-1V» (наращивание) →
  `intensity: "1-4V"` (шкала рисует V1–V4), словесно — в `text`. Две нагрузки в строке («הלוך 2V
  חזור 4V», «1-פרפר 4V 1-חתירה 2V») — `intensity: null`, всё в `text`.
- **«1-(25 סגנון + 75 חת')»** внутри строки — порядок по повторам, это `text`, не отдельные строки.
- **Сокращения:** חת' = חתירה (кроль), סגנון — «свой стиль/выбранный», מעורב — комплекс, זומרס —
  ласты, כפות — лопатки, רגליים — ноги, גב — спина, חזה — брасс, פרפר — баттерфляй, כלב — «собачка»,
  מסרק — «расчёска» (упражнение), יד' ישרות — прямые руки, יציאה — время выхода, מנוחה — отдых.

Как истолкованы спорные места — пиши в журнал, чтобы Влад мог поправить правило, а не каждый лист.

## Пробелы разборщика (CF7)

Лист 22.11 через «Paste» разобрался бы плохо: «100X4-3» дал бы 4 повтора и «3» в тексте, «1:45-2:15»
и «35-45» без «יציאה» остались бы текстом, «יציאה 30-40» — :30 всем уровням, «10'» после строки не
стал бы отдыхом, а «4V-1V» порвался. Пока правила выше применяются руками. Научить им
`workout-parse.ts` — отдельная задача (тест — «лист 5» в `workout-parse.test.mjs`).
