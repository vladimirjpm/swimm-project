# Реестр UI-компонентов клиента

**Правило: прежде чем верстать ячейку, строку или бейдж — найди её здесь.**
Дублирующая вёрстка не просто некрасива: она молча теряет поведение, которое компонент уже
несёт (пометку «время под вопросом», фоллбек эмблемы клуба, формат даты, пояснение к
раунду). Расходится это не сразу, а через месяц, на новом экране, и чинить приходится в
пяти местах.

Компоненты живут в [`client/src/projects/components/mix/`](../client/src/projects/components/mix/)
(конвенция: одна папка = один компонент, экспорт `UI_*`). Крупные блоки — в
`components/deep/` и `components/`.

Добавил новый `UI_*` — добавь сюда строку. Не нашёл нужного и написал свою вёрстку — впиши
её в §5 с причиной, чтобы следующий не искал впустую.

**Посмотреть вживую — dev-витрина `/ui-kit.html`** (только на dev-сервере Vite; страницы нет
в `rollupOptions.input`, в прод-сборку она не попадает). Там компонент рендерится по-настоящему,
пропсы переключаются кнопками, состояние лежит в адресе — ссылкой на конкретный вид можно
поделиться. Реестр компонентов витрины — `client/src/dev/ui-kit/registry.tsx`: добавление
компонента туда = одна запись. Витрина показывает, КАК компонент выглядит; этот файл остаётся
ответом на «что уже есть и чего сознательно нет».

## 3. Заплыв: дисциплина, время, место

| Компонент | Рисует | Ключевые пропы |
|---|---|---|
| `UI_SwimmStyleIcon` | картинку стиля; `icon-len` печатает дистанцию | `styleName`, `styleLen`, `styleType='icon-notext'\|'icon-text'\|'icon-len'`, `lenPlacement='overlay'\|'below'\|'right'` — ГДЕ стоит дистанция в `icon-len` (31.08.2026): поверх иконки в углу (дефолт, как было всегда), строкой под ней или столбиком справа. Дефолт трогать нельзя — `overlay` стоит на дюжине экранов. Вне иконки подложка снимается: она была нужна, только пока число лежало НА рисунке. **Размер задаётся ступенью `size` (06.09.2026): одно значение = пара «картинка + кегль» — 48→10, 64→14, 96→24, 140→32** (таблица `SWIM_ICON_SIZES`, хелпер `swimIconSizes(size)` отдаёт ту же пару тем, кто рисует плитку сам). Тип ступени — числовой union, поэтому IDE подсказывает допустимые значения прямо в JSX. Точечные `iconSize` и `lenSize` перебивают ступень каждый по своей оси (`size={96} lenSize={12}` — та же картинка, число мельче). Задан только `iconSize` — кегль берётся долей от него (0.35, у пятизначной «10000» — 0.24, иначе не влезает); не задано ничего — как исторически: ширина из `className`, кегль 1.25em от плитки, то есть за `text-*` вызывающего. Классы `w-*`/`h-*` на кегль не влияют — это была главная путаница старого API. Тогда же снят пиксельный кегль из мобильного медиазапроса (19px/14px): он перебивал и `text-*`, и настройку компонента, из-за чего на экране уже 768px размер дистанции переставал слушаться вовсе. `lenPlate` — подложка под числом (плотность — токен `--swim-len-plate`): **включена по умолчанию в `overlay`** (06.09.2026, решение Влада) и выключена в `below`/`right`, где число стоит рядом с картинкой. Снять там, где иконка и так на белой плите (`swim-row__plate`), — `lenPlate={false}`. Тогда же удалён мобильный медиазапрос компонента целиком: он держал пиксельный кегль, безусловную подложку и дубль снятия фона — теперь одна модель на все ширины |
| `UI_PoolIcon` | бассейн: svg-дорожки либо подпись-«дорожка» `--25m--` / `-----50m-----` | `styleType`, `label`, `labelClassName`, `iconWidth`. ⚠ Подпись красится ПАРНЫМ токеном режима (`--theme-mode-text`), а не фиксированным серым: `text-gray-800` из палитры Tailwind в тёмной теме давал тёмное по тёмному — «50m» пропадала совсем (замер 1.01, починено 08.09.2026) |
| `UI_DateIcon` | дату: `cube` (плитка), `row-style-1` («30 Jul 2026»), `row-style-2` | `date` — `DD/MM/YYYY` ИЛИ ISO `YYYY-MM-DD` (оба формата реально есть в продукте: статика и API), `styleType`, `fontClassName` (⚠ иначе подставит свой серый мимо токенов) |
| `UI_PositionBadge` | кружок места; 1-2-3 красит медалью при `isAward` | `position`, `fallbackIndex`, `size`, `isAward` |
| `UI_RankOfPeers` | место в РЕЙТИНГЕ и круг сравнения: «#7» и под ним «of 36» | `rank`, `peerCount` (null — подписи нет), `isFirst`, `className`, `captionClassName`. Держит правило «alone» (меньше `MIN_PEERS_FOR_RANK` = 2 ровесников — сравнивать не с кем) и подпись для скринридера. ⚠ Не путать с `UI_PositionBadge`: тот про место В ПРОТОКОЛЕ и красит 1-2-3 медалью, а в сезонном рейтинге медалей не дают |

## 5. Крупные блоки (не в `mix/`)

| Компонент | Где | Рисует |
|---|---|---|
| `DeepSeasonCarousel` | `components/deep/season-carousel.tsx` | карусель сезонов: выбранный строго по центру, соседи кликабельны, свайп, `∞` = все сезоны |
| `DeepTabs` | `components/deep/tabs.tsx` | плитки-табы «папка» |
| `DeepEntityPage` | `components/deep/entity-page.tsx` (+ `entity-page-types.ts`) | **КАРКАС страницы сущности — клуб, пловец и группа.** Скелет «тема → топбар → плашки состояния → шапка → слот → папка табов → панель карточек», который до него был написан руками на каждой странице построчно одинаково. **Каркас тупой**: данных не грузит, про сезон/права/сущность не знает, DTO не нормализует. Два слота — `hero` (вариант шапки, каркас в неё не заглядывает) и `beforeTabs` (карусель сезонов, предстоящие старты). **Табы и карточки — ДАННЫЕ, а не разметка**: `tabs: EntityTabSpec[]` и `cards: () => EntityCardSpec[]`, поэтому «поменять порядок» = переставить элементы массива, «убрать» = не положить (`.filter(Boolean)`); `cards(nav)` — функция, тело считается только у активного таба; `nav.go(id)` переключает таб И поднимает страницу к верху «папки» (нужно дайджесту). `span: 'half'` ставит карточку в половину ширины от 960px (соседние `half` встают парой), `full` разрывает ряд. `locked` + `lockNotice` — «таб виден, но содержимое не положено» (в отличие от «не класть таб вовсе»). `?tab=` каркас держит сам **в обоих режимах** (правило «умолчание без параметра, `replaceState`, не `push`» живёт в одном месте): таб по умолчанию задаётся `defaultTabId` и не обязан быть первым в массиве (у пловца умолчание — `results`), чужой `?tab=` молча падает на первый. **Управляемый режим** (`activeTabId` + `onTabChange`) — когда страница сама гейтит по табу загрузку данных (пловец не шлёт запросы H2H, пока таб не открыт) или разбирает легаси-алиасы `?tab=history|pb|progress`; тогда `onTabChange` кладёт значение в своё состояние и адрес НЕ трогает. `noticeClassName` — если у страницы своя плашка (`.deep-notice` у пловца). `status` считает СТРАНИЦА — правило «Loading только когда данных нет вовсе» (иначе страница прыгает на каждом клике по фильтру). План и решения — [`docs/plans/entity-page-shell-plan.md`](plans/entity-page-shell-plan.md) |

## Как этим пользоваться

1. Собираешься показать данные — найди строку в §1–§5.
2. Компонент есть → бери его, даже если «тут проще написать span». Не подходит по виду —
   у большинства есть `className` / `*ClassName` для перекраски.
3. Компонента нет → проверь §6: возможно, отсутствие уже обдумано.
4. Написал своё → впиши в §6 с причиной. Написал `UI_*` → впиши в §1–§4.
