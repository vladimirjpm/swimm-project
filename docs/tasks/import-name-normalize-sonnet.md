# Задание Sonnet: нормализация имени пловца при матчинге в импорте

**Не запускай других агентов — делай всё сам. Не коммить: изменения оставь в рабочем дереве.**

## Контекст

Причина дублей пловцов найдена (см. `docs/tasks/next-front-plan-3.md` §2):
`JsonImportService` матчит пловца по ключу `LastName|FirstName|BirthYear` **точным
сравнением строк**. Протоколы isr.org.il непоследовательны в символах: еврейский гереш `׳`
(U+05F3) vs ASCII-апостроф `'` (U+0027), двойные пробелы, разный регистр латиницы
(`HARRISON` vs `Harrison`). Не нашлось → создаётся новый Swimmer. Так родились 29
«уверенных» дублей, и **после каждого следующего импорта они будут рождаться снова**.

Задача: нормализовать имя **только для матчинга** (ключ кэша/поиска). Хранимые данные
(`Swimmer.LastName` и т.д.) НЕ меняются — в БД остаётся оригинальное написание.

## Решения (зафиксированы, не пересматривать)

1. **Переиспользуем существующий нормализатор** `SwimmerDedupService.Normalize`
   (`server/Swimm.Infrastructure/Services/SwimmerDedupService.cs:100`) — именно по его
   правилам admin-отчёт дедупа нашёл те самые 29 пар, так что импорт и отчёт останутся
   консистентными. Никакого нового нормализатора и никакого fuzzy (Левенштейн в
   матчинг импорта НЕ тащить).
2. В `Normalize` добавить одну замену: правая типографская кавычка `’` (U+2019) → `'`
   (тот же класс «уверенных» различий, встречается в экспортах). Больше правил не
   добавлять.
3. Нормализуются **фамилия и имя по отдельности**, ключ:
   `$"{Normalize(last)}|{Normalize(first)}|{year}"`. Перестановку имя/фамилия НЕ
   матчить (единственный известный случай `שני עידו`/`עידו שני` Влад склеит руками) —
   иначе рискуем склеить разных людей.
4. Пустые значения: `Normalize(item.LastName ?? "")` — как сейчас (`?? ""`).
5. Спорные пары (`דרזנר דין`/`דרזנר שון` и т.п.) нормализация задевать НЕ должна —
   они различаются буквами, а не пунктуацией; тест на это обязателен.

## Что уже готово (не переделывать)

- `SwimmerDedupService.Normalize` — trim, lower-invariant, финальные ивритские буквы
  (ך→כ …), `׳`→`'`, `״`→`"`, схлопывание пробелов. Публичный static.
- Места матчинга в `server/Swimm.Infrastructure/Services/JsonImportService.cs`:
  - стр. ~136: предзагрузка кэша `swimmerCache.TryAdd($"{s.LastName}|{s.FirstName}|{s.BirthYear}", s)`;
  - стр. ~316: ключ поиска `var swimmerKey = $"{item.LastName}|{item.FirstName}|{item.BirthYear}"`;
  - стр. ~320–323: fallback-запрос в БД точным сравнением.
- Тестовая инфраструктура: `server/Swimm.Tests`, образец сервисных тестов —
  `SwimmerMergeServiceTests.cs` / `SwimmerDedupServiceTests.cs` (in-memory/SQLite паттерн смотри там).

## Шаги

1. В `SwimmerDedupService.Normalize` добавь ветку `'’' => '\''` (рядом с `'׳' => '\''`).
2. В `JsonImportService` заведи один приватный хелпер ключа:
   `private static string SwimmerMatchKey(string? last, string? first, int? year) =>
   $"{SwimmerDedupService.Normalize(last ?? "")}|{SwimmerDedupService.Normalize(first ?? "")}|{year ?? 0}";`
   и используй его в ОБОИХ местах — предзагрузке кэша (~136) и поиске (~316).
   При предзагрузке `TryAdd` оставь как есть: существующие в БД дубли схлопнутся на
   первую запись — это ожидаемо, остальное лечит ручной merge.
3. Fallback-запрос в БД (~320–323) оставь точным сравнением, как есть (SQL не умеет наш
   Normalize; кэш предзагружает всех пловцов, fallback — страховка на коллизии).
4. Тесты (обязательно), новый файл `server/Swimm.Tests/SwimmerImportMatchingTests.cs`:
   - гереш vs апостроф: в БД пловец `בויצ׳וק ניר` (гереш), импорт item с `בויצ'וק`
     (апостроф), тот же год → новый Swimmer НЕ создаётся, результат вешается на
     существующего;
   - типографский `’` vs `'` → матч;
   - `HARRISON Zaq` vs `Harrison Zaq` → матч;
   - двойной пробел внутри имени → матч;
   - **разные люди НЕ склеиваются**: `דרזנר דין` vs `דרזנר שון`, один год → два Swimmer;
   - перестановка `שני עידו` vs `עידו שני` → НЕ матч (два Swimmer);
   - разный BirthYear при одинаковом имени → НЕ матч.
   Прямые юнит-тесты на `Normalize` (новые ветки) можно добавить в существующий
   `SwimmerDedupServiceTests.cs`.

## Проверка

```bash
dotnet build server/Swimm.sln

```
Все существующие тесты должны остаться зелёными (сейчас 277/277).

## Footguns

- Build-lock: если `dotnet build` падает с MSB3027 («Swimm.API.dll is locked») —
  Visual Studio/осиротевший `dotnet run` держит файл; обход: `--configuration Release`
  либо погасить процесс `Swimm.API.exe`.
- Тесты НЕ ходят в сеть и НЕ трогают живую БД.
- Два DbContext — но для этой задачи EF-миграций нет вообще (схема не меняется).

## Вне скоупа (не делать)

- Никакого fuzzy/Левенштейна в импорте; никакой перестановки имя/фамилия.
- Не менять хранимые имена пловцов и не «чистить» существующие данные БД.
- Не трогать merge/dedup UI и `SwimmerMergeService`.
- Не трогать матчинг клубов/соревнований (там свои ключи — отдельная тема).
