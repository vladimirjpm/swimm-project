# docs/tasks — архив заданий, а не статус

Здесь лежат **задания и планы на момент постановки работы**: что нужно сделать, из чего
исходить, чего не переделывать. Их пишут перед работой (часто — чтобы отдать делегату,
`*-sonnet.md`), а после неё **не переписывают**.

> ⚠ **Раздел «что уже готово» / «не сделано» внутри задания — это снимок того дня.**
> К моменту чтения он почти наверняка устарел: задание на то и писали, чтобы состояние
> изменилось. Не принимай его за текущее положение дел.

**Где правда о статусе:**

| Вопрос | Куда смотреть |
|---|---|
| Фаза сделана или нет | [`../ROADMAP.md`](../ROADMAP.md) — единственный источник правды по фазам |
| Незакрытая работа, открытые решения | [`../plans/README.md`](../plans/README.md) |
| Как устроено сейчас | тематические доки: [`../data-integrity.md`](../data-integrity.md), [`../relays.md`](../relays.md), [`../media-page.md`](../media-page.md), [`../competition-overview-cards.md`](../competition-overview-cards.md), [`../ui-components.md`](../ui-components.md), [`../admin-pages/README.md`](../admin-pages/README.md) |

**Зачем тогда хранить.** Ради «почему так»: разобранные развилки, отвергнутые варианты,
контракты API и footguns, которые иначе переизобретут. Дизайн-материал (инвентарь данных,
блоки UI) живёт отдельно — в `docs/design-handoff-*.md` и `!design_handoff/`.

**Заводя новое задание** — ставь дату в заголовке и не описывай состояние проекта шире, чем
нужно для задачи: чем меньше в файле «сейчас у нас так», тем дольше он остаётся полезным.
