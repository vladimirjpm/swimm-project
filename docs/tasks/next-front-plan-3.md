## 1. Merge пловцов — РАЗОБРАН, ждёт решения Влада (к БД НЕ применялось)

Кандидатов **50**: 29 `sure=true` + 21 спорных. Анализ проведён, выводы:

- **29 уверенных — безопасны.** Все различаются одним символом: еврейский гереш `׳`
  (U+05F3) vs ASCII-апостроф `'` (U+0027). Одно исключение — `שני עידו`(6684) ←
  `עידו שני`(7066): перестановка имя/фамилия, клуб и год совпадают.
  Пересечений Id среди 29 НЕТ → защита A2 не сработает, dry-run пройдёт.
- **21 спорных — НЕ склеивать массово. Там живые разные люди:** `דרזנר דין` / `דרזנר שון`
  (брат/сестра, один клуб, 2015, по 8 результатов), `אגבאריה מיאר/ליאן/ביסאן`,
  `סלעי תום/אדם`, `גבארין באנה/איה`, `מחאמיד נאיא/ניל`, `ערבה אגם/אדם`.
  Dry-run их НЕ поймает (заплывы не пересекаются) — защита только глаза Влада.
  Отдельно: мусор из тренировок «דולפין נתניה» (`אדם ט`/`אדם פ`/`אדם`, `עודד`/`עדי`,
  `עילי`) — 0 результатов, без года; им место в сиротах, не в merge.
  Реальные кандидаты среди спорных: `HARRISON Zaq`/`Harrison Zaq` (регистр),
  `NUSEM Shiri`/`Nusem Shiri` (клуб на иврите vs латиницей), `גומשפן יעל`/`גופשפון יעל` (опечатка).

**Проверено, что merge безопасен** (на случай сомнений Влада):
- Дубли — это НЕ задвоенные результаты, а расщеплённая история: напр. `בויצ'וק ניר`
  5814 = соревнование 57 (16/02/2026, 4 заплыва), 59202 = соревнование 1486
  (15/07/2026, 3 заплыва). После склейки — один пловец с 7 заплывами.
- Результаты не удаляются, а перевешиваются (`r.SwimmerId = canonical.Id`);
  удаляется только карточка дубля.
- На `Swimmers` ссылаются ровно 8 таблиц — все 8 сервис перевешивает поимённо.
  У `Results` и `Sys_TrainingResults` FK = `ON DELETE RESTRICT` → БД физически не даст
  удалить пловца с результатами. Забытых каскадов нет.
- Живой dry-run пары 5814←59202 вернул: `["Results: 3 → canonical", "Swimmer 59202 удалён"]`,
  conflicts пусто; БД после dry-run не изменилась (проверено).
- Теряются только поля карточки дубля (клуб/страна/аватар), если у канонического они
  заполнены. У 29 уверенных клубы совпадают; история клубов живёт в `Results.ClubId`.

**UI-порядок** (`/Admin/Swimmers`): «Отметить уверенные» (проставит 29 галок) →
«Dry-run выбранных» → красная «Применить» (разблокируется только после чистого dry-run;
любое изменение галок сбрасывает dry-run). Кнопки массового удаления сирот НЕТ (это B2).

## 2. ПРИЧИНА дублей найдена — дешёвый фикс не сделан

`JsonImportService.cs:315` — ключ пловца `$"{LastName}|{FirstName}|{BirthYear}"`,
поиск в БД **точным сравнением строк**, никакой нормализации. Не нашлось → новый Swimmer.
`SwimmerOrgId` в матчинге НЕ участвует (в протоколах isr.org.il ID пловца нет).

Поэтому гереш vs апостроф = два разных человека. **После следующего импорта дубли
появятся снова** — склейка 29 пар лечит следствие, не причину. Свежий пример:
59202 приехал импортом от 15/07/2026.

**Предложено (Влад не решил):** нормализация имени перед сравнением — гереш→апостроф,
гершаим→кавычки, схлопывание пробелов, регистр для латиницы. Закрывает ~все 29 случаев
+ `HARRISON`/`Harrison`. Хорошо специфицируется → Сонету. Настоящее лечение —
loglig HTML как источник реальных ID (B5-перспектива ниже).

Сонету — механика с ясной спецификацией; в промпт ОБЯЗАТЕЛЬНО «не запускай других
агентов, делай сам»; таск-доки `docs/tasks/*-sonnet.md` самодостаточные; коммит отдельно.
Fable — дизайн/вид (топбар, темы). Сам (Opus) — auth/безопасность, миграции с
неочевидными последствиями, исследование loglig, приёмка и коммиты за агентами.
Параллельным агентам — worktree-изоляция (`isolation: "worktree"`), забирать
cherry-pick'ом; worktree после — удалять.

## Footguns (наследие)

- Build-lock :5078 (Stop-Process осиротевших Swimm.API); Release + :5079 при занятом;
  клиент с `SWIMM_API_TARGET=http://localhost:5079` (конфиг `client-5079` в launch.json).
- Два DbContext: EF-команды с `--context SwimmDbContext`.
- Синтетика 3М (`Note='SYNTH'`, `SwimmerOrgId LIKE 'SYNTH-%'`) — НЕ удалять;
  merge её отсекает сам.
- isr.org.il/loglig — чужой прод: троттлинг не обходить; тесты НЕ ходят в сеть
  (фикстуры в `Swimm.Tests/Fixtures/Discovery`).
- Merge пловцов необратим; применение только из UI после dry-run и «да» Влада.
- Tailwind админки: после правок классов в `Pages/Admin` — `npm run css:build` и коммит
  `admin.min.css`. Для клиента (Vite) этого делать НЕ надо.
- DevAdminBypass работает только в Development — живые проверки админки без логина.
- Antiforgery: админские POST требуют `X-XSRF-TOKEN` (токен `_csrfToken` рендерится в
  страницу; для curl — вытащить со страницы + cookie jar).
