# Задание (Sonnet 5): стартовый протокол — витрина (С7, С8)

## Контекст

Фича «когда и на какой дорожке плывёт мой ребёнок»: перед соревнованием тянем с loglig
стартовый протокол и показываем родителю. Полный план — [`docs/plans/start-list-plan.md`](../plans/start-list-plan.md);
**обязательно прочитай §4** — там продумано, что именно видит человек, с макетами в тексте.

Сервер готов целиком. Твоя работа — клиент: таб на карточке соревнования с тремя уровнями
приближения (С7) и вход по ссылке + блок на странице пловца (С8).

## Решения (зафиксированы, не пересматривать)

1. **Шестой таб карточки соревнования, а не новая страница.** Шелл табов уже работает,
   добавление таба — строка в массиве. Бонусом таб попадает под уже существующие
   `Disallow: /competitions` в `robots.txt` и `noindex` в точках входа: отдельный маршрут
   `/start-list` пришлось бы закрывать заново.
2. **Три уровня приближения на одном табе**, не три страницы: программа дня → заплыв с
   дорожками → карточка пловца. `?swimmer=` открывает сразу третий, `?heat=` второй,
   ничего — первый.
3. **Время показываем приблизительным: `≈14:45`.** Программа в бассейне регулярно отстаёт
   на 20–40 минут; на бортике ориентируются по НОМЕРУ заплыва из громкоговорителя.
   Поэтому номер заплыва и номер события — крупно, время — со значком «≈».
4. **Посевное время — не результат.** В выдаче оно приходит с `quality: "seed"`. Это личный
   рекорд С ДРУГОГО старта. Подписывай его явно («seed 01:42.72» или «entry time»), рядом
   с результатами без пометки не показывай — это инвариант И11.
5. **`SwimRow` НЕ переиспользуем.** Он рисует место / плитку стиля / кто / время / очки /
   дату / дугу уровня — заявка заполняет два слота из семи. Переиспользуем КЛЕТКИ:
   `UI_SwimmStyleIcon`, `UI_SwimmerNameCell`, `UI_SwimTime`. Ищи их в
   `client/src/projects/components/`.
6. **Мобильный — основной вид**, не адаптация: родитель смотрит это стоя у бортика.
   Время и номер заплыва крупно, никакой горизонтальной прокрутки.
7. **Автообновления нет.** В проекте нет ни поллинга, ни SSE, и заводить их тут не надо.
   Вместо этого: метка «updated HH:MM» из поля `updated_at` + кнопка «Refresh».
8. **Весь видимый текст — по-английски** (правило проекта). Комментарии в коде — по-русски,
   как в соседних файлах.

## Что уже готово (не переделывать)

### API (всё анонимное, snake_case, ETag + `Cache-Control: max-age=30`)

| Запрос | Отдаёт |
|---|---|
| `GET /api/start-list/{orgCompId}` | программа: `{org_comp_id, comp_name, days[{date, events[]}], entries, updated_at}` |
| `GET /api/start-list/{orgCompId}/events/{orgDisciplineId}` | `{event, heats[{heat, start_at, round, lanes[]}], updated_at}` |
| `GET /api/start-list/{orgCompId}/swimmers/{swimmerId}` | `{swimmer_name, birth_year, club_name, first_start_at, swims[], updated_at}` |
| `GET /api/start-list/{orgCompId}/clubs/{clubId}` | массив заплывов клуба |
| `GET /api/start-list/upcoming?swimmerId=1&swimmerId=2&days=21` | массив ближайших заплывов |
| `GET /api/start-list/competitions?days=60` | предстоящие соревнования: `[{org_comp_id, comp_name, date_start, date_end, days, entries, swimmers, updated_at}]` |

Нет заявок → `404` (программа/заплыв/пловец). Пустой список для клуба → `200` и `[]`.

**Строка заплыва** (`swims[]`, `lanes[]`) — поля:
`id, org_discipline_id, event_number, distance, style_name, gender, event_category,
age_band, is_relay, heat, lane, heat_start_at, round, seed_time, quality, swimmer_id,
swimmer_name, birth_year, club_id, club_name, result_id, status`.

- `heat_start_at` — **UTC, может быть `null`** (время заплыву ещё не назначили). Показывай
  в местном времени браузера; `null` → «time TBA», а не пустое место.
- `seed_time` — `null` значит «NT» (пловец эту дистанцию ещё не плыл).
- `status` — `entered | swum | no-show`.
- `is_relay` — у эстафеты **четыре строки с одинаковыми `heat` и `lane`** и разными
  пловцами: это одна команда. В виде заплыва (зум 2) склеивай их в одну строку-команду.

Живые данные для разработки уже в локальной БД: **`compID 16835`** (4 события, 137 заявок,
статусы `swum`) и **`compID 16786`** (60 событий, 989 заявок, один день).

## Шаги

### 0. Сервер: отдать `org_comp_id` в overview соревнования (маленький, но обязательный)

Карточка соревнования знает наш `Competitions.Id`, а стартовый протокол адресуется
по `orgCompId` — сейчас клиенту его взять неоткуда.

В `server/Swimm.Application/Dtos/CompetitionOverviewDto.cs` добавь
`[JsonPropertyName("org_comp_id")] public int? OrgCompId { get; init; }` и заполни его
в `server/Swimm.Infrastructure/Repositories/ResultRepository.cs` (там, где собирается
`CompetitionOverviewDto`). Источник значения: `Competition.OrgCompId`, а если он пуст —
`Competition.Event.OrgCompId` (у многодневки штамп стоит на событии; см.
`CompetitionIdentity`). `null` — законное значение: соревнование могли завести руками.

**Таб «Start list» показывай только когда `org_comp_id != null`** — иначе спрашивать нечего.

### 1. С7 — таб с тремя уровнями

1. Добавь `'startlist'` в `CompetitionTab` и в `VALID_COMP_TABS`; в `competition-tabs.tsx` —
   таб `Start list` со счётчиком (`entries` из программы). Таб рисуй, только если
   `org_comp_id != null` и программа не вернула 404 (по образцу таба `Records`, который
   тоже условный).
2. **Зум 1 — программа дня.** Лента по времени, сгруппированная по дням (у многодневки
   несколько дней). Строка: `≈HH:MM · #номер · дистанция + стиль · категория · N заявок`,
   клик разворачивает зум 2. Макет — §4.1 плана.
3. **Зум 2 — заплыв.** Дорожки по порядку, у каждой имя, год, клуб, посевное время.
   Эстафету (`is_relay`) показывай одной строкой-командой с четырьмя именами.
4. **Зум 3 — карточка пловца.** Его 2–5 заплывов за день. Сверху — **«First start ≈HH:MM»**
   и **«Arrive by»** = первый старт минус разминка (константа в коде, 45 минут, с
   комментарием, что это эвристика, а не данные источника). Макет — §4.3 плана.
5. **Поиск по имени** на табе: одно поле, ищет **среди участников этого соревнования**
   (данные уже пришли в программе/выдаче — отдельный эндпоинт не нужен). Совпадение с двух
   букв, без хитрого ранжирования: участников ~500, а не вся база.
6. **Фильтр по клубу** — через `FilterHost`, если он ложится дёшево; если нет — простой
   селект клубов из уже загруженных данных. Не изобретай второй хост фильтров.
7. **Метка «Updated HH:MM» + кнопка Refresh** (решение 7).

### 1a. С7б — предстоящие в общем списке соревнований (решение В9 Влада)

Без этого фича бесполезна ровно там, ради чего делается: у соревнования, которое ещё не
проходило, нет строки в `Competitions`, а значит нет и карточки, на которой жил бы таб.

1. **Секция «Upcoming» на `/competitions`** (`client/src/projects/competitions-project/competitions.tsx`)
   — над существующим списком прошедших. Источник — `GET /api/start-list/competitions`.
   Пусто → секции нет вовсе (а не «нет предстоящих»).
   Строка: название, даты (`19–20 Feb`), «N entries · M swimmers», метка `updated_at`.

2. **Новый маршрут `/competitions/upcoming/{orgCompId}`** в `client/src/utils/routes.ts`.

   ⚠ **Почему отдельный сегмент, а не `/competitions/{orgCompId}`.** В пути
   `/competitions/{id}` живёт наш внутренний `Competitions.Id`, а `orgCompId` — id сайта
   федерации. Это ДВА РАЗНЫХ пространства чисел: 16786 может оказаться и тем, и другим,
   и страница молча открыла бы чужое соревнование. Сегмент `upcoming` их разводит.

   Маршрут ведёт на ту же точку входа `results_main.html` (значит наследует `noindex` и
   `Disallow: /competitions` из `robots.txt` — новую дыру в индексации не копаем).
   Правь **все четыре зеркала контракта**, они перечислены в шапке `routes.ts`:
   `routes.ts` → `client/vite.config.js` (dev-rewrite) → `Program.cs` (прод-rewrite) →
   `server/Swimm.Infrastructure/Services/DataChecks/PublicRoutes.cs`.

3. **Страница предстоящего старта** — тот же шелл `results-main-project`, но:
   шапка соревнования без цифр результатов (их ещё нет), из табов **только Start list**,
   и он же открыт сразу. Никаких Overview/Swims/Clubs/Records — соревнование не проходило.
   Данные берутся по `orgCompId` из пути, а не из `org_comp_id` overview (его тут нет).

4. Когда протокол импортируют, соревнование появится в обычном списке со своей карточкой,
   а старый адрес `/competitions/upcoming/{orgCompId}` обязан продолжать работать: ссылку
   уже переслали в родительский чат. Заявки никуда не деваются, эндпоинты продолжают
   отвечать — просто ничего не ломай.

### 2. С8 — вход по ссылке и «мои старты»

1. `?swimmer={swimmerId}` на табе: открыть сразу зум 3 этого пловца, проскроллить к нему.
   Это тот самый адрес, который пересылают в родительский чат:
   `/competitions/{id}?tab=startlist&swimmer=8241`. **Логин не нужен** — ничего не прячь
   за авторизацией.
2. `?heat={orgDisciplineId}` — открыть зум 2 этой дисциплины.
3. **Блок «Upcoming starts» на странице пловца** (`swimmer-project.tsx`): дёрни
   `/api/start-list/upcoming?swimmerId={id}` и покажи ближайшие заплывы со ссылкой на
   таб соревнования. Пусто → блок не рисуем вовсе (не «нет данных»).
4. **Избранные.** Если пользователь залогинен (`useAuth`), возьми его favorites и
   запроси `upcoming` со всеми `swimmerId` разом (эндпоинт принимает список). Куда
   поставить блок — на главной или на странице пловца — реши сам и напиши в отчёте.

## Footguns

- **Build-lock.** `dotnet build` падает с `MSB3027/MSB3021 … locked by ".NET Host (pid)"` —
  это живой `dotnet run`. Процесс называется `dotnet.exe`, **не** `Swimm.API.exe`.
- **`heat_start_at` в UTC.** Показывать надо местное время. Не пиши свою арифметику
  часовых поясов — сервер уже перевёл израильское местное в UTC, браузеру достаточно
  штатного форматирования.
- **`null` у времени — норма**, а не ошибка данных: заплыву могли ещё не назначить время.
- **Эстафета** — четыре строки с одинаковыми `heat`/`lane`. Не показывай их как четырёх
  отдельных участников на четырёх дорожках: дорожка одна, команда одна.
- **`quality: "seed"`** — не рисуй посевное время тем же компонентом и в том же виде, что
  результат заплыва (И11). Это время с другого старта.
- **Порядок событий**: сортируй по `start_at`, а у событий без времени — по `event_number`,
  иначе они всплывают в начало дня.
- **Не трогай** `swim-row`, `results-table`, `season-best` — стартовый протокол к ним
  отношения не имеет, и правки там ломают чужие экраны.
