## 2. Корень И-62: PDF сводит «כללי» обоих полов в один список

- Страница события loglig (кнопка «תוצאות קטגוריות»,
  `https://loglig.com:2053/LeagueTable/AthleticsDisciplineResults/{id}?isModal=True&showCategories=True`)
  всегда **одного пола** и делится на секции: «גמר ישיר - בנות 13», «… - כללי».
- PDF-экспорт, из которого мы импортируем, печатает «כללי» девочек и мальчиков **одним списком**:
  пол `none`, места сквозные 1…N. Пол импорт потом восстанавливает по карточкам пловцов (Р47), а
  место остаётся сквозным — у девочки 3-е место превращается в 8-е.
- В 16891 у 2015 г.р. (12 лет) своей возрастной секции не было: секция «13» — только 2014, «11» — только
  2016, все двенадцатилетние легли в «כללי». Значит, «כללי» для них — **единственная** секция, места в ней
  настоящие, медали вручали. Поэтому старое правило Р43 («כללי» — открытый финал без медалей и очков)
  здесь не действует: в data-integrity у Р43 записано исключение.
- Масштаб в 16891: 401 строка в «כללי», неверное место у 377, медаль — у 36.

### Два вида «כללי» (правило в коде — `LogligPlaceMatcher.OpenSectionsSplitByYear`)

| Вид | Где | Как считать места |
|---|---|---|
| **Остаток без своей секции** — в «כללי» есть пловец, чей возраст лежит МЕЖДУ младшей и старшей возрастной секцией события, а своей секции у него нет | Эйлат 16891 (секции 11 и 13; 12-летние + четверо 18-летних 2009 г.р.) | внутри **пола + года рождения** (решение Влада 07.11: «Да, по году») |
| **Общий зачёт старших** — в «כללי» только те, кто старше всех возрастных секций | детские лиги: секции 9–13, «כללי» 14–18 лет | внутри **пола** (решение Влада 07.11: «Только по полу»), как на странице loglig |
| **Открытый зачёт чемпионата** — в «כללי» взрослые и отдельные пловцы МЛАДШЕ всех секций, плывущие «вверх» | национальные чемпионаты 273, 166 (секции 15, 16, «17-18») | внутри **пола** (решение Влада 08.11: «Да, сужай»); раньше правило раздавало «1-е место» каждому году |

Почему в Эйлате по году: страница loglig ранжировала 18-летнего מטביי קוצירנקו (2009) вместе с 12-летними,
и он отнимал у них золото. Награждали по возрасту — у קינסברונר действительно 4 золота, у לוקה 3 серебра.
Почему в лигах по полу: по году вышло бы по четыре «первых места» на дисциплину.

- На проде: PR #159 (e3015147).

  не проверено, задумано ли.

## 4. Инструмент `--pull-places` и сопутствующие фиксы

```bash
dotnet run --project server/Swimm.API --no-build --launch-profile ProdAdmin -- --pull-places <discoveredId> [--apply] [--report file.tsv]
```

- Без `--apply` — только смотрит (так прошла вся сверка §5). С `--apply` пишет в прод — **только по
  слову Влада на конкретное соревнование**.
- Код: `Swimm.Application/Mapping/LogligPlaceMatcher.cs` (чистая логика),
  `Swimm.Infrastructure/Services/LogligPlaceRepairService.cs` (I/O),
  `Swimm.Application/Abstractions/ILogligPlaceRepairService.cs`, CLI — `LogligCli.PullPlacesAsync`.
- **Ключ пары:** день + дисциплина + дистанция + пол + заплыв + дорожка. Имена не сравниваются.
  Пара доказана, только если совпали время и год рождения; иначе строка идёт в «расхождения», место
  не трогается.
- **Место** — по номерам секции источника, но среди строк со временем: страница нумерует подряд и снятых
  (снятый 11-й → следующие 12, 13), а в PDF и у нас они 11, 12.
- **Пишет только «כללי».** Расхождения мест в возрастных секциях показывает и не трогает (Р76: это
  напечатано в протоколе).
- Дубль ключа (один заплыв+дорожка у двоих) → план целиком неприменим (`dup-keys`).
- Дни события — через `CompetitionIdentity.ResolveDaysAsync`. `Competitions.OrgCompId` уникален и стоит
  только на одном дне, поэтому искать дни по `OrgCompId` нельзя. На этом же споткнулся ремонт эстафет
  (`LogligRelayBandService`, починен тем же швом).

### Попутные фиксы парсера страниц loglig (`LogligEventResultsParser`)

1. Личное событие без клубного зачёта — 8 колонок с годом рождения. Парсер принимал его за мастерскую
   эстафету и съезжал на колонку. Теперь год узнаётся по содержимому ячейки. Фикстура
   `event-85705-200im-girls-noclubpoints.html`.
2. Время с часами «00:00:00.00» читалось как «00:00.00» плюс статус «00:». Теперь нулевое время —
   «времени нет, статуса нет». Фикстура `event-85623-50free-boys-zero-time.html`.
3. (И-60) Страница эстафеты без клубного зачёта — 7 колонок, парсер ждал 8–10 и отдавал 0 строк.

### Правило Р90: место без времени

Влад: «первое место без времени может быть первым… пока оставь первым, запиши несоответствие и поставь
предупреждение… под проверкой».

- Строка личная, времени нет (пусто, «00:00.00», «00:00:00.00»), статуса снятия нет (NS/DNS/DQ/DNF), а место
  напечатано → хранится как **проплытая**: место из протокола, `TimeFail = false`, времени нет,
  `SuspectReason = placed_without_time` (чип «Under review»).
- Единое определение — `SuspectReasons.IsPlacedWithoutTime`. Им пользуются импорт (`JsonImportService.AddRecord`),
  проверка качества (`SuspectResultDetector`, правило 0) и сверка (`PlacedWithoutTime` у строки источника).
- Со статусом номер по-прежнему не место (И-18).
- В 16891 таких 2 строки (50 вольным, мальчики 13: двое на 1-м месте без времени).

### Ручные правки в 16891 (с разрешения Влада, `/Admin/Results/Edit`)

- בן להמן, 50 баттерфляем, мальчики 13: у нас 00:34.62 / 3-е место, в протоколе (поправлен организатором

- ⚠ **Перезабор опасен у соревнований, где протокол кладёт пловцов в секцию чужого пола** (девочки в
  «בנים 14»): он не просто дублирует, а перезаписывает чужие строки того же заплыва/дорожки. Перед
  `--repull` такого соревнования — сравнить пол строк с полом секции.
- **Починено в коде 07.11** (`ResultMatcher.SamePerson.cs`, отдельный файл поверх `ResultMatcher`):
  1. *тот же пловец под другим полом* — у пловца есть его старая строка на том же месте (заплыв,
     дорожка, раунд, сессия) с другим полом, пара однозначна → сопоставляются ДО ключевого матча;
     пол остаётся хранимый (`ResultMatch.CrossGender`, в импорте — строка журнала «оставлен хранимый»);
  2. *чужую строку не забирать* — FIFO не берёт строку опознанного пловца, если тот сам есть в файле
     под этим ключом.
  Только для опознанных пловцов (SwimmerId > 0) и личных строк — анонимные ноги эстафет, переименование
  (Р5) и обычный матч не задеты. Тесты `ResultMatcherSamePersonTests` (7). Проверено вживую: локальная
  копия comp 1580 (снята до перезабора) → `--repull 98`: 501 обновлено, 0 вставлено, сверка сошлась,
  14 строк «пол в файле ≠ в базе» сохранили свой пол — перекос в этом протоколе в обе стороны
  (и мальчики в девичьих секциях).
- Других соревнований с временем в `TimeFailNote` в базе нет (запрос выше — по всем, не только loglig).
- У comp 1855 у нас имя «איגוד השחייה בישראל», у loglig — «ליגה צפון 1 בית איל» — заодно поправить.

### 6.3 `dup-keys` — общий ключ у чемпионатов (починено 07–08.11, пересверено)

**Причина.** У чемпионатов loglig заводит отдельное событие на каждый возраст, и заплывы в каждом
нумеруются с 1. Поэтому «дата + стиль + дистанция + пол + заплыв + дорожка» на стороне источника
не уникальны. То же у «мокдамот и финал»: дорожка одна и та же в обоих раундах.

**Фикс.** `LogligPlaceMatcher.Pairing.cs`. Строки с общим ключом сводятся по доказательству
(то же время и тот же год рождения). Остаток 1:1 сводится в пару, всё прочее идёт в `Problems`
(«пары не доказаны»), и запись тогда запрещена. Места считаются внутри события и раунда loglig
(`PlaceRowFromSource.Event`, `.Round`). Тесты — `LogligPlaceMatcherTests`, 17/17.

**Пересверка 49 соревнований (08.11, только чтение, сборка `bin/alt`).** Ни одного «пары не
доказаны». Детских — 40.

## 8. Как повторить сверку

```bash
# список discoveredId (loglig-соревнования, уже импортированные) — ids.txt, по одному в строке
bash docs/investigations/2026-11-07-loglig-places-sweep/sweep.sh <папка с ids.txt>
```

- Идёт ~2–3 ч на 237 соревнований; продолжает с места обрыва (пропускает id, уже записанные в `summary.tsv`).
- Требует ProdAdmin-профиль (читает прод-базу, ничего не пишет без `--apply`).

### Footguns, на которые наступили

- **Сторож обязателен.** `timeout` в Git Bash не снимает дерево dotnet на Windows; ночью соревнование #49
  висело 8 ч. В скрипте — `taskkill //F //T //PID $(cat /proc/$bpid/winpid)` через 15 мин.
- **Остановка фоновой задачи не убивает детей** `bash sweep.sh` и `dotnet --pull-places`. Гасить через
  PowerShell: `Get-CimInstance Win32_Process` с фильтром по `*sweep.sh*` / `*--pull-places*` → `Stop-Process`.
- **Пока идёт сверка или ProdAdmin — сборка падает** MSB3027 (DLL заняты). Сначала погасить.
- `prod-sql.mjs` нужен Docker (psql в контейнере `swimm-postgres`).
- EF expression tree не принимает именованные аргументы не по порядку (CS9307) — в проекции
  `SuspectResultService` аргументы позиционно.
- `ProdAdmin` при старте делает `git fetch`; сетевая ошибка — просто повторить.
- **Кодировка лога из Git Bash.** Если `dotnet` запускать не из того окна, кириллица и «»
  превращаются в «?», и `grep '^«'` в скрипте ничего не находит. На 08.11 все 49 строк
  получили `no-report`, хотя прогоны прошли. Цифры в логе целы, разбор шёл по позиции строк.
  Надёжнее брать итог из `report-<id>.tsv` (он в UTF-8) или запускать из PowerShell с
  `[Console]::OutputEncoding=UTF8`.
