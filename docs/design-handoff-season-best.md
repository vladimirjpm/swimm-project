# Тех-бриф для дизайнера: страница `/season-best`

Входные данные для дизайна страницы «списки лучших в сезоне». Всё, что здесь написано,
проверено по коду и по локальной БД 26/08/2026 — это факты, а не пожелания.

Задача словами Влада: **на каждую связку стиль × дистанция × бассейн — список результатов.
Если первые два результата у одного пловца — так и писать. Фильтры по возрасту, полу и
клубу, в строке дата, название соревнования и очки FINA. Карусель сезонов. Фильтры и шапка фильтров —
как на странице results, лишние фильтры убрать (дата, name, position, best level). Всё
модульно, каждый блок легко включается/выключается в HTML. Всё на токенах темы, есть тёмная
и светлая.**

### Адрес — единственный носитель состояния

Идентичности в пути у списка нет, весь фильтр живёт в query (правило `routes.ts`: в путь —
только идентичность ресурса). Генератор и парсер лежат рядом в `routes.ts`:

```
/season-best?season=2025&age=12&gender=female&stroke=freestyle&distance=100&pool=25m&swimmer=7793
```

| Параметр | Значение | Примечание |
|---|---|---|
| `season` | год **начала** сезона: `2025` = «2025/26» | |
| `age` | возраст **в сезоне** | не возраст на дату заплыва |
| `gender` | `male` / `female` | |
| `stroke` | `freestyle`, `backstroke`, `breaststroke`, `butterfly`, `individual_medley` | машинный ключ, в UI `_` → пробел |
| `distance` | без «m»: `50`, `100`, `200` | |
| `pool` | `25m` / `50m` | |
| `swimmer` | кого подсветить в списке | на выборку не влияет |

Любой параметр может отсутствовать — это законный адрес. Дизайн обязан отвечать на вопрос
«что показать, когда дисциплина не выбрана» (§10).

## 2. Реальные данные: что можно показать в строке

Поля берутся из таблицы `Results` + связанные. Всё ниже **уже есть в БД и уже отдаётся**
похожими эндпоинтами — выдумывать ничего не надо:

| Поле в UI | Источник | Заполненность |
|---|---|---|
| Время | `Results.TimeOriginal` («01:02.49»), `TimeMillisecond` для сортировки | 100% |
| Очки FINA | `Results.InternationalPoints` | **100%**, NOT NULL |
| Дата | `Results.CompetitionDate` → формат `DD/MM/YYYY` | 100% |
| Соревнование | `Competitions.Name` | 100%, **часто на иврите** (см. §7) |
| Пловец | `Swimmers.LastName/FirstName` + `LastNameEn/FirstNameEn` | EN-имя есть не у всех |
| Клуб | `Clubs.Name` + `Clubs.NameEn` | 235 клубов; **у 205 настоящее английское имя**, у 30 `NameEn` — копия ивритского (см. §6.5) |
| Логотип клуба | `public/images/club-icon/*.png` + `club-icons-manifest.json` | **всего 34 логотипа на 235 клубов**, остальным `no-club.png` |
| Бассейн | `Competitions.PoolType` = `25m` / `50m` | 100% |
| Возраст в сезоне | вычисляется: `год окончания сезона − BirthYear` | `BirthYear` есть не у всех |
| Пол | `Swimmers.Gender` (а не `Results.Gender`!) | см. §7 |
| Раунд | `Results.Round`, `HeatType` (prelim / final) | заполнено частично |
| Место в протоколе | `Results.Position` | есть, но в списке **не показываем** (§6) |
| Признак «время под вопросом» | `Results.SuspectReason` | 14 строк на 67 170 |

```
 7  01:05.76   HINNAWI KAY ROMA      [HE]         446  02/05/2026  Spring Cup (HE)

10  01:06.85   HINNAWI KAY ROMA      [HE]         462  30/05/2026  Hapoel Champs (HE)
```

**Отсюда видно три вещи, которые определяют дизайн:**

1. **Повторы пловца — норма, а не исключение.** SHILO LIOR занимает места 1, 3, 4, 8 (и 12).
   В сыром списке из 15 строк — всего 7 разных людей. Это ровно тот случай, о котором говорит
   Влад: «если первые два результата у одного пловца — так и писать». Нужен визуальный приём
   для повторов (и, скорее всего, тумблер «все заплывы / лучший на пловца» — §10).
2. **Очки FINA НЕ монотонны времени.** 01:02.49 → 519 очков, а более медленное 01:03.62 → 536.
   Очки приходят из протокола и посчитаны по разным базовым таблицам разных лет. Значит:
   сортировка по времени и сортировка по очкам дают **разный порядок**, и колонка очков не
   может выглядеть как «производная от времени». Не рисуй их как одну шкалу.
3. **Имена в разных регистрах и алфавитах** — `SHILO LIOR` рядом с `Avigdori Shira`. Вёрстка
   не должна рассчитывать на аккуратный Title Case.

### Второй реальный срез — противоположная картина

Адрес прямо со страницы (то, что Влад открывает в браузере):

```
/season-best?season=2025&age=9&gender=female&stroke=breaststroke&distance=50&pool=50m&swimmer=6254
```

`breaststroke 50, 50m, female, возраст 9, сезон 2025/26` — **38 строк, и все 38 разные
пловчихи**. Повторов нет вообще. Причина: в 50-метровом бассейне у 9-летних девочек за весь
сезон прошёл **ровно один турнир** — ISR Summer Champs 8-11, 15–16/07/2026.

```
 #  время      пловец                клуб                       FINA  дата
 1  00:49.64   BARANTSEV SABINA      Hapoel Dolphine Netanya     202  16/07/2026
 2  00:49.79   ABRAMSON YAM PAZ      Hapoel Misgav               200  16/07/2026   <- ?swimmer=6254
 3  00:51.87   RABIN NOAM            Tamnoon Pardesiya           177  16/07/2026
 4  00:52.20   PROFIS PELEG          Hapoel Emek Hefer           174  16/07/2026
 ...
38  01:33.07   HABER RONI            Macabbi Haifa                30  16/07/2026
```

**Тот же срез, но бассейн 25m: 102 заплыва, 56 пловчих, 20 соревнований** — то есть повторы
неизбежны. Один тумблер `25m / 50m` переключает страницу между двумя принципиально разными
картинами. Из этого следуют три требования к макету:

1. **Нарисовать оба состояния списка**: «каждый ровно один раз» и «один пловец на местах
   1, 3, 4, 8». Приём для повторов не должен выглядеть поломкой там, где повторов нет.
2. **Колонки «дата» и «соревнование» могут быть одинаковыми во ВСЕХ строках** (как здесь:
   38 строк с одного турнира, две соседние даты). Тогда они превращаются в шум и должны
   уметь схлопываться — например, в подзаголовок списка «all swims from ISR Summer Champs,
   15–16/07/2026» — либо приглушаться.
3. **Очки FINA монотонны времени, только пока соревнование одно.** Здесь 202, 200, 177,
   174… — идеальный порядок, потому что весь список с одного старта. В срезе из первого
   примера (20 разных турниров) порядок ломается. То есть баг это или нет — зависит от
   среза, и подпись у колонки должна это выдерживать.

**Заголовок страницы на скриншоте читается двусмысленно:** `season 2025/26 · 50 breaststroke · 50m` —
дистанция 50 и бассейн 50m стоят рядом и выглядят как повтор. Нужен приём различения
(`50 m breaststroke` / `LCM 50 m`, разные веса, `UI_PoolIcon` вместо текста).

## 3. API списка

`GET /api/season-best/list` — параметры зеркалят query страницы:

```
?style=freestyle&distance=100&pool=25m&season=2025&age=12&age_to=&gender=female
&club=439&best=false&limit=50&offset=0
```

Строка ответа (`SeasonBestListItemDto`):

```
place, attempt, result_id, time, time_ms, suspect_reason, points, gap_ms,
swimmer_id, name, name_en, gender, age, club_id, club, club_en,
competition_id, competition, pool_type, date (DD/MM/YYYY)
```

Уровень ответа: `season`, `season_label`, `style`, `distance`, `pool_type`, `gender`, `age`,
`club_id`, `best_per_swimmer`, `total`, `offset`, `limit`, `swimmers`, `meets`, `clubs[]`.

Три поля, которых нет в соседних эндпоинтах, и они несут смысл дизайна:

- **`attempt`** — какой это по счёту заплыв ЭТОГО пловца в списке (1 — лучший). Именно им
  строка отличает повтор от нового человека; в UI это подпись «2nd swim».
- **`gap_ms`** — отставание от лидера среза. При фильтре по клубу считается всё равно от
  лидера **общего** рейтинга, а не от лучшего в клубе.
- **`clubs[]`** — опции фильтра клуба, посчитанные ДО фильтра по клубу: иначе, выбрав клуб,
  пользователь терял бы возможность выбрать другой.

Правила выборки (закреплены тестами `SeasonBestRepositoryTests`):
дедупа по пловцу нет (`best=true` включает схлопывание); равные времена делят место
(1, 2, 2, 4); фильтр клуба **не пересчитывает места** — они остаются из общего рейтинга,
с пропусками (#69, #74, #83); masters, эстафетные ноги, `TimeFail` и `SuspectReason` не
участвуют; возраст сезонный.

`GET /api/season-best/options` отдаёт сезоны для карусели (`season`, `label`, `meets`,
`is_display_default`) и стили с реально проплытыми дистанциями. Мусорные ключи стилей из
кривых протоколов в селектор не попадают — работает белый список из пяти видов плавания.

## 4. Сезоны: их сейчас ДВА

В базе только `2024/25` (14 293 результата, 22 соревнования) и `2025/26` (67 170, 130).
Карусель сезонов нарисована на бесконечную ленту, но реально покажет два слота и `∞`.
Проверяй макет и на такой вырожденной ленте.

**Сезон ≠ календарный год.** Сезон федерации: сентябрь–август, метка по году начала.
Старт 31/10/2025 и старт 15/02/2026 — **один** сезон 2025/26. Всё сезонное на клиенте
считает `client/src/utils/helpers/season-helper.ts` (зеркало серверного `SeasonMath`).
Подпись сезона — только `seasonLabel()` → «2025/26». Единственное разрешённое исключение —
слот карусели, там «25/26», потому что в 52px полная запись не влезает.

### Чем строка season-best отличается от строки на скриншоте

На странице пловца EVENT **меняется от строки к строке** (у одного человека разные
дистанции). На `/season-best` дисциплина **зафиксирована фильтром и одинакова во всех
строках** — колонка EVENT там превратится в 38 одинаковых плиток.

Поэтому раскладка переворачивается: **плашка события уезжает в шапку списка, а её место в
строке занимает имя пловца**. Предлагаемый состав (каждая колонка — модуль с флагом):

| Колонка | Ширина (десктоп) | Содержимое | Флаг | Мобайл |
|---|---|---|---|---|
| `PLACE` | 56px | `#1` золотом при первом месте | всегда | 30px |
| `SWIMMER` | `minmax(0,1fr)` | имя (`NameEn` → `Name`) + клуб мелким шрифтом второй строкой | `showClub` для клуба | остаётся |
| `TIME` | 90px | `UI_SwimTime` + бейдж `SB` у лидера | всегда | 62px |
| `FINA` | 62px | очки, `.deep-pb-pts` | `showPoints` | остаётся мелким |
| `MEET` | `minmax(0,1fr)` | название соревнования, `.deep-pb-where` (обрезка многоточием) | `showMeet` | скрыт (`display:none`, как `.deep-pb-where` сейчас) |
| `DATE` | 84px | `.deep-pb-date` / `UI_DateIcon` | `showDate` | скрыт |

**Имя пловца печатается как в протоколе** (`name`, часто на иврите) — так же, как в
таблице результатов и на странице пловца: латиница здесь мешала бы узнать того же человека
при переходе между экранами. Латинское `name_en` доступно за флагом `latinNames`.
Имена, клубы и названия соревнований выводятся с `dir="auto"`, иначе RTL-строка в LTR-ячейке
обрезается многоточием не с той стороны и теряет начало вместо хвоста.
Клубы — так же, как в протоколе, и в строке, и в фильтре, и в чипе шапки. Это не только
консистентность: `UI_ClubIcon` ищет файл эмблемы по ОРИГИНАЛЬНОМУ имени клуба
(`public/images/club-icon/מכבי-חיפה.png`), так что латинское написание оставило бы строку
без логотипа. Поиск в фильтре клубов при этом идёт и по латинице тоже — набирают как
привыкли, показан один вариант.

**Блок «эмблема + имя + клуб» рисует общий `UI_SwimmerNameCell`** — тот же компонент, что в
таблице результатов (`showClubIcon`, `clubIconSide="left"`, `isMe` даёт бейдж ★ ME). Своей
вёрсткой это делать нельзя: он держит манифест эмблем и фоллбек на `no-club.png`, и копия
разъехалась бы на первом же новом клубе.

**Строка красится по полу** — та же мягкая заливка, что в таблице результатов
(`Helper.getGenderBgClass` → `--theme-mode-row-male/female`), здесь через deep-пары
`--deep-male-soft` / `--deep-female-soft`. Отличие: на results пол вычисляется парсингом
названия заплыва (поля пола в тех данных нет), а тут приходит из API и потому надёжен.
Флаг — `genderTint`.

**Подсветка «это я» (`?swimmer=`) фон НЕ красит** — строки уже покрашены по полу, и акцентная
заливка поверх розовой давала грязный оттенок, в котором выбранная строка читалась хуже
соседних. Метка — золотая полоса слева (тот же приём, что у «это я» в таблице результатов)
плюс свечение; полоса нарисована `inset`-тенью, а не `border-left`, иначе сдвигалась бы сетка.

Плашки `EventPlate` на странице **нет вообще** (решение Влада 2026-08-26): дисциплина одна
на весь список, её называют заголовок страницы и чип `Event` в шапке фильтров. Вдобавок
`EventPlate` опирается на классы `.deep-event-plate` / `.deep-stroke-plate` из
`swimmer-page.css`, которого эта страница не подключает, — без них картинка разъезжается
во всю ширину. Захочешь вернуть плашку — сначала перенеси её стили в общий файл.

Важно: **на мобайле у эталона исчезают `MEET` и `DATE`** — там `.deep-pb-where` и последняя
колонка скрыты правилом выше. Влад просил соревнование и дату видимыми, значит для мобайла
нужен свой приём: вторая строка под именем («meet · date» мелким), как сделано в
`.deep-result-row__meet-sub`.

## 6. Фильтры и шапка фильтров — копируем модель страницы results

Это главное указание Влада. Ниже — как оно устроено на `/results` и что именно берём.

### 6.1 Устройство на results

**`FilterSection`** (`components/filter-section/filter-section.tsx`) — просто вертикальный
список карточек, буквально:

```tsx
<FilterActivity />
<FilterResetButton />
<FilterSwimmingStyle />   {/* внутри себя рендерит FilterDistance */}
<FilterEventDate />
<FilterEventCategory />
{/* <FilterDateDropdown /> */}   ← так фильтр выключают: комментируют одну строку
<FilterNameDropdown />
<FilterPositionButtons />
<FilterLevelButtons />
<FilterPoolType />
<FilterGender />
<FilterAge />
<FilterClub />
```

**Это и есть требуемая модульность**: один фильтр = один компонент = одна строка JSX.
Убрать фильтр — убрать строку, и больше нигде ничего не трогать. `FilterDateDropdown`
на results уже так и выключен.

**`FilterCard`** (`filter-card.tsx`) — оболочка одного фильтра, сворачиваемая карточка:

| Проп | Тип | Что делает |
|---|---|---|
| `title` | `string` | название фильтра слева |
| `summary` | `string` | сводка выбранного справа («freestyle · 100m», «25m», «M») |
| `isActive` | `boolean` | фильтр не в дефолте → сводка красится акцентом темы |
| `defaultOpen` | `boolean` | раскрыта ли при первом рендере |

Шапка карточки — название + сводка + шеврон `▼`, контент раскрывается по клику.

**Шапка фильтров** — это `ResultsFilteredInfo`
(`results-table/components/results-filtered-info.tsx`, хендофф `design_handoff_position_filter`):
горизонтальная полоса чипов над таблицей, по чипу на фильтр. Правила из хендоффа, их
нужно сохранить:

- колонка в состоянии «All» **не занимает полноценное место**: на десктопе узкая и
  приглушённая, на мобайле — мелкий чип;
- на мобайле (`< 768px`) полоса в **две строки**: сверху мелко всё, что «All», снизу
  крупно и по центру — выбранное. Пустая нижняя строка не рендерится вообще;
- десктоп: все колонки `flex-1 basis-0`, ширина делится поровну независимо от содержимого;
- чипы по умолчанию некликабельны (выбор живёт в сайдбаре); исключение на results —
  `Position`, он циклится кликом, потому что значений всего три.

**Полоса уже модульна булевыми пропами** — ровно то, что просит Влад:

```tsx
<ResultsFilteredInfo showDate showClub showAge showPoolType showEvent />
```

**Раскладка.** Десктоп: сайдбар слева `lg:w-[340px] lg:shrink-0 hidden lg:block`, контент
справа `lg:flex-1 lg:min-w-0`. Мобайл: сайдбара нет вовсе, вместо него `MobileFiltersDrawer` —
плавающая кнопка «Filters / Apply» снизу по центру + шторка во весь экран, в кнопке
строка-сводка из `summarizeFilters()` вида `freestyle • 100m • female • 25m`.

**Зависимый фильтр.** `FilterDistance` вложен в `FilterSwimmingStyle` и возвращает `null`,
пока стиль не выбран (`if (!filterData || !filters.style_name) return null`). Готовый
прецедент для «дистанция появляется только после выбора стиля».

**Доступность значений.** В paged-режиме опции берутся не из загруженной страницы, а из
`GET /api/Results/filter-hints?field=style|distance|club|competition|name`. Недоступные
значения показываются **disabled, а не скрываются** — иначе фильтр «мигает» составом.

### 6.2 Состав фильтров для season-best

**Оставляем:**

| Фильтр | Компонент-образец | Роль на странице |
|---|---|---|

Раскладка как на results: слева стили **картинками** (`UI_SwimmStyleIcon`), справа за пунктирной линией дистанции выбранного стиля. `individual medley` в узкой колонке подписан «medley», полное имя — в `aria-label` |

| **Gender** | `FilterGender` | |

### 6.3 Шапка фильтров для season-best

Полоса чипов над списком. Правило «All не занимает полноценное место» сохранено, но
двухстрочный вид тут **на всех ширинах**, а не только на мобайле, как на results (решение
Влада 2026-08-26): фильтров шесть, и полоса равных колонок размазывала выбранное между
пустыми «All». Сверху мелкие приглушённые «All» (10.5px), снизу выбранное крупно и
акцентом (14px); пустая строка не рендерится вовсе. Состав после чистки:

| Чип | Значение | Модуль |
|---|---|---|
| `Event` | иконка стиля + дистанция (`UI_SwimmStyleIcon styleType="icon-len"`) | `showEvent` |
| `Pool` | `25m` / `50m` (`UI_PoolIcon`) | `showPool` |
| `Gender` | ♂ / ♀ | `showGender` |
| `Age` | возраст в сезоне | `showAge` |
| `Club` | логотип + имя (`UI_ClubIcon`) | `showClub` |
| `Season` | «2025/26» | `showSeason` |
| ~~`Date`~~, ~~`Position`~~ | — | убраны |

Отдельное решение для дизайна: **сезон живёт в двух местах сразу** — крупной каруселью
(её и просил Влад) и чипом в шапке фильтров. Либо чип `Season` не рисуем вовсе, либо
карусель и чип надо развести так, чтобы это не читалось как два разных контрола на одно
значение. Правило Deep тут жёсткое: cyan-свечение в полосе ровно одно.

### 6.4 Конфликт палитр — решить до макета

Фильтры results написаны на **старых** токенах `--theme-*` (`--theme-mode-surface`,
`--theme-mode-border-drawer`, `--theme-primary`). Заготовка `/season-best` и страница
спортсмена, откуда сюда ведут ссылки, — на **`--deep-*`**.

Скопировать модель фильтров «как есть» значит принести на deep-страницу чужую палитру.
Рекомендация: **берём с results раскладку, поведение и правила (`FilterCard`, состав
сайдбара, drawer, полосу чипов), а красим в `--deep-*`** — то есть deep-вариант
`FilterCard` и полосы чипов. Иначе сайдбар будет выглядеть как кусок другого сайта.
Это решение стоит зафиксировать в хендоффе явно.

### 6.5 Клубы — нужны, и вот что о них важно знать

Влад подтвердил: клуб остаётся и фильтром, и колонкой в строке. Фактура:

**Сколько их.** 235 клубов в базе. В одном срезе (`freestyle 100`, `25m`, сезон 2025/26)
представлено **76 клубов**. Список кнопок, как у стилей, не годится — нужен поиск + список,
как в `FilterClub` на results.

**Имена.** У 205 клубов из 235 `NameEn` — настоящее английское имя («Hapoel Dolphine
Netanya», «Maccabi Rishon Seals», «ALE Ozma Raanana»). У остальных 30 `NameEn` — просто
копия ивритского. Правило вывода: **`NameEn`, если он отличается от `Name`, иначе `Name`**
(и тогда в ячейке будет RTL-строка). Это лучше, чем на соревнованиях — там английских
названий нет почти совсем.

**Логотипы.** В `public/images/club-icon/` лежит **34 файла на 235 клубов**, у остального
фоллбек `no-club.png` (манифест — `public/data/config/club-icons-manifest.json`, генерится
на prebuild). Дизайн не должен опираться на логотип как на носитель узнавания: у двух
клубов из трёх его не будет. `UI_ClubIcon` умеет режимы `icon-text-bottom` и др. и сам
подставляет фоллбек.

**Что фильтр клуба означает на этой странице — решить явно.** Это НЕ клубный рейтинг.
Отфильтровав по клубу, пользователь видит своих пловцов **с их местами из общего
рейтинга** — `#1`, `#7`, `#23`, с пропусками. Если вместо этого пересчитать места внутри
клуба (1, 2, 3 подряд), получится другой продукт — «лучшие в клубе», а он уже есть
отдельно (`GET /api/clubs/{id}/season-best`). Макет обязан показывать разреженную
нумерацию, иначе разработка сделает не то.

**Откуда берётся список клубов для фильтра — задача к API.** На results он приходит из
`useClubSummary(sourceParams)` (очки/медали/пловцы по выбранному соревнованию) — здесь
такого источника нет, соревнование не выбрано. Варианты: `GET /api/Results/filter-hints?field=club`
(есть, но список глобальный) или клубы прямо из ответа списка (тогда фильтр показывает
ровно то, что встречается в срезе). Второе честнее; отметить в хендоффе как требование к
эндпоинту.

Метрики рядом с клубом в карточке фильтра (`UI_ClubDetails` на results показывает очки,
медали, число пловцов) сюда **не переносятся**: они считаются по соревнованию. Если что-то
и показывать — то число заплывов/пловцов клуба в текущем срезе.

## 7. Правила проекта, которые нельзя нарушить

1. **UI только на английском.** Русских строк в интерфейсе быть не должно. Но **данные —
   на иврите**: названия соревнований и клубов приходят из протоколов федерации как есть.
   Вёрстка обязана переживать длинную RTL-строку в колонке «соревнование» (обрезка,
   перенос, tooltip — решай, но решение должно быть).
2. **Время выводится ТОЛЬКО через `UI_SwimTime`.** Он же несёт признак «время под
   вопросом». Носитель строки при этом получает `swimFlaggedRowProps()` → класс
   `swim-flagged-row` (caution-лента слева, токены `--theme-flag-*`). Отступ под ленту
   (`pl-*`) добавляет вызывающий.
3. **Пол берём у пловца (`Swimmers.Gender`), не из строки результата.** `Results.Gender` —
   пол зачёта заплыва, и он бывает ошибочным: одна кривая шапка протокола уводила пловца в
   чужую колонку витрины. В данных пол пишется в двух написаниях (`male`/`M`), наружу
   нормализуется в одно.
4. **Возраст — только сезонный** (`SeasonMath.AgeInSeason` / `ageInSeason`): год окончания
   сезона минус год рождения, один и тот же на все старты сезона. Это НЕ та ось, что в
   справочнике рекордов (там календарная) — расхождение осознанное, решение Влада 22/08/2026.
5. **Что в выборку не попадает вовсе** (правила существующего season best, скорее всего
   сохранятся): соревнования masters (`IsMasters`), эстафетные ноги (`RelayId != null`),
   незачётные (`TimeFail`), помеченные `SuspectReason`, и заплывы без года рождения (нет
   возрастной ступени — сравнивать не с чем).
6. **Правило парных токенов.** Текст на тем-зависимой поверхности красится только парным
   токеном той же поверхности, фиксированных hex быть не должно. Меняешь токен в одном
   режиме — проверь пару в обоих, контраст ≥ 4.5:1.
7. **Ничьи.** Равные времена делят место (так уже сформулировано в легенде на странице
   спортсмена). В примере §2 строки 13 и 14 обе `01:07.05` — случай реален и в макете
   должен быть.

## 8. Темы: две системы токенов, обе живые

**Ось режима** — атрибут `data-mode="light|dark"` на `<html>`, ставит хук `useMode`
(источник истины — `localStorage['swimm-mode']`, первый визит — по `prefers-color-scheme`).

**Палитра страницы** — классы `.theme-deep` (тёмная) / `.theme-deep-light` (светлая) на
корне экрана, все токены в `client/src/projects/components/deep/deep-theme.css`. Страница
спортсмена делает `mode === 'dark' ? 'theme-deep' : 'theme-deep-light'`. Новая страница
делает так же — компоненты используют **только** `var(--deep-*)`.

```
поверхности   --deep-page-bg  --deep-card-bg  --deep-card-bg-raised  --deep-card-bg-row
границы       --deep-card-border  --deep-card-border-soft  --deep-divider
текст         --deep-text  --deep-text-mute  --deep-text-faint  --deep-text-ghost
акцент        --deep-accent (#22d3ee dark / #0e7490 light)  --deep-accent-soft
              --deep-accent-chip  --deep-accent-border  --deep-accent-glow
золото        --deep-gold ...          (достижения, счётчики)
пол           --deep-male / --deep-female (+ -soft, -border)
сегменты      --deep-seg-track  --deep-seg-active-bg  --deep-seg-active-fg
карусель      --deep-strip-bg  --deep-wheel-glow  --deep-wheel-d1/d2/d3  --deep-wheel-off
радиусы       --deep-radius-card 16  --deep-radius-tile 14  --deep-radius-row 12  --deep-radius-pill 999
шрифт         --deep-font-display: 'Archivo Black', sans-serif
```

Вторая система — `--theme-*` в `client/src/index.css` (~700 строк, светлая палитра в
`:root`, тёмная ниже). На ней написаны фильтры results (см. §6.4). Пересечение с deep ровно
одно: токены `--theme-flag-*` (пометка спорного времени) используются в deep-рецептах.

⚠ **`Archivo Black` нигде не подключён** — ни `@font-face`, ни Google Fonts, ни файлов в
`public/`. Фактически везде рендерится системный sans-serif. Либо не рассчитывай на этот
шрифт в макете, либо явно скажи, что его надо подключить (отдельное решение Влада).

Правила света/тени из `deep-theme.css`, которые легко нарушить:
- в светлой теме свечений **нет** (`--deep-wheel-glow: none`): на белом «сияющий» текст
  читается как размытие, роль «выбран» несут цвет-акцент и размер;
- cyan-свечение в полосе фильтров ровно одно: либо центр карусели, либо `All`;
- в карточке единственный `--us`-glow — у строки «это мы».

параметры выносятся в Tweaks. Образец — `!design_handoff/design_handoff_age_records_sb/`.
**Каждый фильтр, каждый чип шапки и каждый блок строки должны иметь свой флаг в Tweaks**,
чтобы Влад щёлкал их прямо в браузере.

**В продакшн-коде.** Три уровня, все уже существуют:

1. фильтр = компонент в списке `FilterSection` → выключается удалением/комментированием строки;
2. чип шапки = булев проп `ResultsFilteredInfo` (`showEvent`, `showPool`, `showAge`…);
3. блок внутри строки = проп с `null`-веткой (прецедент — `FilterDistance`, который
   возвращает `null`, пока стиль не выбран).

Раскладка новой фичи повторяет паттерн `results-table/`:

```
projects/season-best-project/
  season-best-project.tsx     <- оркестратор: читает query, тянет данные, решает что рендерить
  components/                 <- фильтры, шапка фильтров, строка списка, *-mobile / *-desktop
  season-best-page.css        <- то, что неудобно на Tailwind
```

В README хендоффа для каждого модуля нужна строка таблицы: **имя параметра, тип, значение
по умолчанию, что происходит при `false`**.

## 10. Что дизайну придётся решить (и о чём спросить Влада)

Первые три решены в рабочей версии — но именно как «работает», а не «нарисовано»: это те
места, где дизайнеру есть что улучшить.

1. **Дедуп по пловцу — РЕШЕНО в коде:** по умолчанию видны все заплывы, повтор помечен
   подписью «2nd swim» и приглушённым именем, плюс есть тумблер `All swims / Best per
   swimmer`. Дизайну остаётся сам приём: подпись-чип это минимум, возможна мягкая
   группировка или связка повторов линией.
2. **Дисциплина не выбрана — РЕШЕНО:** экран говорит «Pick an event» и отправляет в
   фильтры, а не подставляет свой дефолт. Витрина дисциплин на этом месте была бы лучше —
   открыто.
3. **Реальные значения селектора дисциплины** (по частоте): стили `freestyle` 33 637,
   `backstroke` 13 963, `breaststroke` 12 908, `individual_medley` 11 150, `butterfly` 9 717;
   дистанции `100` 31 442, `50` 22 830, `200` 18 059, `400` 3 981, `800` 991, `1500` 339,
   плюс `1600/3000/5000/10000` (открытая вода) и эстафетные `4X50/4X100/4X200` —
   **эстафеты в списки не идут**.
4. **Возраст: одно значение или диапазон?** В адресе сейчас одно число (`age=12`), но
   `FilterAge` на results умеет диапазон (`age` / `age_to`). Нужен ли режим «все возраста»
   с группировкой заголовками?
5. **Сортировка.** По времени (естественная) или по очкам FINA (даёт другой порядок, §2).
   Если обе — переключатель должен объяснять расхождение, иначе выглядит как баг.
6. **Ограничение выдачи — РЕШЕНО:** 50 строк + кнопка «Show more — 50 of 417», то есть
   размер среза назван вслух. Для 417 строк это 8 нажатий — открыто, нужен ли виртуальный
   скролл или прыжок к своему месту.
7. **Подсветка `?swimmer=`.** Пловец пришёл со своей страницы и должен себя найти —
   рецепт `.deep-stand-row--us` готов, но при повторах подсветится несколько строк сразу.
8. **Честная оговорка.** «Лучший в стране» у нас значит «лучший среди импортированного».
   На соседних экранах это пишут прямым текстом плюс показывают `meets`. Место под эту
   строку в макете нужно.
9. **Сезон в шапке фильтров** — чип или только карусель (§6.3). Клуб — вопрос закрыт:
   нужен (§6.5), но остаётся решить, показывать ли метрики клуба в карточке фильтра.
10. **Палитра фильтров** — подтвердить решение из §6.4 (модель с results, цвета deep).

## 11. Брейкпоинты и мелочи вёрстки

- Мобайл проектируется на **375px**, десктоп — контейнер `max-width: 1180px`
  (на results — сайдбар 340px + `flex-1`). Брейкпоинты: `sm` 640px, `md` 768px
  (граница двухстрочной шапки фильтров), `lg` 1024px (появляется сайдбар).
- Времена и очки — `font-variant-numeric: tabular-nums`, иначе колонки дёргаются.
- Тап-таргет на мобайле ≥ 48px.
- Горизонтального скролла на 375px быть не должно: ряды фильтров переносятся (`flex-wrap`)
  или используют `.deep-swipe-clip` с закреплённым `All`.
- Стек: React 18 + TypeScript + Vite (multi-page, SPA-роутера нет) + Tailwind v4 + Redux Toolkit.
