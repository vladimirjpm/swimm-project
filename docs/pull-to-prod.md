# Как затянуть соревнование в прод

> Скилл **`/pull-to-prod <compID или ссылка isr.org.il>`** ведёт по этой инструкции.
> Записано 05.11.2026 по просьбе Влада на живом случае 16891 («אליפות אילת הפתוחה 2026»), шёл день 1.
> Просьба частая: «затяни в прод https://isr.org.il/comp.asp?compID=NNNN».

Прод-база пишется только из **ProdAdmin**: это локальная админка из свежего master против прод-базы
(В17, [plans/azure-deploy-plan.md](plans/azure-deploy-plan.md) §0-тер-бис). Сам сайт swimhub.co.il
админки не имеет. Просьба Влада «затяни в прод» и есть разрешение на запись. Без неё агент в
ProdAdmin не пишет.

## 0. Выбрать путь

| Ситуация | Путь |
|---|---|
| Соревнование закончилось, протокол полный, в базе его нет | **А** — «Затянуть» в `/Admin/Competitions` |
| Соревнование **идёт** (результаты есть не за все дни или не за все события) | **Б** — по дням, JSON-файлом |
| Уже в базе, протокол поправили или он дополнился | **В** — «Перезатянуть» / `--repull` |
| Чемпионат «утро + вечерний финал», PDF сводит раунды | **Г** — `--pull-events` ([data-integrity.md](data-integrity.md) И-58) |

Как понять, что соревнование идёт: даты на isr.org.il (`comp.asp?compID=`) накрывают сегодня, а у
loglig в PDF есть события, где **ни у одной строки нет времени** (шаг 2 покажет). Если путь А
применить к идущему старту, получатся сотни ложных неявок и все дни одной датой (последней).

## 1. Подготовка (общая для всех путей)

1. **Рабочая копия на master.** ProdAdmin сам делает `git fetch` + `pull --ff-only`. Неотслеживаемые
   файлы не мешают, а изменённые отслеживаемые мешают только при конфликте с pull.
2. **Доступ к прод-базе.** Любой `node server/db/prod-sql.mjs read …` с ответом `Connection refused`
   означает, что IP не в файрволе. Лечится так:
   `powershell -NoProfile -ExecutionPolicy Bypass -File server/db/prodadmin-firewall.ps1`
   (одно правило `auto-<машина>`, обновляется на месте). ProdAdmin вызывает его и сам.
3. **Разведка на проде** (читать можно свободно):
   ```sql
   -- запись автозабора: Id (= discoveredId), LogligId, Status
   SELECT "Id","OrgCompId","LogligId","Status","Name","DateStart","DateEnd"
   FROM "Sys_DiscoveredCompetitions" WHERE "OrgCompId" = <compID>;
   -- уже в базе?
   SELECT "Id","Name","Date","EventId","PoolType","IsAward","ClubPointsDisabled"
   FROM "Competitions" WHERE "OrgCompId" = <compID>;
   -- дни и дисциплины по стартовому протоколу (если его тянули)
   SELECT e."CompDate"::date, s."Name", e."Distance", e."Gender", min(e."OrgEventNumber") ev, count(*)
   FROM "CompetitionEntries" e LEFT JOIN "Styles" s ON s."Id" = e."StyleId"
   WHERE e."OrgCompId" = <compID> GROUP BY 1,2,3,4 ORDER BY 1, ev;
   ```
   ⚠ Таблица — `Sys_DiscoveredCompetitions`, а не `DiscoveredCompetitions`.
   Записи нет → сначала «Проверить сейчас» (sync входящих) в `/Admin/Competitions`.
4. **Сухой разбор протокола** — локально, ничего не пишет:
   ```bash
   ASPNETCORE_ENVIRONMENT=Development dotnet run --project server/Swimm.API --no-build -- \
     --repull <discoveredId> --dry-run --json-out <scratchpad>/<compID>-dry.json
   node server/db/day-json.mjs <scratchpad>/<compID>-dry.json
   ```
   `--no-build` нужен, если ProdAdmin уже запущен (иначе build-lock). Docker выключен (локальная
   база не отвечает) → тот же сухой прогон с `--launch-profile ProdAdmin` вместо Development: он
   только читает. ⚠ Без Docker не работает и `prod-sql.mjs` (psql в контейнере) — проверки тогда
   через ProdAdmin: `GET /api/admin/data-checks`, `GET /api/admin/import-history`, API сайта. Локальный discoveredId
   совпадает с продовым, если локальная база недавно синхронизирована (`/db-sync-from-prod`).
   `day-json.mjs` печатает по дисциплинам: событий, строк, с временем, сколько проплыто.
   Есть дисциплины `0/N` → **путь Б**.
5. **Запустить ProdAdmin:** `preview_start {name: "swimm-api-prodadmin"}` (порт 5078, красная полоса
   PRODUCTION DATABASE). Дождаться ответа `/auth/me`.
6. **Вход.** ProdAdmin пускает только залогиненного Admin. Агент **не логинится сам**: Влад входит
   в панели браузера (Google) и говорит «вошёл». Проверка — `fetch('/auth/me')` → `roles` содержит `Admin`.

## 2. Путь А — «Затянуть» (соревнование закончено)

1. `/Admin/Competitions`. Строку ищем по compID. Если строка не видна (узкая панель, фильтры),
   превью можно открыть из консоли: `await window.discPreview(<discoveredId>, false)`.
2. **Проверить превью до импорта:** число строк против `day-json.mjs`; **даты** (у многодневки
   их должно быть несколько; одна дата = последняя дата диапазона → сначала разобраться, см.
   [plans/multiday-split-plan.md](plans/multiday-split-plan.md) и `--split-days`); флаги (Awards,
   🏆, Masters, «зачёт не ведётся»); **бассейн** — превью часто пишет «— не задан —»: протокол
   loglig длину не печатает. Не угадывать, спросить Влада. Категория — та, что подобрал превью
   (обычно `results-8-99`).
3. «Импортировать» → панель хода внизу справа → итог: **сверка с файлом** «сошлось (N строк)» и
   прогон проверок. Статус записи станет `imported` сам.
4. Чемпионат — дальше `--quality-scan <eventId>` и `--rebuild-club-standings` (см. И-58).

## 3. Путь Б — соревнование идёт: по дням

Почему не А: PDF loglig у идущего старта печатает **все** события. Непроплытые идут строками без
времени (`time_fail=true`), а все строки получают **последнюю** дату диапазона (у 16891 — 07/11, при
днях 05.11 и 06.11). Поэтому берём из разбора только проплытые события одного дня и ставим им
правильную дату.

1. **Дисциплины дня** — из стартового протокола (запрос из §1.3). Ключ для скрипта — `distance|style`
   (`50|freestyle`, `100|individual_medley`, эстафета — `4X50|freestyle`).
2. **Собрать файл дня:**
   ```bash
   node server/db/day-json.mjs <dry.json> --date 05/11/2026 \
     --disciplines "100|individual_medley,50|freestyle,50|backstroke,50|butterfly,4X50|freestyle,200|freestyle" \
     --pool 25m --out <scratchpad>/<compID>-day1.json
   ```
   Непроплытые события дня скрипт пропускает сам и называет их. Проплытым он считает событие,
   у которого в **последнем** заплыве есть время. Строки DQ/NS внутри проплытого события
   остаются: это данные протокола.
   **Эстафеты — отдельным файлом.** PDF сводит все эстафеты дисциплины за день (обе полосы, оба
   пола) в одну секцию без пола со сквозными местами. Что проплыто, смотреть по стартовому
   протоколу: число команд по событиям (`count(DISTINCT ("Heat","Lane"))` по `OrgEventNumber`)
   против числа команд с временем. Если с временем ровно проплытые полосы:
   `--disciplines "4X50|freestyle" --relays-timed-only`. Команда NS в проплытой полосе при этом
   потеряется; если такая есть — добавить её строку руками.
3. **Загрузить в ProdAdmin.** Файловый инпут агенту недоступен, поэтому файл временно кладётся в
   `server/Swimm.API/wwwroot/_tmp-<compID>.json`, а из консоли `/Admin/*` выполняется:
   ```js
   const blob = await fetch('/_tmp-<compID>.json').then(r => r.blob());
   const form = new FormData();
   form.append('file', new File([blob], 'isrorg-<compID>-loglig-<logligId>-day1-<yyyy-mm-dd>.json'));
   form.append('categories', 'results-8-99');
   form.append('newEventName', '<название>');   // ДЕНЬ 1: новое событие
   // form.append('eventId', '<id события>');   // ДНИ 2+: то же событие
   // form.append('overwriteExisting', 'true'); // ДОБАВКА в уже загруженный день (вечерние события,
   //   эстафеты): без неё импорт откажет «Дубль: соревнование … уже содержит результаты». Это
   //   upsert, чужие строки дня не удаляются (deleteMissing не ставить). Сверка покажет
   //   «расхождение» — в файле только добавка, это ожидаемо.
   const q = await (await fetch('/api/admin/import', { method: 'POST', headers: { 'X-XSRF-TOKEN': _csrfToken }, body: form })).json();
   // статус: GET /api/admin/import/status/{q.jobId} до state=completed; смотреть result.reconciliation
   ```
   **Сразу после постановки в очередь удалить** `wwwroot/_tmp-*.json` (иначе уедет в коммит).
   Влад может то же самое сделать руками на `/Admin/Import`.
4. **Только после дня 1** — на `/Admin/Competitions/Edit?id=<id дня 1>`:
   - `OrgCompId = <compID>` — связь с автозабором и стартовым протоколом. Импорт файлом его не
     ставит, в отличие от «Затянуть»;
   - флаги, которые предложил превью (у 16891: «клубный зачёт не ведётся» — на loglig зачёта нет);
   - **Awards (награждение)** — спросить Влада; превью регламент мог не прочесть. Признак на
     loglig: секции по году внутри события («גמר ישיר - בנות 10», «בנות 9») — награждение по
     возрасту. У 16891 — да (Влад, 05.11).
   У каждого **нового дня** флаги дня (Awards, «зачёт не ведётся») ставятся снова: они подневные.
   После этого любой следующий импорт в этот день сам запускает сшивку (§3.6 — возврат неявок).
5. **Эстафеты — после импорта:** `--pull-relays <discoveredId>` (сначала без `--apply`, план
   должен быть «строк к правке N из N»), затем с `--apply`. Ставит пол, полосу и место по
   страницам событий loglig. С 05.11 он пропускает ещё не проплытые эстафетные события и
   понимает эстафеты без клубного зачёта (7 колонок), а с 06.11 видит все дни события, не только
   день с OrgCompId (`CompetitionIdentity`). Ограничение: полоса пишется из шапки
   события («9-10»), год секции («9»/«10») теряется — у награждения по возрасту в полосе видно
   два первых места; медали при этом верные.
5а. **Места личных строк — `--pull-places <discoveredId>`** (сначала без `--apply`, потом с ним).
   Обязательно, если в PDF есть секции «כללי» с полом `none` (`day-json.mjs`/разбор их видно): PDF печатает
   «כללי» девочек и мальчиков одним списком со сквозными местами (И-62). Прогон сверяет со страницами
   событий ВСЕ личные строки (место, время, год), пишет только места «כללי», а расхождения в возрастных
   секциях и по времени выводит списком — их показать Владу.
6. **Сшить старт-лист:** `dotnet run --project server/Swimm.API --no-build --launch-profile ProdAdmin --
   --stitch-start-list <compID>`.
   Импорт в день с OrgCompId запускает её сам; руками — после дня 1 (OrgCompId ставится после
   импорта). С 05.11 (И-60) сшивка понимает идущее соревнование: событие, где ни у одного
   заявленного пловца нет результата, остаётся «заявлен» (строка «ещё не плыли»), заявки дня,
   которого в базе нет, ждут без дня. Неявка (`no-show`) — только в событии, которое уже плыли.
   Возвращать статусы SQL больше не нужно. Если вывод другой — сверь с запросом из §4.
7. **Повторы.** Вечером (или когда допроплывут) снова §1.4 → файл того же дня с `eventId` и
   `overwriteExisting` → §3.5–3.6. День 2 — новый файл с его датой и `eventId`.
8. **Финал**, когда соревнование закончилось: статус записи автозабора → `imported` («✓ имп.» в строке).
   EN-имена — «Синхр. языки». Разбор идёт только по HE: пара HE+EN у идущего старта не склеивается.

## 4. Проверка (для любого пути)

- `SELECT count(*) FROM "Results" WHERE "CompetitionId" = <id>` = строк в файле; сверка «сошлось».
- Сайт: `https://swimhub.co.il/api/results?competitionId=<id>&pageSize=1` → `total`, и страница
  `https://swimhub.co.il/competitions/<id>` (Swims, Clubs, Start list). У 16891 новое соревнование было видно сразу, без сброса кэша.
- Новые ошибки проверок, ничего старого:
  ```sql
  SELECT "CheckId","Severity","EntityId",left("Message",100),"FirstSeenAt"
  FROM "Sys_DataCheckFindings" WHERE "Resolution" IS NULL AND "FirstSeenAt" > now() - interval '3 hours';
  ```
- Старт-лист: `SELECT "CompDate"::date,"Status",count(*) FROM "CompetitionEntries" WHERE "OrgCompId"=<compID> GROUP BY 1,2`:
  `no-show` только у реально проплытых событий.
- **Погасить ProdAdmin** (`preview_stop`): он держит прод-подключение и build-lock.

## 5. Footguns

- **Бассейн не известен ни протоколу, ни часто регламенту** (И-30): «25m» в разборе — это
  умолчание парсера. Спрашивать Влада; от длины зависят рекорды, FINA-очки и PB.
- **Эстафеты у идущего старта**: loglig сводит все полосы эстафеты в одну секцию без пола
  (`4X50 חופשי שליחים`, 21 команда при двух полосах в старт-листе). После загрузки сверить полосы
  (`--pull-relays <discoveredId>`, [relays.md](relays.md)).
- **Секция «כללי»** — отдельная секция той же дисциплины, не дубль. Бывает открытым финалом поверх
  возрастов (1581, Р43 — без медалей) или ЕДИНСТВЕННОЙ секцией какого-то года (16891 — все 2015 г.р.). Во
  втором случае PDF сводит оба пола со сквозными местами — `--pull-places` (§3.5а, И-62).
- Импорт файлом не ставит `OrgCompId` и статус автозабора. Без OrgCompId следующий забор
  стартового протокола и сшивка не найдут соревнование.
- `--repull` на многодневке, лежащей в базе одним днём, откажет («сначала --split-days»). Это
  правильно, обходить нельзя.
