## 1. Зачем экран существует

Один вопрос родителя: **«когда и на какой дорожке плывёт мой ребёнок»**. Не «как прошло
соревнование» — этого ещё не случилось. Протокол публикуют за несколько дней до старта,
и его пересылают в родительский чат клуба ссылкой, поэтому **логина экран не требует**.

Из этого следуют два приоритета, которые нельзя переставить:

1. **Время старта** — главное число экрана.
2. **Дорожка и заплыв** — второе.

Всё остальное (посевное время, категория, клуб) — контекст.

Мобильный — основной вид: протокол смотрят в зале с телефона. Горизонтальной прокрутки
быть не должно нигде.

## 3. Что на экране сейчас, сверху вниз

Файл: `client/src/projects/results-main-project/components/start-list/start-list-tab.tsx`.

### 3.1 Панель «найти своего» (`SwimmerFinder`) — видна всегда

- **Чипы избранных** — только залогиненному. Полоса в токенах `--theme-personal-*`
  (тёплое золото), внутри бейдж «❤ Favorites» и кнопки-имена; primary favorite помечен ⭐
  и стоит первым. Клик → карточка пловца.
- **Поле поиска** по имени, плейсхолдер «Find a swimmer by name — when do they swim?».
  Ищет от двух символов, по всем источникам соревнования сразу, и по ивритскому имени,
  и по английскому.
- **Выдача поиска** — список: имя, год рождения · клуб, справа — **дни, в которые он
  плывёт** («Mon 16 Feb»), число заплывов и время первого старта.

### 3.2 Подтабы источников (`SourceTabs`) — только если источников больше одного

Подпись «дата · #N» плюс число заявок. Один наш старт может быть собран из нескольких
протоколов федерации (окружные чемпионаты), и подтаб = один протокол, а не один день:
в один день бывает два протокола (центр 8-9 и центр 10-11 в примере выше).

**Когда открыта карточка пловца** подтабы меняют смысл: дни, где он плывёт, помечены ✓,
остальные приглушены до 30%, выбранный обведён цветом `--theme-personal-accent`, число
заявок скрыто.

### 3.3 Контент — один из трёх «зумов»

| Зум | Что показывает | Как открывается |
|---|---|---|
| 1. Программа | лента дисциплин дня: время · #номер · дистанция+стиль · категория · сколько заявок | умолчание |
| 2. Заплыв | дорожки: № дорожки · имя с эмблемой клуба · посевное время | клик по строке программы |
| 3. Карточка пловца | «первый старт ≈10:30 — приезжать к 09:45» + его заплывы, сгруппированные по дням | поиск, чип избранного, клик по имени в зуме 2 |

В зуме 1 есть переключатель дней (если в источнике их несколько) и своё поле поиска по
названию дисциплины — **оно дублирует роль верхнего поля и, вероятно, лишнее**.

Над контентом — строка «Updated HH:MM» и кнопка «↻ Refresh»: автообновления нет
принципиально (посев меняют до последнего дня, а дожать изменение до открытой страницы
нечем), поэтому время последнего забора обязано быть на экране.

## 4. Данные, которыми экран располагает

API анонимный, snake_case, `Cache-Control: max-age=30`.

```
GET /api/start-list/{orgCompId}                    программа (дни → дисциплины)
GET /api/start-list/{orgCompId}/events/{id}        заплыв с дорожками
GET /api/start-list/{orgCompId}/swimmers/{id}      карточка пловца (один источник)
GET /api/start-list/swimmers/{id}?orgCompId=…      карточка по всем источникам
GET /api/start-list/search?orgCompId=…&q=…         поиск по имени
GET /api/start-list/{orgCompId}/clubs/{id}         срез клуба («кто из наших плывёт»)
GET /api/start-list/competitions?days=60           предстоящие старты
GET /api/start-list/upcoming?swimmerId=…           ближайшие старты избранных
```

**Одна заявка** (`StartListSwim`) несёт: дистанцию, стиль, пол, категорию, возрастную
полосу, признак эстафеты, номер заплыва, **heat**, **lane**, **дату дня**, **время старта**
(может отсутствовать), раунд (`prelim`/`final`/`timed-final`), **посевное время**, имя
пловца, год рождения, клуб, статус (`entered` / `swum` / `no-show`).

Чего в данных **нет** и не будет к старту: результата, места, очков, медалей.

Срез клуба (`/clubs/{id}`) в интерфейсе **сейчас не используется** — готовый источник для
блока «кто из нашего клуба плывёт».

## 5. Правила, которые нельзя нарушить

1. **Посевное время — не результат.** Это личный рекорд с ДРУГОГО старта. Показывать его
   как время этого заплыва нельзя; сейчас оно подписано меткой «seed», нет посева — «NT».
2. **Строка стартового протокола — НЕ общая строка результата `SwimRow`.** Пробовали
   28.08.2026 и откатили: `SwimRow` собран под результат (место, медаль, очки, дуга уровня,
   крупное время справа) и в протоколе врёт видом — половина ячеек пустует прочерками.
   Общими остаются части: `UI_SwimmStyleIcon` (плитка дисциплины), `UI_SwimTime` (время),
   `UI_SwimmerNameCell` (имя с эмблемой клуба).
3. **Имена пловцов и названия клубов — на иврите**, английские только как фоллбек
   (правило Влада, 28.08.2026). Экран двунаправленный: имена RTL, интерфейс LTR.
4. **Интерфейсные строки — только по-английски.** Иврит на экране — это данные, не UI.
5. **«≈» у времени обязательно.** Заплывы плывут раньше или позже расписания на 20–40
   минут; «10:30» без «≈» читается как обещание.
6. **Полночь = «время не назначено»**, а не 00:00 — источник так печатает.
7. **Combine All Results на этом табе не показывается** — объединять нечего.

## 6. Где экран слаб — что, собственно, нужно от дизайнера

Это список наблюдений, а не техзадание; приоритет расставит дизайнер.

- **Три поля поиска на одном экране** (по имени сверху, по дисциплине в зуме 1) — они
  спорят. Нужна одна понятная точка входа.
- **Два ряда «кнопок-таблеток» подряд**: подтабы источников и переключатель дней внутри
  программы. У составного чемпионата это читается как одно и то же дважды.
- **Карточка пловца — главный экран фичи, но выглядит как список строк.** «Первый старт
  ≈10:30 — приезжать к 09:45» это самое ценное на экране; сейчас это блок-плашка того же
  веса, что и всё остальное.
- **Мобильная вёрстка не проектировалась дизайнером** — сделана «чтобы не ломалось».
- **Нет состояния «протокол ещё не опубликован»** как отдельного экрана: сейчас это просто
  строчка серым текстом.
- **Статусы заявки (`no-show`, `swum`) визуально не выражены вовсе** — а после старта
  протокол превращается в «кто не вышел», и это ценно.
- **Эстафеты**: команда — это одна дорожка с четырьмя именами; сейчас имена перечислены
  через запятую и строка распухает.
- **Срез клуба не показан нигде**, хотя данные есть.

## 7. Токены и палитра

Экран красится общими токенами витрины `--theme-mode-*` (`surface`, `border-input`, `text`,
`text-muted`) плюс «личными» `--theme-personal-*` — тёплое золото, которым размечено всё
«моё» на сайте (полоса favorites в шапке соревнования, PB-бейджи):

```
--theme-personal-bg       #fffdf6 / #241f16   (light / dark)
--theme-personal-border   rgba(212,175,55,.45) / .4
--theme-personal-accent   #8a6d1a / #e3c15c
--theme-personal-badge-bg rgba(212,175,55,.18) / .16
```

Светлая и тёмная темы — обе рабочие, переключаются `data-mode` (см. `client/src/index.css`).
