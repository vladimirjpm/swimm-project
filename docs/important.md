Правило этого файла: пункт сюда попадает, только если у него есть источник в документации

## Данные на витрине

- **Имена пловцов и названия клубов — ивритские по умолчанию, всегда** (решение Влада
  28.08.2026). Английское — только фоллбеком или по явному запросу языка. Это данные, а не
  UI, поэтому правилу «видимый UI только на английском» не противоречит.
  → [CLAUDE.md](../CLAUDE.md), «Golden rules».
- **Видимый интерфейс сайта — только английский.** Русские строки в UI — баг.
  → [CLAUDE.md](../CLAUDE.md).
- **Коды стран — alpha-3 (`ISR`) везде в данных**; alpha-2 только для отрисовки флагов, одна
  точка конвертации. `ISR`.slice(0,2) = флаг Исландии.
  → [ARCHITECTURE.md](ARCHITECTURE.md) §1.
- **Кто подал медиа, знают только модераторы.** Ленты зрителя (клуба, группы, галерея страницы
  группы) отдают `PublishedMediaItemDto` — без email и id владельца; строка inbox-а модерации
  с владельцем — только модераторам. → [media-page.md](media-page.md), «Лента зрителя».

## Места, медали, очки

- **Протокольные места официальные**, Combine All Results — сравнительный вид. На многодневных
  детских стартах медали дают за каждый день: два первых места в одной возрастной группе — норма.
  → [competition-overview-cards.md](competition-overview-cards.md), «Почему у одного соревнования ДВА набора мест».
- **Медаль — одно правило на продукт** (`HelperResults.isMedalPlace`): соревнование награждаемое
  (`IsAward`), время зачтено (не `TimeFail`), не prelim/extra (Р34), не общая секция «כללי» (Р43).
  Само место показываем как в протоколе.
  → [competition-overview-cards.md](competition-overview-cards.md), «Что считается медалью».
- **Эстафета принадлежит всей команде** через `RelayMembers`. Фильтр эстафет по
  `Result.SwimmerId` — баг: эстафету и её медаль увидит только нога-владелец строки.
  → [relays.md](relays.md), «Золотое правило».

## Сезон и возраст

- **Два понятия сезона, путать нельзя.** Календарный (`SeasonMath`, граница 1 сентября) — чему
  принадлежит заплыв. Витринный — какой сезон витрина считает текущим: переключается только
  после последнего зимнего чемпионата.
  → [season-boundary-rule.md](season-boundary-rule.md).
- **Возраст в сезоне — по году ОКОНЧАНИЯ сезона**, один на все старты, только через
  `SeasonMath.AgeInSeason`. Сверка со справочником рекордов — отдельная ось (`RecordAgeAxis`).
  → [data-integrity.md](data-integrity.md) §13.

## Качество данных

- **Время заплыва — только через `UI_SwimTime`, и всегда вместе с признаком качества** (И11).
  Качеств два: `protocol` (ошибка протокола, `SuspectReason`) и `record` (спорная запись
  справочника). DTO со временем без признака роняет тест.
  → [client/CLAUDE.md](../client/CLAUDE.md), «время заплыва — только через UI_SwimTime».
- **Ошибки федерации не чиним — помечаем.** Источник не правим; помеченное остаётся в
  протоколе, но не бьёт рекорды и не показывается достижением. **Наши ошибки — чиним:**
  правило не распространяется на ручной ввод (соревнование, внесённое руками), там
  исправляется сама база (решение Влада 14.09.2026).
  → [data-integrity.md](data-integrity.md), пересмотр решения о «9-11» у #63.
- **Порядок обновления рекордов:** сначала World Aquatics, потом федерация поверх —
  `--records-refresh`. Перепутанный порядок молча откатывает национальные рекорды.
  → [data-integrity.md](data-integrity.md), раздел про `--records-refresh`.
- **Батч рекордов по странам не трогает Израиль** (решение Влада 16.09.2026): `ISR` в прогон
  всех стран не входит, его обновляет только `--records-refresh` — иначе World Aquatics молча
  откатит более свежие рекорды федерации. Там же решено: тянем все 235 реальных стран,
  `RegionCode` берём из запроса, а не из строки отчёта.
  → [plans/records-all-countries-plan.md](plans/records-all-countries-plan.md) §7.
- **Мастерские МИРОВЫЕ рекорды берём, только личные дистанции** (решение Влада 16.09.2026):
  источник `wa-masters` — PDF с worldaquatics.com/masters/records, ось `world/masters`,
  1095 строк, полосы 25-29 … 105-109. Эстафеты не берём: в модели `Record` нет эстафетных
  стилей и пола `mixed`, а полосы там по сумме возрастов четвёрки. Решение «для других СТРАН
  только `open`» это не отменяет — мастерса по странам у World Aquatics нет.
  → [data-integrity.md](data-integrity.md), «Мастерские мировые рекорды»;
  [admin-pages/import.md](admin-pages/import.md).
- **Неправдоподобное время из источника рекордов не блокируем — метим через реестр** (решение
  Влада 15.09.2026): импорт пишет строку как в источнике и заводит её в реестр спорных со
  статусом `candidate`. На сайте метки нет, пока человек не переведёт запись в `open`: автомат
  только предлагает. Живые случаи — «мировой» 40.11 от World Aquatics и два мастерских
  рекорда, потерянных федерацией (правило `slower-than-stored`, добавлено 16.09.2026, И-21).
  → [plans/records-quality-plan.md](plans/records-quality-plan.md) §3-бис, [data-integrity.md](data-integrity.md) И-20.
- **Файлы боевого прогона рекордов сохраняются** — `!records-sources/` (в git не идёт),
  имя `<источник>-<бассейн>__source-<дата справочника>__fetched-<дата скачивания>.pdf`.
  Без архива расхождение не с чем сверять: 16.09.2026 короткая вода мастерсов откатила 18
  рекордов, и доказать, откуда взялись прежние значения, не удалось. Там же чек-лист сверки.
  ⚠ Из него главное: совпадение ВРЕМЕНИ в протоколах ничего не значит, пока не сошёлся пловец,
  а инверсия возрастных полос сама по себе не доказательство — у мастерсов она бывает и в
  честных данных.
  → [data-integrity.md](data-integrity.md), И-21.
- **«В протоколе одно, в базе другое» — сначала** [data-integrity.md](data-integrity.md):
  инварианты, чек-лист и журнал решений. Решения по данным записываются только туда.

## Группы и клубы

- **Клуб — не группа.** Управлять клубом не может никто (назначить управляющего некому), у
  клуба нет подписчиков и уровня `members`. Закрытая аудитория — группа с `JoinPolicy = approval`.
  → [plans/club-subscribers-plan.md](plans/club-subscribers-plan.md).
- **Primary favorite «Me» — недоверенная привязка**: прав и верификации на ней не строим.
  → [hubgroups-architecture.md](hubgroups-architecture.md).
- **Инвентарь тренировки — признак повтора, а не заметка** (решение Влада, 16.09.2026): ласты
  получили свою колонку `Sys_TrainingResults.IsFins` и значок рядом с лопатками и колобашкой.
  Заметка сессии (`Note`) остаётся для того, у чего колонки нет. Там же: пол тренировочного
  повтора берётся из карточки пловца (И14), последняя тренировка — сверху.
  → [data-integrity.md](data-integrity.md), решения Р50–Р53.

## Кэш

- **Страницы, которые правят из их же таба Admin, отдаются браузеру с `no-cache`**, а не
  `max-age`: серверный сброс до кэша браузера не дотягивается.
- **Всё — через `ICacheService`, в кэше только DTO** (не сущности EF, не кортежи), взятое из
  кэша не менять, сброс — по метке, записывать — только `GetOrCreateAsync` (метки таблиц запись
  тогда получает сама). Так переезд на Redis будет заменой одной строки.
  → [ARCHITECTURE.md](ARCHITECTURE.md) §5, [plans/cache-tags-plan.md](plans/cache-tags-plan.md),
  страница `/Admin/Cache`.
- **Запись кэша без меток данных — ошибка** (К5, 15.09.2026): данные читаются ВНУТРИ фабрики
  `GetOrCreateAsync`/`CachedJson`, не до неё. Собранное правда не из базы объявляет
  `CacheTags.NotFromDb`, константный ответ в кэш не кладут. В Development нарушение — исключение.
  → [plans/cache-tags-plan.md](plans/cache-tags-plan.md) §4-8.
- **Диагностика кэша не нагружает сайт** (решение Влада, 15.09.2026): размер записи меряется при
  взгляде админки и запоминается, а не при записи в кэш — путь посетителя за него не платит;
  ответ API знает размер сам. Полный сброс кэша — только с подтверждением: после него сайт
  «холодный». → [admin-pages/cache.md](admin-pages/cache.md), «Размер».
- **Redis (К6) — только вместе с масштабированием** (решение Влада, 15.09.2026): до второго
  экземпляра API он пользы не даёт, а второй экземпляр требует ещё выбора лидера для фоновых
  сервисов, настроек не в памяти и состояния превью не в `IMemoryCache`.
  → [plans/cache-tags-plan.md](plans/cache-tags-plan.md) §5.
- **Сброс после записи в базу — сам, ручной не нужен** (К4, 14.09.2026): `SaveChanges` сбрасывает
  метки изменённых таблиц после коммита. Исключения: запись мимо EF (`ExecuteUpdate`/`Delete`,
  сырой SQL) — явно `db.InvalidateTableCacheAsync<T>()` (`table:T` + `anyrow:T`); то, что живёт не в базе
  (настройки), — общий сброс. → [plans/cache-tags-plan.md](plans/cache-tags-plan.md) §3.2.
- **Точность сброса — до строки** (решение Влада, 14.09.2026): страница одной сущности падает от
  правки своих строк, а не всей таблицы. Сделано для страницы группы, обзора и состава клуба
  (К4б.4–К4б.5), выключатель `CacheRowPrecision` включён по умолчанию (решение Влада, 14.09.2026);
  пловец — по замеру на проде. Сужать чтение можно только запрос, фильтрующий таблицу по FK на
  корень; каждое место сужения — со сценарным тестом (страж `CacheRowsSitesTests`).
  По колонкам не дробим, кроме короткого реестра «служебных» (часто пишут, мало кто читает:
  `LogligId*`, `QualityScannedAt`…; `CacheServiceColumns`, К4б.6) — их правка роняет только
  тех, кто их читает; колонка идёт в реестр только по журналу сбросов. Сужение и колонки — каждое
  со своим выключателем в настройках, оба включены по умолчанию (решения Влада, 14.09.2026).
  → [plans/cache-row-precision-plan.md](plans/cache-row-precision-plan.md).

## Как работаем

- **Перед каждым push — [pre-push-rules.md](pre-push-rules.md)**: «поменял X → обнови Y».
- **Не коммитить и не пушить без просьбы.** Ветка по умолчанию — `master`.
- **Clean Architecture соблюдается**: контроллеры берут только интерфейсы `Swimm.Application`.
  → [CLAUDE.md](../CLAUDE.md), [server/Swimm.Application/CLAUDE.md](../server/Swimm.Application/CLAUDE.md).
- **База: порт 5445, два `DbContext` (EF-команды — с `--context SwimmDbContext`), порядок на
  чистой БД `01-roles.sql` → `--migrate` → `02-grants.sql`**, автомиграций нет.
  → [CLAUDE.md](../CLAUDE.md), «Database» и «Migrations».
- **Всё, что касается входа и доступа, — security-sensitive**: SecurityStamp, антифорджери,
  хэши токенов. Расширять, а не переизобретать.
  → [CLAUDE.md](../CLAUDE.md), «Auth & security model».
