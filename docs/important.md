# Самое важное — правила и решения, которые нельзя потерять

Выжимка на одну страницу: то, что уже стоило багов или долгих разборов и что легко
переизобрести неправильно. Каждый пункт — коротко; подробности и «почему» — по ссылке.
Показывается в админке: **Docs → Important** (`/Admin/Docs/important`).

Правило этого файла: пункт сюда попадает, только если у него есть источник в документации
репозитория. Устарел источник — правится источник, а здесь — ссылка и одна строка.

## Данные на витрине

- **Имена пловцов и названия клубов — ивритские по умолчанию, всегда** (решение Влада
  28.08.2026). Английское — только фоллбеком или по явному запросу языка. Это данные, а не
  UI, поэтому правилу «видимый UI только на английском» не противоречит.
  → [CLAUDE.md](../CLAUDE.md), «Golden rules».
  ⚠ **Одно исключение — международные экраны рекордов** (`/records`, `/records/compare`;
  решение Влада 16.09.2026): там держатель показывается латиницей. Рекорды двух сотен стран
  приходят из World Aquatics латиницей, и одна ивритская строка посреди рейтинга читается не
  как «имя на родном языке», а как сбой кодировки. **Перевода нет:** латинское имя берётся из
  карточки нашего же пловца (`HolderLatinName`), не нашли — остаётся иврит. `/api/records`
  (источник остальной витрины) замену НЕ делает.
  Источников латиницы два: колонка `Records.HolderNameEn` (её приносит World Aquatics и
  **сбрасывает смена времени** — иначе новый рекорд оказался бы подписан прежним держателем;
  правило `HolderLatinName.CarryOver`, одно на импорт и обе админские формы) и словарь по
  карточкам наших пловцов. Вписать имя руками можно полем «Holder (latin)» на `/Admin/Records`.
  **Итог 17.09: 82 строки Израиля из 90 полностью латиницей**, личных рекордов ивритом не
  осталось; 8 оставшихся — эстафеты, где не хватает одного-двух человек из четвёрки.
  ⚠ Имена доставали у источника (`api.worldaquatics.com/fina/athletes`) и записывали по трём
  степеням доказательности; догадки не записывали.
  ⚠ **Разделение источников:** есть карточка пловца — имя берётся ИЗ НЕЁ (словарь), дублировать
  его в `HolderNameEn` не надо, иначе копия разъедется с карточкой. `HolderNameEn` — для
  держателей, которых у нас нет как пловцов. Кого не нашли и почему — data-integrity.md,
  «Имена держателей: чем закрыли и что осталось».
- **Видимый интерфейс сайта — только английский.** Русские строки в UI — баг.
  → [CLAUDE.md](../CLAUDE.md).
- **Коды стран — alpha-3 (`ISR`) везде в данных**; alpha-2 только для отрисовки флагов, одна
  точка конвертации. `ISR`.slice(0,2) = флаг Исландии.
  → [ARCHITECTURE.md](ARCHITECTURE.md) §1.
- **Пловец группы виден только внутри группы** (Р71, решение Влада 29.09.2026). Человека без
  аккаунта и без loglig тренер заводит сам (`Swimmer.PrivateHubGroupId`); снаружи — ни страницы,
  ни поиска, ни состава в общем ответе группы, ни клуба, ни избранного. Новое публичное место,
  где показываются пловцы, обязано фильтровать `PrivateHubGroupId == null`.
  → [hubgroups-architecture.md](hubgroups-architecture.md) §7.
- **Кто подал медиа, знают только модераторы.** Ленты зрителя (клуба, группы, галерея страницы
  группы) отдают `PublishedMediaItemDto` — без email и id владельца; строка inbox-а модерации
  с владельцем — только модераторам. → [media-page.md](media-page.md), «Лента зрителя».
- **🎉 «поздравить с заплывом» — только вошедшие, публично только число** (решение Влада
  25.10.2026, этап 1). Кнопка `UI_CheerButton` в протоколе и `SwimRow` (пловец, группа); число —
  только когда поздравления есть; имён поздравивших не показываем нигде (пловцы — в основном
  дети); неявке (NS/DNS) и пловцу группы поставить нельзя. Этап 2 (имена владельцу, push-сводка)
  не сделан. → [media-page.md](media-page.md), [ui-components.md](ui-components.md).
- **Название соревнования — только `UI_CompetitionName`** (решение Влада 25.10.2026). Он ставит 🏆
  чемпионату по флагу из данных (не по слову «אליפות»), значок роли ❄/☀/🌊 и `dir="auto"`. Новый
  экран с названием старта — через него; нет флага в DTO — добавь `is_championship`, а не правило
  по имени. ⚠ Обрезку (`truncate`) ставь на сам компонент — обёртка срезает начало ивритского
  названия вместе с 🏆. → [ui-components.md](ui-components.md), §3.
- **Значок сезона «зима / лето» — эмодзи ❄️ и ☀️, один на весь проект (окончательное решение Влада 13.11.2026: «символ-эмодзи ❄️ — на весь проект. как и солнце эмодзи»).**
  Рисует его только общий `UI_SeasonIcon` (`components/mix/season-icon`). Линейные рисунки снежинки и
  солнца пробовали в тот же день и убрали — рисунок снова не заводить. Эмодзи рисует система: на
  разных устройствах и в скачанном PNG обложки и плаката он выглядит по-разному, это принято
  осознанно. Не сезон и не меняется: ☀ / 🌙 переключателя темы и значок раздела «☀ Season bests».
  → [plans/my-media-poster-plan.md](plans/my-media-poster-plan.md) §2-бис, [ui-components.md](ui-components.md).

## Места, медали, очки

- **Протокольные места официальные**, Combine All Results — сравнительный вид. На многодневных
  детских стартах медали дают за каждый день: два первых места в одной возрастной группе — норма.
  → [competition-overview-cards.md](competition-overview-cards.md), «Почему у одного соревнования ДВА набора мест».
  Помеченная ошибка протокола (`SuspectReason`) место, медаль и клубные очки не теряет — только
  Best swim и High Point (Р69, Р72, решение Влада 29.09.2026).
- **Клубный зачёт без официального показываем с чипом «Unofficial»** (Р80, решение Влада
  08.10.2026): очки считает автоподбор (2025+ — шкала чемпионата Израиля), но они подписаны
  как наша оценка. Признак — `HasOfficialClubStanding = false` или `null` + «клубный зачёт не
  ведётся», и правило НЕ привязано вручную (ручная привязка = шкала из регламента, чипа нет).
  Не прятать и не подбирать шкалу под каждый мемориал.
  → [competition-overview-cards.md](competition-overview-cards.md), «Top clubs».
- **Статус человека в группе один** (Р74, решение Влада 30.09.2026): Active / On break / Doesn't
  train with us / Inactive. «Не тренируется» — в группе, но не в воде: вне «кто идёт» и дорожек,
  ставит только тренер, «Going» его не снимает. Inactive — скрытая строка состава, Restore вернёт.
  → [data-integrity.md](data-integrity.md) Р74, [hubgroups-architecture.md](hubgroups-architecture.md) §7.
- **Медаль — одно правило на продукт** (`HelperResults.isMedalPlace`): соревнование награждаемое
  (`IsAward`), время зачтено (не `TimeFail`), не prelim/extra (Р34), не общая секция «כללי» (Р43).
  Само место показываем как в протоколе.
  → [competition-overview-cards.md](competition-overview-cards.md), «Что считается медалью».
- **Эстафета принадлежит всей команде** через `RelayMembers`. Фильтр эстафет по
  `Result.SwimmerId` — баг: эстафету и её медаль увидит только нога-владелец строки.
  → [relays.md](relays.md), «Золотое правило».
- **Пол эстафеты: `mixed` ≠ `none`** (решение Влада 22.09.2026). `mixed` — смешанная эстафета
  (и в `Records`, и в `Results`), `none` — пол НЕ ИЗВЕСТЕН (уточняется по loglig). Слепо `none` →
  `mixed` не переводить; доказательство без первоисточника — только состав (есть м и ж,
  `RelayGender.Resolve`). В справочнике `mixed` бывает только у дистанции `4X…`
  (`Record.ValidateGender`); в карточку пловца пол эстафеты не идёт никогда. Эстафета с `none`
  не получает метку рекорда; возрастная ступень эстафеты — по САМОМУ СТАРШЕМУ участнику.
  → [plans/records-relays-plan.md](plans/records-relays-plan.md), [data-integrity.md](data-integrity.md) И-29.
- **Место пловца «среди сверстников» считается там, куда ведёт ссылка** (решение Влада
  24.09.2026): обычный старт — ровесники по году рождения без мастерса (срез `/season-best`
  с `age`), мастерский — его группа протокола «45-49» (срез с `age_group`). Одно правило
  `RankAmongPeers` на панель Season best и SB в H2H.
  → [plans/athlete-page-plan.md](plans/athlete-page-plan.md), «Перф».
- **Счётчик заплывов — «проплыл/заявлен» (решение Влада 24.10.2026).** Неявка (NS/DNS) —
  строка протокола без заплыва: заявлен на 3, не вышел на один — «2/3», а не «3». DQ и DNF —
  старт был, идут в «проплыл». Правило одно — `StartStatus.IsNoStart` (клиент —
  `HelperResults.isNoStart`, подпись `swimsLabel`).
  → [competition-overview-cards.md](competition-overview-cards.md), «Панель клуба в табе Clubs».
- **Рекорд помеченной строки виден, но не считается (решение Влада 25.10.2026, исключение в Р76).**
  New records и таб Records показывают рекорд, который заявляет строка с `SuspectReason`, с чипом
  «⚠ Under review»; в счётчики он не идёт, чистый рекорд той же клетки не вытесняет, справочник
  `Records` не трогается. Бейдж в строке протокола, Best swim, SB, High Point — по-прежнему нет.
  → [competition-overview-cards.md](competition-overview-cards.md), «New records»; [data-integrity.md](data-integrity.md) Р76, И-55.

## Сезон и возраст

- **Два понятия сезона, путать нельзя.** Календарный (`SeasonMath`, граница 1 сентября) — чему
  принадлежит заплыв. Витринный — какой сезон витрина считает текущим: переключается только
  после последнего зимнего чемпионата. **Витринный держит только сезонные РЕЙТИНГИ** (Season
  best, SB, места среди ровесников — уточнение Влада 26.10.2026): списки стартов (карусель
  пловца, My media) открываются на сезоне последнего старта, а рейтинг прошлого сезона рядом
  подписан «Season 2025/26» (`UI_SeasonTitle`). Таблица SB для сезона новее витринного пустая.
  → [season-boundary-rule.md](season-boundary-rule.md), «Уточнение 26.10.2026».
- **Возраст в сезоне — по году ОКОНЧАНИЯ сезона**, один на все старты, только через
  `SeasonMath.AgeInSeason`. Сверка со справочником рекордов — отдельная ось (`RecordAgeAxis`).
  → [data-integrity.md](data-integrity.md) §13.

## Качество данных

- **Время заплыва — только через `UI_SwimTime`, и всегда вместе с признаком качества** (И11).
  Качеств два: `protocol` (ошибка протокола, `SuspectReason`) и `record` (спорная запись
  справочника). DTO со временем без признака роняет тест.
  → [client/CLAUDE.md](../client/CLAUDE.md), «время заплыва — только через UI_SwimTime».
- **Промежуточные доклеиваются БЕЗ переимпорта** (решение Влада 20.09.2026): отдельная
  операция `--attach-splits` (она же кнопка «⏱ Промежуточные» в панели строки
  `/Admin/Competitions`) дописывает `RelayMembers.SplitTime` и `Results.TimeSplit` к
  строкам, которые уже в базе, а не перезаливает протокол. **У этих полей ровно один
  писатель — доклейка**; импорт с 20.09.2026 их не трогает, за ним остались мастерс-сборка
  эстафет и владелец строки (первая нога). Переимпорт ради промежуточных задваивает соревнование,
  когда старые строки импортированы иначе (1581: 3561 строка).
  С 23.11.2026 (решение Влада) та же доклейка идёт **сама после каждого импорта**, который что-то
  записал и знает compID (тумблер `SplitAttachOnImport`), — писатель полей всё тот же; кнопка
  осталась для повтора. Итог — подпись шага 9 чек-листа и аудит актором `auto:import`.
  → [plans/splits-backfill-championships-plan.md](plans/splits-backfill-championships-plan.md) §6,
  [data-integrity.md](data-integrity.md) И-28, [admin-pages/competitions.md](admin-pages/competitions.md)
  «⏱ Промежуточные».
- **Английское имя пловца: пустое лучше чужого** (10.10.2026; Влад поручил решить «хорошо и
  надолго», правило выбрано по этому поручению — пересмотреть можно). Импорт не пишет EN-имя, которое не подходит к ивритскому (`EnglishNameFit`:
  иврит в латинице или чужие слова) — поля остаются пустыми, витрина показывает иврит. Причина:
  импорт дозаполняет только ПУСТЫЕ EN-поля, и чужое имя не перезаписал бы никто. Новые случаи
  ловит проверка `swimmers.en-name-mismatch`, чинит `--fix-en-names` по карточке loglig.
  → [plans/en-names-handoff.md](plans/en-names-handoff.md), [data-integrity.md](data-integrity.md) И-50.
- **Ошибки федерации не чиним — помечаем.** Источник не правим; помеченное остаётся в
  протоколе, но не бьёт рекорды и не показывается достижением. **Наши ошибки — чиним:**
  правило не распространяется на ручной ввод (соревнование, внесённое руками), там
  исправляется сама база (решение Влада 14.09.2026).
  → [data-integrity.md](data-integrity.md), пересмотр решения о «9-11» у #63.
- **Сбой хронометража заплыва ловится по заявкам** (25.10.2026, Р87; ждёт подтверждения Влада).
  Автопометка `seed_time_jump`: минимум две дорожки одного заплыва на 13%+ быстрее заявочного
  времени при сиде от 250 очков FINA. Нужна сшивка заявок (`CompetitionEntries.ResultId`) — на
  импорте она идёт ПЕРЕД сканом качества; сшили позже — прогони скан ещё раз. Голый процент без
  уровня сида ловит новичков.
  → [data-integrity.md](data-integrity.md) И-55, Р87.
- **Порядок обновления рекордов:** сначала World Aquatics, потом федерация поверх —
  `--records-refresh`. Перепутанный порядок молча откатывает национальные рекорды.
  → [data-integrity.md](data-integrity.md), раздел про `--records-refresh`.
- **Батч рекордов по странам не трогает Израиль** (решение Влада 16.09.2026): `ISR` в прогон
  всех стран не входит, его обновляет только `--records-refresh` — иначе World Aquatics молча
  откатит более свежие рекорды федерации. Там же решено: тянем все действующие страны,
  `RegionCode` берём из запроса, а не из строки отчёта.
- **Расформированные федерации и нейтральные сборные — не страны** (решение Влада 16.09.2026,
  после боевого прогона): ГДР, СССР, Чехословакия, Югославия, Саар, Родезия, ОАР, Южный
  Вьетнам, Вест-Индия, Нидерландские Антилы, Сербия и Черногория, ОК-92 и нейтральные ART,
  NIA, ROC, RSF источник отдаёт наравне со странами — регион у них заполнен, отсев по пустому
  региону их не ловит. Убраны из прогона списком `NotCurrentCountries` и из базы (217 строк);
  действующих стран **215**. Цена: рекорд, который источник держит только под старым кодом,
  исчезает вместе с ним (400 к/п ж 50 м у Германии).
  → [data-integrity.md](data-integrity.md), И-24.
  → [plans/records-all-countries-plan.md](plans/records-all-countries-plan.md) §7.
- **Мировой рекорд ≠ лучший результат в истории** (разбор И-23, 17.09.2026): у дисциплин,
  ставших рекордными позже самого плавания, заплыв быстрее мирового рекорда — норма, а не
  конфликт источников. World Aquatics ведёт рекорды эстафет **4×50 только с 2013 года**,
  поэтому Франция 1:20.77 (Rijeka, 2008) законно быстрее мирового 1:21.80 (USA, 2018) — верны
  ОБЕ строки. Правило сторожа `faster-than-world-record` этого не различает и по построению
  не будет: прежде чем заводить претензию «страна быстрее мира», проверь, **с какого года
  дисциплина рекордная**. Отдельную сущность «примечание к дисциплине» заводим, когда таких
  фактов наберётся три (решение Влада 17.09.2026).
  → [data-integrity.md](data-integrity.md), И-23.
  → [plans/records-quality-plan.md](plans/records-quality-plan.md) §5.
- **Мастерские МИРОВЫЕ рекорды берём, только личные дистанции** (решение Влада 16.09.2026):
  источник `wa-masters` — PDF с worldaquatics.com/masters/records, ось `world/masters`,
  1095 строк, полосы 25-29 … 105-109. Эстафеты не берём: в модели `Record` нет эстафетных
  стилей и пола `mixed`, а полосы там по сумме возрастов четвёрки. Решение «для других СТРАН
  только `open`» это не отменяет — мастерса по странам у World Aquatics нет.
  → [data-integrity.md](data-integrity.md), «Мастерские мировые рекорды»;
  [admin-pages/import.md](admin-pages/import.md).
- **Мировые ЮНИОРСКИЕ рекорды (WJR) берём; подпись — «World Junior», не «WR»** (решения Влада
  21.09.2026): мировых рекордов по отдельному году не существует, WJR — один на полосу
  (ж 14–17, м 15–18). Полоса лежит в `AgeKey` («14-17»), матч с израильским возрастом — по
  полосе, вне полосы эталона нет. Источник `wa-junior` — JSON-выдача WA, не XLSX (там 504).
  Эстафетные WJR берём, но только после СРОЧНОГО пункта ROADMAP «Эстафеты в Records».
  → [plans/world-junior-records-plan.md](plans/world-junior-records-plan.md);
  [data-integrity.md](data-integrity.md), «Мировые юниорские рекорды».
- **Свежесть справочника рекордов — журнал проверок, на витрине «checked», не «updated»**
  (решения Влада 21.09.2026): дата по КАЖДОМУ источнику, без свёртки в минимум; пока только
  кнопка/CLI, расписание — на Azure; порог «пора проверить» 7 дней; писем нет. Сбой источника
  дату не сдвигает. Изменения в `country/*/open` (два хозяина, И-13) — не «ждёт Apply».

## Кэш

- **Страницы, которые правят из их же таба Admin, отдаются браузеру с `no-cache`**, а не
  `max-age`: серверный сброс до кэша браузера не дотягивается.
- **Всё — через `ICacheService`, в кэше только DTO** (не сущности EF, не кортежи), взятое из
  кэша не менять, сброс — по метке, записывать — только `GetOrCreateAsync` (метки таблиц запись
  тогда получает сама). Так переезд на Redis будет заменой одной строки.
  → [ARCHITECTURE.md](ARCHITECTURE.md) §5, [plans/cache-tags-plan.md](plans/cache-tags-plan.md),
  страница `/Admin/Cache`.
- **Запись кэша без меток данных — ошибка** (К5, 15.09.2026): данные читаются ВНУТРИ фабрики
  `GetOrCreateAsync`/`CachedJson`, не до неё. Собранное правда не из базы объявляет
  `CacheTags.NotFromDb`, константный ответ в кэш не кладут. В Development нарушение — исключение.
  → [plans/cache-tags-plan.md](plans/cache-tags-plan.md) §4-8.
- **Диагностика кэша не нагружает сайт** (решение Влада, 15.09.2026): размер записи меряется при
  взгляде админки и запоминается, а не при записи в кэш — путь посетителя за него не платит;
  ответ API знает размер сам. Полный сброс кэша — только с подтверждением: после него сайт
  «холодный». → [admin-pages/cache.md](admin-pages/cache.md), «Размер».
- **Redis (К6) — только вместе с масштабированием** (решение Влада, 15.09.2026): до второго
  экземпляра API он пользы не даёт, а второй экземпляр требует ещё выбора лидера для фоновых
  сервисов, настроек не в памяти и состояния превью не в `IMemoryCache`.
  → [plans/cache-tags-plan.md](plans/cache-tags-plan.md) §5.
  *14.10.2026: настройки уже в БД, сброс между процессами — мост `pg_notify`, фоновых джобов на
  проде нет (В17) — из трёх условий второго экземпляра осталось состояние превью; Redis по-прежнему
  только с масштабированием.*
- **Сброс после записи в базу — сам, ручной не нужен** (К4, 14.09.2026): `SaveChanges` сбрасывает
  метки изменённых таблиц после коммита. Исключения: запись мимо EF (`ExecuteUpdate`/`Delete`,
  сырой SQL) — явно `db.InvalidateTableCacheAsync<T>()` (`table:T` + `anyrow:T`); то, что живёт не в базе
  (настройки), — общий сброс. → [plans/cache-tags-plan.md](plans/cache-tags-plan.md) §3.2.
- **Точность сброса — до строки** (решение Влада, 14.09.2026): страница одной сущности падает от
  правки своих строк, а не всей таблицы. Сделано для страницы группы, обзора и состава клуба
  (К4б.4–К4б.5), выключатель `CacheRowPrecision` включён по умолчанию (решение Влада, 14.09.2026);
  пловец — по замеру на проде. Сужать чтение можно только запрос, фильтрующий таблицу по FK на
  корень; каждое место сужения — со сценарным тестом (страж `CacheRowsSitesTests`).
  По колонкам не дробим, кроме короткого реестра «служебных» (часто пишут, мало кто читает:
  `LogligId*`, `QualityScannedAt`…; `CacheServiceColumns`, К4б.6) — их правка роняет только
  тех, кто их читает; колонка идёт в реестр только по журналу сбросов. Сужение и колонки — каждое
  со своим выключателем в настройках, оба включены по умолчанию (решения Влада, 14.09.2026).
  → [plans/cache-row-precision-plan.md](plans/cache-row-precision-plan.md).

- **Оспоренное время защищено от источника** (17.09.2026, И-25): претензия в реестре со
  статусом `open` / `reported` / `accepted` заставляет импорт НЕ БРАТЬ это значение — в базе
  остаётся прежнее. `candidate` не защищает: автомат только предлагает. Единственное
  сознательное отступление от «копия обязана совпадать с источником», и отступает человек.
  Сам справочник мы всё равно не правим. Механизм профилактический: живого случая нет.
  → [data-integrity.md](data-integrity.md) И-25, [plans/records-quality-plan.md](plans/records-quality-plan.md) §3-трис.
- **Возраст в справочнике рекордов — КАЛЕНДАРНЫЙ** (`RecordAgeAxis.Calendar`: год заплыва минус
  год рождения), и это не то же самое, что возраст пловца у нас (сезонный). Разбирая «рекорд
  переехал на соседнюю ступень», считай по оси СПРАВОЧНИКА — иначе починка источника читается
  как потеря рекорда (на этом ошиблись 17.09.2026, И-25).
  → [data-integrity.md](data-integrity.md) §13, `CompetitionRecordsDetector`.
- **Эстафеты мастерс-чемпионатов — из пособытийных данных loglig** (решения Влада, 19.09.2026):
  пол женские/мужские `female`/`male`, микст `none`; категория — полоса по СУММЕ возрастов
  (`160-199`, у микста `mix-160-199`), `event_style_age` — её нижняя граница числом; место —
  внутри полосы. Только мастерс-чемпионаты; детские эстафеты — полосами `RelayBandReconstructor`.
