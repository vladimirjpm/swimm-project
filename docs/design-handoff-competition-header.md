# Design handoff — Competition Header + 3 таба (results_main.html)

Модульная шапка соревнования + три таба, по образцу Group Header
(`client/src/projects/results-main-project/components/group-header/` + `GroupTabs`).
Показывается, когда выбрано соревнование (нет `?group=`).

## Цель

Дать соревнованию «лицо»: шапка с метаданными и действиями + три таба —
**Overview** (дэшборд, дефолт), **Swims** (текущая таблица результатов),
**Clubs** (клубный зачёт). Всё модульно: слоты и карточки заменяются/расширяются
независимо, как в Group Header.

## Общая структура

```
CompetitionHeader
├── CompetitionHeaderTop      — идентичность + действия (Add video)
├── CompetitionToolbar        — селектор соревнования + Combine All Results
└── CompetitionTabs           — Overview | Swims | Clubs (локальный toggle, ?tab= в URL)
Контент таба под шапкой.
```

Один HTML: `results_main.html?competitionId=X&tab=overview|swims|clubs`.
Табы — локальный toggle (как Competitions/Trainings у группы), шапка между
табами не перезагружается, селектор соревнования один.

### CompetitionHeaderTop

Фон `--theme-primary`, текст `--theme-mode-accent-text` (правило парных токенов,
`client/CLAUDE.md`).

- **Слева (identity):** название; мета-строка: даты (`date`–`date_end`), флаг
  страны (`UI_FlagEmoji`), бассейн (25m/50m), статус-бейдж `live`/`upcoming`,
  бейджи `Masters`/`Awards`, число результатов.
- **Справа (actions):** **Add video** (только `isAuthenticated`) — существующий
  `AddLinkModal` с `fixedCompetitionId` (уровень `competition` поддержан сервером).
  Гостю — скрыта или ведёт в логин-модал.

Данные уже есть в `CompetitionSourceDto` (`/api/competitions`).
⚠️ Города/локации в модели НЕТ (`Competition` без поля City) — в v1 не показываем.

### CompetitionToolbar

- Селектор соревнования (текущий `DataSourceDDL`).
- Тогглер **Combine All Results** — переносится сюда из фильтров
  (`filter-recalculate.tsx`). Условия видимости прежние
  (`show_combine_all_results` && не paged-режим); рендерить только когда доступен,
  без disabled-заглушки. Логически действует на таб Swims.

## Таб 1: Overview (ДЕФОЛТ)

Дэшборд соревнования. Загружается первым; результаты для Swims подтягиваются
**в фоне после** полной загрузки Overview (lazy).

Блоки (сверху вниз, все — карточки, каждая кликабельна и ведёт линком куда надо:
на пловца, клуб, заплыв):

1. **Герой-блок** — крупно название, даты, статус, бассейн; для многодневных —
   список дней с переходом в Swims конкретного дня.
2. **Моё на этом соревновании** (только залогиненный, если есть данные):
   «Я был на этом соревновании» — мои заплывы (N), лучший результат, линки на
   каждый заплыв. Источник: результаты primary favorite / привязанных пловцов.
3. **Новые рекорды** — карточки `record`, если рекорды на соревновании были.
4. **Медиа** — публичные фото/видео (`/api/media/results?competitionId=`),
   превью + лайтбокс `UI_SwimmerGallery`; CTA «Add the first video» для
   залогиненного при пустой галерее.
5. **Суперлативы (fallback-карточки)** — показываются ВСЕГДА (вычислимы из
   результатов), поэтому пустого дэшборда не бывает:
   - лучший заплыв соревнования (max `international_points`) → линк на заплыв;
   - лучший клуб по рейтингу → линк на клуб;
   - лучший клуб по золотым медалям → линк на клуб;
   - пловец с наибольшим числом медалей → линк на пловца;
   - (расширяемо — контракт карточки generic по `type`, новый вид = новый `case`).
6. **Сводка** — число результатов, дней, участников, клубов.

Порядок/композиция блоков — на усмотрение дизайнера; контракт — блоки 2–5
скрываются по-отдельности, если данных нет (кроме суперлативов — они есть всегда,
если есть хоть какие-то результаты).

## Таб 2: Swims

Текущий results_main как есть: фильтры (`FilterSection`) + `ResultsTable` /
мобильные drawer'ы. Ничего не ломаем. Данные грузятся в фоне после Overview.

## Таб 3: Clubs

Клубный зачёт соревнования. Бэкенд-основа: существующий серверный club-summary
(фаза 3.4) — адаптировать под competitionId.

- Таблица клубов: медали (🥇🥈🥉), очки/рейтинг.
- Клик по клубу → его пловцы и результаты на этом соревновании (drill-down).
- Линки на пловцов → карточка пловца.

## Данные / API (сводка)

- Метаданные: есть (`/api/competitions`).
- Медиа: есть (`/api/media/results?competitionId=`); add — `POST /api/me/media`
  (rate-limit 20/мин, потолок 500, https-only youtube/vimeo).
- **Нужен новый эндпоинт**: `GET /api/competitions/{id}/overview` — серверный
  билдер по образцу `HubGroupHighlightsBuilder`, кэшируемый. Отдаёт: рекорды
  соревнования (у `Record` нет FK на Competition — вычислять из результатов),
  суперлативы (лучший заплыв/клубы/пловец), сводку, дни. Один запрос на весь
  Overview (кроме медиа и «моего» блока).
- «Моё на соревновании»: по результатам favorites залогиненного (уточнить —
  возможно, хватает существующих API избранного).
- Clubs: адаптация club-summary под competitionId.

## Модульность / переиспользование

- `HighlightCard` вынести из `group-header/` в общий `components/highlights/` —
  одна карточка на обе шапки и на суперлативы Overview.
- DTO карточки — общий generic-контракт (`type` + payload), новый вид карточки =
  новый `case`, неизвестный тип → `null` (forward-compat).
- Add video — `AddLinkModal` + `useUserMedia` как есть.
- Табы — паттерн `GroupTabs`.

## Решения (зафиксировано)

- **Overview — дефолтный таб.** Результаты Swims грузятся в фоне после него.
- Пустого дэшборда нет: суперлативы всегда рендерятся из результатов.
- Всё кликабельно: карточки ведут линками на пловца/клуб/заплыв.
- Залогиненный видит персональный блок «мои заплывы на этом соревновании».
- Combine All Results — в тулбар шапки, условия видимости прежние.

## Открытые вопросы дизайнеру

1. Селектор соревнования: внутри шапки (toolbar) или отдельным контролом над ней?
2. Мобильный вид: identity-строка — что сворачиваем первым; Overview-карточки —
   grid vs горизонтальный скролл (у группы <lg — скролл).
3. Лента-«тизер» хайлайтов в самой шапке (2–3 карточки над табами): нужна или
   Overview достаточно?
4. Live-соревнование: особый вид героя-блока (пульс/бейдж, автообновление)?

## Вне скоупа v1

- Город/локация соревнования (нет в БД).
- Публикация приватного медиа с модерацией (`docs/media-page.md`) — v1 показывает
  только публичное.
- Отдельные HTML-страницы под табы — всё в одном `results_main.html`.
