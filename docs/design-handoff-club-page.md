# Design handoff — страница клуба (club page)

Материал для claude.ai/design. Парный документ к
[design-handoff-athlete-page.md](design-handoff-athlete-page.md) — тот же принцип: **какие
данные реально есть**, откуда, и что придётся доложить на сервере.

Дата сборки: 2026-07-29. Ветка: `feature/point-rules-schema`.

---

## 0. Главное отличие от страницы спортсмена

У спортсмена уже есть **и** идентичность (`/swimmers/{id}`), **и** профильный эндпоинт
(`GET /api/swimmers/{id}`), **и** карьерный агрегат. У клуба нет **ничего** из этого:

| | Спортсмен | Клуб |
|---|---|---|
| Чистый URL | ✅ `/swimmers/{id}` | ❌ нет — `club` в query как **фильтр** |
| Профильный API | ✅ `/api/swimmers/{id}` | ❌ нет |
| Агрегат | ✅ `/api/athletes/career` | ◐ `/api/club-summary` — **по одному соревнованию**, не по клубу |
| Идентификация в результатах | ✅ `swimmer_id` в `ResultDto` | ❌ **только строка `club`/`club_en`** |
| Медиа | ✅ `/api/swimmers/{id}/media` | ❌ нет (есть у hub-групп) |

То есть страница клуба — это **не «как у спортсмена, только про клуб»**, а стройка с нуля
поверх существующих агрегатов. Объём работ по серверу заметно больше.

---

## 1. Что есть сейчас

### 1.1 Сущность `Club` ([Club.cs](../server/Swimm.Domain/Entities/Club.cs)) — она очень бедная
`Id, Name (иврит/кириллица), NameEn, IsPseudo, CountryId → Country`

**И это всё.** Нет: города, года основания, сайта, тренеров, соцсетей, поля логотипа,
описания. Дизайн не может опираться на «инфо о клубе» — его физически нет в БД.

- **`IsPseudo`** — в графе клуба протокола иногда стоит страна/сборная («USA», «Israel»,
  «M25», «Maccabiah MIX»). Такие записи исключаются из club-summary и дедупа. **У псевдоклуба
  страницы быть не должно** (или должна быть явно иная — «сборная», не «клуб»).

### 1.2 Логотип — файлы по **имени**, не по id
`UI_ClubIcon` (квадрат, `object-contain`, картинка-плейсхолдер) и `UI_ClubLogo`
(круг фиксированного диаметра 26/38/40px, `object-cover`, фолбэк — **инициалы** клуба,
для иврита — ивритские буквы) собирают путь как
`images/club-icon/{имя-с-заменёнными-пробелами-и-кавычками}.png`.

⚠️ Отсюда два следствия для дизайна и для бэклога:
1. **Переименование клуба в админке ломает его логотип** (файл не переименовывается).
2 .Логотипа у большинства клубов нет → **круг с инициалами — не край, а норма**;
   ровно как аватар у спортсмена. `UI_ClubLogo` уже решает «разноформатные PNG прыгают
   в строке» — переиспользовать, не изобретать.

### 1.3 `GET /api/club-summary` → `ClubSummaryDto` (главный существующий агрегат)
Параметры области: `competitionId` (число или `last`) · `eventId` · `country` · `poolType` ·
`dateFrom`/`dateTo` · `combined`.

```jsonc
{ "club": "…имя…", "points": 1673, "swimmerCount": 24,
  "successfulCount": 19, "gold": 5, "silver": 3, "bronze": 4 }
```

- Ключ — **имя клуба**, не id (`club` → `relay_team_name` → `club_en`).
- `swimmerCount` — сколько пловцов клуба стартовало; `successfulCount` — сколько с зачётным
  результатом (не DSQ/DNS). Пара «участвовало / доплыло» — хороший визуал.
- Есть `dateFrom`/`dateTo` — **значит сезонный разрез клуба технически уже доступен**, просто
  никто его так не вызывает. Это самый дешёвый путь к «статистике по годам».

### 1.4 Клубные очки — самое содержательное, что есть
- `PointRuleClubs` + `PointRuleClubsEntry`: `Version` («2025.01»), `EffectiveFrom`, `Scope`
  (`all`/`masters`/`non-masters`), `DefaultPoints`, `MaxScoringPlace`, **`RelayMultiplier`**
  (по регламенту бугрим — эстафета ×2), `ManualOnly` + шкала «место → очки».
- Правило **привязывается к соревнованию** (см. [pointsrules.md](admin-pages/pointsrules.md),
  [points-rules-per-competition-plan.md](points-rules-per-competition-plan.md)).
- Очки считает **только сервер**: `ResultDto` отдаёт `club_points` и `combined_club_points`
  в каждой строке. Клиент их показывает; локальный расчёт
  (`club-points-helper.ts` → `/api/club-points`) остался фоллбеком для старых статических
  источников.
- Витрина: `CompetitionOverviewDto` → `top_clubs`, `top_clubs_men`, `top_clubs_women` (топ-10;
  правила и оговорки — [competition-overview-cards.md](competition-overview-cards.md)).
  **`EventCategory` в клубном зачёте сознательно не учитывается.**

### 1.5 Связи, из которых можно собрать контент
- **Ростер:** `Swimmer.ClubId` → пловцы клуба (в БД есть, **API нет**).
- **Результаты:** `ResultRecord.ClubId` (FK есть!) → все заплывы клуба. Имя клуба нигде не
  денормализовано — результаты ссылаются по `ClubId` ([clubs.md](admin-pages/clubs.md)).
- **Официальная группа клуба:** `HubGroup.ClubId` + `HubGroup.IsOfficial` (одна на клуб,
  partial unique index) + заявки `Sys_HubGroupClubRequests` → бейдж «Official Group of {Club}»
  и ссылка на страницу группы.
- **Страна:** alpha-3 (`ISR`), флаг через `UI_FlagEmoji`.

### 1.6 Клиент — что уже написано
- `useClubSummary` (хук) + `HelperClub.getClubsSummary` (legacy-расчёт на клиенте).
- **`UI_ClubDetails`** — уже богатая карточка клуба в `filter-club` (paged-ветка): очки,
  медали, счётчики пловцов, выбор клуба. Это фактически готовый «блок клуба» — на странице
  переиспользовать.
- `UI_ClubIcon` / `UI_ClubLogo` (§1.2).

### 1.7 Админка (для полноты картины, не для дизайна)
[/Admin/Clubs](admin-pages/clubs.md): дедуп-кандидаты, merge (dry-run → apply),
dedup-ignore, переключение `IsPseudo`, `Edit` (переименование + аудит `club.update`),
фильтры качества `no-swimmers` / `no-country`. После merge клубов было **231 → 128**.

## 2. Чего НЕТ — что придётся доложить

### 2.1 Идентичность и маршрут (блокер №1)
`club` в [routes.ts](../client/src/utils/routes.ts) — это **вид/фильтр в query**, по правилу
проекта («в путь — только идентичность ресурса»). Для страницы нужен новый ресурс
`/clubs/{id}` и синхронная правка **трёх зеркал контракта**: `routes.ts`,
`cleanUrlRewrite` в `vite.config.js` (dev), rewrite-middleware в `Program.cs` (прод) —
плюс новая html-точка входа в `rollupOptions.input` (как `swimmer.html`).

### 2.2 `club_id` в результатах (блокер №2)
`ResultDto` отдаёт только `club` / `club_en` строками. Все клубные агрегаты клеятся **по
имени** (`club → relay_team_name → club_en`). Для страницы «по id» нужен шов: либо добавить
`club_id` в `ResultDto`, либо сервер сам резолвит `id → набор имён`. Второе — грязнее (клубы
с одинаковыми именами и следы дублей), первое — правильнее, но трогает горячий путь.

Почему это важно именно для клуба: после merge дублей **старые id исчезают**, а имена
остаются — значит страница по id должна выживать склейку (редирект `merged_into`), иначе
ссылки будут ломаться после каждой чистки.

### 2.3 Профиль клуба — `GET /api/clubs/{id}`
```jsonc
{ "id": 42, "name": "…", "nameEn": "…", "countryCode": "ISR", "countryName": "Israel",
  "isPseudo": false, "logoUrl": null,          // §1.2 — сейчас неоткуда взять
  "swimmerCount": 63, "activeSwimmerCount": 41, // всего в справочнике / стартовали в этом сезоне
  "firstSeason": 2019, "lastSeason": 2025,
  "officialGroup": { "slug": "dolphin-netanya", "name": "…" } | null }
```

### 2.4 Статистика по сезонам — `GET /api/clubs/{id}/timeline`
Сезон в проекте уже определён единообразно: **1 сентября — 31 августа**, метка по году начала
(`2025` → `2025/26`).

```jsonc
"seasons": [
  { "season": 2025, "label": "2025/26",
    "competitions": 11, "swimmers": 41, "races": 388,
    "points": 8420, "gold": 22, "silver": 18, "bronze": 15,
    "bestRank": 2,                 // лучшее место клуба в зачёте соревнования за сезон
    "personalBests": 143,          // сколько личников улучшено пловцами клуба
    "newRecords": 3 }              // рекорды, установленные пловцами клуба
]
```
⚠️ **Семантическая мина:** очки начисляются по правилу **конкретного соревнования**
(`PointRuleClubs` с привязкой). Складывать очки за сезон по разным правилам можно, но это
«сумма несравнимых величин» — как складывать баллы разных экзаменов. Либо показываем сумму с
явной сноской, либо показываем **место в зачёте** каждого соревнования вместо суммы очков.
Это продуктовое решение, а не техническое; в дизайне лучше заложить оба варианта.

### 2.5 Остальные блоки
- `GET /api/clubs/{id}/roster` — состав: пловцы + возраст + сколько заплывов/очков за сезон
  (пагинация, сортировки). Основа — `Swimmer.ClubId`.
- `GET /api/clubs/{id}/records` — «клубные рекорды»: лучшее время по оси
  **стиль × дистанция × бассейн × пол**, без эстафет и DSQ. **Ровно такая ось уже реализована
  для hub-групп** (фаза 8.3, «рекорды группы») — переиспользовать логику, не писать заново.
- `GET /api/clubs/{id}/competitions` — история участия: соревнование, дата, очки, медали,
  место клуба в зачёте.
- Медиа клуба — **нет**. У hub-групп есть `Sys_HubGroupMedia`. Если нужно клубу — либо
  показывать медиа официальной группы (дешево и логично), либо новая таблица.

## 3. Блоки, которые предлагаю дизайнить

1. **Hero** — круглый логотип (или инициалы) + имя (HE/EN, RTL) + флаг страны + бейджи
   («Official group», `local`/псевдоклуб) + счётчики «N swimmers · since 2019».
2. **KPI-полоса** — Points · Medals (🥇🥈🥉) · Swimmers · Competitions · Best rank.
3. **Season switcher** — All-time / 2025-26 / 2024-25 … (из `timeline.seasons`).
4. **График по сезонам** — очки/медали столбцами + линия «место в зачёте» (или только места,
   см. мину в §2.4).
5. **Top swimmers клуба** — лидеры по очкам/медалям за выбранный сезон, строки как в
   `UI_ClubDetails`, клик → страница спортсмена.
6. **Ростер** — таблица состава с возрастными группами, фильтр по полу/возрасту.
7. **Клубные рекорды** — матрица стиль × дистанция, раздельно 25m/50m (времена несравнимы).
8. **История соревнований** — список с местом клуба, очками, медалями.
9. **Официальная группа** — карточка-ссылка на hub-группу клуба (если есть), с её медиа.
10. **Сравнение с другими клубами** — позиция в общем зачёте сезона (данные для этого уже
    есть: `/api/club-summary` по датам).

## 4. Footguns — дизайн обязан учесть

- **Псевдоклубы** (`IsPseudo`) — страны/сборные в графе клуба. Не «клуб», страницы либо нет,
  либо она честно называется иначе.
- **Дубли и merge** — клубов было 231, после склейки 128. Страница по id должна переживать
  merge (редирект), иначе внешние ссылки гниют.
- **Логотип живёт в файле по имени** — переименование ломает картинку; инициалы — штатный вид.
- **Эстафеты ×2** (`RelayMultiplier`) и ключ клуба `relay_team_name` для эстафетных строк.
- **`swimmerCount` ≠ `successfulCount`** — «стартовало» и «доплыло» разные числа, не путать.
- **25m / 50m несравнимы** — клубные рекорды раздельно.
- **RTL**: имена клубов на иврите; смешанные строки (иврит + латиница + цифры).
- **Темы** light/dark через `data-mode` + правило парных токенов, контраст ≥ 4.5:1.
- **UI строго English** (данные — на иврите).
- Пустые состояния — норма: нет логотипа, нет медиа, нет официальной группы, нет рекордов,
  клуб без пловцов (такие есть — фильтр качества `no-swimmers`).
