## 1. Зачем

Промежуточные (этапы эстафет + отрезки личных заплывов) есть пока ровно у одного соревнования —
зимнего чемпионата мастерсов 2026 (comp 64, discovery 55): его переимпортировали 19.09.2026.
Остальные чемпионаты затянуты до появления доклейки, и у них промежуточных нет. Следствия:

- метка **«Relay lead-off»** у рекорда на странице пловца (`RelayLeadOffMatcher`) находит
  рекорд, проплытый первым этапом эстафеты, только если у этой эстафеты есть промежуточные —
  сейчас сработала один раз (30.25 Гостомельской);
- отрезки личных заплывов (`time_split`, раскрываются по клику на время) — только у comp 64.

Бэкфилл = переимпорт каждого чемпионата тем же путём, что и кнопка «Перезатянуть»
(`--repull <discoveredId>`): доклейка промежуточных вызывается там сама, только для чемпионатов.

## 3. Как прогонять (порядок на каждое соревнование)

1. **Бэкап** всей БД перед серией (`docker exec swimm-postgres pg_dump -U swimm -d swimm -Fc > …`).
2. `ASPNETCORE_ENVIRONMENT=Development dotnet run -c Release --no-launch-profile --project server/Swimm.API -- --repull <discoveredId>`
   - `-c Release` — чтобы не упереться в build-lock запущенного API (Debug-папку держит он);
   - в выводе смотреть строку `Эстафеты: …` (сколько доклеено / «эстафеты мастерс собраны»,
     «личные промежуточные: пловцов в источнике N, доклеено M») и `Сверка с файлом: сошлось`.
3. **Детские эстафеты — это доклейка (этап 1)**, ключ upsert не меняется: `--delete-missing` НЕ
   нужен. Он нужен только для мастерс-чемпионатов (сборка эстафет целиком меняет пол и
   категорию — см. relays.md, этап 2).
4. Проверить: `Competitions.HasSplits = true`, число эстафет с `RelayMembers.SplitTime`,
   число `Results.TimeSplit`.
5. После серии — сбросить кэш (`/Admin/Cache` → «Сбросить весь кэш») или перезапустить API:
   CLI пишет мимо кэша запущенного API.

Время: loglig тянется вежливо (пауза 2 с между запросами), на чемпионат уходит примерно
(дисциплин × 2 с) — у больших стартов 2–4 минуты.

## 4. На что смотреть (грабли, которые уже ловили)

- **Имена ног:** разборщик собирает переносы фамилий (конечная буква, дальность 12 pt), но
  после прогона полезно поискать новых пловцов без личных заплывов, заведённых этим импортом
  (так ловили «רבינוביץבץ», «BEN SHOHA») — запрос в data-integrity.md, И-28.
- **Детские эстафеты** разбиты по полосам `RelayBandReconstructor` — доклейка должна находить
  пару по заплыву/дорожке/времени; если «не нашлось в протоколе» много — разбираться, а не
  лечить сборкой целиком (сборка только для мастерсов).
- **Отрезки личных:** сумма отрезков обязана дать итог, иначе пловец пропускается — большое
  «в источнике N, доклеено M» с разрывом значит сдвиг колонок вёрстки (как у 400 м до правки).
- **Два соревнования без строки discovery** (8-11 зима 2026; טריילז лето 2026, дни 1560–1562) —
  выяснено 19.09.2026: оба затянуты старым путём из JSON (файлы `client/public/data/json`
  удалены в тот же день, данные в БД), `Competitions.OrgCompId` у них пустой.
  - 8-11 зима (57–59) — склейка четырёх окружных стартов, discovery 67–70 (loglig
    14208/14218/14220/14221), связь только в `CompetitionSources`. `--repull 67…70` **НЕЛЬЗЯ**:
    импорт ищет соревнование по `OrgCompId` строки discovery и заведёт 4 дубля.
  - טריילז лето (1560–1562) — строку в loglig ещё найти.
  - Путь для обоих: сперва научить импорт писать в соревнование через `CompetitionSources`
    (или привязать `OrgCompId`), потом переимпорт. Отдельная задача.
