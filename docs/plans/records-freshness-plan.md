# Свежесть справочника рекордов: проверка обновлений и «Updated …» на витрине (U1–U7)

**Статус: НЕ НАЧАТО (план 21.09.2026).** Кода нет. Решение Влада: продумать проверку
обновлений для ВСЕХ источников рекордов — мастерс, юниорских (будущий `wa-junior`,
[world-junior-records-plan.md](world-junior-records-plan.md)) и остальных — и показ даты
последнего обновления на клиенте.

## 1. Что есть сегодня — не перепроверять

- **Источники** (`IRecordSourceProvider`, ключ `Source`), порядок применения — САМО
  ПРАВИЛО (решение Влада 24.08, И-13), живёт в `Program.cs` у `--records-refresh`:
  `worldrecords` (WR + NR World Aquatics, XLSX) → `wa-masters` (PDF WA) → `isrorg-age` →
  `isrorg-masters` (PDF федерации). Будущий `wa-junior` встаёт к World Aquatics, до федерации.
- **Прогон:** `dotnet run -- --records-refresh [--dry-run]` — fetch → дифф
  (`RecordDiffService`: изменится / новых / нет в источнике) → apply. В админке то же —
  `/api/admin/records/fetch` + `/apply` на `/Admin/Import`, и отдельно прогон по странам.
- **Архив первоисточников:** `!records-sources/` + `SHA256SUMS.txt` (правила 11/11-бис
  pre-push-rules): боевой прогон обязан оставить файл с новой контрольной суммой.
- **Дата у записи:** `Record.UpdatedAt` — «когда МЫ обновили запись» (не путать с
  `RecordDate` — когда рекорд установлен). Ставится при создании/правке/апдейте диффа.
- **Чего НЕТ:** журнала «когда источник проверялся и что сказал». `UpdatedAt` меняется,
  только если запись изменилась, поэтому по нему нельзя отличить «проверили вчера, всё
  то же» от «не проверяли полгода». Это главный пробел.

## 2. Три разных даты — не смешивать

| Дата | Отвечает на вопрос | Где живёт |
|---|---|---|
| `RecordDate` | когда рекорд установлен спортсменом | `Records`, из источника |
| **проверено** (`CheckedAt`) | когда мы последний раз сверились с источником | **новое**, журнал проверок |
| **изменено** (`ChangedAt`) | когда справочник в последний раз реально поменялся | **новое**, журнал применений (≈ max `UpdatedAt` по оси) |

На витрине честная подпись — **«проверено»**, а не «изменено»: «Records checked 3 days
ago» говорит правду, даже если мировой рекорд не бит два года. Одна дата «Updated» без
уточнения врала бы в обе стороны.

## 3. Модель: журнал проверок источников

Новая таблица `Sys_RecordSourceChecks` (служебная, `Sys_*` — публичной роли `swimm_ro` не
видна; витрина получает даты через API):

| поле | смысл |
|---|---|
| `Source` | ключ провайдера (`wa-masters`, `wa-junior`, …) |
| `Scope` | ось, которую покрывает источник (`world/masters`, `country/ISR/age`, …) — одной строкой |
| `CheckedAt` (UTC) | когда сходили в источник |
| `Outcome` | `unchanged` / `changes-found` / `applied` / `failed` |
| `SourceHash` | SHA-256 полученного файла — «источник не менялся» ловится ДО парсинга |
| `Changed/Added/Missing` | счётчики диффа |
| `Error` | текст сбоя (`failed`: 504, таймаут, формат поменялся) |
| `AppliedAt` | когда дифф применён (для `applied`) |

⚠ **Проверка и применение — разные шаги**, как и сейчас (dry-run → Apply). Проверка
пишет журнал всегда; применение — только по кнопке админа. Автоприменения НЕТ: И-21 (два
рекорда «потеряла» федерация) и И-26 показали, что источник ошибается, и дифф должен
посмотреть человек. Сторожа импорта (`RecordPlausibility`, `faster-than-world-record`,
slower-than-stored) остаются в силе.

## 4. Как проверять обновления

- **U-проверка = fetch + хэш + dry-run дифф** по каждому источнику, результат — строка
  журнала. Хэш совпал с прошлой проверкой → `unchanged` без парсинга (дёшево). Не совпал →
  парсим, считаем дифф: пустой → `unchanged` (файл пересобран, данные те же), нет → 
  `changes-found`.
- **Когда запускать:**
  1. кнопкой «Проверить все источники» на `/Admin/Import` (и CLI `--records-check`);
  2. **по расписанию** — фоновой задачей раз в сутки (ночью по Израилю). ⚠ ПРОДА НЕТ
     (проверено 15.09): на локальной машине расписание имеет смысл, только пока API
     запущен; на Azure — тем же `BackgroundService`. Вопрос §7-2.
- **Порядок** — тот же список, что у `--records-refresh`: проверка не применяет, но
  отчёт читается в том же порядке, в котором потом нажмут Apply.
- **Сбой источника — не «нет обновлений».** 504/таймаут пишется `failed` с текстом, и
  «проверено» для этого источника НЕ сдвигается. Живой пример: `WJ` у World Aquatics
  отвечает 504 (21.09) — такая проверка обязана выглядеть как сбой, а не как свежесть.

## 5. Где это видно админу

- **Дашборд `/Admin`** — блок «Свежесть рекордов» (правило 2 pre-push: MD страницы):
  по строке на источник — «проверено N дней назад», исход, «есть N изменений → Import».
  Порог «пора проверить» — старше 7 дней или последний исход `failed` (жёлтым).
  Дашборд уже показывает похожее («WA-дифф 11 изменений ждёт /Admin/Import») — это
  место и расширяем, не заводим второе.
- **`/Admin/Import`** — у каждого источника дата последней проверки и последнего
  применения рядом с кнопками Fetch/Apply.

## 6. Как показывать дату на клиенте

- **API:** в ответе справочника рекордов (и в `/api/swimmers/{id}` рядом с `records`) —
  `sourcesCheckedAt`: по источникам, которые питают показанное, **минимальная** дата
  проверки (честно по самому отстающему). Плюс `sourcesChangedAt` — для подсказки.
- **Где на витрине:**
  - `/records` — строкой под заголовком: «World records checked 21 Sep 2026 · World
    Aquatics». На табе Masters — дата `wa-masters` и `isrorg-masters`, на NR — `worldrecords`
    и `isrorg-*`, будущий World Junior — `wa-junior`.
  - страница пловца, секция «Official records» — мелко в легенде под карточками, рядом с
    уже существующей подписью про тёзок.
- **Формат:** относительная дата («3 days ago») с полной датой в `title`; UI английский
  (правило продукта). Проверка старше 30 дней или `failed` — без алармизма на витрине,
  просто дата; тревога — дело админки.
- ⚠ Показываем «**checked**», не «updated» (см. §2).
