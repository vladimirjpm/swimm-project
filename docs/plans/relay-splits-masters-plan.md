# Эстафеты мастерс-чемпионатов из пособытийных данных loglig (этап 2)

Статус: **СДЕЛАН 19.09.2026** — `RelayMastersBuilder`, comp 64 переимпортирован: 124 команды
в 6 дисциплинах, места = loglig по категориям (119/119), клубный зачёт = официальный (общий
10/10 первых клубов, мужской и женский — первые тройки). Итог — §5. Заведён 19.09.2026. Этап 1 — промежуточные к найденным эстафетам —
сделан, см. [../relays.md](../relays.md), «Промежуточные эстафет», и
[../data-integrity.md](../data-integrity.md), И-28.

## 1. Проблема

Зимний чемпионат мастерсов 2026 (comp 64, loglig 13805), замер 19.09.2026:

| | loglig | у нас |
|---|---|---|
| эстафетных дисциплин | 6 (4×50 в/с ж, м — 9.01; микст комплекс — 9.01; микст в/с — 10.01; комплекс ж, м — 10.01) | 2 (freestyle, individual_medley) |
| команд | 124 | 79 |
| места | внутри категории (полосы по сумме возрастов: 100-119, 120-159, 160-199, 200-239…) | сквозные по секции |
| категория | пол × сумма возрастов | у всех `mix-120-159` |

Причина: общий PDF печатает эстафеты четырьмя секциями «4X50 / מאסטרס שליחות» **без названия
стиля и пола**, основной парсер склеивает их в две дисциплины и часть теряет. Микст потерян
целиком — с ним, например, 1:58.43 команды Гостомельской (её этап 27.11).

## 2. Идея

Для мастерс-чемпионатов эстафеты строить **целиком** из пособытийного источника loglig, а не
только доклеивать к ним промежуточные: у каждой дисциплины сетки есть стиль, дистанция и пол
(`FetchDisciplineGridAsync`), а PDF «זמני ביניים» даёт полосу («160-199 מאסטרס שליחים»),
место внутри полосы, заплыв, дорожку, итог, клуб и ноги с промежуточными
(`LogligRelaySplitParser` уже читает всё, кроме полосы и места).

## 3. Этапы

1. **Разборщик:** полоса (строка «NNN-NNN מאסטרס שליחים») и место (число перед «מיקום») на
   команду. Тест на фикстурах 73056/73037.
2. **Построение строк:** эстафетные строки JSON из пособытийных данных — поля соревнования из
   любой строки основного разбора, пол из сетки, категория по полосе, место внутри полосы,
   владелец строки = первая нога. Основной разбор эстафет для таких соревнований выбрасывается
   целиком (всё или ничего, как у доклейки).
3. **Переимпорт:** меняется ключ upsert эстафет (`Gender`, категория) — старые строки не
   обновятся, а останутся рядом. Нужен `--repull … --delete-missing` или точечное удаление
   старых эстафет соревнования до импорта; медиа/реакции на эстафетах comp 64 проверить до.
4. **Сверка:** 124 команды, места = loglig, клубный зачёт не разошёлся.

## 5. Итог (19.09.2026)

- Решения §4 приняты Владом по рекомендациям: пол `female`/`male`, микст `none`;
  категория — полоса по сумме возрастов (`160-199`, `mix-160-199`), `age_group` = полоса,
  `event_style_age` = нижняя граница числом; только мастерс-чемпионаты (признак — строка
  полосы у каждой команды PDF).
- Разборщик: полоса, статус DQ/NS, ноги без промежуточных. Пол — из категории сетки по слову
  пола (`LogligRelaySplitProvider.RelayGender`): разбор сетки брал первое слово «מאסטרס» → none,
  первый прогон положил все эстафеты микстом — поймано проверкой базы, перезалито.
- Переимпорт comp 64 — `--repull 55 --delete-missing` (бэкап БД перед): 79 старых строк
  удалены, 124 новые; личные 1265 строк не тронуты; сверка 1389 строк сошлась.
- Место внутри «дисциплина × пол × полоса» по времени; DQ без места. Совпадение с
  `AthleticsDisciplineResults?showCategories=True` — 119 из 119 команд с временем.

2. Категория: `mix-120-159` сейчас — это тоже пол+полоса? Сверить с `RelayBandReconstructor`
   и правилами очков мастерсов до того, как менять.
3. Только мастерс-чемпионаты или все чемпионаты (детские эстафеты у нас разбираются полосами
   `RelayBandReconstructor`, и там всё сходится с официальным зачётом)?
