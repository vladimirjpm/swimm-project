Понятийная основа, из которой всё выведено (решение Влада 09.09): **клуб и группа — не разные
сущности, а два вида одного, коллектив пловцов.** Группа = неофициальный клуб, который заводит
кто угодно. Отсюда «одна реализация, разные варианты» во всём — от страницы до публикаций.

## 4. СЛЕДУЮЩАЯ ЗАДАЧА: фильтр статусов на `/my-media`

Запрос Влада: «сделай фильтр на статусы — private / pending / published, что там есть».

⚠ **Фильтр уже написан и работает.** Заводить новый не надо — надо его ОТКРЫТЬ.

Что есть сейчас:

- значения ровно те, что просили: `all · private · pending · published · rejected`
  (`STATUSES` в `components/my-media-filter-panel.tsx:86`);
- статус карточки выводится из публикаций — `derivedCardStatus` в
  `components/status-styles.ts:16` (нет публикаций → `private`; есть pending → `pending`;
  есть approved → `published`; иначе `rejected`);
- карточка фильтра называется «Publication status» и живёт в шторке More filters.

Почему Влад его не видит — три условия, все в коде:

1. `my-media-filter-panel.tsx:310` — карточка рендерится **только при `segValue === 'with'`**
   (сегмент «With video»);
2. `my-media.tsx:248` — фильтр **применяется** только при `seg === 'with'`;
3. `my-media.tsx:570` — при уходе с сегмента `with` статус **сбрасывается** в `all`.

То есть: сперва переключи сегмент на «With video», потом открой More filters — и фильтр там.

Что стоит сделать (решение за Владом, я бы взял вариант Б):

- **А. Снять привязку к сегменту.** Статус есть у любого медиа, не только у видео: «private»
  это отсутствие публикаций, а оно осмысленно и для фото. Убрать три условия выше —
  фильтр станет доступен всегда.
- **Б. Поднять из More filters наверх.** Сделать статусы отдельным рядом чипов рядом с
  «Shared with» (тот ряд уже есть: `groupFilter` в `my-media.tsx`) — тогда фильтр видно без
  открытия шторки, а это ровно то, чего не хватило.
- **В. Добавить в словарь цель.** После работы по клубам у публикации есть `target_type`
  (`group` \| `club`), а чипы «Shared with» показывают только группы. Логично, чтобы клуб
  тоже был чипом.

⚠ Не изобретать свой словарь статусов: он один на продукт — `visibilityLabel` в
`status-styles.ts` (`private → members → everyone`), и правило «слово `published` из UI
убрано» уже принято (docs/media-page.md §7).

соревнования, но не его id, а `routes.competitionSwims` просит id.

## 6. Footguns этой сессии — сэкономят час

1. **`DevAdminBypass`** (`appsettings.Development.json`). Неаутентифицированный запрос получает
   синтетического админа, поэтому **curl пишет админские ручки без логина**. Но:
   - `/auth/me` отвечает `isAuthenticated:false` (у синтетической личности нет claim email) →
     **таб `Admin` в браузере не появится**, хотя API от того же браузера пустит;
   - у него `NameIdentifier = "0"`, а `DecidedByUserId` ссылается на `Sys_AppUsers` →
     **решение по заявке падает 500 на FK**. Свойство обхода, не ручки; под реальным логином
     всё работает. Касается и групповых решений, то есть было и до этой сессии;
   - owner-scoped ручки (`/api/me/media/{id}/publish-targets`) под ним возвращают пусто —
     владелец медиа не id 0.
2. **Кэш витрин 60 секунд** (`Cache-Control: public, max-age=60`), и браузер держит ответ даже
   после сброса серверного кэша. Правишь настройки руками — либо жди минуту, либо читай API
   с `cache: 'no-store'`.
3. **HMR оставляет две копии модуля контекста** при правке нескольких файлов подряд: страница
   падает с `useLoginModal must be used within <LoginModalProvider>`, хотя провайдер на месте.
   Лечится перезапуском dev-сервера. Консоль браузера при этом держит старые записи и после
   перезагрузки — проверять надо по DOM.
4. **Build-lock**: `dotnet build` падает на MSB3027, пока жив запущенный API. Останови процесс,
   потом собирай (правило из корневого CLAUDE.md, ловилось трижды за сессию).
