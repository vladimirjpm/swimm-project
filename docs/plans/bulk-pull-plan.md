# Пакетное затягивание входящих (/Admin/Competitions)

Статус: **РЕАЛИЗОВАНО** (2026-08-23), Б1–Б6 закрыты; тесты 1336/1336, живой прогон на
ноябре 2025 сделан. Решения Влада приняты — открытых нет. Что и где лежит —
[`../admin-pages/competitions.md`](../admin-pages/competitions.md), раздел «Пакетное
затягивание»; здесь остаются обоснования решений.

Задача: сейчас каждое соревнование затягивается по одному (кнопка «Затянуть» → превью →
импорт). В ноябре 2025 таких строк 20, за сезон — сотня. Нужен пакетный забор: отметил
фильтрами год/месяц, нажал одну кнопку, все строки затянулись и разложились на
**беспроблемные** (импортируются одной кнопкой) и **проблемные** (разбираются руками).

Читать вместе с [`../admin-pages/competitions.md`](../admin-pages/competitions.md) — там
устройство страницы, счётчики «затянуто + нечего тянуть / всего», превью и регламент.

---

## 1. Место в UI

Строка итога под чипами месяцев (`Всего: 20 · месяц: Nov`) — кнопка действует на строки
**текущей страницы списка** (20/стр; при cap 30 это и есть вся выборка одного месяца):

```
Всего: 20 · месяц: Nov   [☐ включая чемпионаты]  [ ⏬ Затянуть все незатянутые (17) ]
```

Отдельного экрана нет **сознательно**: выборка уже задаётся фильтрами страницы
(сезон/месяц/дисциплина/тип), и второй экран пришлось бы учить тем же фильтрам заново.
Кнопка стоит там же, где счётчик долга, — иначе «сколько тянуть» и «затянуть» окажутся
в разных местах.

Результат — **раскрывающаяся панель «Пакетное затягивание»** под этой же строкой, не
модал: работа идёт минуты, из неё надо уметь уйти и вернуться.

В пачку берутся строки стадии `OnSite`, у которых нет `IsNothingToPull` (пустой протокол /
Ignored) — тот же предикат, что у счётчика. Иначе кнопка и чип разойдутся в числах.

### «Включая чемпионаты» — по умолчанию ВЫКЛ

Чемпионат = сработал **любой** из двух источников:
- имя — `CompetitionAdminRepository.LooksLikeChampionship` (`אליפות` + `ישראל`, слова
  проверяются по отдельности: между ними бывает спонсор). Уже есть, на нём живёт `?kind=champ`;
- регламент — `RegulationAnalysisDto.IsChampionship`.

Исключённые **не тянутся вовсе**; панель пишет «исключено: 3 чемпионата» со списком имён.
Чемпионаты Влад разбирает руками — там медали, зачёт и категории решаются штучно.

## 2. Как работает забор

Фоновая работа с прогрессом; строки обрабатываются **последовательно** — параллельно
долбить loglig нельзя.

| Метод | Что делает |
|---|---|
| `POST /api/admin/discovery/bulk-pull` `{ids[], includeChampionships}` | ставит пачку, отдаёт `batchId` |
| `GET  /api/admin/discovery/bulk-pull/{batchId}` | `{done, total, finished, rows[]}` — панель поллит |
| `POST /api/admin/discovery/bulk-import` `{batchId, ids[]}` | по каждому разбору существующий `IImportJobQueue.Enqueue` |

На каждую строку выполняется то же, что и в одиночном `Preview`: PDF HE+EN → парсер →
`IOfficialClubStandingService.ProbeAsync` → регламент (§3) → превью рекордов. Батч
**переиспользует** одиночный путь, а не повторяет его.

Превью кладутся в тот же `IMemoryCache`, но с **TTL 60 мин** вместо 15: иначе первое
протухнет раньше, чем доедет двадцатое. Cap пачки — **30 строк** (иначе «Все / 342»
превращается в получасовой забор десятков мегабайт в память).

`batchId` живёт в `sessionStorage` — панель восстанавливается после перезагрузки страницы,
как открытые панели строк.

Импорт идёт через существующую очередь: дальше всё видно в /Admin/ImportHistory, статус
`imported` проставляет фоновый обработчик. Ничего нового в импорте не появляется.

## 3. Регламент (תקנון) — забирается автоматом

**Где лежит** (проверено 2026-08-23): не на isr.org.il, а на loglig — на странице
`LeagueTable/AthleticsDisciplines/{logligId}` стоит
`<a href="/LeagueTable/ShowLeagueDoc/{docId}">תקנון</a>` рядом с кнопкой `דירוג מועדונים`;
отдаёт `application/pdf` (docId 2502 — 380 КБ, `%PDF-1.7`). Ссылка есть не у всех стартов.

**Лишнего кода не пишем.** Ту же страницу читает `LogligClient.GetCompetitionStandingAsync`
(берёт с неё `seasonId` и id заплывов), а разбор PDF целиком умеет существующий
`IRegulationAnalyzer` (медали / командный зачёт / чемпионат, с цитатами, с учётом
перевёрнутого иврита). Добавилась одна регулярка по разметке + скачивание PDF; ни нового
клиента, ни нового парсера.

⚠ Поправка к первой редакции плана: «без лишнего запроса» не вышло. Зачёт и регламент
запрашиваются НЕЗАВИСИМО (разные потоки: зачёт нужен и там, где регламент не нужен), поэтому
страница соревнования качается дважды — +1 GET на строку при 13 уже имеющихся. Протаскивать
HTML через два DTO ради этой экономии не стали.

**Меняется одно ранее принятое правило.** Сегодня записано: анализатор ничего не решает
сам, находки показываются с цитатами, галочки ставит человек — документ чужой, произвольной
формы. В пачке человека нет, поэтому находки **применяются автоматически**, а цитаты
**сохраняются**: видны в строке панели и уезжают в аудит `competition.bulk-import`, чтобы
основание можно было проверить постфактум. Ослабление осознанное, записать в доку явно.

Ручной вход (приложить файл) остаётся — для стартов без ссылки.

## 4. Классификация строк

| Признак | Флаг | В автоимпорт |
|---|---|---|
| Забор/парсинг упал (`LastError`, BadRequest) | 🔴 ошибка | нет |
| `resultCount == 0` / «No competitions found» | ⚪ нечего тянуть (авто-`EmptySourceAt`) | нет |
| Бьёт **хоть один** рекорд | 🟡 рекорды — ручная проверка | **нет** |
| Уже есть в БД (`existingCompetitionId`) | 🟡 нужно решение «перезаписать?» | нет |
| В файле > 1 дня (`competitions.length > 1`) | 🟡 нужно решение по событию | нет |
| Зачёт есть, шкала не совпала ни с одним правилом | 🟡 нужно правило очков | нет |
| `warnings` непустые | 🟡 предупреждения парсера | нет |
| Ссылки `תקנון` нет / PDF не разобрался | 🟠 **без регламента** | **да**, галочка отмечена — можно снять |
| Ничего из перечисленного | 🟢 беспроблемная | да |

Правила, которые стоит понимать, а не просто прочитать:

- **Рекорд — всегда ручная проверка.** Настоящий рекорд событие редкое; протокол, который
  их бьёт, чаще означает кривой разбор. Порога нет: хоть один — в проблемные.
- **Клубный зачёт — два источника, и они не взаимозаменяемы.** Галочку «зачёт ведётся»
  ставит **регламент**; правило очков — только **фактическая loglig-проба шкалы**. Если
  шкала не совпала ни с одним правилом — строка проблемная. Иначе соревнование уедет на
  автоподбор правила по дате: ровно так зимний чемпионат 2025 получил чужую шкалу.
- **Без регламента — не повод не импортировать.** Категория и результаты уже польза,
  медали/зачёт доставляются галочками в панели строки. Но строка помечена, и её видно.

## 5. Импорт

`[ Импортировать отмеченные (14) ]`. Отмечены по умолчанию 🟢 и 🟠. Над таблицей —
переключатель **«снять все без регламента»**: прогнать пачку без них и вернуться к ним
отдельно.

Всем импортируемым проставляется категория **`results-8-99`** («Age 8-99», ключ в БД есть).

**Жёсткое правило: массовый импорт никогда не ставит `overwriteExisting` и `deleteMissing`.**
Массового удаления результатов одной кнопкой не даём; «Перезатянуть» остаётся одиночным.

Если отметить проблемную строку руками, она поедет с дефолтами (без категорий сверх 8-99,
без правила очков) — это подписано в панели.

источникам; парс ссылки `ShowLeagueDoc` на фикстуре реальной страницы loglig.

## 7. Решения (приняты 2026-08-23)

1. Категория всем импортируемым — `results-8-99`.
2. Чемпионаты по умолчанию не тянутся; чекбокс «включая чемпионаты» = false.
3. Рекорды не заносим автоматом: любой побитый рекорд → ручная проверка.
4. Регламент качаем сами (§3), а не просим файл; находки применяются автоматом, цитаты — в аудит.
5. Строка без регламента импортируется, но помечена; есть переключатель «снять все без регламента».
6. Клубный зачёт: галочка от регламента, правило очков только от loglig-пробы; несовпадение шкалы → проблемная.

## 8. Что получилось (2026-08-23)

- **Б1** — `ILogligClient.GetRegulationAsync` + `IRegulationFetchService`; одиночная кнопка
  «Проверить регламент» тянет сама, файл остался запасным входом.
- **Б2** — логика «Затянуть» переехала из контроллера в `IDiscoveryPreviewService`, TTL
  разбора 15 → 60 мин; `IBulkPullService` (синглтон, последовательный обход, cap 30) +
  три эндпоинта; вердикт считает `BulkPullClassifier` (чистая функция).
- **Б3** — кнопка, чекбокс «включая чемпионаты», панель с поллингом и `sessionStorage`.
- **Б4** — `bulk-import` через ту же очередь + аудит `competition.bulk-pull` /
  `competition.bulk-import` (вердикты, цитаты регламента, ссылка на PDF).
- **Б5** — `BulkPullClassifierTests` (13) + `BulkPullServiceTests` (8) + парс ссылки
  `ShowLeagueDoc` на фикстуре; весь набор 1336/1336.
- **Б6** — раздел в `docs/admin-pages/competitions.md`, исправлено прежнее утверждение
  «регламента на сайте нет».

**Живой прогон:** ноябрь 2025 (20 незатянутых), пачки на 2 и 3 строки — все `Clean`,
регламенты найдены (`ShowLeagueDoc/2658, /2631, /2670, /2684, /2690`), 257–465 результатов,
рекордов 0. Медалей ни в одном: у лиговых регламентов их и нет — проверено извлечением
текста PDF, это не сбой чтения. **Импорт вживую не запускался** — первое нажатие за Владом.

Что осталось на будущее (не блокирует):
- флаг 🏆 у импортированного чемпионата по-прежнему ставится руками: payload импорта его не
  несёт, а чемпионаты в пачку по умолчанию и не идут;
- кандидаты берутся со СТРАНИЦЫ списка (20/стр), а не со всей выборки фильтров; при cap 30
  это совпадает, но при 50/стр разошлось бы.

## 9. Как вернуться к работе

Прочитать `docs/admin-pages/competitions.md` (устройство страницы, счётчики, превью,
регламент), затем §3 и §4 здесь — в них вся суть. Точка входа в код:
`DiscoveryAdminController.Preview` (одиночный путь, который батч переиспользует) и
`LogligClient.GetCompetitionStandingAsync` (страница, где лежит ссылка на регламент).
