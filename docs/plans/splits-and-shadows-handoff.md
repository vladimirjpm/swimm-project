# ПЕРЕДАЧА: промежуточные и пловцы-тени (сессия 19–20.09.2026)

Читать первым, если продолжаешь промежуточные (splits) или чистку пловцов-теней.
Планы: [splits-attach-without-repull-plan.md](splits-attach-without-repull-plan.md),
[splits-backfill-championships-plan.md](splits-backfill-championships-plan.md).
Журнал данных: [../data-integrity.md](../data-integrity.md), И-28 (три записи подряд в конце).

## 1. Где мы (короткая версия)

Промежуточные (этапы эстафет + отрезки личных заплывов) раньше приезжали побочным эффектом
полного переимпорта — и на comp 1581 это задвоило соревнование (3561 лишняя строка).
Теперь их приклеивает ОТДЕЛЬНАЯ операция, которая пишет два поля к строкам, уже лежащим в
базе, и не может ничего задвоить. Импорт промежуточные больше не пишет вовсе.

Попутно выяснилась причина «пловцов-теней»: протокол и loglig режут имя на имя/фамилию
по-разному, поэтому ключ пловца не совпадает. Починено фоллбеком в импорте.

## 3. Как это работает теперь

```bash
# сухой прогон (ничего не пишет), затем боевой
dotnet run -c Release --no-build --no-launch-profile --project server/Swimm.API -- \
  --attach-splits <competitionId> [--loglig <id>] [--dry-run]
```

- пишет РОВНО два поля: `RelayMembers.SplitTime`, `Results.TimeSplit`; строк не создаёт и не
  удаляет, мест/пола/категории не трогает, ключ upsert не участвует;
- прогон идёт по ВСЕМ дням события, какой бы день ни передали; отчёт — с разбивкой по дням;
- `--loglig` нужен только стартам без строки discovery;
- **то же самое кнопкой** «⏱ Промежуточные» в раскрытой панели строки `/Admin/Competitions`
  (Д5, #81): первый клик — сухой прогон, «Применить» появляется, только если есть что писать;
- идемпотентна: повторный прогон пишет 0;
- ⚠ **у полей `split_time` / `TimeSplit` ровно ОДИН писатель — доклейка.** Импорту остались
  мастерс-сборка эстафет и владелец строки (первая нога).

Код: `SplitAttachMatcher` (Application, правило), `LogligSplitSourceProvider` (Parsing,
источник), `SplitAttachService` (Infrastructure, запись), флаг в `Program.cs`.
Тесты: `SplitAttachMatcherTests` (11), `SplitAttachServiceTests` (6).

## 6. Полезные запросы

```sql
-- пловцы, заведённые последней серией (порог = max(Id) из бэкапа перед прогоном)
select s."Id", s."FirstName", s."LastName", s."BirthYear",
       (select count(*) from "Results" r where r."SwimmerId"=s."Id" and r."RelayId" is null) personal,
       (select count(*) from "RelayMembers" m where m."SwimmerId"=s."Id") legs
from "Swimmers" s where s."Id" > 62907 order by s."Id";

-- сколько промежуточных у соревнования
select (select count(*) from "Results" where "CompetitionId"=1581) results,
       (select count(*) from "Results" where "CompetitionId"=1581 and "TimeSplit" <> '') with_splits,
       (select count(*) from "RelayMembers" m join "Results" r on r."RelayId"=m."RelayId"
         where r."CompetitionId"=1581 and m."SplitTime" is not null) legs;
```

## 7. Грабли этой сессии (не наступать заново)

- **Ручная транзакция при retry-стратегии** падает с «does not support user-initiated
  transactions» — только через `Database.CreateExecutionStrategy()`. In-memory тесты это НЕ
  ловят, ошибка живёт на настоящем Postgres.
- **Перед `--repull` соревнования, импортированного не этим путём** (раунды, ручные склейки,
  старый JSON), сравнивать число строк до/после: «Сверка с файлом: РАСХОЖДЕНИЕ» — тот самый
  признак. Лучше вообще не гонять: для промежуточных теперь есть доклейка.
- **Перестановку имени и фамилии склеивать НЕЛЬЗЯ** — решение проекта, тест
  `Import_NameSurnameSwap_NotMerged`. Правило границы обязано её пропускать.
- **Лимит 5 dev-серверов на папку.** Когда слоты заняты другими чатами, поднимать связку
  `stack-5181-api5079` (API + клиент одним процессом). `dotnet` под `start /b` может пережить
  остановку превью и держать Release-сборку.
