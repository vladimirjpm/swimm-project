## 5. Решения, которые нельзя переизобрести

- **Избранные — ДЕФОЛТ состава, а не сам состав.** Отметить можно кого угодно, включая
  чужой клуб; обратно в favorites это НЕ пишется.
- **«Плана нет» ≠ «сохранён пустой план».** В первом подставляем избранных, во втором
  человек снял всё сам. Поэтому `null` против пустых списков — не «пустота значит нет».
- **Карточка — главный экран таба**, открывается сама, как только состав известен; ссылку
  с `?swimmer=`/`?heat=` не перебивает.
- **Открытая share-ссылка НЕ перезаписывает план получателя** — своим состав становится
  после первой правки, тогда же `?plan=` уходит из адреса. Галочки в ссылку не едут.
- **Ручное и автоматическое — в разных полях.** Флаг чемпионата ставит забор
  (`IsChampionship`), админ правит `IsChampionshipOverride`; иначе идемпотентный перезабор
  затирал бы решение человека. Разминка — только руками.
- **Многодневка живёт на уровне СОБЫТИЯ.** Программы грузятся у всех источников: у
  составного чемпионата дни лежат по разным протоколам.
- **Метки участника в строке D3 — отдельная колонка слева, а не приписка к имени.**
  Имена ивритские: любой значок, стоящий в одной строке с именем, двунаправленный
  алгоритм уносит на противоположный край — звезда "⭐ имя" рисовалась справа, а суффикс
  "· CLUB" слева (макет дизайнера этого не показывал, у него имена-плейсхолдеры). Теперь
  ⭐/CLUB стоят в своей ячейке фиксированной ширины, RELAY/leg/статус — ячейками справа от
  имени, контейнер строки `dir="ltr"`. Побочно выровнялись начала имён столбиком.
  Обратно "в имя" эти значки возвращать нельзя ни в каком виде (правка 30.08.2026).
- **Правый столбик строки D3 — «где в протоколе»** (правка 30.08.2026): категория, под ней
  `Heat N`, под ними дорожка каждого участника (`Line 4`, на узком экране `L4`). Раньше
  категория и заплыв стояли в шапке слева, а дорожка — у правого края: три подписи об одном
  и том же месте были растащены по строке. Дорожка теперь видна и когда выбран ОДИН пловец
  (`showNames=false`) — раньше в этом режиме её не было вовсе.
- **Посев — у имени участника, не в шапке строки.** Посев у каждого свой; в шапке он мог
  стоять только когда в заплыве один участник, у остальных врал бы. На узком экране уходит
  под имя, на широком идёт следом. Нет посева — `NT` на том же месте.
- **Состав эстафеты виден целиком, без нумерации ног** (вариант A, решение Влада
  30.08.2026): под строкой команды перечислением идут все её ноги, свой пловец — золотом.
  Номера («leg 3») НЕ печатаем: колонки порядка ног в схеме нет, порядок в перечислении —
  по id заявки, то есть по порядку затягивания протокола. По той же причине пометка
  `leg N` рядом с командой теперь показывается, только когда состава под строкой нет.
  Состав приходит, когда следят за КЛУБОМ (`/{comp}/clubs/{id}` отдаёт все четыре ноги);
  следя за одним пловцом, клиент получает только его ногу, и список из одного имени не
  рисуется — см. `PlanRowEntry.members`.
- **Пловцов из `?plan=` надо ЗАГРУЗИТЬ, хотя в состав они не входят** (фикс 30.08.2026).
  Ссылку открывает чужой человек: этих пловцов нет ни в его избранном, ни в его сохранённом
  плане, а `useEffectivePlan` грузил карточки только по этим двум спискам — карточка
  приходила пустой («Nothing on this day»), а чип показывал `#6601` вместо имени. Клубы в
  ссылке при этом работали (их тянет другой хук), поэтому баг и дожил до сюда: проверяли на
  ссылке, где пловец лежал в локальном плане. Теперь id из ссылки идут третьим аргументом
  `alsoLoadSwimmerIds`; на состав это не влияет — правило «ссылка не перезаписывает план
  получателя» держится тем, что `sharedPlan` показывается мимо `plan`.
- **Программа (зум 1) сгруппирована по дисциплине** (решение Влада 30.08.2026), а не идёт
  плоским списком по времени: «50m freestyle» повторялось восемь раз подряд, по разу на
  возраст, и дисциплину приходилось искать глазами. Теперь дисциплина — карточка, внутри
  время и возрастная группа. Порядок групп — по ПЕРВОМУ событию, то есть день по-прежнему
  читается сверху вниз. Группировка — чистая `groupEventsByDiscipline` в helpers.
- **Категория в программе берётся из `gender`+`age_band` через `bandLabel`,** а не из
  `event_category`: у источника он ивритский («בנות 11»), и на витрину не идёт — то же
  правило, что в строке плана.
- **Цвет текста таба задан ЯВНО на контейнере.** На странице результатов висит легаси-класс
  `.dolphine-training`, а `results-table.css` красит его в `green`; всё, что своего цвета не
  ставило, наследовало зелёный — поэтому программа была зелёной, а карточка плана нет (она
  красит себя сама). Правило в CSS не трогали: тот же класс в `results-main-project.css`
  красит в `red`, и кто на них ещё завязан — неизвестно.
- **Строка D3 — не `SwimRow`** (правило хендоффа, откат 28.08.2026). Общие части взяты:
  `UI_SwimmStyleIcon`, `UI_SwimTime`.
- **Токены Deep объявлены на классе**, а не на `:root` — таб включает их сам
  (`theme-deep` / `theme-deep-light`); без этого весь дизайн рисуется пустыми переменными.
- **В метке строки «seed», а не «PB»** — посев это не результат (правило №1 хендоффа).
- **Времени нет = полночь в источнике** → «not scheduled», а не 00:00.
