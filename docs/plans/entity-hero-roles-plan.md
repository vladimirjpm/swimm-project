## 4. Ш2 — RSVP (сделан 28.09.2026)

**Модель.** `Sys_HubGroupTrainingRsvps` (миграция `AddHubGroupTrainingRsvps`, БЕЗ grant
`swimm_ro`, `swimm_rw` — по default privileges): `HubGroupId`, `SessionDate`, `SessionStart`
(«HH:mm»), `UserId`, `Answer` (`yes|maybe|no`, CHECK), `Note` (`late|first-hour|leaving-early`,
CHECK), `SetByUserId` (тренер, если ответил за человека; SetNull), `UpdatedAt`. Уникально
`(HubGroupId, SessionDate, SessionStart, UserId)`. Каскад по группе и пользователю. Удаление
группы считает ответы в перечне потерь (аудит), в «есть что терять» они не входят.

**Занятие не строка** — расписание регулярное; ключ `yyyy-MM-dd-HHmm` (`next_training.id` в
ответе страницы). Правила — чистые функции `Swimm.Application/Mapping/TrainingRsvpRules.cs`:
занятие должно быть в расписании; смотреть — окно [−7; +28] дней; отвечать участнику — до
начала занятия, управляющему — ещё 7 дней после (поправить по факту); вперёд — не дальше 28.

**API** (`HubGroupTrainingRsvpController`, `TrainingRsvpService`) — личные, `private, no-store`:
- `GET /api/hub-groups/{id}/rsvp/{session}` → счётчики, `total` (активные участники-аккаунты),
  `mine`, `is_member`, `can_manage`, `can_answer`; управляющему ещё `people` (все активные с
  ответами, по группам ответа).
- `PUT …/rsvp/{session}` `{answer|null, note?, user_id?}` → то же целиком. `user_id` — только
  управляющему и только за активного участника (403 / 400). Управляющий вне состава сам за себя
  не отвечает: в полосе он не считается.
- Кто смотрит: управляющий (`CanEdit`) или активный участник-аккаунт; остальным 403.
- **Ничего из ответов не лежит в общем ответе страницы группы**: он кэшируется один на всех, а
  состав участников-аккаунтов — приватный. Поэтому отдельный личный запрос.
- Ответы ушедших и pending не считаются; при выходе из группы ответы на ПРЕДСТОЯЩИЕ занятия
  удаляются (прошлые остаются историей).

**Клиент.** Хук `use-training-rsvp.ts` — один экземпляр на страницу, ответ оптимистичный с
откатом и текстом отказа. `components/group-rsvp.tsx` — полоса + счётчики, три кнопки (нажатая
залита, повторный тап снимает), строка тренера (аватары идущих + «Who's coming →» в Trainings),
список людей по группам с ответом за человека, чип липкой полосы. Шапка: участнику — кнопки,
управляющему — строка тренера, управляющему в составе — оба. Trainings → Sessions: карточка
«Next training» (счётчики, свои кнопки, у тренера — список). Текст на залитой кнопке —
`--deep-accent-ink` (в тёмной теме цвета светлые).

Тесты — `TrainingRsvpTests` (20): ключ и окно, счётчики и знаменатель, снятие ответа, заметка
к «не приду» снимается, ответ за участника и пометка «by coach», отказы, выход из группы.

**Не сделано (дальше):** `Remind N` (нет канала), список «кто идёт» участникам (по настройке
группы), быстрые заметки в UI (сервер их уже принимает) и вид по дорожкам — Ш3, баннер
«сверху» — Ш4.

## 5. Ш3 — решения до начала работы (обсуждение 28.09.2026)

**Главное правило — И15 в [`docs/data-integrity.md`](../data-integrity.md) (Р54–Р57):
своё пространство свободно, чужое — только через доверие, выданное источнику один раз.**

**Откуда дорожки** (по порядку):
1. Опубликованный план на дату занятия (`Sys_LanePlans`, фаза 8.14) — как есть, подпись
   «Coach's plan».
2. Плана нет — раскладка на лету `LaneAllocation.AutoLanes` по ответам going + maybe
   (соседние уровни сливаются при нехватке дорожек — правило «13 человек на 3 дорожки» уже
   есть, лимита людей на дорожку нет — решение 27.09), подпись «Auto · by level». В базу не
   пишется.
3. Уровней нет — те же дорожки, порядок состава (`HubGroupMember.SortOrder`, затем имя):
   детерминированно, не «каждый раз по-разному».
4. Настройка группы «Lane view: Auto / Plan only / Off» — тренер может выключить, чтобы никого
   не путать; `Off` — только список «кто идёт».

**Заявления действуют только внутри группы** (предложение Влада 28.09.2026, Р55): пловцы и
результаты с аккаунтами не связаны; «Me» и «Family» — заявления пользователя, и они действуют
только в ЗАКРЫТОЙ части его групп (тренировки, дорожки, RSVP, `members`-медиа), а наружу
(карточка пловца, протокол, поиск, публичная страница группы) не выходят. Внутри группы люди
знают друг друга, тренер поправит.

**Кто стоит на дорожке** — кружок одного аккаунта, пловец для него выбирается по порядку:
метка членства от тренера (`HubGroupUserMember.SwimmerId`, перебивает заявления) → «Me» → первый
«Family» из состава группы → сам аккаунт под именем аккаунта (кого нет в loglig; имя видят
только участники группы). Уровень для аккаунта без пловца — на членстве аккаунта (новая
приватная `Sys_`-связь; `HubGroupSwimmerLevel` ключуется пловцом). Два аккаунта назвали себя
одним пловцом — оба кружка с меткой «2 claim», тренер разбирается.

**Флаг «Active / On break»** (Влад, 28.09.2026 — «кто-то пропадает на полгода или бросил»):
- ОДИН флаг на человека в группе, приватный (`Sys_`, на публичную страницу не выходит).
  Стоит на аккаунте, а через метку тренера / «Me» — и на его пловце; пловцу состава без
  аккаунта (большинство Дельфина из сидера) тренер ставит флаг напрямую.
- Ставит тренер (таб Swimmers, рядом с уровнем); **сам участник тоже может**: «On break until
  <дата>» (травма, отпуск, армия) — после даты снова активен.
- Влияет: RSVP — нет в знаменателе и в «No answer»; дорожки — нет в Auto lanes и Distribute,
  в «Unassigned» редактора не лезет (руками перетащить можно).
- НЕ влияет: доступ к группе (это не статус членства — `active` решает доступ к тренировкам),
  публичный состав, зачёт и рекорды группы (история остаётся).
- Возврат: неактивный сам ответил «Going» → снова активен, тренеру пометка «back after N months».
- Автоподсказки тренеру («не ходит 8+ недель — отметить?») **не делаем**.

**«Сам себя» НЕ делаем** (28.09.2026, отменяет вариант из начала обсуждения): кнопка создания
пловца из аккаунта нарушала бы правило 3 [hubgroups-architecture.md](../hubgroups-architecture.md)
(«аккаунт ↔ пловец связи нет») и открывала фейковые публичные профили с чужим именем. Правило 3
остаётся. Проверка имени, метка «Self-added», склейка с loglig — не нужны.

**Тренировочные времена** вносит только тренер/админ группы (Р57); видны только аудитории
группы (И16).

**Ш3.1 — сделано (28.09.2026), сервер.**
- **«On break»** — `Sys_HubGroupBreaks` (миграция `AddHubGroupBreaksAndAccountLevels`, БЕЗ grant
  `swimm_ro`): субъект — ровно одно из `UserId` / `SwimmerId` (CHECK), история строками
  (`Since`, `Until` — последний день включительно, null — бессрочно; `EndedAt`, `EndedByRsvp`),
  открытый перерыв у субъекта один (частичные UNIQUE). Правила — `HubGroupBreakRules` (участник
  себе — только с датой, тренер — любому и бессрочно; до 366 дней; пометка «back after» 14 дней).
  API `GET/PUT /api/hub-groups/{id}/breaks` (`HubGroupBreaksController`, личное, no-store):
  участник — свой, управляющий — все действующие + недавние возвращения.
- **Флаг один на человека** — `HubGroupBreakQuery`: перерыв аккаунта кладёт на перерыв его
  пловца по метке тренера и наоборот. «Me»/«Family» в связку пока НЕ входят — это Ш3.2
  (резолвер «кто на дорожке»; база — `LanePlanService.LoadMySwimmersAsync`).
- **RSVP**: на перерыве и не ответил — не в `total` и не в «нет ответа» (в списке тренера —
  последним, `on_break`); ответил — считается как все. «Going» на занятие ВНУТРИ перерыва
  закрывает его (`EndedByRsvp`), тренеру `back_after_days`; перерыв, кончающийся раньше
  занятия, не трогается. Зрителю — `on_break`, `break_until`.
- **План дорожек**: `on_break` у пловца на дату плана; Distribute / Auto lanes без `swimmer_ids`
  берут состав БЕЗ тех, кто сегодня на перерыве (названных руками не фильтруют).
- **Уровень аккаунта** — `Sys_HubGroupAccountLevels` (пара к уровню пловца, тот же составной FK):
  `PUT /api/me/hub-groups/{id}/account-levels/{userId}`, в ответе `levels` — `accounts`
  (активные, с меткой тренера и уровнем) и `accountCount` у уровня; удаление уровня снимает.
- **Расписание**: `usual_lanes` (1..12) и `lane_view` (`auto|plan|off`, auto хранится как
  отсутствие ключа; наружу — `EffectiveLaneView`) в JSON `HubGroups.TrainingSchedule`.
- **Склейка пловцов** переносит перерывы на канонического (оба открыты — дубль закрывается).
- Тесты — `HubGroupBreakTests` (15), всего 2510/2510. Вживую на Postgres (`utest-open`):
  отказы 400/403, частичный UNIQUE и CHECK держат, «Going» закрыл перерыв, `total` 2 → 1,
  уровень аккаунта; тест-группа возвращена (перерывы, ответы, уровни, расписание — убраны).
- Не сделано сознательно: перерывы/уровни аккаунтов в перечне потерь при удалении группы
  (каскад их уносит); клиент — Ш3.3.
