## 3. Ключевые решения сессии (не переизобретать)

**Модель доверия одной фразой — «группа только следит; публичное — только Trusted»** (Р65):

- **Своё свободно, чужое — через доверие, выданное источнику один раз** (И15). Админ сайта не
  одобряет каждую запись — он ставит флаг источнику (`Trusted` у группы; официальная группа
  клуба доверенная сама).
- **«Everyone 🌐» — только у доверенной группы.** У недоверенной уровня нет (сервер отказывает,
  в селектах пункт погашен); её старые public-публикации (флаг сняли) = members везде, и на
  странице группы тоже. Путь «сам пловец по привязке аккаунта» (Р61) снят.
- **Состав группы — «Following»**, не «Swimmers»: группа ни о ком не заявляет «плавает у нас».
  У клуба «Swimmers» остаётся (данные федерации). Роли coach/captain наружу не отдаются
  (общий ответ пишет всем `member`), порядок «тренер первым» остаётся; `is_admin` — остаётся
  (привязка аккаунта от админа сайта). Роли видит только управляющий в редакторе состава.
- **Жалобы:** порог открытых жалоб (настройка, дефолт 3) прячет медиа ВЕЗДЕ, включая страницу
  группы, — никому, и админу сайта на витринах тоже; владелец видит своё с пометкой и не может
  поделиться. Тренер видит число и причины без имён; имена и текст — только админ сайта.
  Жаловаться можно только на то, что видно (то же правило, что показ и лайк).
- Карточка охвата в табе Admin группы: доверенной — зелёная «✓ Trusted»; недоверенной — только
  если подписана на клуб; без подписки — ничего (Р63).
- **Заявления «Me» / «Family» действуют только внутри группы** (Р55): по ним строятся дорожки,
  RSVP и связка флага «On break»; наружу от имени пловца они ничего не показывают.
- **«Создать себя пловцом» НЕ делаем** — «аккаунт ↔ пловец связи нет»; кого нет в loglig, тот
  стоит на дорожке аккаунтом, уровень ставится на членство аккаунта.
- **Тренировочные времена вносит только тренер/админ группы** (Р57) и видит только группа (И16,
  держит `TrainingResultsPrivacyTests`).
- Дорожки: опубликованный план → иначе авто по уровням на `usual_lanes` (или последнего плана)
  → уровней нет — подряд идущие куски → дорожек не знаем — одна «вода». «Не уверен» занимает
  место. Тренер выключает вид (`lane_view: off`). «Who's coming»: по умолчанию участники видят
  имена, тренер может скрыть.
- «On break»: один флаг на человека; тренер — любому и бессрочно, участник — себе и до даты;
  «Going» на занятие внутри перерыва его снимает; автоподсказок «не ходит N недель» нет.
- Квоты действуют и на админа сайта (поднимает настройку); настройки в памяти — после рестарта
  дефолты (в т.ч. порог жалоб).

6. **Уборка после проверки** (обязательно), `docker exec swimm-postgres psql -U swimm -d swimm -c '…'`:

## 5. Грабли

- **API Влада на :5078 запущен через `dotnet run` из той же ветки** — новые изменения он видит только
  после перезапуска. Его не глушить; собирать в scratchpad (`dotnet build … -o <scratchpad>`) или
  проверять на стенде 5183+5082. Миграции к базе можно применять при живом API.
- **Любое НОВОЕ публичное место, где показываются пловцы**, обязано фильтровать
  `PrivateHubGroupId == null` (Р71, `docs/important.md`): страница, поиск, клуб, общий ответ группы.
  Общий ответ страницы группы кэшируется один на всех — пловцов группы в нём нет, свои получают
  их личным запросом `/private-members`.
- **`Sys_TrainingResults.SwimmerId` — RESTRICT.** Удаляя пловца (или группу, чьи пловцы уходят
  каскадом), сначала убирай его времена / сессии группы — иначе падение (поймано 29.09).
- **Прод-дамп:** `dump-seed.sh` вырезает пловцов групп из `COPY "Swimmers"` (строка «пловцов групп
  вырезано» в выводе); `HubGroups` в прод не едет.
- **Очки FINA наружу — только `r.IsParaPoints ? 0 : r.InternationalPoints`** (Р67); новая выборка
  по очкам без этого вернёт пара-очки в Best swim.

- **Id публикации ≠ id медиа.** Ленты группы и клуба (`PublishedMediaItemDto.id`) и inbox —
  id публикации; жалобе и лайку нужен `media_id`. У `group.gallery` публикации — с минусом.
- **Страница недоверенной группы публикации не читает** (`GetApprovedForGroupAsync(public)` сразу
  пуст) — поэтому удаление медиа её кэш не роняет; тесты кэша на живой базе это учитывают.
- **Vite HMR после правок многих модулей** может оставить две копии `login-modal-context` →
  белая страница. Лечится перезапуском стенда. Ошибки `WebSocket … failed` — HMR стучится в
  остановленный стенд, не баг.
- **Скриншот pane иногда пустой** (сразу после скролла/перехода) — повторить скриншот. При
  эмуляции 1280px он мелкий — геометрию проверять через `javascript_tool`. Тема сайта — свой
  переключатель 🌙 (`data-mode`), `resize_window colorScheme` её не меняет.
- **`innerText` отдаёт текст в верхнем регистре**, если CSS `uppercase`.
- **Частичные UNIQUE и CHECK** (перерывы, «other требует текст» у жалоб) InMemory-тесты не ловят —
  проверять на Postgres.
- **Архитектурные тесты по исходникам** (`DirectMemoryCache…`, `TrainingResultsPrivacyTests`)
  падают, если `--artifacts-path` вне репо. Новое место чтения тренировок — строка в `Allowed` с
  причиной, иначе тест красный.
- **Ответы, имена, дорожки, роли — только личным запросом** (`/rsvp`, `/breaks`): общий ответ
  страницы группы кэшируется один на всех, прятать на клиенте мало.
- Правки python-скриптом: сохранять CRLF/LF файла (`newline=''`); строки с `"""` в C# (сырые
  строки EF `@"""…"""`) python-литералом не заменить — такие правки делать через Edit.
- В рабочей копии лежат файлы Влада (`docs/plans/lane-plans-plan.md`, `!design_handoff/…`) —
  коммитить только свои пути, `git add -A` нельзя.
