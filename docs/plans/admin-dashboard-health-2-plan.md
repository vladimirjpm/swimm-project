# План: Админ-дашборд 2.0 — «Здоровье данных»

Расширение текущего `/Admin` (Index.cshtml). Сейчас там: stats-grid (5 счётчиков),
status-grid (5 карточек «требует внимания»), вкладка Users. Цель — один экран,
на котором видно **все** проблемы с данными и их масштаб, каждая карточка кликабельна
и ведёт на страницу, где проблему чинят.

Документ — вход для дизайна (claude.ai/design): здесь список метрик, группировка,
семантика цветов и источники данных. Вёрстку/визуал придумывает дизайн.

---

## Принципы

- **Карточка = проблема, а не таблица.** Крупное число — то, что требует действия.
  Мелкие подстроки — контекст (total, «из них …»).
- **Цвет = состояние:** зелёный (0 проблем), оранжевый (есть работа), красный
  (блокирующее/растёт), серый (не проверялось / нет данных).
- **Всё кликабельно** → соответствующая админ-страница с готовым фильтром.
- Все данные — один запрос `/api/admin/dashboard/status` (расширяем существующий
  `DashboardStatusService` + `DashboardStatusDtos`). Дорогие подсчёты — кэш 1–5 мин.

## Блоки и метрики

### 1. Пловцы (→ /Admin/Swimmers)
| Метрика | Источник | Цвет |
|---|---|---|
| Всего пловцов (крупно total; подстроки: isr / local / SYNTH-синтетика) | `Swimmer.Origin`, `SwimmerOrgId` | нейтральный |
| Спорные дубли (уже есть) | `SwimmerDedupService` unsure | оранж >0 |
| Уверенные дубли (подстрока) | sure | оранж >0 |
| Сироты — без результатов/групп/медиа/аккаунта (уже есть подстрокой — поднять) | OrphanQuery | оранж >0 |
| Без SwimmerOrgId (не-синтетика без реального ID федерации) — **новое** | `SwimmerOrgId is null && Origin='isr'` | оранж |
| Пловцы без результатов — **новое**, отдельно от сирот (у пловца могут быть группы/медиа/аккаунт, но ни одного заплыва) | нет ResultRecord и RelayMember | оранж |
| Loglig: не привязано / на проверке / отклонено (уже есть) | `LogligIdStatus` | инфо |

### 2. Клубы (→ /Admin/Clubs)
| Метрика | Источник | Цвет |
|---|---|---|
| Всего клубов (подстроки: реальные / псевдо `IsPseudo`) | `Club` | нейтральный |
| Спорные дубли (уже есть) + уверенные подстрокой | `ClubDedupService` | оранж >0 |
| Клубы без пловцов — **новое** (мусор после merge) | нет Swimmer.ClubId и результатов | оранж |
| Клубы без страны — **новое** | `CountryId is null` | серый/оранж |
| Заявки на статус клуба pending (→ /Admin/HubGroupClubRequests) — **новое**. Это заявки групп SwimHub на официальную привязку к клубу; НЕ путать с заявками на вступление в группу (те — в блоке 6) | `HubGroupClubRequest.Status='pending'` | оранж >0, это очередь на решение админа |

### 3. Соревнования (→ /Admin/Competitions)
| Метрика | Источник | Цвет |
|---|---|---|
| Всего соревнований (подстроки: с результатами / пустых) | `Competition`, наличие Results | нейтральный |
| Входящие не загружено (уже есть) | Discovery `new` | оранж |
| Discovery с ошибкой — **новое** | `DiscoveredCompetition.LastError != null` | красный |
| Без OrgCompId — **новое** (нет шва с Discovery, матч только по имени+дате) | `Competition.OrgCompId is null` | серый — долг бэкфилла |
| Ignored (подстрока) | Status='ignored' | серый |
| Соревнования без результатов — **новое** (импорт упал/забыт) | count(Results)=0 | оранж |

### 4. Результаты и качество данных (→ /Admin/Results) — **новый блок**
| Метрика | Источник | Цвет |
|---|---|---|
| Всего результатов | `ResultRecord` | нейтральный |
| TimeFail (DQ/DNS/DNF) — подстрока, это не проблема | `TimeFail` | инфо |
| Результаты без клуба / без пловца-FK аномалии | null-FK | красный >0 |
| Эстафеты без участников — **новое** | Relay без RelayMember | оранж |

### 4a. Рекорды (→ /Admin/Records) — **новый блок**
Отдельные карточки по наборам рекордов (оси регион/источник — как в импорте 2.6):
| Метрика | Источник | Цвет |
|---|---|---|
| Карточка на каждый набор: World (worldaquatics), Israel (isr.org.il), …: сколько рекордов, дата последней загрузки/обновления | `Record.UpdatedAt` по региону, `ImportHistory` (records-импорты) | серый если давно (> N мес), нейтральный иначе |
| Кнопка **«Проверить апдейты»** — запускает fetch+дифф импорта рекордов 2.6 (dry-run) **синхронно, с индикатором прогресса прямо на дашборде** (спиннер/статус по источникам), по завершении показывает «есть N изменений» → ссылка на /Admin/Import с готовым диффом | существующий пайплайн records-импорта | оранж если дифф непустой |

### 5. Медиа (→ /Admin/Media)
| Метрика | Источник | Цвет |
|---|---|---|
| Всего медиа (подстроки по MediaType/Visibility) | `UserMedia` | нейтральный |
| Битые ссылки (уже есть) | `LinkOk=false` | красный >0 |
| Не проверялось | `LinkCheckedAt is null` | серый |
| На модерации (публикации в группу, ждут одобрения) — **новое** | pending visibility-заявки | оранж — очередь админа |

### 6. Пользователи и группы (→ /Admin/Users, /Admin/HubGroups) — **новый блок**
| Метрика | Источник |
|---|---|
| Всего пользователей / активных за 7 дней | `AppUser.LastSeenAt` |
| Деактивированные (подстрока) | IsActive=false |
| Группы всего / официальных | HubGroup |
| Заявки на вступление в группы pending (approval-группы) — отдельная карточка, НЕ смешивать с заявками на статус клуба из блока 2 | membership requests |

### 7. Системная строка (внизу, мелко) — **новое**
- Последний импорт: дата + статус (`ImportHistory`).
- Последняя проверка ссылок медиа: дата.
- Последний discovery-скан: `DiscoveredCompetition.LastSeenAt` max.
- Ошибок в audit за 7 дней / последние действия админа (ссылка → /Admin/Audit).

  (снапшоты счётчиков) можно добавить v2, если понадобится «растёт/падает».

## Реализация (после дизайна)
1. Расширить `DashboardStatusDtos` + `DashboardStatusService` новыми счётчиками
   (сгруппировать DTO по блокам). Дорогие запросы — `IMemoryCache` 2 мин.
2. Переверстать status-grid в `Pages/Admin/Index.cshtml` по макету из claude.ai/design
   (Tailwind, пересобрать `admin.min.css`).
3. Ссылки-фильтры: убедиться, что целевые страницы принимают query-параметры
   (например `/Admin/Competitions?filter=no-results`) — добавить где нет.
4. Юнит-тесты на новые счётчики в `Swimm.Tests` (edge: пустая БД, только синтетика,
   ignored-пары дедупа).
5. Обновить `docs/admin-pages/index.md`.

## Решено
