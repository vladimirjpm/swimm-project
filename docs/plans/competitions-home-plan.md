⚠ **Как раскладывать (главная ловушка А1).** В хендоффе значения даны прямо ролям `--t-*`, а у нас
роли — производные от палитры `--deep-*`, и часть компонентов (`.deep-card`, `.deep-pill`, табы,
сегменты, `SwimRow` через `--sr-*`) берёт `--deep-*` напрямую. Поэтому значения ставим на
**уровне `--deep-*`** там, где у роли есть палитровый источник (`--deep-card-border`,
`--deep-text*`, `--deep-accent*`, `--deep-card-bg-raised`…), иначе страницы разъедутся: роли станут
синими, а карточки останутся teal. Прямые `--t-*` оверрайды — только для ролей без палитрового
источника, и **после** общего блока ролей (порядок в файле решает).

## Часть Б — главная `/competitions`: календарь сезона

Начинается **только после А6.**

### Экран (из хендоффа)

1. Заголовок страницы — как сейчас.
2. **Строка управления**: слева `‹ October 2026 ›` (в виде Year — `Season 2026/27`), сегмент
   **Full year · Full month · Meet days** (порядок такой, по умолчанию Full month), справа — фильтр
   по типу.
3. Тело вида. 4. Под календарём — кубы выбранного дня (только Full month). 5. **Records & standards**
   — 5 плиток: National records (`/records`), World records, World junior, H2H records
   (`/records/compare`), Normatives (страница нормативов, В7).

**Фильтр по типу:** чипы All · Pool swimming · Open water · Artistic swimming, иконка + число meets.
Мульти-выбор, All сбрасывает. Выбран — рамка accent + `--t-accent-soft`. Число — по текущему месяцу
(Month/Meet) или сезону (Year).

**Full year:** сетка 4×3 (телефон — 2 колонки), месяцы сезона Sep–Aug. Карточка: месяц + год, общее
число; строки Swimming / Open water / Artistic (0 → opacity .35); 🏆 у типа, если в месяце чемпионат
этого типа (`--t-champ-ink`); внизу полоса мини-бейджей чемпионатов (`--t-champ-strip-*`) или «No
championships». Текущий месяц — рамка `--t-accent`, фон `--t-nested`; прошедшие — opacity .6. Клик
по месяцу → Full month этого месяца.

**Full month (десктоп):** 7 колонок, неделя с **воскресенья**. Ячейка min-height 112px: число, до 3
плашек, дальше «+N more». Обычный meet — `--t-nested`; чемпионат — `--t-champ-chip-bg` /
`--t-champ-ink` + мини-бейдж группы слева. Многодневный тянется через дни (скругления на первом и
последнем, дальше `↳ Day 2`; на конце месяца обрывается без скругления, в следующем продолжается
`↳ Day N`). Сегодня — обводка accent; прошедшие дни — opacity .6; выбранный — фон `--t-nested` +
обводка accent. Клик по дню → кубы дня ниже. Легенда: Championship / Meet / Today.

**Meet days:** все meets месяца кубами, 4 в ряд (телефон 1), по дате начала.

**Куб:** плитка даты в левом верхнем углу (день недели caps 10px, число 20px, месяц `--t-accent-text`
11px; своя рамка только справа и снизу, скруглён нижний правый); справа сверху бейдж группы — только
у чемпионатов бассейна (40px, три полосы: верх светлый с ❄/☀ + 🏆, середина `--t-accent` с буквой
K/Y/J/A/M, низ светлый с возрастом `--t-badge-ink`); у чемпионатов открытой воды и артистики вместо
бейджа текст 🏆 `Open water championship` / `Artistic championship` (11px, 500, `--t-champ-ink`).
Название на иврите `dir="rtl"`, выровнено влево, **всегда 2 строки** (line-clamp 2, min-height 2.7em).
`площадка · возраст` (text-2, 12px). Низ: статус-тег + действие (`Startlist →` / `Results →` /
`Details →`). Чемпионат — фон `--t-champ-bg`, рамка `--t-champ-border`. Многодневный частично
загруженный — куб на 2 колонки, полоса дней (сегменты 4px: загружено — accent, нет — border;
подписи `Day 1 · 16 Oct ✓`), статус `In progress`, действие `Day 1 results →`; загружен целиком —
1 колонка, `Complete`, `Full results →` (В8). Cancelled — opacity .5, тег, без ссылки; Postponed —
тег `Postponed → 21 Nov` + Details (В4: данных пока нет).

**Телефон (375):** сегмент Year · Month · Meet + кнопка Type (funnel) — раскрывает 4 кнопки типов
плавно (`grid-template-rows 0fr→1fr .28s ease`, `opacity .22s`, без анимации при
`prefers-reduced-motion`); при выбранных типах у кнопки рамка accent и число. Month — по умолчанию
одна неделя (`‹ Week 18–24 Oct ›` + 7 ячеек с точками), тап по месяцу (▾/▴) разворачивает месяц;
точка meet 5px, чемпионат — мини-бейдж 14×18 с буквой; день с чемпионатом — `--t-champ-strip-*`.
Ниже кубы выбранного дня. Meet — горизонтальная лента дней с meets (тайл 52px), тап фильтрует кубы,
повторный — все. Year — 2 колонки. Records — плитки 2×2 + Normatives.

**Пустые и доступность:** вид без данных — сегмент disabled (opacity .45, not-allowed,
`aria-disabled`); день без meets — «No meets on this day.»; месяц без meets — «No meets this month».
`:focus-visible` — outline 2px `--t-accent`, offset 2px; ячейки — `button` или `role="button"` +
Enter/Space; сегмент — `role="radiogroup"`/`aria-pressed`, выбранный — сплошной
`--deep-seg-active-bg`, разделители `--t-divider`. Hover — фон `--t-nested`. «Сегодня» — по дате
Asia/Jerusalem.

## Часть В — весь календарь сезона, без постоянных обращений наружу (19.10.2026, решения приняты; сервер В1′–В4′ готов)

**Проблема.** Календарь показывает только затянутое (В2) — будущих стартов в нём нет, а «Full
year» без будущего пуст. Плюс локальный API при каждом перезапуске сам ходит на isr.org.il и
loglig: фоновые задачи помнят «последний запуск» в памяти, и перезапуск обнуляет его.

**Что уже есть.** Список isr.org.il (`competitions.asp`, страницы «прошедшие» + «будущие») отдаёт
**весь сезон одним запросом** — по ней фоновая задача и кнопка «Проверить сейчас» заполняют
`Sys_DiscoveredCompetitions`. На 19.10 в локальной базе 46 строк сезона 2026/27 (9.10.2026 —
30.07.2027): имя, даты, площадка, дисциплина, OrgCompId, loglig-id, статус. Прошлые сезоны тянутся
той же кнопкой с `cYear` — один раз, дальше лежат.

**Схема.**
1. **Сайт наружу не ходит никогда.** `/api/competitions/calendar` читает только нашу базу
   (справочник + входящие), ответ в кэше; сброс — мостом кэша, когда синхронизация что-то записала.
2. **Календарь = справочник + входящие.** Строка входящих без затянутого соревнования (матч по
   OrgCompId, как в /Admin/Competitions) идёт в календарь как будущий / незатянутый meet: даты, имя,
   площадка, тип, чемпионат (по названию), действие `Details →` — наша страница предстоящего
   `/competitions/upcoming/{orgCompId}` (есть со стартового протокола), если заявок нет — страница
   isr.org.il. Наружу отдаются только эти поля. Скрытые админом (ignored) не показываются.
3. **Кто ходит наружу — только ProdAdmin**, по расписанию, которое **помнит последний запуск в
   базе** (не в памяти): перезапуск не запускает задачу заново. Интервал списка — раз в сутки
   (список меняется редко) + кнопка «Проверить сейчас». loglig календарю не нужен вовсе: он для
   стартовых протоколов (за 2–3 дня, кнопкой) и импорта.
4. **Локальная разработка — фоновые задачи выключены** по умолчанию (`BackgroundJobs:Enabled=false`
   в Development); входящие приезжают в локальную базу синхронизацией с прода
   (`/db-sync-from-prod`, таблица `Sys_DiscoveredCompetitions` добавляется в её список — личных
   данных в ней нет) или кнопкой вручную.
5. **Cancelled / Postponed (В4) получают источник даром:** синхронизация видит, что у той же
   OrgCompId сменилась дата → запоминает прежнюю → `postponed` (`Postponed → новая дата`); строка
   будущего старта пропала из списка isr.org.il при успешной синхронизации → `cancelled`. Без новых
   обращений наружу.

**Решения Влада (19.10.2026, все — «да»):** **В9** — В2 пересмотрен: календарь показывает и будущие /
незатянутые старты из входящих; **В10** — фоновые задачи в локальной разработке выключены; **В11** —
`Sys_DiscoveredCompetitions` входит в `/db-sync-from-prod`; **В12** — ProdAdmin обновляет список раз в
