# Тестовые персонажи (utest-*) — план

Статус: решения приняты 24.09.2026. **Этап 1 сделан 24.09.2026** (не закоммичено): флаг
`IsTest`, миграция `AddHubGroupIsTest` (применена локально), правило видимости, админка,
тесты `HubGroupTestGroupTests`. Устройство — `docs/admin-pages/hubgroups.md` «Тестовые группы».
**Этап 2 сделан 24.09.2026** (не закоммичено): сидер `--seed-personas`, прогнан на локальной
базе. **Этап 3 сделан 24.09.2026** (не закоммичено): переключатель персонажа — см.
«Переключатель» ниже. Остался этап 4 — ждёт [family-favorites-plan.md](family-favorites-plan.md).

Цель — набор dev-пользователей с «говорящими» именами, чтобы проверять любой экран глазами
разных ролей (гость, участник группы, родитель, админ группы…) — и руками, и в браузерных
проверках агента.

## Решения Влада (24.09.2026)

1. **Все тестовые пользователи начинаются с `utest`.** Email — `utest-<роль>@swimm.test`
   (зона `.test` зарезервирована, почта никуда не уходит); имя на экране тоже с `utest`.
   Префикс — единственный признак «это тестовый аккаунт»: по нему их находит сидер, чистка,
   фильтры и правило видимости тест-групп.
2. **Родитель — без прав**, дети = избранное с пометкой «семья»
   ([family-favorites-plan.md](family-favorites-plan.md)). `utest-parent` — не в группе, двое
   детей помечены семьёй.
3. **Переключатель персонажа без перезапуска — делаем.** Только Development: `?as=<ник>` /
   dev-кука + плашка «вы: utest-…» с выбором персонажа и списком тест-групп. Надстройка над
   `DevAdminBypass` — на проде ветка мертва так же.
4. **Тестер — только через переключатель.** Отдельной роли/настройки «тестеры» и своего
   входа с особыми правами нет.
5. **Тест-группа — флаг в админке** (`HubGroup.IsTest`, галочка в `/Admin/HubGroups/Edit`).
   Любую группу можно сделать тестовой; сидер персонажей просто ставит флаг своим группам.

## Правило видимости тест-группы (`IsTest`)

- Видят: **site-админ** и аккаунты с префиксом **`utest`**. Всем остальным группы нет —
  404, не заглушка «только для участников» и не кнопка «вступить».
- Для utest-персонажей группа ведёт себя как обычная: open/approval и галочка приватности
  работают как у любой группы — ради этого и флаг отдельный. (Приватность `IsPublic=false`
  не годится: у приватной группы вступление всегда заявкой, open не проверить —
  `HubGroupUserService.JoinAsync`.)
- **В публичном каталоге нет никогда, даже для utest** — иначе каталог кэшировался бы на
  пользователя. Вход — прямая ссылка, «My groups» (если персонаж участник) и панель
  переключателя.
- **Страница тест-группы — `private, no-store`**, как у приватной: общий HTTP-кэш не унесёт
  ответ другому. Серверный кэш payload общий — но до него доходит только тот, кто прошёл
  проверку доступа (остальным 404 раньше).
- Отсеивать из всех чужих выдач: каталог, страница клуба, подписки на клуб, счётчики
  дашборда и т.п. — полный список мест собрать на старте работы.
- В админке — метка `TEST` у группы и фильтр в списке.

## Что уже есть и на что опираемся

- `DevAdminBypassEmail` — dev-подмена личности по email (конфиги `*-preview-user` /
  `*-guest` в `.claude/launch.json`); пока смена = перезапуск API.
- Аккаунты, группы, участники, медиа, тренировки на прод НЕ переносятся
  (`server/db/seed-tables.txt`). ⚠ Исключение — `Swimmers` (включая `Origin='local'`):
  «детей» и пловцов тест-групп брать из существующих, новых local не заводить — утекут.

## Переключатель (этап 3)

- **Сервер** — `Swimm.API/Security/DevAdminBypass.cs`. Dev-кука `swimm_dev_persona` (ник
  utest-персонажа или `utest-guest`) выбирает, от кого идёт неаутентифицированный запрос; нет куки —
  личность по умолчанию (`DevAdminBypassEmail`, как раньше). Ручки, только при DevAdminBypass
  в Development:
  - `GET /api/dev/personas` — кто выбран, список персонажей (есть ли в базе, активен ли),
    тест-группы;
  - `GET /api/dev/persona?as=<ник|utest-guest|default>` — поставить/снять куку (неизвестный ник — 400).
    GET нарочно: можно дёрнуть адресной строкой, агенту — одним fetch.
- **Клиент** — `client/src/dev/persona-switcher/`: плашка «DEV · <кто>» внизу слева на каждой
  странице, по клику — список персонажей и ссылки на тест-группы; выбор ставит куку и
  перезагружает страницу. Вставляет её плагин `devPersonaSwitcher` в `client/vite.config.js`
  (`apply: 'serve'`) — ни одной правки точек входа, в прод-сборку не попадает. Нет dev-ручек
  (API запущен гостем, `--DevAdminBypass false`) — нет и плашки.
- **Настоящий вход сильнее переключателя**: при куке логина персонаж не действует, панель
  пишет об этом красной строкой.
- `utest-blocked` и персонаж, которого нет в базе, идут **гостем** — настоящий вход такого
  пользователя тоже не пустил бы.
- Кэш личностей в middleware — 30 с (а не вечный, как было): `--seed-personas --reset`
  пересоздаёт пользователей с новыми id.
- Связка для проверки глазами: конфиг `stack-5181-api5079-personas` в `.claude/launch.json`
  (API из Release с `--no-build` на 5079 + клиент на 5181; перед запуском —
  `dotnet build server/Swimm.API -c Release`). Старая `stack-5181-api5079` — гостем, без плашки.
- Проверено вживую 24.09: default → efreet007; `utest-member` видит обе тест-группы и
  тренировки, «My groups» = обе; `utest-newbie`/`utest-pending` — группа 200, тренировки 403;
  `utest-guest`/`utest-blocked` — аноним, тест-группа 404; `?as=bogus` → 400; без перезапуска API.
