## 2. Задача

Одна панель фильтров, работающая:
- на results (Redux `filterSelected`, опции из `window.filter_data`, disabled из выборки),
- на `/season-best` (состояние в query, опции из `GET /api/season-best/options`, disabled не нужен),
- на будущих экранах (клуб, группа) — с их источниками.

Требование Влада: **не переписывать заново то, что уже работает.**

## 3. Варианты

### A. Контекст-адаптер («параметр для стора») — РЕКОМЕНДУЕТСЯ

Заводим контекст, который отвечает на вопросы «откуда значения, куда писать, откуда опции»:

```ts
export interface FilterHost {
  /** Текущие значения. Ключи — поля FilterSelected; хост сам маппит на свою модель. */
  values: Partial<FilterSelected>;
  /** Записать изменение. Хост решает: dispatch в Redux или правка query. */
  set(patch: Partial<FilterSelected>): void;
  /** Опции фильтров: стили с дистанциями, полы, бассейны. */
  options: FilterOptions;
  /** Есть ли такое значение в текущей выборке; не задан — всё доступно. */
  isAvailable?(kind: FilterKind, value: string): boolean;
}
```

Реализации:
- `ReduxFilterHost` — **ровно текущее поведение** (`useAppSelector` + `dispatch` +
  `getFilterData()` + `useFilteredByTypeResults()`). Отдаётся по умолчанию, если провайдера
  нет, — то есть results после правки работает так же, как до неё.
- `QueryFilterHost` — состояние в адресе (`routes.ts` / `parseSeasonBestQuery`), опции из
  `/api/season-best/options`, `isAvailable` не задан.

В каждом фильтре четыре строки связи схлопываются в одну:

```jsx
const { values, set, options, isAvailable } = useFilterHost();
```

**Объём:** новый файл контекста ~80–120 строк, правка 8 файлов по 3–5 строк, по провайдеру
на страницу, снос `SbCard` и `sb-filters.tsx` (~300 строк уходит).
**Риск:** низкий. Правки механические, results защищён дефолтным хостом.
**Минус:** «общая модель значений» остаётся плоским `FilterSelected` — у `/season-best`
поля называются иначе (`stroke` против `style_name`), маппинг живёт в хосте.

### B. Разделить каждый фильтр на «чистый» и «подключённый»

`FilterGenderView({ value, options, onChange })` — ничего не знает о хранилище;
`FilterGender()` — тонкая обёртка, берёт данные из Redux и рендерит View. Results остаётся
на обёртках, новые страницы берут View напрямую.

**Объём:** вдвое больше файлов (по два на фильтр), ~300 строк движения.
**Риск:** низкий, но правок больше.
**Плюс:** самая честная архитектура, View тестируется без стора.
**Минус:** дороже A при том же результате; каждой странице придётся собирать панель руками
из View — то есть «сборка панели» дублируется вместо фильтров.

### C. Минимальный — только оболочка

Сделать `FilterCard` тем-нейтральным (цвета в локальные CSS-переменные с фоллбеком на
`--theme-*`) и снести `SbCard`. Фильтры остаются дублированными.

**Объём:** 1 файл + удаление ~50 строк. **Риск:** почти нулевой.
**Минус:** убирает один дубль из трёх; главная работа не сделана.

### 5.1 Что сделано в Ф1–Ф2 и что от этого требуется дальше

**Ф1 (сделан).** Палитра карточки и сегментных кнопок вынесена в локальные токены с
фоллбеком на нынешние — на results не изменилось ни одного пикселя, проверено вживую
(`rgb(33,40,54)` фон карточки в dark, `12px` радиус, светлая тема тоже).

- `filter-card.tsx`: `--fc-bg`, `--fc-border`, `--fc-title`, `--fc-summary`,
  `--fc-summary-active`, `--fc-chevron`, `--fc-radius`.
- `filter-section.css`, `.fseg`: `--fseg-border`, `--fseg-bg`, `--fseg-text`,
  `--fseg-hover-border`, `--fseg-hover-text`, `--fseg-active-border`, `--fseg-active-bg`,
  `--fseg-active-text`.
- Геометрия (отступы, кегль) НЕ токенизирована намеренно: панель должна быть одинаковой
  везде, разной — только палитра. Исключение `--fc-radius`: у deep свой радиус плиток
  (14px против 12px), и карточка с чужим скруглением видна рядом с ними.
- Ф4 переопределяет эти токены на `/season-best` (в `.sb-filters` или на корне страницы) —
  и `SbCard` со своим CSS уходит целиком.

**Ф2 (сделан).** Шов — `filter-section/filter-host.tsx`. Решения, которые Ф3 и Ф4 обязаны
удержать (менять — только осознанно, а не «мне так удобнее»):

1. **`values` — плоский `Partial<FilterSelected>`.** Поля могут быть не заданы, поэтому
   в фильтре читаем с дефолтом: `const gender = values.gender ?? 'all'`.
2. **`set(patch)` мержит в самые свежие значения** (через ref внутри хоста), поэтому
   фильтру НЕ нужно тащить весь объект и делать `{...filters, x}`. Смысл ref — не «гонка
   двух кликов» (React 18 флашит клики синхронно, такой гонки нет), а постоянная ссылка на
   `set` плюс защита от протухшего замыкания: колбэк из прошлого рендера смержил бы патч в
   устаревшие значения.
3. **`options` — единственный источник того, что рисовать.** `getFilterData()` из фильтров
   ушёл; пустой список опций = карточку не рисуем (было `if (!filterData) return null`).
4. **Ось доступности узкая: `FilterKind = 'style' | 'distance'`.** Гасятся ровно те две
   вещи, что гасились раньше. Пол и бассейн не гасились никогда — не начинать. Дистанции
   считаются для ВЫБРАННОГО стиля, хост знает его сам, передавать не нужно.
   `isAvailable` объявлен НЕобязательным: чужой хост (`/season-best`) вправе его не давать —
   там доступность не нужна вовсе.
4a. **`FilterSelected.style_len` теперь `number | string`** (правка сделана в Ф2, `tsc` чист).
   Это не послабление, а снятие лжи: `filter_data` отдаёт дистанции строками, включая
   эстафетные «4X50», и стор всегда хранил их. Без этого `set({ style_len: len })` в Ф3 не
   собрался бы вовсе. **Та же ложь осталась ещё в двух местах** — `filter-types.ts` и
   `utils/interfaces/filter-data.ts` объявляют `style_len: number[]`; снять её — первый шаг
   Ф3 (он тянет за собой сигнатуру `updateFilter` в `filter-distance`, а это уже его файл).
   Обходить через `Number(len)` НЕЛЬЗЯ: «4X50» превратится в `NaN`, а `results-table`
   сравнивает `event_style_len === style_len.toString()`, то есть со строкой «NaN».
5. **Списки, которые не «гасятся», а приходят готовыми (клубы, возраста) — это `options`,
   а не `isAvailable`.** Форма клуба уже объявлена: `FilterClubOption { value, label, stats? }`,
   где `value` — то, что уезжает в модель (у results имя клуба, у season-best `club_id`
   строкой), а `stats` — метрики для `UI_ClubDetails`. **Возрастные опции сознательно не
   объявлены**: у results там ещё и годы соревнований, диапазон `age`–`age_to` и masters-режим
   с группами «25-29» — форму решать на месте, в Ф3, и вписать сюда.
6. **Провайдер стоит на панели** (`filter-section.tsx` обёрнут в `<ReduxFilterHost>`): дорогая
   часть — чтение `filter_data`, скан выборки, подсказки фильтров — считается ОДИН раз на
   панель. Без провайдера фильтр всё равно работает (`useFilterHost()` соберёт Redux-хост на
   месте), но уже по копии на фильтр — это страховка, а не рабочий путь.

   ⚠ Правило хуков не даёт «не вызывать» фоллбек при живом провайдере, поэтому у
   `useReduxFilterHost(active)` есть **спящий режим**: при `active === false` он не читает
   глобалку, не сканирует выборку (`useFilteredByTypeResults(enabled)`) и не запрашивает
   подсказки — остаётся подписка на стор. **Ф3, добавляя фильтр, ничего для этого не делает,
   но и ломать не должен**: любая новая дорогая работа в хосте обязана стоять за тем же
   `active`. Иначе на Ф4 каждый фильтр `/season-best` понесёт мёртвый Redux-хост, а
   `getFilterData()` начнёт писать `console.error` на каждый рендер — `season-best.html` не
   подключает `data/filter-data.js`, его грузит только `results_main.html`.
7. **Чужой хост подставляется ТОЛЬКО через `<FilterHostProvider host={…}>`.** Сам контекст
   наружу не экспортируется намеренно — чтобы Ф4 не собирал провайдер руками и не появилось
   двух способов делать одно и то же:

   ```tsx
   const host = useQuerySeasonBestHost();          // Ф4, своя реализация FilterHost
   return <FilterHostProvider host={host}><FilterSbPanel /></FilterHostProvider>;
   ```

**Хвост Ф2 закрыт в Ф3.** Пока стиль и дистанция считали доступность сами, её же считал хост:
в paged-режиме это давало 10 запросов `/api/results/filter-hints` на загрузку вместо прежних 6
(панель монтируется ДВАЖДЫ — сайдбар и мобильная шторка, и хост живёт в каждой). После
перевода обоих фильтров на `isAvailable` замер вернулся к 6 (style×2, distance×2, name×2),
а `useFilteredByTypeResults`/`useResultsLoadMode`/`useFilterHints` из фильтров ушли совсем.

**Ф3 (сделан).** На хост переведены стиль, дистанция, возраст, клуб и сброс — в фильтрах не
осталось ни одного `useAppSelector`/`dispatch`. Решения, которые Ф4 обязан удержать:

1. **Возрастные опции — `FilterAgeOptions { mode, values, compYears }`** (форма, которую §5.1
   п.4 оставлял открытой). `mode` не косметика, а смысл кнопок: `birth-year` (results — годы
   рождения, работает диапазон долгим нажатием, под кнопкой подпись «(12-13)» из `compYears`),
   `age-group` (мастерсы — готовые группы протокола «25-29», заголовок карточки становится
   «Age Group»), `age` (сезонный возраст — то, что понадобится `/season-best`). Диапазон
   разрешён ТОЛЬКО у `birth-year`.
2. **Клубы — `FilterClubOptions { items, searchable }`.** Поиск включает хост, а не компонент:
   на results поле появляется только в paged-режиме, где список приходит с сервера и бывает
   длинным; локальная сводка по выборке обходится без него. У `/season-best` поиск был всегда —
   значит хост ставит `searchable: true`. Если Влад захочет одинаково везде — это решение об
   UI, а не о шве, менять в одном месте.
   Строка клуба: есть `stats` — рисуется `UI_ClubDetails` с медалями и очками, нет — простая
   кнопка с подписью. Второй ветки на results не бывает, она для страниц без зачёта.
3. **Сброс — `reset()` в хосте, обязательный метод.** Кнопка не знает ни набора полей, ни
   умолчаний. **Решение Влада 2026-08-26: сброс сбрасывает и клуб.** Старая кнопка его не
   трогала (и заодно забывала `age_to` — верх диапазона годов), то есть «Reset Filters»
   оставлял два фильтра включёнными; теперь оба обнуляются. Проверено прямо в состоянии:
   до нажатия `{age:'2013', age_to:'2015', club:'בני הרצליה', gender:'male'}`, после —
   `{age:'all', club:'all', gender:'all'}` и `age_to` нет вовсе, список 890 строк.
   У другой страницы свои умолчания — на то `reset()` и в хосте.
4. **Дистанции окончательно строковые.** `filter-types.ts` и `utils/interfaces/filter-data.ts`
   больше не врут (`style_len: string[]`), запись идёт строкой. Третья копия того же типа
   живёт в `filter-trainig-section.tsx` — это отдельная панель тренировок, её не трогали.
5. **Один осознанный фикс поведения.** Долгое нажатие на возрастной ГРУППЕ мастерсов («40-44»)
   раньше писало в фильтр строку «NaN» (`Number('40-44')` = NaN) и обнуляло список. Теперь
   диапазон собирается только у годов рождения. Проверено на Maccabiah 2026 Masters: долгое
   нажатие ничего не ломает.

**Ф4 (сделан).** `/season-best` больше не имеет своей панели: `components/sb-filters.tsx`
(~300 строк вместе с двойником `SbCard`) удалён, вместе с ним ушло 70 строк мёртвого CSS
(`.sb-card*`, `.sb-seg*`, `.sb-event*`, `.sb-club*`, `.sb-search`). Появилось три файла:

- `sb-filters-model.ts` — модель среза `SbFilters` и подписи (`strokeLabel`, `clubLabel`,
  ступени возраста). Жила внутри панели, к панели отношения не имела;
- `sb-filter-host.ts` — **`QueryFilterHost`**: перевод общей модели в `SbFilters` и обратно.
  Здесь же правило «смена стиля сбрасывает дистанцию, которой у нового стиля нет» — оно
  про данные страницы, а не про кнопку;
- `components/sb-filter-panel.tsx` — сборка: провайдер + пять общих карточек + своя карточка
  «Rows». Сезон и «Rows» сознательно НЕ фильтры общей модели: карусель сезонов и способ
  показа живут отдельно.

Палитра приезжает переопределением токенов на `.sb-filters` (**не на корне страницы** — см.
ловушку про `.fseg` ниже). Проверено: активная кнопка берёт `--deep-accent-chip`/`--deep-accent`,
карточка — `--deep-card-bg` и радиус 14px, ни одного `--theme-*` не просочилось.

Чего Ф4 потребовал от общего шва (мелкие добавки, results от них не изменился):

1. `FilterStyleOption.label?` — подпись стиля. Results печатает `style_name` как раньше,
   season-best даёт «individual medley» вместо машинного ключа.
2. `FilterClubOption.note?` — приписка справа в строке клуба (число заплывов); рисуется
   только у строк без `stats`.
3. Класс `filter-club-list` на списке клубов — зацепка для страницы, которой нужен предел
   высоты (в сайдбаре 300px полсотни клубов уводили карточку на два экрана). Список вынесен
   в свой контейнер, чтобы «all» и поле поиска не уезжали вместе с прокруткой.
4. Сводка клуба печатает ПОДПИСЬ, а не значение: у season-best значение это `club_id`, и в
   шапке карточки стояло бы «439».
5. `FilterCard` сам импортирует `filter-section.css` — иначе на странице, собранной без
   `filter-section.tsx`, карточка покрашена, а `.fseg` внутри неё нет.
6. Заголовок карточки возраста при `mode: 'age'` — «Age in season».

Осознанные отличия вида от прежней панели `/season-best` (следствие «панель одна»):
пол подписан «M/W», а не «♂ Male / ♀ Female»; карточка дисциплины называется «Swimming
Style», а не «Event»; возраста — обычный перенос кнопок, а не свайп-лента. Если что-то из
этого важно сохранить — это правка общего компонента, и тогда она приедет и на results.

**Дыра в адресе, найденная на Ф4 и закрытая по решению Влада:** `parseSeasonBestQuery` читал
season, stroke, distance, pool, gender, age и swimmer, но НЕ читал `club` и `best` — хотя
страница их туда писала, и присланная ссылка открывалась без выбранного клуба. Теперь читает
оба, и генератор `routes.seasonBest()` умеет их писать — контракт снова симметричен, как и
обещает комментарий над `SeasonBestQuery`. Проверено: ссылка с `&club=439&best=true` открывает
срез с клубом и режимом «Best per swimmer» (14 строк).

**Ф5 (сделан).** [`docs/ui-components.md`](../ui-components.md) больше не врёт: в §5 карточка
фильтра описана как тем-нейтральная, `Filter*` — как ОБЩИЙ сайдбар двух страниц, и добавлена
строка про сам шов `FilterHost`. Из §6 ушли две строки про дубли (`SbCard` и «сами фильтры»),
осталась одна — полоса чипов `ResultsFilteredInfo` ↔ `sb-filter-bar`, последний дубль этой
подсистемы; она сводится тем же приёмом и ждёт решения (§4 п.4).

**Две ловушки, которые всплыли при проверке Ф1–Ф2 — держать в голове на Ф3 и Ф4:**

- **`.fseg` живёт не только в панели фильтров.** Им же покрашены табы раундов и кнопка
  «Show more» в `results-table.tsx`. Значит, в Ф4 токены `--fseg-*` переопределять можно
  ТОЛЬКО на контейнере панели (`.sb-filters` или обёртка сайдбара), но не на корне страницы
  и не на `:root` — иначе вместе с фильтрами перекрасится таблица результатов.
- **Ф4 обязан привезти на страницу и CSS сегментных кнопок.** `.fseg`/`.fseg-active` живут в
  `filter-section.css`, а он импортируется только из `filter-section.tsx`. На deep-странице,
  собранной без этой панели, карточка покрасится (Tailwind лежит в общем бандле), а кнопки
  внутри — нет. Лечится одной строкой: `import './filter-section.css'` перенести (или
  продублировать) в `filter-card.tsx`, чтобы карточка была самодостаточной.
- **Доступность дистанций в хосте сравнивает СТРОКИ, а старый `filter-distance` — числа.**
  Это осознанно: у эстафет дистанция «4X50», `Number('4X50')` даёт `NaN`, а `Set` сравнивает
  NaN с NaN как равные — из-за чего старый код включал кнопку «4X50» всякий раз, когда в
  выборке попадалась любая нечисловая дистанция. Строковое сравнение честнее, но это
  ЕДИНСТВЕННОЕ место, где Ф3 сознательно меняет поведение: проверь на соревновании с
  эстафетами, что «4X50» гаснет и зажигается там, где надо.

**Проверено вживую на Ф4** (`/season-best?season=2025&age=12&gender=female&stroke=freestyle&distance=100&pool=25m`):

- адрес открывает ровно тот срез: карточки показывают «freestyle · 100m», «25m», «W»,
  «12», шапка страницы — «Season best — girls 12»;
- смена пола на M → адрес `gender=male`, заголовок «boys 12», список пересобран;
- клуб: поиск на месте (и НЕ уезжает с прокруткой), выбор пишет `club=439`, сводка
  карточки печатает имя клуба, список 51 → 33 строки;
- смена стиля с freestyle 800m на breaststroke убирает дистанцию из адреса (800 брассом
  нет) и страница честно говорит «Pick an event»;
- «Rows»: `best=true`, 27 → 12 строк, подпись под списком меняется;
- Reset гасит сужения и оставляет сезон с дисциплиной: адрес становится
  `?season=2025&stroke=breaststroke&distance=100`, сама кнопка Reset исчезает;
- мобильная ширина 375px: сайдбар прячется, кнопка «Filters» раскрывает ту же панель;
- консоль **пустая** — в том числе нет `filter_data is not loaded from window`, хотя эта
  страница глобалку не подключает: спящий хост её не читает (см. §5.1 Ф2 п.6);

**Проверено вживую на Ф3** (`?eventId=13` и Maccabiah 2026 Masters):

  сверено с API (0 / 180 / 96 / 144 результата); выбор 4X50 показывает эстафеты (61 строка,

`document.getAnimations().forEach(a => a.finish())`.

## 6. Контекст: страница `/season-best` (сделана 2026-08-26, в `master`)

Нужен, чтобы новый чат понимал, откуда взялся дубль и что трогать при Ф4.

**Сервер:** `GET /api/season-best/list` (ранжированный список среза) и
`GET /api/season-best/options` (сезоны для карусели + стили с дистанциями). Старый
`GET /api/season-best` не тронут — он про другое (по лидеру на ступень возраста).
Файлы: `SeasonBestController.cs`, `SeasonBestRepository.cs`, `SeasonBestListDtos.cs`,
`ISeasonBestRepository.cs`. Тесты — `SeasonBestRepositoryTests.cs`, всего 1449/1449 зелёные.

**Клиент:** `client/src/projects/season-best-project/` — `season-best-project.tsx`
(оркестратор), `components/sb-filters.tsx` (дубль панели), `components/sb-filter-bar.tsx`
(дубль полосы чипов), `components/sb-list.tsx` (список), `season-best-modules.ts` (флаги
блоков), `season-best-page.css`. Хук — `hooks/useSeasonBestList.ts`.

**Возрастные оси (добавлено 2026-08-26, решение Влада).** Их на странице ТРИ, и все три
живут в одной карточке «Age in season»:

1. **Сезонный возраст 8–20** — основная лестница, обычные (не мастерские) старты.
2. **«21+»** — взрослые в обычных стартах. Уходит в API как `age=21&age_to=99`; до этой
   правки ~1300 заплывов за сезон были видны только под «All». Отдельных кнопок 21…39 нет:
   после 22 лет в списке единицы людей.
3. **Мастерские группы** («19-24», «25-29», …) — вторая шкала под чертой (`FilterAgeOptions.extra`).
   Выбор группы переключает выборку ЦЕЛИКОМ на мастерские соревнования: `masters=true&age_group=…`.
   Раньше мастерсы не показывались вовсе (`&& !r.Competition.IsMasters`), теперь запрос идёт
   либо по мастерским, либо по обычным — смешать их нельзя, иначе в одном рейтинге окажутся
   12-летние и 47-летние.

Правило простое: **группа задана ⇒ мастерский срез, снята ⇒ обычный**. Отдельного тумблера
«дети/мастерсы» нет намеренно — ось возраста и есть ответ на вопрос «с кем сравниваем».
Места у мастерсов считаются ВНУТРИ группы: у них ровесник — это пятилетка, а не год.
Сетка групп приходит из данных (`/api/season-best/options` → `age_groups`), а не списком в
коде; мусорные подписи протокола отсеиваются по сходимости с возрастами — история в
[`docs/data-integrity.md`](../data-integrity.md) §9, решения 2026-08-26.

**Решения по странице** (менять только по решению Влада):
- дедупа по пловцу нет: один человек законно занимает 1-е, 3-е и 4-е места, повтор помечен
  «2nd swim»; схлопывание — тумблер `best=true`;
- фильтр по клубу **не пересчитывает места** — они остаются из общего рейтинга (#69, #74);
- имена и клубы печатаются как в протоколе (иврит), латиница за флагом `latinNames`;
  по оригинальному имени клуба `UI_ClubIcon` находит эмблему;
- `?swimmer=` — это «пришли по ссылке», **не «я»**: бейджа ★ ME там быть не должно
  (привязка из URL недоверенная);
- строки красятся по полу (`--deep-male-soft` / `--deep-female-soft`);
- блок «эмблема + имя + клуб» рисует общий `UI_SwimmerNameCell`; дата — `UI_DateIcon`;
  бассейн — `UI_PoolIcon`; время — `UI_SwimTime`.

Тех-справка для дизайнера — [`../design-handoff-season-best.md`](../design-handoff-season-best.md).
