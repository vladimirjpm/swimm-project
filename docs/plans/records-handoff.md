## Как устроено

- **Источники** (`IRecordSourceProvider`): `worldrecords` (XLSX API World Aquatics: WR + NR
  одной страны по GUID), `wa-masters` (PDF мастерских мировых), `isrorg-age` и
  `isrorg-masters` (PDF федерации). У всех PDF-источников ссылки резолвятся со страницы-
  оглавления: в адресе зашита дата, прямой URL протухает при каждом обновлении.
- **Путь:** дифф по 8 осям (`RecordDiffService`) → превью → Apply. Apply **только добавляет и
  обновляет**, удалений нет; метки кэша запись получает сама (К4).
- **Порядок источников — само правило** (И-13): `worldrecords` → `wa-masters` → `isrorg-age`
  → `isrorg-masters`. Зашит списком в `--records-refresh`; перепутаешь — молча откатятся
  израильские рекорды. По той же причине **Израиль никогда не входит в батч по странам**.
- **Разбор PDF федерации не зависит от вёрстки выпуска** (И-26, 17.09.2026): строки
  собираются кластеризацией по разрыву, слова ячейки склеиваются по зазору, слова имени
  вынимаются из соседних колонок. До этого каждый новый выпуск давал десятки ложных изменений
  дат и составов. Сторож — `IsrOrgAgeRecordsColumnDriftTests`.
- **Защита оспоренного времени** (И-25, 17.09.2026): претензия со статусом
  `open` / `reported` / `accepted` (`RecordIssueStatuses.SourceOverruled`) заставляет Apply
  НЕ БРАТЬ это значение — в базе остаётся прежнее. Единственное отступление от «копия обязана
  совпадать с источником», и отступает человек: `candidate` не защищает. Ключ — тот же, что у
  реестра (8 осей + время), поэтому починка файла снимает защиту сама. В превью строка
  зачёркнута, счётчик «Защищено реестром»; CLI печатает `🛡`.
- **Сторож** (`RecordPlausibility`), три правила: мировой улучшен за раз > 3 %; не-мировой
  рекорд быстрее мирового — у мастерса **своей полосы**, у остальных абсолютного; строка стала
  медленнее той, что в базе (исключение — `country/*/open`, там пишут два источника и откат в
  середине цепочки штатный). Находки идут в реестр **кандидатами**: на витрине метки нет, пока
  человек не переведёт в `open`. Претензию на то же значение повторный импорт не воскрешает ни
  в каком статусе.
- **`TimeMs`** — вычисляемая колонка (`GENERATED ... STORED` из `Time`, функция
  `swim_time_ms`). Приложение её не пишет, разъехаться с `Time` она не может.
- **`HolderNameEn`** — английское имя держателя. Заполняет источник, который сам отдаёт
  латиницу; **смена времени его сбрасывает** (`HolderLatinName.CarryOver`). ⚠ Есть карточка
  пловца — имя берётся ИЗ НЕЁ (словарём), дублировать в `HolderNameEn` не надо.
- **Состав эстафеты** нормализуется при разборе (`ParseRelayRoster`): ноги сортируются
  `StringComparer.Ordinal`, имя каждой — «Имя Фамилия». Порядок плавания мы этим теряем, но
  его и не было — источник его не сохраняет.
- **Архив источников** — `!records-sources/` (коммитится): PDF как доказательство + CSV
  разобранных строк как инструмент сверки, по контрольной сумме. Формат CSV один на всех —
  `RecordCsvDump` (LF, без BOM, сортировка по восьми осям Ordinal). Правила 11 и 11-бис в
  [../pre-push-rules.md](../pre-push-rules.md).

## Открытые хвосты

- **«Страна быстрее мира» ≠ ошибка.** В базе осталась ровно одна такая строка — Франция,
  4×50 в/с м 25 м (1:20.77 против 1:21.80), и она ВЕРНА. Прежде чем заводить претензию на
  такую строку, проверь, **с какого года дисциплина рекордная** (records-quality-plan.md §5).

  Krichevsky»): Израиль в батч не входит по И-13. Перепишет следующий `--records-refresh`, тем
  же парсером и без отдельного действия.
- **8 эстафетных строк Израиля остаются с ивритом** — не хватает одного-двух человек из
  четвёрки, и этих людей нет ни у нас, ни у World Aquatics. Разбор и полный список —
  data-integrity.md, «Имена держателей: чем закрыли и что осталось».

## Как проверять вживую

```bash
# пробный прогон четырёх источников (ходит в сеть; строки ⚠ — находки сторожа)
dotnet run --project server/Swimm.API -- --records-refresh --dry-run

# выгрузка источника в CSV для архива и сверки
dotnet run --project server/Swimm.API -- --records-dump <источник> <путь к .csv>

# тесты рекордов
dotnet test server/Swimm.Tests --filter "FullyQualifiedName~Record"

# мастерские мировые на РЕАЛЬНЫХ PDF (иначе скипаются): положить в папку
# CurrentWorldRecords-Individual-LCM.pdf и …-SCM.pdf
SWIMM_WA_MASTERS_DIR=<папка> dotnet test server/Swimm.Tests --filter "FullyQualifiedName~WaMasters"

# целостность архива источников
cd !records-sources && sha256sum -c SHA256SUMS.txt
```

**Витрину смотреть так:** `swimm-api` (5078) + `client-5180` из `.claude/launch.json`, дальше
`http://localhost:5180/records` и `/records/compare`.

⚠ **Панель админки в pane может не отрисовываться** (окно за другим окном — скриншот падает по
таймауту). Тогда админские ручки удобнее дёргать напрямую: GET `/api/antiforgery/token` с
`-c cookiejar`, потом тот же токен заголовком `X-XSRF-TOKEN`. Дев-обход логина включён
(`DevAdminBypass`), но конфиг `swimm-api-preview-user` входит НЕ админом — админку он не пустит.

⚠ **`preview_stop` иногда не добивает процесс** — остаётся `dotnet exec Swimm.API.dll` и
держит DLL. Тогда обычный build-lock: найти по `Get-CimInstance Win32_Process` и убить.

**Спортсмен у World Aquatics** (этим искали английские имена держателей; ходит в сеть):

```bash
curl -A "Mozilla/5.0" "https://api.worldaquatics.com/fina/athletes?name=Polonsky"
curl -A "Mozilla/5.0" "https://api.worldaquatics.com/fina/athletes/1135457/results"
```

Первый даёт имя, дату рождения, гражданство и пол; второй — все заплывы, по которым рекорд
опознаётся однозначно (дата + дисциплина + время). `User-Agent` обязателен: без него
worldaquatics не отвечает вовсе.

⚠ Прогон через ЖИВОЙ API метки кэша ставит сам (проверено дважды). А CLI
(`--records-refresh`, `--records-dump`) — отдельный процесс, его записи идут мимо кэша
запущенного API: после него «Сбросить весь кэш» на `/Admin/Cache` или перезапуск.
