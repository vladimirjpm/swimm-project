## Как устроено

- **Источники** (`IRecordSourceProvider`): `worldrecords` (XLSX API World Aquatics: WR + NR
  одной страны по GUID), `wa-masters` (PDF мастерских мировых), `isrorg-age` и
  `isrorg-masters` (PDF федерации). У всех PDF-источников ссылки резолвятся со страницы-
  оглавления: в адресе зашита дата, прямой URL протухает при каждом обновлении.
- **Путь:** дифф по 8 осям (`RecordDiffService`) → превью → Apply. Apply **только добавляет и
  обновляет**, удалений нет; метки кэша запись получает сама (К4).
- **Порядок источников — само правило** (И-13): `worldrecords` → `wa-masters` → `isrorg-age`
  → `isrorg-masters`. Зашит списком в `--records-refresh`; перепутаешь — молча откатятся
  израильские рекорды.
- **Сторож** (`RecordPlausibility`), три правила: мировой улучшен за раз > 3 %; рекорд страны
  или возраста быстрее мирового; строка стала медленнее той, что в базе (исключение —
  `country/*/open`, там пишут два источника и откат в середине цепочки штатный). Находки идут
  в реестр **кандидатами**: на витрине метки нет, пока человек не переведёт в `open`.
- **`TimeMs`** — вычисляемая колонка (`GENERATED ... STORED` из `Time`, функция
  `swim_time_ms`). Приложение её не пишет, разъехаться с `Time` она не может.
- **`HolderNameEn`** — английское имя держателя. Заполняет источник, который сам отдаёт
  латиницу; **смена времени его сбрасывает** (`HolderLatinName.CarryOver`, одно правило на
  импорт и обе админские формы) — иначе новый рекорд оказался бы подписан прежним держателем.
  ⚠ Есть карточка пловца — имя берётся ИЗ НЕЁ (словарём), дублировать в `HolderNameEn` не надо.
- **Архив источников** — `!records-sources/` (коммитится): PDF как доказательство + CSV
  разобранных строк как инструмент сверки, по контрольной сумме. Правило 11 в
  [../pre-push-rules.md](../pre-push-rules.md).

**Кода в плане осталось на одну задачу:**

1. **Правило 2 сторожа для мастерсов** — мерит рекорд СТРАНЫ абсолютным мировым; с

**Первым делом — ПОЛНЫЙ прогон по странам.** Он нужен дважды: перепишет ~1959 эстафетных строк
на нормальный состав (см. ниже) и создаст первый файл архива батча. Оба изменения ждут именно
его: подмножество стран не архивируется, а эстафеты чинятся только там, где их перезапишут.
После прогона — закоммитить выгрузку и дописать `SHA256SUMS.txt` (правило 11-бис).

**Повторить прогон**, когда понадобится: кнопка «Прогнать все страны» на `/Admin/Import` →
«Рекорды». ⚠ Идёт час-два, **не переживает рестарт API** — в это окно не пересобирать проект.
Кэш после заливки через живой API сбрасывать не надо (проверено: метки сработали сами);
после CLI — надо.

## Открытые хвосты

- **«Страна быстрее мира» ≠ ошибка.** После разбора И-23 в базе осталась ровно одна такая
  строка — Франция, 4×50 в/с м 25 м (1:20.77 против 1:21.80), и она ВЕРНА: World Aquatics
  ведёт рекорды 4×50 только с 2013 года. Прежде чем заводить претензию на такую строку,
  проверь, с какого года дисциплина рекордная (records-quality-plan.md §5).
- **8 эстафетных строк Израиля остаются с ивритом** — не хватает одного-двух человек из
  четвёрки, и этих людей нет ни у нас, ни у World Aquatics. Разбор и полный список —
  data-integrity.md, «Имена держателей: чем закрыли и что осталось».
- **Эстафеты шумели в диффе — починено 17.09**, но ЦЕНОЙ одного разового переписывания.
  Порядок ног в источнике не фиксирован, и раньше эстафетные строки показывались
  «изменившимися» при каждом прогоне. Теперь состав нормализуется при разборе
  (`WorldRecordsParser.ParseRelayRoster`): ноги в устойчивом порядке, имя каждой — «Имя
  Фамилия». ⚠ В базе пока лежат старые, испорченные строки вида «Alain, LEVEAUX Amaury,
  GILOT Fabien, BOUSQUET Frederick Bernard» — первый же полный прогон покажет ВСЕ ~1959
  эстафетных строк изменившимися и перепишет их. Это ожидаемо и делается один раз.
- **У Германии пустует 400 к/п ж 50 м** — строка Петры Шнайдер помечена в источнике как `GDR`,
  а `GDR` мы больше не тянем (И-24). Осознанная цена решения, не баг.
- **Правило `slower-than-stored` не отличает потерю рекорда от починки источником.** Живой
  случай: откат 40.11 → 51.68 — это World Aquatics убирает свой же мусор (И-20), а правило
  видит замедление. Как убрать — `records-quality-plan.md` §3-бис.
- **Откуда взялись наши прежние значения короткой воды мастерсов — не установлено** (И-21).
  Ради этого и заведён архив источников: в следующий раз сверять будет с чем.
- **Адрес 25 м в `appsettings` протухнет** при следующем обновлении справочника. Починят
  ссылку на странице федерации — поле очистить, резолвер подхватит сам.
- **Эстафетные мастерские мировые рекорды не берём:** в модели `Record` нет эстафетных стилей
  и пола `mixed`, а полосы там по СУММЕ возрастов четвёрки («100-119») — это другая ось.
- **7 новых карточек пловцов — без единого заплыва**, формально те же «пловцы-тени», что 85
  штук из ног эстафет. Заведены осознанно и целиком из источников; автоматическая чистка сирот
  трогать их не должна.
- ⚠ **`TimeMs`: отзовут `EXECUTE` у `PUBLIC`** в порядке закручивания гаек — встанут все
  вставки рекордов, а сообщение будет про функцию, а не про права.

## Как проверять вживую

```bash
# пробный прогон четырёх источников (ходит в сеть; строки ⚠ — находки сторожа)
dotnet run --project server/Swimm.API -- --records-refresh --dry-run

# выгрузка источника в CSV для архива и сверки
dotnet run --project server/Swimm.API -- --records-dump <источник> <путь к .csv>

# тесты рекордов
dotnet test server/Swimm.Tests --filter "FullyQualifiedName~Record"

# мастерские мировые на РЕАЛЬНЫХ PDF (иначе скипаются): положить в папку
# CurrentWorldRecords-Individual-LCM.pdf и …-SCM.pdf
SWIMM_WA_MASTERS_DIR=<папка> dotnet test server/Swimm.Tests --filter "FullyQualifiedName~WaMasters"

# целостность архива источников
cd !records-sources && sha256sum -c SHA256SUMS.txt
```

**Витрину смотреть так:** `swimm-api` (5078) + `client-5180` из `.claude/launch.json`, дальше
`http://localhost:5180/records` и `/records/compare`.

**Спортсмен у World Aquatics** (этим искали английские имена держателей; ходит в сеть):

```bash
curl -A "Mozilla/5.0" "https://api.worldaquatics.com/fina/athletes?name=Polonsky"
curl -A "Mozilla/5.0" "https://api.worldaquatics.com/fina/athletes/1135457/results"
```

Первый даёт имя, дату рождения, гражданство и пол; второй — все заплывы, по которым рекорд
опознаётся однозначно (дата + дисциплина + время). `User-Agent` обязателен: без него
worldaquatics не отвечает вовсе.

⚠ Прогон и CLI — отдельные процессы, их записи идут мимо кэша ЗАПУЩЕННОГО API. После заливки
— «Сбросить весь кэш» на `/Admin/Cache` или перезапуск, иначе страницы с рекордами до суток
показывают прежнее.
