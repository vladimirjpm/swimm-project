# Уровни пловцов и план дорожек

Статус: **фаза 8.14 закрыта, всё в master** — L1–L5 (PR #98, 26.09.2026) и Auto lanes (PR #99,
27.09.2026). Открытых решений нет; дальше — таблица «Позже» по запросу Влада. Фаза 8.14 в
[`../ROADMAP.md`](../ROADMAP.md). **Новый чат — начинать с раздела «Как вернуться к работе» в конце.**
Пример из жизни — группа `dolphin-netanya-masters`: 20 пловцов, свободно 6 дорожек;
дорожка 1 — уровень 1 (сильнейшие), 2–3 — уровень 2, 4–5 — уровень 3, 6 — уровень 4
(начинающие). Тренер раскладывает людей и пишет задание на каждую дорожку; пловец заходит
и видит, где он плывёт и что делает.

Принцип: **первая версия — самая простая, но так, чтобы усложнение встало без переделки
модели** (таблица «Позже» в конце).

## Решения Влада (26.09.2026)

1. **Уровни — свои у каждой группы, со стандартным набором и правкой.** При первом открытии
   группа получает 4 стандартных (`1 — Advanced`, `2`, `3`, `4 — Beginner`); тренер
   переименовывает, добавляет, удаляет. Не фиксированные 10 и не «у каждого тренера свои»:
   тренер = админ группы, админов у группы может быть несколько.
2. **Названия уровней участникам показываем** — на доске дорожек видно «Lane 6 · Beginner».
3. **План видят только участники** — управляющие + активные аккаунты группы
   (`HubGroupUserMember.Status = active`). Публичной странице группы и гостю — нет.
   Та же аудитория, что у тренировок.
4. **План — на конкретную дату** (+ кнопка «Copy from previous plan»). Недельного
   расписания нет.

## Решения по модели (приняты в обсуждении)

- **Всё приватное — `Sys_`-таблицы без `swimm_ro`**, как тренировки
  ([`../hubgroups-architecture.md`](../hubgroups-architecture.md) §7). Уровень — оценка
  тренера, публичный read-путь его физически не видит. Всё через `SwimmDbContext`.
- **Уровень пловца ключуется `(HubGroupId, SwimmerId)`, НЕ `HubGroupMember.Id`.** Клубных
  пловцов пересборка подписки удаляет и заводит заново (§4а) — уровень потерялся бы вместе
  со строкой состава.
- **План — снимок.** Назначения «пловец → дорожка» хранятся явно; смена уровня пловцу или
  состава группы старые планы не переписывает. Уровень — только вход для кнопки
  «Distribute», дальше тренер двигает руками.
- **План ≠ тренировка.** `Sys_TrainingSessions` — это результаты (времена) после
  тренировки, план — то, что было задано до. Связь оставлена на потом (nullable FK).

## Модель

```
Sys_HubGroupLevels          Id, HubGroupId, Rank (1 = сильнейший), Name(50), Description(300)?, Color(9)?,
                            SubLevels (1..5, 1 = нет подуровней; 20.10.2026)
                            индекс (HubGroupId, Rank) НЕ уникальный (список сохраняется целиком с
                            перенумерацией — уникальный падал бы на перестановке); AK (HubGroupId, Id)
                            — цель составного FK уровня пловца
Sys_HubGroupSwimmerLevels   HubGroupId, SwimmerId, LevelId, SubLevel? (1..5)            PK (HubGroupId, SwimmerId)
                            FK (HubGroupId, LevelId) → уровень ЭТОЙ ЖЕ группы, ON DELETE CASCADE
                            (строка уходит = «без уровня»)
Sys_LanePlans               Id, HubGroupId, Date (date), LaneCount (1..12), Note(500)?, MaxPerLane? (1..20),
                            Status (draft|published), CreatedByUserId? (SET NULL), CreatedAt, UpdatedAt
                            UNIQUE (HubGroupId, Date)   ← снять, когда появится StartTime
Sys_LanePlanLanes           PlanId, LaneNo, LevelId?, Workout(4000)?       PK (PlanId, LaneNo)
                            LevelId ON DELETE SET NULL; строки 1..LaneCount есть всегда
Sys_LanePlanSwimmers        PlanId, SwimmerId, LaneNo?, OrderNo            PK (PlanId, SwimmerId)
                            OrderNo — порядок внутри дорожки (кто ведёт); FK на дорожку нет —
                            границы держит сервис (сокращение дорожек иначе упиралось в порядок команд EF)
```

Три корзины в редакторе плана, без лишних флагов:
- строка с `LaneNo` — пловец на дорожке;
- строка с `LaneNo = null` — **Unassigned** (пришёл, но не разложен: нет уровня или его
  уровню не дали дорожку);
- строки нет — **Not today** (снят тренером).

Кто вообще попадает в план: состав группы — `HubGroupMember` без `IsExcluded` (ручные +
клубные), тот же читатель состава, что у страницы.

## Распределение (чистая функция, Application-слой)

`LaneDistribution.Distribute(lanes: [(LaneNo, LevelId?)], swimmers: [(SwimmerId, LevelId?, SortKey)])`
→ `[(SwimmerId, LaneNo?)]`.

- Для каждого уровня: его дорожки по возрастанию `LaneNo`, его пловцы по `SortKey`
  (`HubGroupMember.SortOrder`, затем имя) → режутся на **подряд идущие куски** поровну (±1,
  большие куски первыми). Не «по кругу» (так было в первой версии плана): когда порядок
  станет «по скорости», быстрые окажутся вместе на меньшем номере дорожки, а не вперемешку.
- Пловец без уровня или с уровнем без дорожек → `LaneNo = null` (Unassigned).
- Детерминирована — одинаковый вход даёт одинаковый выход (нужно для тестов).
- «Distribute» пересобирает черновик целиком; если тренер уже двигал людей руками —
  подтверждение «Manual moves will be lost». Снятые (Not today) не возвращаются.

## Права и видимость

- **Править** уровни и планы: `HubGroupPermissions.CanEdit` (владелец, админ группы,
  site-админ). Мутации — antiforgery, как всё в группах.
- **Видеть** опубликованный план: управляющий ИЛИ `IsActiveAccountMemberAsync` (готовая
  проверка из `HubGroupTrainingRepository`, ей же закрыты тренировки). Pending-заявка
  доступа не даёт. Черновик видят только управляющие.
- **«Моя дорожка»** — только подсветка (сделано в L4). Источники по порядку: `me` —
  привязка аккаунта админом сайта (`AppUser.SwimmerId`, /Admin/Users) и избранное «Me»;
  `family` — избранное-семья и метка членства в ЭТОЙ группе (`HubGroupUserMember.SwimmerId`,
  «за какого пловца этот аккаунт»). Берутся только пловцы, стоящие в плане (дорожка или
  Unassigned). Прав не даёт — правила «primary favorite недоверенный» и «аккаунт ↔ пловец
  связи нет» про права, не про подсветку. Привязка по инвайту (§7) для этого не нужна.
- **Не кэшировать** — приватные данные на аккаунт, как тренировки.

## API

Уровни — только управляющим, поэтому живут под `/api/me/hub-groups` рядом с остальным
самообслуживанием групп и, как оно, в **camelCase** (`HubGroupLevelsController`, сделано в L1):

```
GET    /api/me/hub-groups/{id}/levels                      CanEdit → { levels[{id, rank, name, description, color, swimmerCount}],
                                                           swimmers[{swimmerId, name, nameEn, birthYear, gender, clubName, levelId}] };
                                                           у группы без уровней сначала заводит стандартные 4
PUT    /api/me/hub-groups/{id}/levels                      CanEdit → { levels[{id|null, name, description, color}] } — весь список,
                                                           порядок = ранг, отсутствующие удаляются; отвечает как GET
PUT    /api/me/hub-groups/{id}/swimmer-levels/{swimmerId}  CanEdit → { levelId | null } → 204
```

Планы дорожек читают и участники, поэтому один контроллер `HubGroupLanePlansController`
под `/api/hub-groups/{id}/lane-plans`, **snake_case** и на вход, и на выход (как публичные
ответы групп и тренировки) — сделано в L2. `{date}` — строго `yyyy-MM-dd`, иначе 400.

```
GET    /api/hub-groups/{id}/lane-plans                     участник → [{date, status, lane_count}] новые сверху, только published;
                                                           управляющему — и черновики (до 200 строк)
GET    /api/hub-groups/{id}/lane-plans/{date}              участник → доска {date, status, lane_count, note, updated_at,
                                                           lanes[{lane_no, level{id,rank,name,color}|null, workout, swimmers[]}],
                                                           unassigned[], not_today[], can_edit,
                                                           my_swimmers[{swimmer_id, kind: me|family}]}; swimmers[] =
                                                           {swimmer_id, name, name_en, birth_year, level_id (текущий), left_group}.
                                                           not_today — только управляющему; черновик участнику — 404
PUT    /api/hub-groups/{id}/lane-plans/{date}              CanEdit → {lane_count, note, lanes[{lane_no, level_id, workout}],
                                                           swimmers[{swimmer_id, lane_no|null}]} — план целиком (новый — draft,
                                                           статус существующего не трогает); порядок в swimmers = порядок в
                                                           дорожке; отвечает доской
POST   /api/hub-groups/{id}/lane-plans/distribute          CanEdit → {lane_count, lanes, swimmer_ids|null} →
                                                           {swimmers[{swimmer_id, lane_no}]}; null = весь видимый состав.
                                                           Ничего не сохраняет
POST   /api/hub-groups/{id}/lane-plans/auto-lanes          CanEdit → {lane_count, swimmer_ids|null} → {lanes[{lane_no, level_id}],
                                                           swimmers[{swimmer_id, lane_no}]}: дорожки между уровнями по числу
                                                           пришедших + раскладка. Ничего не сохраняет; ни у кого нет
                                                           уровня — 400 с подсказкой
POST   /api/hub-groups/{id}/lane-plans/{date}/publish      CanEdit → 204
POST   /api/hub-groups/{id}/lane-plans/{date}/unpublish    CanEdit → 204 (обратно в черновик)
DELETE /api/hub-groups/{id}/lane-plans/{date}              CanEdit → 204 / 404
```

«Copy from previous» ручки НЕ получил (решение L5): копия — это заготовка редактора на
клиенте, сохраняется обычным PUT. Так тренер правит копию до записи, и у сервера нет второго
пути создания плана.

`my_swimmers` («Your lane») приходит и в ответе PUT — считается для того, кто сохранил.

Какой план открывается участнику по умолчанию: ближайший опубликованный с `Date >=`
сегодня **по Asia/Jerusalem**, иначе последний прошедший.

## UI (видимый текст — English)

- **Страница группы, новый таб `Lanes`** (`?tab=lanes`, каркас табов `group-page.tsx`):
  не участнику — замок (`locked`, как у Trainings: «Lane plans are visible to group
  members only.»). Участнику — выбор даты + доска: карточка на дорожку (номер, уровень,
  задание, люди). Сверху карточка **«Your lane»**, если подсветка нашлась. Мобильный
  вид — карточки столбиком, своя первой.
- **Управляющему в том же табе** — выбор даты (стрелки по планам + поле «любой день»), на
  пустом дне «Create plan» и «Copy from <дата>»; в редакторе: число дорожек, заметка,
  **«Auto lanes»** (дорожки между уровнями сами), уровень на дорожку, **«Distribute by level»**,
  перетаскивание (плюс выпадашка «Lane N / Unassigned / Not today» на телефоне), ↑ «кто ведёт»,
  корзины Unassigned / Not today, задание текстом с «Same workout as lane N−1» (соседу того же
  уровня); на доске — Edit, Publish / Unpublish, Delete.
- **Уровни** — карточка `Levels` в табе `Admin` группы: список уровней (имя, описание, цвет,
  порядок) и состав с выпадашкой уровня у каждого пловца, фильтр «No level».
- **Уровень из таба `Swimmers`** (27.09.2026) — управляющему в карточке `Members` у каждого
  пловца та же выпадашка уровня (точка цвета + «N · Name» / «No level»), в подзаголовке
  «N without a level». Участнику и гостю уровни не грузятся вовсе.
- Новых маршрутов нет (таб через `?tab=`) — три зеркала маршрутов не трогаем.

## Footguns — проверить при реализации

- ✅ **Склейка пловцов** (`SwimmerMergeService`) переносит `Sys_HubGroupSwimmerLevels` и
  `Sys_LanePlanSwimmers` (L5). SwimmerId — часть ключа, поэтому строка дубля пересоздаётся на
  канонического; канонический уже в той же группе/плане — его строка главнее. Без этого каскад
  по SwimmerId молча унёс бы уровень и места в планах при удалении дубля.
- ✅ **Удаление группы** — `delete-impact` считает `LeveledSwimmers` и `LanePlans` (L5), они же
  входят в `HasContent`; показываются в «My groups» и в админке.
- **Удаление уровня** — пловцы становятся «без уровня» (каскад строки), дорожки в старых
  планах теряют подпись (SET NULL). Подтверждение с числом затронутых пловцов.
- **Пловец ушёл из группы** — из старых планов не удаляем (снимок), в новых его нет.
- Миграция через `/db-migrate` (`--context SwimmDbContext`); таблицы `Sys_` → в
  `02-grants.sql` ничего не добавляем (только `swimm_rw` по умолчанию — сверить, как
  сделано у `Sys_TrainingSessions`).
- `seed-tables.txt` — уровни/планы в дамп НЕ едут: висят на `HubGroups`, а группы не едут
  (владелец — аккаунт). Уровни и планы записаны туда (L1, L2).

## Сделано

### L1 — уровни (26.09.2026)

- **Модель.** `HubGroupLevel` → `Sys_HubGroupLevels` (Rank не уникален: список сохраняется
  целиком с перенумерацией, уникальный индекс падал бы на перестановке «1↔2»);
  `HubGroupSwimmerLevel` → `Sys_HubGroupSwimmerLevels`, PK `(HubGroupId, SwimmerId)`.
  FK на уровень **составной** `(HubGroupId, LevelId)` → альтернативный ключ `(HubGroupId, Id)`
  уровня: уровень чужой группы база не примет. Удаление уровня/группы/пловца — каскад.
  `swimm_rw` получил DML через default privileges, `swimm_ro` — ничего (проверено в БД).
- **Правила** — `HubGroupLevelRules` (Application): стандартный набор `Advanced /
  Intermediate / Developing / Beginner`, проверка списка (1..12 уровней, имя 1..50 без дублей
  по регистру, описание ≤300, цвет `#rrggbb`), ранг = место в списке.
- **Сервис** — `HubGroupLevelService`: все записи под advisory-lock группы (`HGLV`), чтобы
  два первых открытия не завели набор дважды. Уровень ставится только пловцу видимого
  состава (не скрытому клубному); счётчики — по составу (ушедший хранит уровень, но не
  считается).
- **Контроллер** — `HubGroupLevelsController` (`CanEdit`, antiforgery). Ошибки — английским
  текстом, клиент показывает их как есть.
- **Клиент** — `components/group-levels.tsx`, карточка в табе Admin между расписанием и
  Joining: список уровней (просмотр → Edit levels → черновик с цветом, именем, описанием,
  ↑↓✕, Save; удаление занятого уровня — через `ConfirmDialog` с числом пловцов), ниже состав
  с фильтром-чипами (All / по уровню / No level) и выпадашкой уровня, которая сохраняет
  сразу (оптимистично, откат с ошибкой). Цвет по рангу — `components/level-color.ts`, его же
  возьмёт доска дорожек.
- **Тесты** — `HubGroupLevelTests` (17): правила, стандартный набор один раз, только видимый
  состав, чужой уровень/посторонний/скрытый отклоняются, уровень переживает клубную
  пересборку, перестановка/переименование/удаление с очисткой назначений.
- **Проверено вживую** (стенд `stack-5183-api5082-personas`, тест-группа `utest-open`):
  тренер видит 4 стандартных, ставит уровни, удаляет занятый уровень через подтверждение;
  участник — 403, гость — редирект на вход (как у всего `/api/me`), без antiforgery — 400,
  чужая группа — 403; на 375 px горизонтальной прокрутки нет. Тестовые уровни после проверки
  удалены.

### L2 — план дорожек, сервер (26.09.2026)

- **Модель** — `LanePlan` / `LanePlanLane` / `LanePlanSwimmer` → `Sys_LanePlans` /
  `Sys_LanePlanLanes` / `Sys_LanePlanSwimmers` (миграция `AddLanePlans`, check-ограничения
  на статус, 1..12 дорожек, номер дорожки ≥ 1). `swimm_rw` — DML, `swimm_ro` — ничего.
- **Правила** — `LanePlanRules`: дата `yyyy-MM-dd` (2000..2100), план приводится к полному
  виду (дорожки 1..N все, недостающие — пустые), порядок пловцов во входе = порядок в дорожке.
- **Распределение** — `LaneDistribution` (кусками, см. выше).

### Auto lanes (решение Влада 26.09.2026, после L5)

Тренер задаёт только число дорожек — «Auto lanes» сам делит их между уровнями по числу
пришедших и раскладывает людей (Distribute остаётся: он раскладывает по уровням, которые тренер
поставил дорожкам сам). Решения: **соседние уровни при нехватке дорожек объединяются, лимита
людей на дорожку нет.**

- **Функция** — `LaneAllocation.AutoLanes` (Application, чистая, детерминирована):
  считаются пришедшие с уровнем (без уровня — Unassigned, удалённый уровень — тоже).
  Дорожек не меньше уровней — каждому по одной, остальные по одной уходят уровню с наибольшим
  числом людей на дорожку (при равенстве — сильнейшему); дорожек у уровня не больше, чем людей,
  лишние остаются без уровня. Дорожек меньше уровней — разбиение на подряд идущие группы с
  наименьшей самой многолюдной дорожкой (динамика по префиксам), при равенстве сливаются слабые.
  Сильные — на меньших номерах; внутри группы люди режутся кусками, на общей дорожке сперва
  сильнейший уровень.
- **Модель не менялась**: у дорожки один уровень — общей дорожке подписью ставится сильнейший из
  слитых (Developing + Beginner → «Developing»), а люди на ней — обоих уровней. Повторный
  Distribute по такому плану отправит слабый уровень в Unassigned (у него нет своей дорожки) —
  повторно жать надо Auto lanes.
- **Клиент** — кнопка «Auto lanes» рядом с «Distribute by level»: ставит уровни всем видимым
  дорожкам (задания остаются на своих номерах) и раскладку; «Not today» не трогает. Если уровни
  дорожек или люди уже заданы — подтверждение.
- **Тесты** — `LanePlanTests`: пример «Дельфина» 4/7/6/3 на 6 дорожек → 1, 2–3, 4–5, 6; слияние
  слабых соседей; минимум самой загруженной дорожки (2/2/10 на 2 → [1,2] и [3]); одна дорожка;
  дорожек не больше людей; пропуск пустых и удалённых уровней; детерминизм; сервис (текущие
  уровни, 400 без уровней, границы числа дорожек).
- **Проверено вживую** (`utest-open`, уровни 2/3/0/1): 3 дорожки → Advanced, Intermediate,
  Beginner; 2 → Advanced и Intermediate+Beginner (4 на второй); 5 → по две Advanced и Intermediate
  + Beginner; 1 → все вместе. В редакторе задание дорожки 2 осталось, повторный запуск
  спрашивает подтверждение. Тестовые уровни удалены.

### Подуровни и перелив (запрос и решения Влада 20.10.2026)

Запрос: «Advanced 1, Advanced 2 — в случае чего (нет мест) Advanced 2 перейдёт на дорожку
Intermediate». Подуровень — это порядок перелива, когда на дорожке не хватает мест.

**Решения Влада (20.10.2026):**
1. **Модель — номер внутри уровня**, а не отдельные записи уровней с родителем: у уровня
   «сколько подуровней» (1 = нет, до 5), у пловца — номер (1 = верхний). Подпись дорожки —
   по-прежнему уровень.
2. **«Нет мест» = лимит людей на дорожку** — поле «Max per lane» в плане (1..20, по умолчанию
   «No limit»). Без лимита перелива нет вовсе (решение 26.09 «лимита нет» осталось поведением
   по умолчанию).
3. **Только вниз**: «Advanced 2 → дорожка Intermediate». Вверх («Intermediate 1 → дорожка
   Advanced») никто не поднимается.
4. **По одному человеку**, а не подуровнем целиком: уходит столько, сколько нужно, первым —
   последний в порядке.

**Правила перелива** (`LaneOverflow`, Application, чистая функция; общая для Distribute и Auto lanes):
- блок — дорожки одного уровня (у Auto lanes при нехватке дорожек — группа слитых соседних),
  блоки по силе (по рангу, не по номеру дорожки);
- уйти может только **нижний подуровень** уровня, у которого подуровней 2+ (в слитом блоке —
  только слабейшего уровня); без подуровня и у уровня без подуровней — никто;
- уходят, **только если внизу есть место** — с учётом цепочки: нижний блок может сам отдать своих
  нижних дальше вниз и так освободить место; места нет нигде — дорожка остаётся переполненной
  (в редакторе счётчик «7 / 6» цветом тревоги);
- **только на соседний блок**: перешедший дальше не идёт, даже если ниже свободно;
- пришедшие сверху **ведут** дорожку (они сильнее); внутри уровня подуровень 1 первым, без
  подуровня — в конце;
- на дорожку уровня, у которого сегодня никого нет, перелиться тоже можно (блоки строятся от
  дорожек, а не от людей).

Ответ Distribute / Auto lanes теперь идёт **по дорожкам** (внутри — кто ведёт), Unassigned в
конце: редактор кладёт людей в дорожку в порядке ответа, а прежний «порядок состава» не дал бы
подуровню 1 и пришедшим сверху встать первыми.

- **Модель** — миграция `AddLevelSubLevels`: `Sys_HubGroupLevels.SubLevels` (int, default 1,
  CK 1..5), `Sys_HubGroupSwimmerLevels.SubLevel` (int?, CK 1..5), `Sys_LanePlans.MaxPerLane`
  (int?, CK 1..20). Применена к локальной базе. У аккаунтов без пловца подуровня нет: в план они
  не попадают и на перелив не влияют.
- **Сервер** — `PUT …/levels` принимает `subLevels` (null — у существующего как было); подуровней
  стало меньше — «Advanced 3» становится нижним, подуровней не стало — подуровень снимается.
  `PUT …/swimmer-levels/{id}` принимает `subLevel` (у уровня без подуровней не хранится, вне
  1..N — 400). План: `max_per_lane` во входе PUT / distribute / auto-lanes и в ответах списка и
  доски; у пловца доски — `sub_level`. Склейка пловцов переносит подуровень.
- **Клиент** — `level-select.tsx` (общая выпадашка «1 · Advanced 2» для карточки Levels и таба
  Swimmers); в редакторе уровней — выбор «No sub-levels / 2…5 sub-levels»; в тулбаре плана —
  «Max per lane» (новый план берёт лимит соседнего); на плашке пловца — цифра подуровня рядом
  с точкой цвета уровня (видно, кто пришёл сверху).
- **Тесты** — `LaneOverflowTests` (24 случая): пример Влада 9/3 → 6/6, без лимита никто не двигается, по
  одному, только вниз, нет места — остаётся переполненным, цепочка, один шаг вниз, без подуровня
  не двигается, ранг важнее номера дорожки, перелив на пустой уровень, Auto lanes, порядок ответа;
  правила лимита и подуровней; сервисы (подуровень пловца, сжатие подуровней, лимит в плане).
  `LanePlanPgTests.SubLevelsAndMaxPerLane_OnPostgres` — запись, сжатие и CK на живой базе.
- **Проверено вживую** (стенд `stack-5185-api5084-migr`, `utest-open`, теперь id 289): Advanced и
  Intermediate по 2 подуровня, 6 пловцов (A1, A1, A2, A2, I1, I2), 2 дорожки, лимит 3, Auto lanes →
  дорожка 1: A1, A1, A2 («3 / 3»), дорожка 2: A2 (ведёт), I1, I2; Save — лимит и подуровни в
  ответе; таб Swimmers показывает «1 · Advanced 2»; 375 px без горизонтальной прокрутки. Тестовые
  план и уровни удалены.
- **Не тронуто сознательно** — вид по дорожкам на занятие без плана (`TrainingLaneView`, Ш3.2):
  он раскладывает на лету без лимита, подуровни на него не влияют.

- Стенд: конфиг `stack-5183-api5082-personas` в `.claude/launch.json` (API 5082 из Debug
  `--no-build` + Vite 5183) — не мешает :5078 Влада и чужому :5079. Перед запуском
  `dotnet build server/Swimm.sln`; если :5078 из Debug запущен — сборка упрётся в лок, тогда

  Когда Debug занят (ProdAdmin Влада) — стенд `stack-5185-api5084-migr`: API из конфигурации
  `Migr` (`dotnet build server/Swimm.API -c Migr`, свой `bin/Migr`, лок не мешает) + Vite 5185.
  ⚠ Тесты, читающие исходники (HostingMode, DataVersionPg, DirectMemoryCache…), с
  `--artifacts-path` вне репо падают «корень не найден» — их гонять `dotnet test -c Migr`.
- Персонажи: `GET /api/dev/persona?as=utest-coach` (владелец тест-групп), `utest-member`
  (участник обеих), `utest-newbie` (вошёл, не в группе — замок), `utest-pending` (заявка в
  `utest-approval` — замок), `default` — вернуть. Тест-группы: `utest-open` (id 285),
  `utest-approval` (id 286); у `utest-open` 6 пловцов.

  `PUT /api/me/hub-groups/285/user-members/12/label {swimmerId}` под тренером (12 = `utest-member`);
  после проверки вернуть `{swimmerId: null}`.
- Уборка после проверки: `delete from "Sys_LanePlans" where "HubGroupId" in (285,286)` и то же для
  `"Sys_HubGroupLevels"` (уровни пловцов уходят каскадом). ⚠ Уровни группы 17
  (`dolphin-netanya-masters`) — настоящие, Влада: их не трогать.
- Pane: скриншоты иногда не отдаются, если окно свёрнуто — проверять через DOM (`javascript_tool`),
  клики — через `el.click()`; скрипт с `location.reload()` обрывается — перезагрузку делать
  отдельным вызовом `navigate`.

**Известные ограничения (сознательно, не баги).**

- У дорожки один уровень: Auto lanes при нехватке дорожек кладёт соседние уровни на одну и
  подписывает её сильнейшим. Distribute по такому плану слабый уровень отправит в Unassigned —
  нужно жать Auto lanes. Лечится «несколько уровней на дорожке» (таблица уровней дорожки) — если
  попросят.
- Вход админа группы через Google (служебный `UpdatedAt`) сбрасывает кэш страниц его групп —
  метка своей строки корня; редко и дёшево.
- Клиентских юнит-тестов нет (в клиенте нет тестового раннера) — правила редактора (копия
  прошлого плана, убранные дорожки → Unassigned) проверены только вживую.
