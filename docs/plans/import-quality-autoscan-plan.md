# Автозапуск проверки качества при импорте (необязательный)

Статус: **СДЕЛАНО 29.09.2026** (решение Влада, Р70 в docs/data-integrity.md) ровно по §2:
`JsonImportService` принимает необязательный `ISuspectResultService` и после коммита сканирует
каждое затронутое событие (или день без события); итог — строкой «Качество: …» в логе импорта.
Повод: день 1512 переимпортировали 19.09, автопометки сбросились, и отсечка 50 м вместо финиша
на 400 в/с (117 333 очка) месяц висела «лучшим заплывом». Тесты — `ImportRecalculationTests`
(`Import_RunsQualityScan_ForTouchedCompetition`, `QualityScanFailure_DoesNotRollBackImport`).
Ниже — исходный план (заведён 2026-08-01) для истории.

## 1. Что есть сейчас

Проверки данных существуют, но **не на импорте**, а рядом. Полная картина:

| Слой | Где | Что делает | Гейт? |
|---|---|---|---|
| Парс | `POST /api/admin/parse-pdf` → превью | `resultCount`, список соревнований, совпадения с БД, `warnings` (грубый греп debug-лога по «warn/skip/fail» — `PdfResultSourceProvider`) | глазами человека |
| Импорт | `JsonImportService.ImportAsync` | `diagnosticLog`: формат, ненайденные ключи категорий, псевдоклубы, детали upsert, конфликт `OrgCompId` | нет, ничего не блокирует |
| История | `ImportHistory.Approved = false` | ручной флаг на `/Admin/ImportHistory` | нет, ни на что не влияет |
| Качество результатов | `SuspectResultDetector` + `SuspectResultService` | 5 автоправил (быстрее МР, эстафетное время в личном, выброс от медианы, расхождение пола, дубль заплыва) | помеченные не бьют рекорды |
| Мониторинг | `DataQualityService` + дашборд | FK-аномалии, пустые эстафеты, пловцы без OrgId/результатов, дубли зачёта | read-only |
| Рекорды | `RecordDiffService`, `RecordQualityService` | дифф с подтверждением; сверка справочника с протоколами | apply — руками |

**Дыра:** `SuspectResultService.ScanAsync` вызывается ровно из одного места —
`SuspectResultsAdminController` (кнопка «Качество» в `/Admin/Competitions`). В
`JsonImportService` его нет. Импортировал соревнование — до ручного клика никто ничего
не проверил.

Полумера сделана 2026-08-01: кнопка вынесена из раскрывающейся панели прямо в строку
таблицы и стала акцентной («⚑ Качество»), чтобы хотя бы попадалась на глаза.

## 2. Что предлагается

Вызывать `ScanAsync` для каждого затронутого соревнования в конце `ImportAsync`, ровно
по образцу пересчёта Combine All Results, который там уже живёт:

- **после** `tx.CommitAsync()`, а не внутри транзакции;
- в `try/catch` — упасть на проверке нельзя, иначе откатятся уже загруженные результаты;
  ошибку писать в `diagnosticLog` с подсказкой «прогоните кнопку вручную»;
- результат писать туда же: `Качество: помечено N, снято M, ручных сохранено K`;
- по СОБЫТИЮ целиком, если импорт задел многодневку (у `ScanAsync` уже есть `eventId`).

Ручные пометки (`SuspectReasons.Manual`) правило не трогает, поэтому переимпорт их не
затрёт — это уже гарантировано самим сервисом.

## 3. Приёмка

- [x] После импорта файла с заведомо битой строкой (быстрее мирового рекорда) она
      помечена без ручного клика.
- [x] Ручная пометка, поставленная до переимпорта, осталась после него (гарантирует сам сервис).
- [x] Падение проверки не откатывает импорт — результаты на месте, в логе сообщение.
- [x] Тест на то, что импорт вызывает скан (шпион `ISuspectResultService`).

## 4. Почему необязательный

Кнопка работает и покрывает те же случаи; автозапуск — про то, чтобы не забыть.
Цена — импорт становится чуть дольше и приобретает зависимость от ещё одного сервиса.
Если импорт станет пакетным (много файлов подряд), скан лучше вешать на очередь
(`ImportJobQueue`), а не на каждый файл — тогда этот план надо переписать.

Связано: [качество рекордов](records-quality-plan.md) (тот же подход, но для справочника
рекордов), `docs/competition-overview-cards.md` (что считают карточки и почему помеченные
строки не бьют рекорды).
