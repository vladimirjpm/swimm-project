# Английские имена пловцов: проверка, сторож импорта, починка (10.10.2026)

Справочник и журнал темы «английское имя не подходит к ивритскому». Читать, если на витрине
у пловца чужое или ивритское имя в английском режиме, если `/Admin/Health` показывает
`swimmers.en-name-mismatch`, или перед правкой `EnglishNameFit` / `ImportSwimmerResolver`.
Инцидент — [data-integrity.md](../data-integrity.md), И-50; предыстория — И-47 (сверка с loglig
08.10) и И-48 (переносы имён).

## 1. Что случилось

На летнем чемпионате 8–11 «דרום» (comp 1486, loglig 15157) у пловцов из блока неявок английские
имена съехали на соседа: «פוגל דודוביץ איתן» получил «ELKIN DANIEL», «סגרון נועם» — «סגרון | EYTAN».
Причин две, обе в паре протоколов HE+EN:

1. **Июльский разбор EN-строки сдвигал имена неявок на строку.** Нынешний парсер этого не делает
   (сверено 10.10 по паре «заплыв + дорожка» на всём протоколе 1486).
2. **Имя переносилось в ячейке ВМЕСТЕ с клубом** — строки над и под данными несут куски обеих
   колонок: «EVEN CHEN Hapoel Jerusalem Swim» / данные / «NEUBAUER club». Обрывком имени их не
   считали, EN-фамилия терялась, и импорт клал в EN-поле иврит («ברוטמן | BRUTMAN»). Починено в
   парсере 10.10 (`11f49d8d`, `IsrOrgCompetitionParser.LeadingUpperLatinWords`): на протоколе 1486
   восстановлено 14 строк, ни одна заполненная не изменилась.

Сверка И-47 (08.10) вылечила большинство таких имён по карточкам loglig, но оставила «съезд
EN-строки на соседа» неразобранным и не дала способа узнавать новые случаи. Это закрыто здесь.

## 2. Как устроено теперь — три защиты

| Где | Что делает | Файл |
|---|---|---|
| **Правило** | Подходит ли EN-имя к ивритскому: каждое латинское слово обязано найтись среди ивритских (скелет согласных). Одно лишнее латинское слово при двух совпавших — второе имя («MICHEL LEIB \| BRUTMAN»), не ошибка | `Swimm.Application/Mapping/EnglishNameFit.cs` |
| **Сторож импорта** | Импорт не пишет пловцу EN-имя, если оно ивритское или чужое; строка уходит в диагностику импорта («EN-имя … не записано пловцу …») | `ImportSwimmerResolver.SetEnglishName` |
| **Проверка реестра** | `swimmers.en-name-mismatch` (Warning) на `/Admin/Health` — после каждого прогона реестра | `DataChecks/NameDataChecks.cs` |
| **Починка** | `--fix-en-names` по английской карточке loglig, с аудитом | `EnglishNameRepairService`, `EnglishNameRepairPlanner` |

**Почему пустое лучше чужого.** Импорт дозаполняет ТОЛЬКО пустые EN-поля
(`FillEnglishName`). Чужое имя не перезапишет никто и никогда, а пустое заполнит первый же
протокол или карточка. Витрина при пустом EN показывает иврит — по правилу «имена на иврите
по умолчанию» это нормальный вид.

### Правило `EnglishNameFit`, по шагам

- Сравнение по скелету согласных (`NameTransliteration`, откалиброван в И-47), порог слова **0.6**.
- Направление — от латиницы к ивриту. Наоборот нельзя: на loglig часто нет второго имени
  («פלדמן איתן | צבי» ↔ «FELDMAN EITAN»).
- Граница имени и фамилии не значит: слова сравниваются общим мешком, латинское слово — и с
  каждым ивритским, и с парой соседних (склейка «MATANILAN» ↔ «מתן אילן»).
- Два чтения, которых нет в общем скелете (общий не трогали — на нём стоит импорт): «ו» как V
  («דוד» ↔ «DAVID») и «TS»/«CH» как два звука («ALTSHUL» ↔ «אלטשול», «LEIBOVITCH» ↔ «ליבוביץ»).
- Короткое слово («EVA», «ABU» — одна согласная) и не совпавшее — не улика; совпавшее короткое
  («ELLA» ↔ «אלה») засчитывается.
- «Чужое» — два лишних латинских слова или одно при одном совпавшем.

### Разрез строки карточки — `SplitLatinName`

Карточка loglig отдаёт имя одной строкой, в любом порядке («MICHEL LEIB BRUTMAN», «SIGRON NOAM»).
Перебираются все разрезы в обоих порядках. Годится разрез, у которого в каждом поле есть слово
своего ивритского поля, нет слова, похожего только на другое поле, и не больше одного слова без
пары — и стоит оно в ИМЕНИ (второе имя). Слово без пары в фамилии — отказ: так разрез подгоняется
под ивритскую границу, которая сама неверна («עבד | אלקדר» при карточке «ABED ALRAHMAN ABED
ALKADER»). Счёт — сумма похожестей плюс бонус 0.3 за поле с тем же числом слов, что в иврите.
Берётся лучший, только если он опережает второй на 0.1; иначе отказ — решает человек.

## 3. Калибровка (10.10.2026, вся база — 5921 карточка)

| Что | Итог |
|---|---|
| `Assess` | подходит 5549, нечего сравнивать 315, **чужое 32, иврит в латинице 25** |
| `SplitLatinName` на 3675 пловцах с согласованными полями (обе строки «Имя Фамилия» и «Фамилия Имя») | **7347 верно, 0 ошибок, 3 отказа** (служебные «ABO», «AL», «-») |

Первая версия правила («каждое ИВРИТСКОЕ слово обязано найтись») давала 316 «ошибок» — почти
все из-за второго имени. Версия без чтения «ו = V» давала ~90 ложных «Давидов». Не возвращаться
к этим вариантам.

## 4. Команды

```bash
dotnet run --project server/Swimm.API -- --fix-en-names --report <файл.tsv>
```

Сухой прогон: читает английские карточки (пауза 1 с), печатает решение по каждому кандидату,
базу не трогает. С `--apply` — одна транзакция, аудит `swimmer.en-name-fix` на каждую строку
(было / стало / карточка / причина в `DetailsJson`, иврит читаемый). Пловец, у которого EN-поля
поменялись после чтения, пропускается. `--ids 1,2,3` — только эти пловцы. Перед `--apply` —
бэкап базы.

```bash
dotnet run --project server/Swimm.API -- --check-data
```

Прогон реестра: проверка `swimmers.en-name-mismatch` пишет находки на `/Admin/Health`.

Решения починки (`EnglishNameRepairPlanner`): карточка подходит → **Write**; карточка пишет те же
слова, что уже стоят (прозвище, своя транслитерация) → **Keep** («Принять»); иврит в латинице →
**Clear**; имя чужое, а карточка не подходит → **Clear**; имя чужое, карточки нет → **Keep**
(руками). Карточка на иврите (у игрока нет латиницы) — это «карточки нет».

## 7. Грабли

- **Английская карточка loglig** открывается только с ДВУМЯ куками: `_culture=en-US` и
  `DetailsPageVisited=visited`; без второй — бесконечный редирект. Общий HttpClient «loglig» для
  этого нельзя: его контейнер кук один на все запросы, и английская кука переключила бы язык всему
  остальному. Отдельный клиент `loglig-en` (`UseCookies = false`, кука заголовком).
- **У игрока без латиницы** английская карточка отдаёт ивритский заголовок — это не EN-имя.
- **`EnglishNameFit` живёт в `Swimm.Application`**, а не в `Swimm.Parsing`: Infrastructure (проверка,
  импорт) не ссылается на Parsing. Туда же переехал `NameTransliteration` (10.10).
- Калибровочные прогоны (одноразовые консольки) — в scratchpad, не в репо; повторить можно по этому
  документу: выгрузка `Swimmers` в TSV → `EnglishNameFit.Assess` / `SplitLatinName` на каждой строке.
