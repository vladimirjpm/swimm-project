**Дополнено 2026-08-01 (после K6).** Карточка времён разошлась на две — подробности и
причины в [club-page-model.md](club-page-model.md) §4.6, правило возраста — §4.7.

- **Season best** (`GET /api/clubs/{id}/season-best?pool=&season=`) — пловцы клуба, которые
  в сезоне **первые по стране** в слоте `дисциплина × бассейн × пол × возрастная ступень`.
  Лидер считается по всей базе. Всегда ОДИН сезон, глобальный фильтр сезона не слушает.
  Подпись «among N meets in our database» обязательна: «первый в Израиле» = первый среди
  импортированного. Клуб 438, сезон 2025/26: 28 плиток, 21 старт в расчёте.
- **Record wall** (`GET /api/clubs/{id}/record-wall?pool=`) — официальные рекорды из
  `Records`, связанные с клубом **по названию** (у `Record` нет `SwimmerId`/`ClubId`).
  У клуба 438 — 24 записи. Сезона нет: рекорд живёт, пока его не побили.
- **⚠ Возраст в сезоне** = год окончания сезона минус год рождения, один на весь сезон
  (`SeasonMath.AgeInSeason`). Первая версия считала по году заплыва — декабрьские и
  февральские старты одного пловца разъезжались по двум ступеням. Правило применено также
  к ростеру и Top swimmers, поэтому подписи возраста там сдвинулись на год.
- **Раскладка:** Top swimmers + Swimmers парой, Season best + Record wall парой,
  Competition timeline ушёл вниз. Общая форма карточек времён — `club-record-card.tsx`.

**Качество официальных рекордов** (тот же день, отдельный план
[records-quality-plan.md](records-quality-plan.md)): ошибки федерации не чиним, а помечаем —
`Sys_RecordIssues` + сверка `Sys_RecordVerifications`, вкладка «Спорные записи» на
`/Admin/Records`, метрики и кнопка «Сверить с протоколами» на `/Admin`. Первая претензия
RQ-1 посеяна миграцией.

Попутно: дедуп-эвристика «одинаковое имя» (`8d01b1d`), фикс пересчёта зачётов при merge
(`7badee6`), фикс «age 2025» (`784518b`), дизайн-хендофф (`3eb0fb3`).

**Данные:** Влад склеил все 68 клубов-дублей — групп с одинаковыми именами **0**.
У Дольфина стало 171 пловец / 1589 результатов / 14 зачётов.

## 2. Ключевые решения (не переоткрывать)

1. **Зачёт = одно соревнование** (для многодневного — событие целиком). Накопительных
   зачётов из нескольких стартов нет. Роль (❄/☀) **выводится сама** из
   `IsChampionship` + `PoolType` (25м → зима, 50м → лето); `StandingKindOverride` —
   только для исключений вроде открытой воды.
2. **Места — протокольные.** На многодневках медали вручают за каждый день, внутри дня
   возрасты плывут разными заплывами. `CombinedPlace` — сравнительный вид, не официальный.
   Полное объяснение: `docs/competition-overview-cards.md`, раздел «Почему у одного
   соревнования ДВА набора мест».
3. **Сравнимы только ранги, не очки** — у каждого старта своё правило начисления.
4. **Зачёт образуют только категории возрастной лестницы** (`Category.ReservedKeys`);
   кастомные (`result-maccabiah`) — нет.
5. **Merge мягкий, без 301**: `/clubs/{старый id}` отдаёт клуб-приёмника.
6. Тренеры, фото клуба и open water — **сознательно пустые карточки**, данных нет.

## 3. Что осталось / где искать проблемы

### Отложено осознанно
- **Тренеры** — источника нет вовсе; карточка рисует «Coach data is not collected yet».
  Нужно решение: ручной справочник, заявки от официальных hub-групп, или роль-пользователь.
- **Фото клуба** — `Club.PhotoUrl` не заводили; вариант «показывать медиа официальной
  hub-группы» не реализован.
- **Open water** — категории `ow-3km`/`ow-5km` не заведены, импорта нет. Модель готова:
  `StandingKindOverride = 'openwater'`.

### Известное упрощение
`ClubCompetitionStandings` хранит **одну** таблицу на соревнование, даже если оно висит в
двух группах лестницы (Хадера-2026, Лига-3). По модели их должно быть две — отдельно Kids,
отдельно Young. Сегодня ни один **чемпионат** не двухкатегорийный, поэтому грид не врёт;
KPI и история уже схлопывают такие старты по `CompetitionId`, чтобы не удваивать очки.
Если появится двухкатегорийный чемпионат — понадобится ключ по категории в таблице зачёта.

### Спорная пара дедупа, оставленная Владу
`אלומה עירוני הוד השרון` #447 против `הפועל עירוני הוד השרון` #1329 — имена РАЗНЫЕ
(אלומה / הפועל), связаны только 21 общим пловцом. Если это один клуб, сменивший
принадлежность, склеить вручную.

### Не сделано намеренно
Ссылок на страницу клуба из публичных мест (таблица клубов соревнования, фильтры) пока нет —
это отдельная работа. Страница доступна по прямому адресу.

## 4. Как поднять и проверить

```bash
docker compose -f server/docker-compose.yml up -d
dotnet run --project server/Swimm.API --configuration Release --urls http://localhost:5079
npm --prefix client run dev          # либо конфигурация client-5079 из .claude/launch.json
```

Открыть `http://localhost:5174/clubs/438` (порт Vite может отличаться — смотри вывод).

Полезные адреса:
- `/clubs/1271` — клуб без результатов, проверка пустых состояний;
- `/clubs/1291` — склеенный клуб, должен показать 438;
- `/Admin/Competitions/Edit?id=57` — селект «Роль в клубном зачёте»;
- `/Admin` — метрика «Дубль клубного зачёта» (сейчас 0).

Аварийный пересчёт зачётов, если цифры разошлись:
```bash
dotnet run --project server/Swimm.API -- --rebuild-club-standings
```

⚠ **Build-lock:** Visual Studio держит Debug-выход `Swimm.API`. Собирать
`--configuration Release`, API поднимать на :5079, чужие процессы не убивать.

## 5. Уроки этой сессии (стоят того, чтобы помнить)

- **Три ошибки из четырёх нашлись только живой проверкой, а не тестами**, потому что
  неверные цифры выглядели правдоподобно: удвоение KPI на двухкатегорийных стартах
  (20236 вместо 16057), «age 2025» вместо пустого возраста, фильтр пола по `"M"/"F"`
  при том, что в базе `"male"/"female"`. Сверять агрегаты между собой, а не только
  смотреть, что «похоже на правду».
- **XML-док у поля может врать.** `Swimmer.Gender` подписан «M / F», а в базе 2475
  `"male"` против 13 `"M"`. Сверяться с данными.
- **В проекте жили две нумерации сезона** (год начала и `cYear` федерации) — теперь обе
  в `SeasonMath` с предупреждением.
- **Склейка вскрыла дырку в пересчёте зачётов**: пересчёта по соревнованиям канона мало,
  нужны ещё зачёты самого дубля, собранные ДО переноса результатов.
