# Мировые юниорские рекорды (WJR) — правая сторона карточки у юношеских рекордов (J1–J7)

**Статус: СДЕЛАНО — J0–J7 (21.09.2026), ветка `world-junior-records`.** WJR залиты в локальную
базу (70 строк, `--records-refresh --source wa-junior`, архив — `!records-sources/`). Хвост вне
плана — эстафетные WJR: **сделаны 22.09.2026** в [records-relays-plan.md](records-relays-plan.md)
(Э1 однополые, Э3 смешанные с полосой 14–18; 9 строк залиты). Продолжение
[records-world-compare-plan.md](records-world-compare-plan.md) (Р1–Р7, в master, PR #83) —
читать его §1–§4 первым: карточка, `worldRecord`, варианты `UI_H2H*` уже есть.

## 1. Зачем

Карточка «рекорд против мирового» на странице пловца рисует ВСЕ официальные рекорды, но
правая сторона заполнена только у мастерских — мировых по юношеским возрастам у нас нет
(в базе `country/age` есть, 783 строки; `world/junior` и `world/age` — ноль строк).

Официальных мировых рекордов **по отдельному году** (12, 13, 14…) не существует — World
Aquatics их не ведёт. Официальные есть только **World Junior Records**: одна полоса на пол.
Их и заводим.

## 2. Решения Влада (21.09.2026)

1. **Заводим WJR** в справочник и подключаем к карточке.
2. **Подпись — «World Junior»**, не «WR» и не «world record»: иначе читается как «мировой
   рекорд твоего возраста», которого нет.

## 3. Что уже известно — не перепроверять

- **Полосы WJR** (правило World Aquatics, возраст на 31 декабря года заплыва):
  **женщины 14–17, мужчины 15–18**. Оба бассейна.
- **Ось совпадает с нашей.** WJR считает возраст по КАЛЕНДАРНОМУ году — и справочник
  рекордов у нас на календарной оси (правило «ось справочника КАЛЕНДАРНАЯ», И-25,
  [data-integrity.md](../data-integrity.md)). Пересчёта не нужно.
- **Матч НЕ точный, а по полосе** — главное отличие от мастерс. У мастерс ступени
  мировые и израильские совпадают один в один; здесь израильский ключ — один возраст
  (`AgeKey="15"`), а WJR — полоса. Правило: `country/age` возраста N и пола G получает WJR
  пола G, если N входит в полосу пола G. Остальное (стиль, дистанция, бассейн) — точно.
- **Следствие, которое UI обязан признать:** одно и то же время WJR встанет против
  нескольких израильских ступеней (рекорд 15 лет и рекорд 17 лет — против одного WJR).
- **Вне полосы — пусто навсегда:** 10–13 у обоих полов, 18 у девушек, 14 у юношей. Для
  них официального эталона нет в принципе.
- **Схема готова:** `Record.Categories` уже содержит `"junior"`
  (`Swimm.Domain/Entities/Record.cs`), формат `AgeKey` для него не зафиксирован
  («по данным, напр. U17»). Миграция не нужна.
- **Карточка готова:** `worldRecord` в `HeldRecordRow`/`SwimmerHeldRecordDto`, заполнение в
  `SwimmerPageRepository.GetRecordsHeldAsync` (ключ `WorldRecordKey`), качество по И11.

## 4. Вопросы — все закрыты 21.09.2026

1. **ИСТОЧНИК — ЗАКРЫТ (J0, 21.09.2026).** Не XLSX, а **JSON-эндпоинт**, которым питается
   сама страница [worldaquatics.com/swimming/records](https://www.worldaquatics.com/swimming/records)
   (фильтр Record Type → `WJ=World Junior Records`):
   `GET api.worldaquatics.com/fina/records/SW?recordCode=WJ&eventTypeId=&region=&countryId=&gender=F|M&pool=LCM|SCM`
   — 200, JSON. Образцы — `!records-sources/wa-junior-*__fetched-2026-09-21.json`.
   - XLSX-отчёт `/fina/records/report?recordCode=WJ` — **504 через 90 с**, повторено для SCM
     и LCM; даже `WR` там отвечает ~60 с. Отчёт для WJ не собирается за таймаут шлюза — не
     брать. (Комментарий в `WaMastersRecordsSourceProvider` «только WR|NR» — про отчёт, для
     JSON-эндпоинта неверен; поправить в J1.)
   - JSON тоже медленный: **30–90 с** на запрос (F LCM — 90 с, на грани). В провайдере —
     таймаут с запасом (≥ 180 с) и ретрай; четыре запроса можно параллельно.
   - Одна страница: `pageSize=50`, `totalRowCount` 18–25 — пагинация не нужна, но проверять
     `totalRowCount == records.Length` и падать, если нет.
   - Поля: `disciplineDistance`, `disciplineGroup` («Freestyle», «Medley», «… Relay»),
     `time`/`timeFormatted`, `fullName`, `nationalityCode`, `date`, `officialName`, `city`,
     `yearOfBirth` (не у всех), `recordStatus`.
   - ⚠ **Несколько строк на дисциплину — норма ответа, хотя `current=true`:**
     - повторённый рекорд (то же время): M SCM 50 бат — KHARUN 22.28 дважды (13 и 14.12.2022);
       M LCM 50 в/с — ANDREW 21.75 дважды + SHEREMET 21.75 (2025);
     - **побитый рекорд остаётся в выдаче**: M LCM 200 спина — MURATORY 1:54.87 (11.08.2026)
       и KOLESNIKOV 1:55.14 (2017).
     Правило для J1: по дисциплине берём **минимальное время**; при равенстве — как
     `WorldRecordsParser` поступает с совместными WR (сверить в J1, не изобретать своё).
   - Эстафеты в выдаче есть (`… Relay`) — отбрасываются (§4-3).
   - Индивидуальных дисциплин: LCM — 17 у обоих полов, SCM — 18 (есть 100 комплекс).
2. **`AgeKey` для junior — РЕШЕНО 21.09.2026 (Влад): полоса** — `"14-17"` у женщин,
   `"15-18"` у мужчин. В ключе видно, какую полосу покрывает строка; матч «возраст в полосе»
   читает её же, а не константу в коде.
3. **Эстафеты — РЕШЕНО 21.09.2026 (Влад): БЕРЁМ**, включая смешанные. Но `Records` эстафет
   сейчас не умеет (⚠ поправка 22.09: однополые — умеет, `Distance=4X100m`; нет только
   `Gender=mixed`, см. [records-relays-plan.md](records-relays-plan.md)) — это отдельный СРОЧНЫЙ
   пункт [ROADMAP](../ROADMAP.md) «Эстафеты в справочнике рекордов». Порядок: J1 импортирует
   индивидуальные сразу; эстафетные строки WJR провайдер парсит тоже, но пишет их, когда
   готов срочный пункт (до того — пропуск с явной строкой в отчёте импорта, не молча).
   Израильских эстафетных рекордов в справочнике пока нет — правая сторона карточки у
   эстафет появится вместе с ними.

## 5. Этапы

- **J0. Источник — СДЕЛАН 21.09.2026** (§4-1): JSON `fina/records/SW?recordCode=WJ`, образцы в
  `!records-sources/`, строки в `SHA256SUMS.txt`.
- **J1. Импорт — СДЕЛАН 21.09.2026.** `WaJuniorRecordsSourceProvider` (JSON, 4 запроса
  параллельно, повтор на 5xx, проверка `totalRowCount`), карточка на `/Admin/Import`, строка
  в «Проверить апдейты» дашборда, место в `--records-refresh` за `wa-masters`. Сторож:
  WJR быстрее WR → `faster-than-world-record`; юниорский в эталон не входит. Тесты —
  `WaJuniorRecordsSourceProviderTests` (реальные ответы J0), `RecordImportPlausibilityTests`
  (`Junior_*`). Живая выгрузка: 74 строки (70 после дедупа), 8 эстафетных пропущено.
  Пишет `world/junior`; ось упсерта ни с кем не пересекается — порядка источников нет.
- **J2. Сервер: матч по полосе — СДЕЛАН 21.09.2026.** В `GetRecordsHeldAsync` второй путь:
  строка `country/age` без мастерского эталона получает WJR того же пола/бассейна/стиля/
  дистанции, если `WorldJuniorBand.Covers(полоса, возраст)` (`Swimm.Application/Mapping`).
  `adults` и возраст вне полосы — `null`. Ось `world/junior` (~70 строк) грузится одним
  запросом, только если у пловца есть возрастные рекорды. В DTO `worldRecord` два новых поля:

  junior). Качество WJR — по тому же ключу претензий (И11). Тесты —
  `HeldRecordWorldJuniorMatchTests` (границы обеих полос, вне полосы, `adults`, пол/бассейн/

  `WorldJuniorBand.Covers`).

## 6. Как проверять

`preview_start { name: "stack-5181-api5079" }` — ⚠ API там из **Release** с `--no-build`:
после правки сервера `dotnet build server/Swimm.sln -c Release`, иначе превью молча
показывает старый бинарь. Пловцы для проверки — подобрать запросом: юноша 15–18 и
девушка 14–17 с рекордами `country/age`, плюс кто-то 10–13 (правая сторона пустая).

```sql
-- кандидаты: держатели юношеских рекордов в полосе WJR
select "HolderName", "Gender", "AgeKey", count(*)
from "Records" where "RegionType"='country' and "Category"='age'
  and (("Gender"='female' and "AgeKey" in ('14','15','16','17'))
    or ("Gender"='male'   and "AgeKey" in ('15','16','17','18')))
group by 1,2,3 order by 4 desc limit 20;
```
