# Мировые юниорские рекорды (WJR) — правая сторона карточки у юношеских рекордов (J1–J7)

**Статус: НЕ НАЧАТО (план 21.09.2026).** Кода нет, ветки нет. Продолжение
[records-world-compare-plan.md](records-world-compare-plan.md) (Р1–Р7, в master, PR #83) —
читать его §1–§4 первым: карточка, `worldRecord`, варианты `UI_H2H*` уже есть.

## 1. Зачем

Карточка «рекорд против мирового» на странице пловца рисует ВСЕ официальные рекорды, но
правая сторона заполнена только у мастерских — мировых по юношеским возрастам у нас нет
(в базе `country/age` есть, 783 строки; `world/junior` и `world/age` — ноль строк).

Официальных мировых рекордов **по отдельному году** (12, 13, 14…) не существует — World
Aquatics их не ведёт. Официальные есть только **World Junior Records**: одна полоса на пол.
Их и заводим.

## 2. Решения Влада (21.09.2026)

1. **Заводим WJR** в справочник и подключаем к карточке.
2. **Подпись — «World Junior»**, не «WR» и не «world record»: иначе читается как «мировой
   рекорд твоего возраста», которого нет.

## 3. Что уже известно — не перепроверять

- **Полосы WJR** (правило World Aquatics, возраст на 31 декабря года заплыва):
  **женщины 14–17, мужчины 15–18**. Оба бассейна.
- **Ось совпадает с нашей.** WJR считает возраст по КАЛЕНДАРНОМУ году — и справочник
  рекордов у нас на календарной оси (правило «ось справочника КАЛЕНДАРНАЯ», И-25,
  [data-integrity.md](../data-integrity.md)). Пересчёта не нужно.
- **Матч НЕ точный, а по полосе** — главное отличие от мастерс. У мастерс ступени
  мировые и израильские совпадают один в один; здесь израильский ключ — один возраст
  (`AgeKey="15"`), а WJR — полоса. Правило: `country/age` возраста N и пола G получает WJR
  пола G, если N входит в полосу пола G. Остальное (стиль, дистанция, бассейн) — точно.
- **Следствие, которое UI обязан признать:** одно и то же время WJR встанет против
  нескольких израильских ступеней (рекорд 15 лет и рекорд 17 лет — против одного WJR).
- **Вне полосы — пусто навсегда:** 10–13 у обоих полов, 18 у девушек, 14 у юношей. Для
  них официального эталона нет в принципе.
- **Схема готова:** `Record.Categories` уже содержит `"junior"`
  (`Swimm.Domain/Entities/Record.cs`), формат `AgeKey` для него не зафиксирован
  («по данным, напр. U17»). Миграция не нужна.
- **Карточка готова:** `worldRecord` в `HeldRecordRow`/`SwimmerHeldRecordDto`, заполнение в
  `SwimmerPageRepository.GetRecordsHeldAsync` (ключ `WorldRecordKey`), качество по И11.

## 4. Открытые вопросы (решить В НАЧАЛЕ нового чата)

1. **ИСТОЧНИК — не подтверждён.** Проверено 21.09.2026 живыми запросами к XLSX-отчёту
   `api.worldaquatics.com/fina/records/report`:
   - `recordCode=WR` — 200, xlsx (работает, как и раньше);
   - `recordCode=WJR` — сразу **400** (кода нет);
   - `recordCode=WJ` — **не 400**, а **504 через 90 с** (дважды). То есть код, похоже,
     принимается, но отчёт не отдаётся. ⚠ Комментарий в `WaMastersRecordsSourceProvider`
     утверждает «отчёт знает только WR|NR, любой другой код даёт 400 (16.09)» — с `WJ`
     это уже не так, но и рабочим его не назвать.

   Порядок проверки: повторить `WJ` для SCM/LCM (другое время суток); если отдаётся —
   это лучший путь (тот же парсер `WorldRecordsParser`, что у WR). Если нет — искать PDF
   на сайте World Aquatics по образцу мастерс (`WaMastersRecordsPageResolver`, страница
   `worldaquatics.com/masters/records`). Правило проекта: первоисточник качаем сами
   ([feedback-fetch-sources-myself]), неофициальные подборки «мировых по возрастам» не берём.
2. **`AgeKey` для junior:** предлагаю полосу `"14-17"` / `"15-18"` — в ключе видно, какую
   полосу покрывает строка, и матч «возраст в полосе» читает её же. Альтернатива `""` —
   тогда полоса живёт в коде по полу, и данные её не показывают.
3. **Эстафеты** — как у мастерс, сознательно НЕ берём (в `Record` нет эстафетных стилей и
   пола mixed)? Предлагаю не брать.

## 6. Как проверять

`preview_start { name: "stack-5181-api5079" }` — ⚠ API там из **Release** с `--no-build`:
после правки сервера `dotnet build server/Swimm.sln -c Release`, иначе превью молча
показывает старый бинарь. Пловцы для проверки — подобрать запросом: юноша 15–18 и
девушка 14–17 с рекордами `country/age`, плюс кто-то 10–13 (правая сторона пустая).

```sql
-- кандидаты: держатели юношеских рекордов в полосе WJR
select "HolderName", "Gender", "AgeKey", count(*)
from "Records" where "RegionType"='country' and "Category"='age'
  and (("Gender"='female' and "AgeKey" in ('14','15','16','17'))
    or ("Gender"='male'   and "AgeKey" in ('15','16','17','18')))
group by 1,2,3 order by 4 desc limit 20;
```
