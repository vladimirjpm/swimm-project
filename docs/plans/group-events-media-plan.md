# События группы и видео к ним (план, 30.09.2026)

Запрос Влада (30.09.2026): «сегодня нам делали подводную съёмку» — нужно завести у группы
**событие** (тренировка, но без времён) и прицеплять к нему видео: своё — любой участник, для
всех — тренер/админ группы. Статус: **Е1–Е3 сделаны 30.09.2026 (§7–§7б)** — сервер, видео от участников, экран.

## 1. Для чайника — что есть сейчас

- **Журнал тренировок** есть, но тренировка в нём появляется только **вместе со временами**
  пловцов. Завести тренировку руками нельзя никому — ни API, ни экрана; все сессии в базе
  залиты разово скриптом (`--seed-dolphin-training`).
- Видео к тренировке прицепить можно (`Sys_HubGroupMedia.TrainingId`), но **только тренеру/админу**
  и только к тренировке со временами — пустая в списке не видна.
- **Расписание** («вт 20:00», «иду / не приду») — правило повторения, а не записи: к конкретному
  вторнику ничего не прицепить.
- **My media** — своё видео участника: привязка к заплыву на соревновании, публикация в группу
  через одобрение. К тренировке — нельзя, и оно требует пловца (у аккаунта его может не быть).

## 2. Идея одной фразой

**Событие = сессия тренировки без времён.** Тренер заводит его кнопкой (дата, название, по желанию
— время из расписания); к нему добавляют видео: участник — своё, тренер — любое. Видит только
группа. Если потом к той же сессии появятся времена — это та же запись, ничего не переносится.

## 3. Разведка кода (30.09.2026) — на что опираемся

| Кусок | Где | Что важно |
|---|---|---|
| Сессия | `TrainingSession` → `Sys_TrainingSessions` | `HubGroupId`, `ExternalTrainingId` (UNIQUE в группе), `Name` (текст плана), `Date`, `PoolType`, `Note`. Автора, названия и времени начала нет |
| Создание сессии | `DolphinTrainingSeeder`, `PersonaSeeder` | только CLI; API/UI нет |
| Чтение журнала | `HubGroupTrainingRepository.GetTrainingsAsync`, `GET /api/hub-groups/{slug}/trainings` | идёт ОТ результатов → сессия без времён и её медиа не видны; права CanEdit или активный участник, без кэша |
| Медиа | `Sys_HubGroupMedia` + `HubGroupMediaService.AddAsync` | `TrainingId` принадлежит группе; при `TrainingId` видимость принудительно public/без якорей; добавлять/удалять — только CanEdit; удаление без проверки автора; жалоб нет |
| Клиент журнала | `training-by-session.tsx` | группирует по `trainingId` (число из `ExternalTrainingId`, у нечислового = 0!), лента медиа — `TrainingMediaStrip` |
| Редактор медиа | `my-groups-panel.tsx` `MediaEditor` | список тренировок строит из `/trainings` → пустых нет |
| Приватность | `TrainingResultsPrivacyTests` | новый файл, читающий `Sys_Training*`, — строка в `Allowed` с причиной |
| Кэш | страница группы кэшируется, медиа тренировок в неё НЕ встроено | новый эндпоинт — личный, `no-store`, кэш не нужен |

## 4. Предлагаемое устройство (рекомендации — ждут «да», §6)

**Модель — расширить `TrainingSession`, новую сущность не заводить.** Миграция:
`Title` (≤100, «Underwater filming»), `StartTime` (`HH:mm`, nullable — привязка к слоту
расписания/RSVP), `CreatedByUserId` (nullable, SetNull), `CreatedAt`. Событие, заведённое
кнопкой, получает `ExternalTrainingId = "ev-<id-подобное>"` (нечисловой — клиент журнала надо
перевести с `trainingId` на `sessionId`, иначе все события слипнутся в один `0`).

**Медиа — та же `Sys_HubGroupMedia` с `TrainingId`, но добавлять может участник.**
- Новый путь: `POST /api/hub-groups/{id}/sessions/{sid}/media` — CanEdit **или** активный
  участник (если группа не выключила, §6-3). Автор — `CreatedByUserId`.
- Удалить: автор — своё, CanEdit — любое.
- Потолки (как у групп, `HubGroupQuotaRules`): на событие ~50 ссылок, от одного участника ~10;
  rate limit — общий для мутаций групп.
- Видимость — как у тренировок: CanEdit и активные участники. Наружу — никогда (в v1).

**API событий** (личное, `private, no-store`, права — как у журнала):
- `GET /api/hub-groups/{id}/sessions?from=&to=` — список сессий (и со временами, и без):
  id, дата, начало, название, есть ли времена, медиа.
- `POST` / `PUT` / `DELETE /api/hub-groups/{id}/sessions[/{sid}]` — только CanEdit. Удалить
  можно лишь сессию **без времён** (сессии Дельфина с временами так не удалить).

**Клиент** — таб Trainings → Sessions:
- «+ New event» у тренера (дата по умолчанию сегодня; если на эту дату есть слот — время
  подставляется, событие связывается с занятием из расписания).
- Список прошедших сессий/событий карточками: название, дата, лента медиа, «+ Add video» у
  участника (URL + подпись), ✕ у своего/у тренера.
- Журнал тренировок и `MediaEditor` видят и события без времён.

## 6. Решения (Влад, 30.09.2026: «всё по рекомендациям»)

Приняты все рекомендации ниже. По п. 7 — **в интерфейсе это «Training»**, что это съёмка, видно
из названия; **отдельного типа («event») нет**: признак «есть времена» сервер берёт из наличия
результатов, фильтр «только съёмки» понадобится — добавить поле одной миграцией.

> **Дополнено 01.10.2026:** поле добавлено — тип тренировки из фиксированного списка
> (`TrainingSessionType`, миграция `AddTrainingSessionType`), см. Р7
> [trainings-tab-redesign-plan.md](trainings-tab-redesign-plan.md). Название остаётся свободным.

1. **Модель:** событие = сессия тренировки без времён (реком.) или отдельная сущность «событие»?
2. **Кто заводит событие:** только тренер/админ группы (реком.) или любой участник?
3. **Кто добавляет видео:** все активные участники по умолчанию + настройка группы «только
   тренер» (реком.) — или всегда только тренер?
4. **Видео участника:** видно группе сразу, тренер может удалить (реком.) — или через одобрение
   тренера, как публикации My media?
5. **Кто видит:** только группа (реком., как тренировки) — или у доверенной (Trusted) группы
   можно выносить на публичную страницу?
6. **Только видео или и фото/альбомы?** Реком.: те же типы, что у медиа группы (image / video /
   album-ссылка).
7. **Название в интерфейсе:** «Event», «Session» или «Training»? (UI на английском.)
8. **My media:** показывать ли участнику его видео с событий в `/my-media` — реком. позже, не в v1.

## 7. Е1 — сделано (30.09.2026)

- Миграция `TrainingSessionCreatedInApp`: у `Sys_TrainingSessions` поля `Title` (≤100),
  `StartTime` (`HH:mm`), `CreatedByUserId` (SetNull), `CreatedAt`. Применена к локальной базе.
- `TrainingSessionRules` (проверка ввода: дата `yyyy-MM-dd` от 2000 г. и не дальше года вперёд,
  название обязательно, начало строго `HH:mm`, потолок 5 тренировок группы на дату; ключ
  `ui-<16 hex>`), `ITrainingSessionService` / `TrainingSessionService`.
- `HubGroupTrainingSessionsController` — `api/hub-groups/{id}/sessions`: `GET` (управляющие и
  активные участники, `can_manage`), `POST` / `PUT {sid}` / `DELETE {sid}` — только управляющие;
  `private, no-store`, rate limit групп.
- Поведение: при создании пустые начало и бассейн берутся из расписания (начало — если в этот
  день ровно одно занятие); у тренировки с временами дата и бассейн не меняются, удалить её
  нельзя; удаление пустой уносит её медиа. Времён сервис не читает — только «есть ли» (строка в
  `TrainingResultsPrivacyTests.Allowed`).
- Тесты `TrainingSessionTests` (15: правила ввода и сервис), всего 2598/2598 зелёные. Вживую на стенде
  5183+5082: тренер заводит/правит/удаляет, участник читает и получает 403 на запись,
  посторонний — 403, аноним — редирект на вход (как у RSVP).
- ⚠ **Дата — полночь UTC** (`timestamp with time zone`, как у сидера): `Kind = Unspecified`
  Npgsql не пишет — поймано только на стенде, InMemory не ловит; тест держит `Kind == Utc`.

## 7а. Е2 — сделано (30.09.2026)

- `POST /api/hub-groups/{id}/sessions/{sid}/media` — управляющий всегда, активный участник —
  если у группы не «только тренер»; `DELETE …/media/{mediaId}` — автор своё, управляющий любое.
  Проверки ссылки — те же, что у медиа группы (`HubGroupMediaService.AddAsync`, одно место).
- Потолки: 50 ссылок на тренировку (`MaxMediaPerSession`), 10 от одного участника
  (`MaxMediaPerMember`; управляющего не касается).
- Настройка группы «кто добавляет видео» — `training_media` в расписании (`members` по
  умолчанию, хранится только `coach`; сохраняется вместе с расписанием — у группы без
  занятий в расписании действует умолчание). Отдаётся в `training_schedule` страницы группы.
- Список `GET …/sessions` — `can_add_media`, у каждой ссылки `mine` / `can_delete` для зрителя;
  кто добавил, наружу не отдаётся (правило лент группы, important.md).
- Миграция `HubGroupMediaAuthorSetNull`: `Sys_HubGroupMedia.CreatedByUserId` — nullable,
  SetNull вместо RESTRICT (теперь автор — и участник: удаление его аккаунта не должно
  упираться в ссылку группы; ссылка без автора удаляется только управляющим).
- Тесты: `TrainingSessionTests` (+9 по Е2), `HubGroupBreakTests` (сохранение настройки);
  всего 2607/2607. Вживую на стенде: тренер и участник добавляют, участник удаляет только своё
  (чужое — 403), http-ссылка — 400, «только тренер» — участнику 403 и `can_add_media: false`,
  тренер удаляет ссылку участника.
