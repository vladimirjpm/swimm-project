# План — правила входа и регистрации: одна воронка, включаемые правила

**Статус:** ☐ не начато (поставлено 16.10.2026, просьба Влада). **Оценка:** 2–3 дня.
Соседний план — [content-permissions-plan.md](content-permissions-plan.md) (права на медиа).

## Зачем

16.10.2026 галочка 13+ убрана: она заставляла ребёнка, которому родитель разрешил вход через Google Family
Link, отмечать неправду ([important.md](../important.md)). Но ограничения ещё могут понадобиться:
возраст по странам (пользователи не только из Израиля), закрытие регистрации на время, ручное одобрение
новых аккаунтов. Нужно, чтобы любое такое правило:

- **включалось и выключалось в админке** без деплоя;
- **работало для всех способов входа** — Google, email, будущие SMS, Apple и т. п.;
- писалось маленьким отдельным классом с тестами, не трогая остальной код.

**Не цель:** собирать возраст, документы, номер телефона или согласие родителей **сейчас**. План делает
только каркас; конкретное правило включается отдельным решением (юридические оговорки — ниже).

## Как сейчас (сверено с кодом 16.10.2026)

Логика входа разбросана:
- **Google:** `AuthController.CompleteGoogleSignInAsync` — поиск по `(Provider, ProviderKey)`, привязка к
  существующему email только при `email_verified` (`Security/GoogleClaims.cs`), создание пользователя,
  проверка `IsActive`, история входов, кука (`IssueAuthCookieAsync`).
- **Email и пароль:** `LocalAuthService.RegisterAsync` / `LoginAsync` (Argon2id, токены, блокировка
  после неудачных попыток); куку выпускает контроллер.
- Новый способ входа сегодня = копия этой логики.

## Устройство

### 1. Одна воронка для всех способов входа

- Провайдер только **доказывает личность** и отдаёт `ExternalIdentity`: способ входа (`google`, `local`,
  `sms`…), id у провайдера, email, подтверждён ли он, имя, фото.
- Всё остальное — в одном сервисе `IAccountSignInService` (Application — интерфейс, Infrastructure —
  реализация): найти или создать аккаунт, прогнать правила, записать историю входов. Кука остаётся в
  контроллере (это HTTP).
- Google-callback и email-логин зовут этот сервис; будущий SMS — тоже. Правила безопасности входа
  (`Provider+ProviderKey`, `email_verified`, `IsActive`) переезжают в сервис **без изменений** и
  получают свои тесты.

### 2. Правила — маленькие классы в одном списке

```
interface ISignInRule
{
    string Key { get; }                                    // "min-age-by-country", "registration-open"…
    SignInDecision Evaluate(SignInContext ctx);            // Allow | Deny(reason) | RequireStep(stepKey)
}
```

- `SignInContext`: способ входа, новый ли аккаунт, email и его подтверждённость, страна (если известна),
  сведения из пройденных шагов (например заявленный год рождения).
- Сервис прогоняет правила по порядку: первый `Deny` — отказ с причиной; первый `RequireStep` — пауза на
  шаге; иначе — вход.
- Правило — чистая функция от контекста и своих настроек → юнит-тесты без базы. Новое правило =
  новый класс + строка регистрации в DI.

**Примеры правил (делать по мере надобности, не сразу):**

| Правило | Что делает |
|---|---|
| `registration-open` | закрыть регистрацию новых аккаунтов (вход старых работает) |
| `min-age-by-country` | шаг «укажи год рождения», если в стране пользователя есть порог; ниже порога — отказ или шаг согласия |
| `blocked-countries` | отказ регистрации из перечисленных стран |
| `verified-email-only` | регистрация только с подтверждённым email |
| `manual-approval` | новый аккаунт создаётся неактивным до одобрения админом |

### 3. Включение — в админке

- Настройки правил — в `Sys_AdminSettings` (реестр `AdminSettingsService`, `/Admin/Settings`): уже в
  базе, прод видит правку через мост кэша, ProdAdmin меняет без деплоя.
- Например: `SignInRegistrationOpen = true`, `SignInMinAgeByCountry = {}` (пусто = выключено;
  `{"US":13,"DE":16}` — включено для двух стран).
- **По умолчанию всё выключено** — поведение после плана то же, что сейчас.

### 4. Общий механизм шагов

- `RequireStep(stepKey)` — вход на паузе: данные провайдера ждут во временной куке (как было у удалённого
  шага 13+, схема `AuthSchemes.External`, 5 минут), человек видит страницу `/auth/step/{stepKey}`.
- Шаг сохраняет результат в контекст и возвращает в воронку — правила прогоняются снова.
- Новый вид шага = одна страница и обработчик; механизм общий.

## Страна — честно

Сейчас надёжно определить страну нечем:
- Cloudflare отдаёт страну (`CF-IPCountry`) только в режиме прокси, а записи сайта сознательно
  **DNS only** (иначе ломаются сертификат Azure и IP посетителей — [deploy.md](../deploy.md));
- Azure страну не даёт.

Варианты: спросить страну при регистрации (просто, на слово); бесплатная база IP→страна GeoLite2
(неточно, VPN обходит, нужна лицензия MaxMind); включить прокси Cloudflare (пересмотр прежних решений).
**Рекомендация:** правила по странам — только когда появятся пользователи не из Израиля, начиная со
«спросить страну».

## Юридические оговорки (из постановки Влада, 16.10.2026)

- Вход через Google (включая Family Link) и будущий SMS **не считаются** доказательством возраста или
  согласия родителя.
- Перед включением возрастных правил или сбора возраста — отдельно проверить требования израильского
  закона о защите частной жизни и согласия родителей; отсутствие галочки не означает соответствия закону.
- Не собирать дату рождения без конкретной необходимости; если правило её требует — хранить минимум
  (год, не дату) и описать в `/privacy`.
