## 0. Что выяснили (прод, 18.11)

**Причина.** Клуб в карточке пловца (`Swimmer.ClubId`) импорт пишет **только когда он пуст**
(`JsonImportService.EnrichSwimmerFromResult` :1737 и `EnrichSwimmersFromResultsAsync` :1921).
После первого импорта клуб не меняется никогда. Админского поля для него тоже нет. У каждой
строки результата клуб свой (`Results.ClubId`), он верный: история клубов в базе уже есть.

⚠ Комментарий в `ImportSwimmerResolver` и Р79 в `docs/data-integrity.md` говорят, что в карточке
«клуб последнего старта». Это неправда, поправить вместе с Ф1.

**Масштаб на проде:**

| Что | Сколько |
|---|---|
| Пловцов с результатами | 6 759 |
| Клуб в карточке ≠ клубу последнего старта | **538** (529 из них стартовали в этом сезоне) |
| Пловцов больше чем с одним клубом (без псевдоклубов) | 568: 536 с двумя, 29 с тремя, 3 с четырьмя |
| Из них в двух клубах в одно время (периоды пересекаются) | 67 |

**Часть «смен клуба» на деле дубли клубов**, которые не склеились:
`הפועל ג׳מים אילת` / `הפועל ג'מים אילת` (гереш против апострофа), `SWIM TLV` / `TLV SWIM`,
`Swimming Eilat` / `Eilat Swimming`, `הפועל באר שבע` / `Hapoel Beer Sheva`.
Поиск дублей их пропускает: `same-name` группирует по точному имени, а `levenshtein`
пропускает пары, совпавшие после `Normalize` (`ClubDedupService.cs` :104 и :182). Пара
«гереш/апостроф» не попадает ни туда, ни туда. Перестановку слов не ищет никто.
Есть и похожее на переименование: `הפועל עירוני הוד השרון` → `אלומה עירוני הוד השרון`
(у нескольких пловцов в одну дату). Решать человеку: переименование клуба или новый клуб.

**Где клуб берётся из карточки (а значит, устарел), а где из строки** — аудит кода 18.11:

| Верно уже сейчас (клуб строки) | Устарело (клуб карточки) |
|---|---|
| Протокол, SwimRow, карточки Overview, клубный зачёт | Шапка страницы пловца (`ResultRepository.GetSwimmerProfileAsync` :923) |
| Combine All Results | Стороны H2H: таб и `/h2h` (`SwimmerPageBuilder.cs` :656), игнорируют `?season` |
| Season best, фильтр по клубу | «Club best» в личных рекордах (`SwimmerPageRepository.cs` :310) |
| My swims, обложки My media | Ростер клуба и число пловцов (`ClubPublicRepository.cs` :69, `ClubOverviewRepository.cs` :102) |
| Подписка группы на клуб (`HubGroupClubRoster`) | Списки группы, уровни, «добавить из клуба» |
| Стартовые протоколы (клуб заявки) | Избранное, поиск, выбор соперника |
| | SEO: заголовок пловца, ссылки пловец↔клуб |
| | Публикация медиа на страницу клуба: старый клуб можно, новый нельзя |
| | Сопоставление при импорте, loglig, стартовых листах: ищет по старому клубу, плодит дубли пловцов |

У Season best есть свой край. При «лучший раз пловца» строки сначала схлопываются до одной
(`SeasonBestRepository.cs` :349), а фильтр по клубу идёт после (:385). Пловец, который за сезон
плыл за два клуба, виден только в клубе своего лучшего заплыва.

## 2. Этапы

### Ф0. Дубли клубов (данные, сначала)
- Поиск дублей: `same-name` группировать по `Normalize(Name)` (гереш = апостроф), новая
  эвристика `word-order` (тот же набор слов в другом порядке). Юнит-тесты на обе пары.
- Склейку на проде запускает Влад через `/Admin/Clubs` в ProdAdmin. Агент готовит список.
- Пару `הוד השרון` проверить по протоколам: переименование клуба или новый клуб.
- **Готово, когда:** список кандидатов на проде пуст или каждый кандидат разобран.

### Ф1. Текущий клуб сам (сервер)
- Одно правило К2 в Application (чистая функция + тесты): вход — строки пловца
  (клуб, дата, псевдо, закрепление), выход — клуб или «не менять».
- Импорт: после записи результатов пересчитать клуб у **затронутых** пловцов (не у всех).
- CLI `--refresh-swimmer-clubs [--dry-run]` — разовый догон 538 пловцов. Dry-run печатает
  «пловец, был, стал, дата последнего старта».
- Журнал смен: таблица `Sys_SwimmerClubChanges` (пловец, было, стало, когда, источник:
  import / cli / admin). Карточка на дашборде «Club changes, 7 days: N» + список
  со ссылками. Так видно автоматику, и её можно откатить.
- Закрепление К3: колонка `Swimmers.ClubLocked` (миграция) + поле в `/Admin/Swimmers`.
  MD страницы обновить.
- Кэш: смена FK уже сбрасывает `row:Swimmers:{id}` и оба клуба (тест
  `SwimmerMovedToAnotherClub_DropsItsRow_AndBothClubs`). Проверить, что профиль
  `swimmer-profile:{id}` тоже уходит.
- Исправить комментарий в `ImportSwimmerResolver` и Р79. Решение записать в `data-integrity.md`.
- **Готово, когда:** у 6073 на проде Raanana; dry-run догона разобран Владом; повторный
  импорт Эйлата клуб не дёргает.

### Ф2. История клубов + значок + окно (сервер + клиент)
- `GET /api/swimmers/{id}/clubs` → `[{seasonStart, clubId, name, nameEn, logo, swims, firstDate, lastDate}]`.
  Строится из `Results`, склеенные сведены к приёмнику, псевдо выкинуты.
  Можно положить в профиль пловца полем `clubHistory`, чтобы не делать второй запрос.
- `UI_SwimmerIdentityHero`: рядом с чипом клуба значок (например ⇄), если клубов > 1. Клик
  открывает окно истории (К5). Подписи на английском, названия клубов на иврите
  (фоллбек — EN). Значок сезона — `UI_SeasonIcon`.
- Тот же значок можно ставить в боковых карточках H2H (одна компонента).
- **Готово, когда:** у 6073 значок и две строки истории; у пловца с одним клубом значка нет;
  проверено в pane на светлой и тёмной теме, мобильная ширина.

### Ф3. Сезонные экраны (сервер + клиент)
- Стороны H2H (таб и `/h2h`): клуб из строк выбранного сезона (последний старт в сезоне).
  Без сезона — текущий клуб.
- Season best: фильтр по клубу применять **до** схлопывания «лучший раз пловца».
  Тест: пловец за два клуба в сезоне виден в обоих.
- «Club best» в личных рекордах: клуб строки, а не карточки.
- Ростер клуба и число пловцов — по К7.
- **Готово, когда:** чек-лист §3 зелёный.

### Ф4. Остальное, что читает клуб карточки
- Сопоставление при импорте, loglig, стартовых листах: «клуб совпадает» = клуб из истории
  за 2 последних сезона, а не только `Swimmer.ClubId`. Тесты в `ImportSwimmerResolver`.
- Публикация медиа на страницу клуба: разрешить текущий клуб (после Ф1 это само станет верно;
  проверить).
- Группы, избранное, поиск, SEO: после Ф1 станут верны сами. Отдельной работы нет, только проверка.

## 5. Переименование клуба: Hapoel → Aluma (Ход ха-Шарон)

**Решение Влада 18.11:** `הפועל עירוני הוד השרון` (1372) и `אלומה עירוני הוד השרון` (1454) — один
клуб, который сменил название. Склеить в Aluma (1454), но старое название должно где-то остаться,
в истории клуба.

### 5.1 Что мешает просто нажать «склеить»

- **Цепочки склеек уже есть на проде.** `1329 → 605 → 1372`, `1361 → 447 → 1372`, `1408 → 447 → 1372`.
  Страница `/clubs/{id}` проходит только один шаг (`ClubPublicRepository.cs` :41), поэтому
  `/clubs/1329` сегодня открывает пустой 605. После склейки `1372 → 1454` пустыми станут ещё
  `/clubs/447` и `/clubs/605`. Сам запрет цепочек (`ClubMergeService` :106) проверяет только два
  клуба пары, а ссылки на дубль не трогает.
- **Импорт не знает старых названий.** Склеенные клубы в кэш импорта не попадают
  (`JsonImportService.cs` :420). Если перезалить протокол 2024/25, где напечатано `הפועל עירוני הוד השרון`,
  импорт заведёт **новый** клуб с этим названием. Так происходит после любой склейки, но здесь
  старых протоколов много: 48 соревнований.
- **Строки старого клуба ничем не помечены.** Склейка перенесёт 1887 строк на 1454, и потом уже не
  узнать, какие из них были напечатаны под старым названием. Границу по дате не провести: старое
  название встречается до 16.02.2026 (соревнование 57), а Aluma — уже с 24.10.2025.
- `NameEn` у 1454 сейчас на иврите.

## 6. Смена клуба — только с подтверждением loglig

**Решение Влада 18.11:** «если клуб поменялся — сверяйся с логлиг. если там не поменялся — пока не меняй».

### 6.1 Что знает loglig (проверено 18.11)

- У 6380 из 6776 пловцов на проде есть подтверждённый `LogligId`. Карточка
  `https://loglig.com:2053/Players/Details/{LogligId}?seasonId=…` показывает клуб (`LogligClient.GetPlayerCardAsync`
  → `LogligPlayerCard.ClubName`, чип «אגודה»).
- Если пловец больше не зарегистрирован, вместо клуба loglig пишет **«ארכיון איגוד»** (архив федерации).
- Выборка: 25 случайных кандидатов на смену (без пары Ход ха-Шарон) + 6073 и 7839:
  - **22** — loglig = новый клуб (6073 → Raanana тоже). Одно из них `TLV SWIM` против нашего `SWIM TLV` — дубль из Ф0;
  - **4** — «ארכיון איגוד»;
  - **0** — loglig = старый клуб.

### 6.2 Правило

Импорт (и догон `--refresh-swimmer-clubs`) больше не меняет клуб сам, а заводит **кандидата**.
Кандидат применяется, только если loglig подтверждает:

| Что на loglig | Что делаем |
|---|---|
| Клуб = новый клуб кандидата | **Меняем** `Swimmers.ClubId`, журнал (источник `loglig`) |
| Клуб = старый клуб в карточке | **Не меняем**, кандидат ждёт, перепроверка позже |
| «ארכיון איגוד» | **Не меняем**, кандидат ждёт: на дашборде отдельный список «loglig: archive», решает человек (руками + закрепление) |
| Третий клуб | **Не меняем**, на дашборд: «loglig: другой клуб» |
| Нет `LogligId` / карточка не открылась | **Не меняем**, кандидат ждёт; без `LogligId` — список на дашборде |

- Названия сравнивать после `Normalize` и через прежние названия / склеенные клубы (`ClubNames`, `MergedIntoId`):
  `TLV SWIM` должен совпасть с `SWIM TLV`, если они склеены.
- Сеть — не внутри импорта. Импорт только пишет кандидата. Проверяет фоновая служба (рядом с батчем loglig,
  видна в `/Admin/Jobs`): после импорта и раз в сутки. Последовательно, ~1 запрос в секунду, с кэшем ответа на сутки.
- Ждущий кандидат исчезает сам, если следующий старт снова за клуб из карточки.
- Закреплённого пловца (`ClubLocked`) не трогаем, как и раньше.
- Дашборд «Club changes»: применённые за 7 дней + ждущие по причинам (loglig = старый клуб / архив / другой клуб / нет ID).
- `Loglig:SeasonId` надо держать актуальным (сейчас 1786 = 2026/27).

### 7.2 Ф4 — зачем клуб при узнавании пловца и чем сверять

Точное совпадение «фамилия + имя + год» клуб не проверяет. Клуб нужен только **запасным путям**
(`ImportSwimmerResolver`: другое написание `FindBySpelling`, переставленные имя/фамилия `FindBySwappedHalves`,
год со сдвигом на сто лет `FindByCenturyShift`). Там совпадение клуба — второе доказательство, что это тот же
человек. Сейчас сравнивается только с `Swimmer.ClubId`. Если ребёнок перешёл и напечатан с другим написанием,
доказательство не сходится → новая карточка-дубль.

- **История клубов** (любой клуб за последние 2 сезона) помогает, только если он уже плыл за новый клуб
  раньше, а карточка ещё не обновилась (кандидат ждёт loglig). Первый старт за новый клуб она не спасает.
- **loglig лучше для этого случая:** у кандидата есть `LogligId` → карточка loglig показывает клуб протокола
  (и тот же год) → тот же человек. Строки PDF своего loglig-id не несут, поэтому сверка — по карточке найденного
  кандидата.
- Предложение: принимать как доказательство клуб карточки **ИЛИ** клуб из истории за 2 сезона **ИЛИ**
  клуб на карточке loglig (через кэш ответов из §6, запрос только в этих редких запасных случаях).
  Новое совпадение пишется в диагностику импорта, как сейчас.

**Сделано 19.11 (ветка `claude/club-masters-f4`, Р109).** `ImportClubEvidence` — общий для трёх запасных путей и ног
эстафет. Шаги по порядку, на каждом нужен ровно один подошедший кандидат, следующий — только если не подошёл никто:
карточка → история с 1 сентября прошлого сезона (канон после склеек) → loglig (только `Verified` loglig-id, кэш
кандидата §6 → сеть; ≤ 20 карточек за импорт, ~1 запрос/с, ≤ 3 кандидата; «ארכיון איגוד» и незнакомое название —
не доказательство). Диагностика: «(тот же год и клуб «…» — клуб карточки / клуб из истории за 2 сезона / клуб на
карточке loglig #id «…»)». Тесты — `ImportClubEvidenceTests` (15 случаев).
