# Follow-up: обрезанные фамилии в составах эстафет (HE-экспорт)

Статус: **известное ограничение, не начато** (2026-07-20). Отдельная задача,
требует человека с исходными PDF и чтением ивритских имён — это ревью, не код.

## Суть

Реконструкция состава эстафеты (`IsrOrgCompetitionParser.ReconstructEnRelaySwimmerNames`)
собирает фамилию из фрагментов по X-колонкам. Она умеет:
- перенос одной колонки (Last ИЛИ First) на соседней строке;
- двойной перенос (и Last, и First сразу);
- перенос через разрыв страницы (с переносом X-диапазонов колонок);
- RTL-раскладку HE-экспорта (роль колонок из шапки `שם משפחה`/`שם פרטי`/
  `שנת לידה`, а не «фамилия слева»).

Она НЕ умеет: фамилию, разбитую на ТРИ фрагмента вокруг уже найденного ядра —
`KOZUC` / `HOWIC Micael 2009` / `Z` → должно быть `KOZUCHOWICZ`, а выходит
обрезанный средний кусок `HOWIC`.

## Почему не чинится «точечно»

Любой механизм, дособирающий префикс+суффикс вокруг ядра, чинит не только
Brazil 01:59.77, но и ещё ~15 строк в тех же фикстурах. Среди них два класса
(проверено по сырым словам PDF):
- **настоящие починки** — `Levi RKOWS` → `TSCHERKOWSKI` (значит «RKOWS» в
  текущих «64/64» — сама по себе обрезанная фамилия);
- **возможная склейка чужих кусков** — `Sagie ROTEN` → `Sagie COHENROTENBERG`,
  где `COHEN`/`ROTEN`/`BERG` в одном блоке, но могут быть разными людьми.
  По PDF не различить — нужен человек.

Вывод: текущие HE «64/64 non-null» почти наверняка содержат несколько тихо
обрезанных фамилий. Тест на утечку года (`\b\d{4}\b`) это НЕ ловит — короткая
неверная фамилия не год.

## Что делать в этой задаче

1. Реализовать сшивку префикс+суффикс вокруг ядра (в обеих раскладках).
2. Прогнать обе фикстуры, выписать ВСЕ изменившиеся строки.
3. Человек сверяет каждую с исходным PDF, отделяя реальные починки от склеек.
4. Если склейки неизбежны для части строк — оставлять их null, а не
   правдоподобно-неверными (правило «меньше уверенности — null»).
5. Добавить тест, ловящий обрезки (например, сверка HE↔EN по всем общим
   строкам должна давать 0 расхождений; сейчас 0 на 38 общих, но многие
   строки не пересекаются и потому не проверены).

## Пока задача не сделана

- **Источник по умолчанию — EN**: он даёт 62/64, где всё либо верно, либо
  честный null. HE даёт больше заполненных, но с тихими обрезками — хуже.
- Импортировать HE-файл на прод НЕ рекомендуется до фикса.
- Двуязычный режим (HE основной + EN вторичный) берёт состав из HE
  (`IsrOrgParser.cs:248` `rHe.RelaySwimmers ?? rEn.RelaySwimmers`) — значит
  унаследует те же обрезки; чинить вместе с этой задачей.

`ageGroup=0`). Не сегодняшняя регрессия, отдельный разбор.
