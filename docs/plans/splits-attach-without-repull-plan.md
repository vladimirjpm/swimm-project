Статус: **Д1–Д4, Д6-для-1581 и Д7 СДЕЛАНЫ 20.09.2026**; осталось Д5 (кнопка в админке) и
טריילז лето (нужен `LogligId`). Решения §6 приняты Владом 20.09.2026.
Доклейка — ОСНОВНОЙ путь получать промежуточные, а не запасной для 1581 (решение Влада):
[important.md](../important.md), «Качество данных»;
[splits-backfill-championships-plan.md](splits-backfill-championships-plan.md) §6.
Устройство промежуточных — [../relays.md](../relays.md); история — [../data-integrity.md](../data-integrity.md), И-28.

## 1. Зачем

Сегодня промежуточные приезжают ПОБОЧНЫМ ЭФФЕКТОМ полного переимпорта (`--repull`): протокол
качается заново, `RelaySplitEnricher` / `IndividualSplitEnricher` дописывают промежуточные в
разобранный JSON, и соревнование импортируется целиком. Цена ошибки — задвоенное
соревнование: у 1581 старые строки импортированы с раундами (`HeatType=final`,
`Round=timed-final`, пустой `EventCategory`), новый разбор даёт `EventCategory=16` без
раундов, ключ upsert не совпал и приехали вторые 3561 строка (И-28).

Доклейка ничего не перезаливает: качает из loglig ТОЛЬКО промежуточные, сопоставляет их со
строками, которые уже в базе, и дописывает ровно два поля:

- `RelayMembers.SplitTime` — этапы эстафет;
- `Results.TimeSplit` — отрезки личных заплывов (формат `«31.52;34.84»`).

Ничего не создаётся и не удаляется; места, пол, категория, состав, владелец строки не
меняются. Ключ upsert не участвует вообще.

⚠ **Что доклейка НЕ делает** (и не должна): не заводит недостающие эстафеты и ноги, не
чинит пол/категорию/полосу, не пересобирает мастерс-эстафеты. Это работа импорта
(`RelayMastersBuilder`, этап 2 relays.md) — здесь она осталась бы вторым способом делать то
же самое.

## 3. Правило сопоставления

Ключи берём те же, что у JSON-доклейки, — иначе получим второй набор правил.

**Эстафеты.** Кандидат — строка `Results` соревнования с `RelayId != null`:
стиль (`Styles.Name`) + дистанция (`Distance`) + `Heat` + `Lane` + время (`TimeOriginal`).
Только однозначное совпадение; 0 → `unmatched`, >1 → `ambiguous`.
Найдено — сверяем состав по годам рождения (`RelayMembers → Swimmers.BirthYear`,
мультимножество, как в `RelaySplitEnricher`); не сошлось → `birthYearMismatch`, не пишем.
Совпало — пишем `SplitTime` ноге с тем же `LegOrder`.

⚠ Порядок ног в базе и в PDF совпадает по `LegOrder` = `order` источника. Если у эстафеты в
базе ног нет вовсе (`RelayMembers` пуст) — это НЕ случай доклейки: сначала
`RelayMemberBackfillService`, отчёт скажет «ног в базе нет».

**Личные.** Кандидат — строка `Results` соревнования с `RelayId == null`:
стиль + дистанция + пол (`Gender`) + время + год рождения пловца. Только однозначное
совпадение. ⚠ Сумму отрезков с итогом сверяет РАЗБОРЩИК (`LogligIndividualSplitParser`,
±0.02) — пловец с несошедшейся суммой до доклейки не доезжает, второй такой проверки в
матчере нет намеренно.

**Идемпотентность.** Повторный прогон переписывает те же значения теми же; если значение
уже стоит и совпадает — не трогаем (не плодим записи в журнале сброса кэша).

## 4. Этапы

- **Д1. Порт правила в чистые функции.** ✅ **Сделано 20.09.2026.** `SplitAttachMatcher`
  (`Swimm.Application/Mapping`): на вход `RelayRow`/`SwimRow` (строки базы) и
  `SplitSourceTeam`/`SplitSourceSwim` (источник), на выход `SplitAttachPlan` — список
  «нога → время этапа», «строка → отрезки» и `SplitAttachReport`. Без EF и без сети.
  Решения по ходу:
  - **время сверяется в миллисекундах**, а не строками: у базы формат протокола, у loglig
    свой («1:52.30» = «01:52.30»); общий разбор — `RelayLeadOffMatcher.ToMs`;
  - **сумму отрезков НЕ проверяем** — это делает `LogligIndividualSplitParser` (±0.02), и
    пловец с несошедшейся суммой сюда не доезжает; вторая проверка разъехалась бы с первой;
  - **«ног в базе нет» — отдельный счётчик**, а не `unmatched`: состав заводит
    `RelayMemberBackfillService`;
  - типы матчера вписаны в белый список инварианта И11 (`SwimTimeQualityInvariantTests`):
    время в них — ключ сопоставления, а не показываемый результат.

## 5. Тесты (Swimm.Tests, к Д1)

- эстафета: совпала по heat/lane/времени → ноги получили `SplitTime` по `LegOrder`;
- состав по годам не сошёлся → не пишем, счётчик `birthYearMismatch`;
- два кандидата с одинаковым временем в одной дорожке → `ambiguous`, не пишем;
- ног в базе нет → отдельный счётчик, не `unmatched`;
- личный: совпал → отрезки склеены через `;`;
- личный: то же время, другой год рождения → `unmatched`;
- личный: два заплыва одного года и времени → пропуск (неоднозначно);
- время в разных форматах («1:52.30» / «01:52.30») — совпадение;
- повторный прогон ничего не меняет (идемпотентность).

## 6. Решения Влада (20.09.2026)

1. **`LogligId` — параметром, колонку в `Competitions` НЕ заводим.** По умолчанию берём из
   строки discovery по `OrgCompId`; нет строки — `--loglig <id>` в CLI и поле в форме кнопки
   (id виден в адресе loglig). Причина: у склеенных стартов (8-11 зима — четыре окружных)
   одного id не существует, колонка врала бы.
2. **Прогон — на ВСЕ дни события сразу.** Промежуточные качаются на весь турнир, поэтому
   `competitionId` резолвим к `EventId` и раскладываем по всем его дням за один заход:
   меньше запросов к loglig и нельзя забыть день. Отчёт — с разбивкой по дням.
3. **Д7 — только ПОСЛЕ боевого прогона (Д6).** Пока доклейка не доказана на 1581 и
   остальных, `--repull` продолжает тянуть промежуточные; снимаем вызов после.
