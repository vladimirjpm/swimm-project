# План — страница H2H: один компонент на таб и на страницу

Сравнение двух пловцов уже работает **табом** страницы пловца (`/swimmers/{id}?tab=h2h&rival={id}`,
макет `!design_handoff/design_handoff_h2h/`, устройство — [athlete-page-plan.md §12](athlete-page-plan.md)).
Этот план — про **отдельную страницу** `/h2h`, где выбираются ОБА пловца, и про то, чтобы
экран при этом остался **одним компонентом**, а не второй копией.

> **СТАТУС 02.09.2026: X1–X6 СДЕЛАНЫ, страница работает вживую.** Ветка `h2h-tab`,
> коммиты `be36e93` (X1) … `445f760` (X5). Тесты 1598/1598, `tsc` и сборка чистые.
> Открытые вопросы — §9: они не блокируют, но решить их стоит до того, как страницу
> кто-то найдёт (её пока нет в меню — только по прямой ссылке).

Решения Влада от 02.09.2026, с которых план начинается:

- адрес — **`/h2h?a=&b=`** (всё в query, как у `/season-best`): пустые слоты тоже адресуемы,
  а пара в пути потребовала бы второго формата адреса для «ещё никто не выбран»;
- слева по умолчанию — **«ME»** (primary favorite залогиненного), **но параметром**: чтобы
  переключить на «два пустых слота» правкой одного значения, а позже — настройкой;
- сезон выбирается **той же каруселью**, что на страницах пловца и клуба.

## 2. Шов: `UI_H2HCompare` — один экран, два вызова

Сборка переезжает в семейство как **`components/mix/h2h/h2h-compare.tsx`**. Компонент не
знает ни про табы, ни про роуты — только про две стороны и данные сравнения.

```tsx
/** Слот стороны: занят пловцом либо пуст. */
type H2HSlot =
  | { kind: 'swimmer'; swimmer: H2HSwimmer; stats?: H2HStats;
      isFavorite?: boolean | null; onToggleFavorite?: () => void;
      /** null — сторону нельзя сменить (таб: левый = хозяин страницы). */
      onClear?: (() => void) | null }
  | { kind: 'empty'; label?: string; onPick: () => void };

interface H2HCompareProps {
  left: H2HSlot;
  right: H2HSlot;
  /** null — сравнения нет: выбран не каждый, либо запрос ещё идёт. */
  compare: SwimmerCompare | null;
  state: { loading: boolean; error: boolean };
  /** Выбор пловца — свой у таба (соперник) и у страницы (любой из двух слотов). */
  picker?: React.ReactNode;
  /** Строку season bests прячем за карьеру: мест среди сверстников там нет. */
  showSeasonBests?: boolean;
}
```

Кто что передаёт:

| | Таб `?tab=h2h` | Страница `/h2h` |
|---|---|---|
| `left` | `swimmer` хозяина страницы, `onClear: null` | выбранный A либо `empty`; сменяем |
| `right` | соперник либо `empty` | выбранный B либо `empty` |
| `picker` | один список (ищем соперника) | тот же список, но пишет в **активный слот** |
| сезон | из карусели страницы пловца | из карусели самой страницы |

Панель таба после переезда — десяток строк: собрать слоты и отдать компоненту. Вся вёрстка,
включая шапку, статы, карточки заплывов и разделитель, живёт в одном месте.

⚠ **`useFavoritesContext` внутрь компонента не тащим.** Сердечко приходит пропсами
(`isFavorite` + `onToggleFavorite`), потому что страница и таб живут в разных провайдерах, а
компонент из `mix/` не должен требовать чужого контекста — правило семейства
`UI_SwimmerIdentity*`, там та же развилка уже решена так.

## 3. Адаптер ширины — container queries, а не медиазапросы

Сегодня `h2h.css` ужимается по **вьюпорту** (`@media (max-width: 900px)`). Для одного
компонента на двух экранах это неверно: в табе он живёт в панели (у которой свои поля и
сайдбар страницы), на `/h2h` — во всю ширину. Один и тот же вьюпорт даёт разную доступную
ширину, и компонент должен смотреть на СВОЙ контейнер.

```css
.h2h-scope { container-type: inline-size; container-name: h2h; }

@container h2h (max-width: 780px) { /* столбик, узкие колонки, дата скрыта */ }
```

- обёртка `.h2h-scope` — внутри самого компонента, чтобы вызывающий не мог забыть её поставить;
- **порог 780px подобран замерами, а не на глаз**: в панели таба контейнер равен 795px при
  окне 900px и 306px при окне 375px, то есть прежняя граница «окно ≤900» соответствовала
  контейнеру ~796. Взято 780 — полный макет на 795px ещё читается (проверено: имена не
  обрезаются, переполнения нет), а на 700 уже нет. Побочный эффект осознан: на окне 900px
  экран теперь показывает полный макет, а раньше ужимался;
- `@media` в файле не осталось вовсе — все правила были про доступную ширину.

Поддержка: Chrome 105+, Safari 16+, Firefox 110+ — совпадает с тем, что уже требует проект
(`color-mix`, `:has`). Фоллбека не делаем: без container queries компонент просто останется в
широком варианте, вёрстка не ломается.

**Явный параметр плотности не заводим.** Соблазн `density="compact|full"` есть, но тогда
вызывающий обязан угадать свою ширину — а он её не знает (панель таба на 1280px шире, чем
страница на 900px). Container queries снимают вопрос целиком; если позже понадобится
принудительный режим (например, печать), он добавится атрибутом `data-h2h-density` поверх.

## 4. Контракт адреса

```
/h2h                         оба слота пусты (либо «ME» слева — см. §5)
/h2h?a=6066                  выбран один
/h2h?a=6066&b=6069           сравнение
/h2h?a=6066&b=6069&season=2025|all
```

Три зеркала контракта правятся вместе (правило `client/CLAUDE.md`):

1. `client/src/utils/routes.ts` — генератор `routes.h2h({ a, b, season })` + разбор
   `parseH2HQuery()` рядом с ним (как `SeasonBestQuery`);
2. `cleanUrlRewrite` в `client/vite.config.js` — `h2h → /h2h.html` (dev);
3. rewrite-middleware в `server/Swimm.API/Program.cs` — та же строка (прод).

Плюс точка входа: `client/h2h.html` + `client/src/pages/h2h-page.tsx`, и `h2h` в
`rollupOptions.input`. Порядок параметров в адресе — `a`, `b`, `season`: пустые не пишем.

**Ссылка с таба на страницу сделана** (02.09.2026): в шапке панели таба справа — пилюля
«Full page →» на `routes.h2h({ a: хозяин, b: соперник, season })`. Пару и сезон уносим с
собой, иначе переход стоил бы повторного выбора: с `?tab=h2h&rival=6069` при сезоне 2025/26
она ведёт на `/h2h?a=6066&b=6069&season=2025`, без соперника — на `/h2h?a=6066&season=2025`,
в режиме ∞ — с `season=all`.

Обратно со страницы на таб не ведём: таб — часть профиля, а страница самостоятельна. Со
страницы есть только ссылка на профиль левого пловца.

## 5. «ME» слева — параметром

```ts
/**
 * Кем занят левый слот на пустой странице: 'me' — primary favorite залогиненного,
 * 'empty' — оба слота пусты. Значение живёт ОДНОЙ константой, чтобы переключение
 * стоило одну правку; когда появится экран настроек — переедет туда, тип не изменится.
 */
export type H2HDefaultLeft = 'me' | 'empty';
export const H2H_DEFAULT_LEFT: H2HDefaultLeft = 'me';
```

Правила:

- `a` в адресе всегда сильнее умолчания: пришли по ссылке — открылось ровно то, что в ней;
- у гостя и у залогиненного без «ME» умолчание молча вырождается в `empty` — заглушки
  «войдите, чтобы сравнивать» тут не место, страница работает всем;
- подстановка «ME» **не пишется в адрес** сразу: пока пользователь не выбрал второго, адрес
  остаётся `/h2h` — иначе ссылка «пустая страница» превращалась бы в чужую личную.

**Сделано в X4** вместе с выбором сторон. Попутно из таба убрана кнопка «Clear» в шапке
панели: сбросить соперника можно крестиком на его карточке — тем же жестом, что на
странице. Два одинаковых действия рядом заставляли бы выбирать между ними на ровном месте.

## 6. Сезон и карусель

- список сезонов = **объединение** `profile.seasons` обоих пловцов (у соперника бывают
  сезоны, которых нет у первого; пересечение прятало бы данные, которые есть у одного);
- умолчание — витринный сезон (`isDisplayDefault`) из профиля A, как на странице пловца;
  без A — витринный сезон из `useShowcaseSeason` (общий шов, `docs/season-boundary-rule.md`);
- `∞` (карьера) работает так же, как в табе: сравнение по карьерным лучшим, строка
  season bests скрыта;
- сезон пишется в адрес (`season=2025|all`), чтобы ссылка открывала то же самое.

## 8. Что решено заранее (не переоткрывать)

- **Компонент один, вызова два.** Причина не в экономии строк: цифры сравнения (счёт, статы,
  бейджи SB/REC) считаются на сервере, но раскладка «кто слева, кто справа, что победа» —
  на клиенте, и две копии этой раскладки разъедутся на первом же изменении правил.
- **Слот — данные, а не режим.** Компонент не знает слов «таб» и «страница»: он видит
  занятый слот или пустой. Поэтому «левый нельзя менять» выражается через `onClear: null`, а
  не через `variant="tab"`.
- **Ширина решается контейнером, а не пропом** (§3).
- **Сравнение по-прежнему только парное.** Троих и больше не планируем: макет, счёт «3–2»,
  сетка `1fr · центр · 1fr` и правило «cyan = быстрее» держатся на паре.

## 8-тер. Бейджи SB и REC — починка 02.09.2026

Поймано Владом на паре 7424 × 62098 («у этих двоих должен быть и SB, и рекорды»).

**REC не работал у взрослых ВООБЩЕ** — и в H2H, и в личниках страницы пловца. Запрос шёл в
`Category='age'` с ключом-числом, а рекорды взрослых лежат иначе: `masters/{полоса}` и
`open`; `age/{число}` есть только у детей 10–18, а `age/adults` — это эстафеты.

Теперь ступень выбирается **по заплыву**, теми же правилами, что у детектора рекордов
соревнования (`CompetitionRecordsDetector.CandidateKeys`): открытый рекорд страны плюс
`masters/{полоса}` для мастерского старта либо `age/{возраст}` для обычного. Возраст — по оси
`RecordAgeAxis` из настроек, как у детектора: разъедутся правила — бейдж начнёт спорить с
карточкой «New records». Репозиторий получил общий `GetNationalRecordsAsync(регион, пол,
категория, ключ)`, старый метод стал его частным случаем.

⚠ Бейджа может не быть у настоящего рекордсмена, и это НЕ баг: метим по времени, а
рекордный заплыв может быть вне базы. Живой пример — 62098: держит открытый рекорд 21.08,
но лучший его полтинник в наших данных 21.22 (рекорд поставлен до периода импорта).

**Личники (`/personal-bests`) починены тем же швом** (02.09.2026): ступень выбирается по
заплыву, приоритет у возрастной, открытый рекорд — фоллбек. Ответ несёт `nationalRecordScope`
(«age 14», «masters 45-49», «open»), и подпись строки говорит, чем мерили, — «national age
record» у взрослого было бы неправдой. Проверено: 7424 → «masters 45-49» (дельта 0, её же
рекорды), 62098 → «open» (+0.14), 7796 → «age 12», 6066 → дельты нет.

Две ловушки, найденные при этом:

1. **Открытый рекорд — эталон ВЗРОСЛОГО.** Девятилетней он давал «Δ Israel +19.18» до
   взрослого рекорда: детская лестница справочника начинается с 10, и ниже сравнивать не с
   чем. Отсечка — `IsAdultSwim` (мастерский старт либо возраст выше 18).
2. **В `Countries` ДВА Израиля**: «ISR» (id 10, «Israel») и «IL» (id 111), на второй смотрит
   **791 пловец**. Рекорды лежат под «ISR», поэтому этим 791 они не находились вовсе — ни в
   личниках, ни в H2H. В репозитории добавлена защита (`NormalizeRegion`: «IL» → «ISR»), но
   это дыра ДАННЫХ: страны нужно склеить, иначе она всплывёт в любом новом месте, где
   код страны участвует в поиске.

**SB в режиме ∞** больше не прячется: места считаются за ВИТРИННЫЙ сезон (как фильтр Season
best страницы пловца), а строка статов подписана «season bests · 2025/26», чтобы цифра не
читалась как «за всё время». Бейдж на строке при этом ставится по `ResultId`: если карьерное
лучшее показано из другого сезона, бейджа нет — иначе он обещал бы первое место времени,
которого в том сезоне не показывали.
