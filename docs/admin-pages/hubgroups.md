# /Admin/HubGroups — группы SwimHub

Файлы: `Pages/Admin/HubGroups/Index.cshtml`, `Edit.cshtml`; API — HubGroup*-сервисы
(`HubGroupAdminService`, `HubGroupCrudCore`, media/user/permission-сервисы).

Неформальные объединения пловцов (группы/клубы/сборные): CRUD, участники
(members-слой), медиа группы, join policy. Публичная витрина — на клиенте.

## Deep-link фильтры (T3b)

`?filter=official` — как раньше (только официальные группы). `?tab=requests` —
секция «Заявки на вступление (pending)» под тулбаром (тогл-ссылка в шапке или
deep-link с дашборда): `HubGroupUserMembers.Status == "pending"`, через
`IDataQualityService.GetPendingJoinRequestsAsync` (топ-200 + total). Read-only —
группа/email/дата подачи, без approve/reject (это Sys_-таблица, решения принимают
владельцы/админы конкретной группы вне этой страницы).

## Подписка на клуб в форме Edit (2026-09-10)

Шапка формы пишет «подписка на клуб «X»» и сколько пловцов скрыто владельцем; счётчик
участников — только видимые. У пловца из подписки в таблице пометка «из подписки на клуб»
(и «· скрыт владельцем»), а кнопка вместо «Удалить» — **«Скрыть»**: удалённого клубного вставила
бы следующая пересборка. Скрытого вернуть отсюда — добавить его руками (строка станет ручной).
Самой подписки форма не меняет — это делает владелец (API `…/club-subscription`, клиент — П3).
Модель — `docs/hubgroups-architecture.md` §4а.

## Удаление (2026-09-10)

И в списке, и в форме Edit подтверждение показывает **перечень потерь**: пловцы в составе,
аккаунты, админы группы, тренировки с результатами, медиа, публикации участников,
официальный статус, заявка — только ненулевое. Скрипт один на обе страницы —
`_DeleteConfirm.cshtml` (`hubGroupDeleteConfirm(id)` поверх `adminConfirm`), данные — из
`GET /api/me/hub-groups/{id}/delete-impact` (у админа сайта `CanDelete` на любую группу).
Ивритские имена в тексте диалога изолированы символами FSI/PDI — иначе «ёлочки» вокруг них
встают задом наперёд. Удаление пишется в аудит `hubgroup.delete` самим `DeleteAsync`.
Правило целиком — `docs/hubgroups-architecture.md` §3.

## Тестовые группы (2026-09-24)

Галочка **«Тестовая группа»** в форме Edit (`HubGroup.IsTest`, миграция `AddHubGroupIsTest`).
Ставится и снимается ТОЛЬКО здесь: `HubGroupInputDto.IsTest` читает лишь `HubGroupAdminService`,
общий `HubGroupCrudCore.Apply` поле не трогает — владелец из «My groups» пометку не поменяет.
В списке у такой группы метка `TEST`, фильтр над таблицей: Все / Без тестовых (`?filter=real`) /
Тестовые (`?filter=test`) / Официальные.

Правило видимости (план — `docs/plans/test-personas-plan.md`): видят site-админ и аккаунты с
email на `utest` (`TestAccountRules`); остальным группы НЕТ — 404 на странице, результатах,
тренировках, медиа и во всех ручках `My groups` (`HubGroupPermissionService` отдаёт
`Exists=false`), вступить нельзя. В каталоге `/groups` её нет никогда, даже для utest; в
подсказке «кто ещё следит за клубом» и в счётчике групп дашборда — тоже. Ответы страницы
тестовой группы уходят с `private, no-store`, как у приватной. Для utest-аккаунтов группа в
остальном обычная: open/approval и галочка «Публичная» работают как везде.

⚠ Официальной тестовая группа быть не может (`CK_HubGroups_TestNotOfficial`): заявку на статус
не примут, одобрить старую нельзя, официальную нельзя пометить тестовой.
