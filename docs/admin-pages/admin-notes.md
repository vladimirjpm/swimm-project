# Справки админки «ⓘ» — механизм для всех страниц

Короткое пояснение «почему так» рядом с названием службы, параметра или блока: значок **«ⓘ»**, по
клику попап с текстом. Тексты — MD-файлы в [`docs/admin-notes/`](../admin-notes/README.md), один
файл на справку, имя файла = ключ. Сделано 20.11.2026 (первая справка — почему выключена пакетная
привязка loglig-id). Своей страницы нет: механизм живёт в каркасе `_Layout` и работает на любой
`/Admin/*`; список всех справок — раздел `/Admin/Docs/notes` ([docs.md](docs.md)).

**Добавить справку = положить файл `docs/admin-notes/<ключ>.md`.** Код не правится: если на
странице уже стоит метка с этим ключом (у служб `/Admin/Jobs` — всегда, `job.<ключ службы>`),
значок появится со следующей загрузки страницы.

## Файлы

| Что | Где |
|---|---|
| Тексты | `docs/admin-notes/*.md`; формат и имена — [README папки](../admin-notes/README.md) |
| Порт | `IAdminNotes` (`Swimm.Application/Abstractions`): `List()`, `Get(key)`; DTO — `Swimm.Application/Dtos/AdminNotesDtos.cs` (`AdminNoteInfo`, `AdminNoteView`) |
| Разбор файла | `AdminNoteParser` (`Swimm.Application/Mapping`): заголовок `# …`, «Проверено: ДД.ММ.ГГГГ», тело; форма ключа `IsValidKey` |
| Реализация | `Swimm.API/Services/AdminNotesService.cs` (singleton). В API-слое, как `/Admin/Docs`: тот же поиск корня репозитория `DocsRenderer.FindRepoRoot` и тот же Markdig-рендер `DocsRenderer.Render` |
| Ручки | `AdminNotesController`: `GET /api/admin/notes` — список, `GET /api/admin/notes/{key}` — одна справка (404, если нет). `[Authorize(Roles="Admin")]` + `[AutoValidateAntiforgeryToken]`, как соседние |
| Клиент | `wwwroot/js/admin/admin-notes.js`, подключён в `Pages/Admin/_Layout.cshtml` для всех страниц |
| Docs | `Pages/Admin/Shared/AdminNotesDocs.cs` — раздел «Справки админки» из папки; пункт сайдбара «Admin notes» |
| Тесты | `AdminNoteParserTests`, `AdminNotesServiceTests`, `AdminNotesControllerContractTests` |

## Контракт

`GET /api/admin/notes` → `[{ key, title, checked, path }]`, `checked` — `"2026-11-20"` или `null`
(строки «Проверено» нет / дата не разобралась), `path` — `docs/admin-notes/<ключ>.md`.

`GET /api/admin/notes/{key}` → `{ key, title, checked, path, html }`; `html` — тело без заголовка и
строки «Проверено» (их попап рисует сам). Нет справки или ключ не той формы — 404.

## Как ставить значок

```html
<span data-note="job.loglig-batch"></span>       <!-- кнопка «ⓘ» с попапом -->
<span data-note-mark="job.loglig-batch"></span>  <!-- только пометка, без кнопки -->
```

- `data-note` — скрипт кладёт внутрь настоящий `<button>` (`aria-label` «Справка: <заголовок>»,
  `aria-haspopup="dialog"`, `aria-expanded`). Клик по нему не всплывает (стоит внутри кликабельной
  шапки — она не сработает).
- `data-note-mark` — для мест, которые сами `<button>`/`<a>` (дорожка и плитка `/Admin/Jobs`):
  кнопка в кнопке — невалидный HTML. Пометка не кликается отдельно; страница сама решает, что делать
  по клику (Jobs открывает панель и `AdminNotes.open(key)`).
- Справки с ключом нет — метка прячется (`hidden`), пустая метка и до загрузки списка не даёт
  промежутка (`[data-note]:empty { display:none }` в `Styles/admin.css`).
- Метки, дорисованные позже (`innerHTML` опроса Jobs раз в 30 с), подхватывает `MutationObserver`.
  Страница, которой важно вернуть фокус на значок после перерисовки, зовёт `AdminNotes.scan(root)`
  сразу после `innerHTML` (так делает `jobs-detail.js`).
- `window.AdminNotes`: `scan(root)`, `open(key)`, `has(key)`, `close()`.

## Поведение попапа

Один элемент `#admin-note-pop` на страницу (`role="dialog"`, не модальный), `position: fixed`:
под значком, если снизу места мало — над ним; не вылезает за экран; уже 640 px — во всю ширину с
отступом 8 px; высота не больше 80% окна, длинный текст прокручивается внутри. В шапке — заголовок и
«проверено ДД.ММ.ГГГГ» (старше 90 дней или без даты — жёлтым «цифры могли устареть»), внизу —
«Открыть в Docs ↗» и путь файла. Закрывается Esc (раньше обработчиков страницы — у Jobs Esc
сначала закрывает попап, потом панель), ✕, повторным кликом по значку и кликом мимо. После Esc и ✕
фокус возвращается на значок; после клика мимо — остаётся там, куда кликнули. Перерисовали место со
значком, пока попап открыт, — попап переезжает к новому значку с тем же ключом.

## Безопасность

- **Ключ из запроса в путь не подставляется.** Сервис перечисляет файлы папки и ищет ключ в этом
  списке; плюс форма ключа `[a-z0-9.-]`, без `..`, слэшей и обратных слэшей. `README.md` справкой не
  считается.
- **Сырой HTML в MD выключен** (`DisableHtml` в `DocsRenderer`) — тег из файла не исполнится в
  странице админки. Клиент вставляет готовый `html` как есть, всё остальное — через `textContent`.
- Справки только для админа; на проде (Azure) админки нет, и `/api/admin/*` закрыт `HostingMode.IsAdminPath`.

## Кэш

Разбор и HTML кэшируются в памяти по ключу и сверяются с временем изменения и размером файла при
каждом запросе: правка файла видна со следующего открытия попапа (на уже открытой странице текст
держится в памяти до перезагрузки), перезапуск не нужен. Новый файл — со следующей загрузки страницы
(список ключей грузится один раз на страницу).

## Грабли

- Корень репозитория ищется подъёмом от ContentRoot, как у `/Admin/Docs`. В опубликованной сборке
  папки нет — список пуст, значков нет, ошибок нет.
- Ключ — в нижнем регистре: `job.LogligBatch.md` не найдётся (имя файла не по форме ключа пропускается).
- Текст справки устаревает вместе с цифрами — правило «поменял поведение → обнови справку и дату» в
  [pre-push-rules.md](../pre-push-rules.md) (п. 15-бис).
