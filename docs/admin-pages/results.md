# /Admin/Results — ручная правка результата

Файлы: `Pages/Admin/Results/Index.cshtml(.cs)` (переход по Id),
`Edit.cshtml(.cs)` (форма); репозиторий `IResultAdminRepository`
(`ResultAdminRepository`); парс времени — `SwimTime` (Application/Mapping).

## Что делает

Точечное исправление **одной строки результата** (опечатка протокола) вместо
переимпорта всего соревнования. Index — переход к форме по `Id` результата
(виден в браузере данных Admin/Api). Edit — правит: время, место / место в
возр. группе, heat, lane, очки, дистанцию, пол, возр. группу, EventStyleAge,
дисквалификацию (флаг + пометка), заметку; плюс переназначение пловца/клуба по Id.

## Ключевые правила (security-sensitive)

- Меняет **публичные данные** → после сохранения `ICacheService.InvalidateAllAsync()`
  (репозиторий) + запись в аудит (7.4): `result.edit` со снимком `{before, after}`.
- **Время**: текст `м:сс.дд` / `сс.дд` → мс через `SwimTime.ParseToMs` (та же логика,
  что в импорте). Пусто → время снимается (null). Непарсящийся ввод — ошибка, а не
  тихое обнуление. Обратно мс → текст через `SwimTime.FormatMs` (сотые).
- **Эстафетные строки** (`RelayId != null`) не правятся — состав живёт в RelayMembers,
  переназначение пловца порвало бы связь.
- Переназначаемые пловец/клуб валидируются на существование (FK `Restrict`).
- Числовые поля проверяются под check-констрейнты БД (Heat/Lane ≥ 0, Position > 0/null,
  очки ≥ 0) — понятная ошибка до SaveChanges.

## Deep-link секция «Аномалии» (T3b)

> Общая картина проверок данных, инварианты и чек-лист «вижу кривые данные» —
> [docs/data-integrity.md](../data-integrity.md). Эта секция — одна из его витрин.

Под формой перехода — сворачиваемая секция `<details>`, грузится лениво (клик по
заголовку или `?filter=fk-anomaly|empty-relay|no-gender|duplicate-exact` — раскрывает и
подсвечивает нужный блок) через `GET /api/admin/results/anomalies`
(`ResultsAdminController` → `IDataQualityService`).
Отдаёт `{ fkAnomalies, emptyRelays, noGender, exactDuplicates }` — по `{total, items}`, топ-200 каждая;
предикаты FK/эстафет те же, что `DashboardStatusService.Results.FkAnomalies/EmptyRelays`
(в проде ожидаемо пусто — FK держит целостность). Read-only; строки линкуют на Edit.

**`exactDuplicates`** (инвариант И10) — строки, где совпадает ВСЁ: соревнование, пловец,
дисциплина, заплыв, дорожка, время. Так не бывает — дорожку в заплыве занимает один пловец
один раз, значит это след импорта (2026-08-03: 5 таких строк, инцидент И-7). Лечится
переимпортом с «удалять лишние»: ключ upsert включает заплыв и дорожку, поэтому копии
схлопываются. Повтор дисциплины с **разным** временем законен (предварительные/финал,
перезаплыв) и сюда не попадает — его отдельно метит правило `duplicate_swim`, которому как
раз нужно разное время. Группировка идёт по составному ключу с вычисляемым `RelayId != null`;
перевод в SQL стережёт `DataQualityPgTests` (на InMemory такая поломка невидима).

**`noGender`** — личные результаты с пустым полом. Появляются законно: в шапке протокола
пола нет (смешанный заплыв «שומרי שבת», см. [import.md](import.md)), а у пловца он неизвестен —
подставлять наугад нельзя. Лечится так: проставить пол пловцу и переимпортировать протокол.
Эстафеты исключены — там пола нет по определению.
