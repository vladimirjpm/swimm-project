# /Admin/Clubs — дубли клубов

Файлы: `Pages/Admin/Clubs/Index.cshtml`; API `ClubsAdminController`
(`/api/admin/clubs`): dedup-candidates, merge, dedup-ignore(+remove/список),
{id}/status. Сервисы: `ClubDedupService`, `ClubMergeService`.

Аналог страницы Swimmers для клубов: кандидаты на склейку, dry-run → apply,
скрытие «не дублей». Плюс переключение статуса клуба (псевдо-клубы `IsPseudo`).

## Мягкая склейка (K2) и публичная страница клуба

Merge **не удаляет** клуб: строка остаётся, у неё проставляется `Club.MergedIntoId`.
Так ссылки на старый Id не гниют — `/clubs/{старый id}` показывает клуб-приёмника
(редиректа нет, решение Влада 2026-08-01). Склеенные исключены из дедуп-кандидатов,
выпадашки клубов hub-групп, подсказок фильтра, «дыр данных», счётчиков дашборда и — что
важнее всего — из кэша клубов в импорте: иначе следующий импорт нашёл бы дубль по имени
и повесил новые результаты на клуб, которого уже нет.

Повторная склейка уже склеенного блокируется (иначе цепочка A → B → C, которую пришлось
бы разматывать рекурсивно). На Edit склеенного клуба висит плашка со ссылкой на приёмника;
у любого клуба в шапке — ссылка на его публичную страницу `/clubs/{id}`.

После merge пересчитывается материализованный клубный зачёт (`ClubCompetitionStandings`),
причём ДВУМЯ проходами: по зачётам, где стоял сам дубль (собираются ДО переноса
результатов), и по соревнованиям канона. Ручной прогон, если что-то разошлось:
`dotnet run --project server/Swimm.API -- --rebuild-club-standings`.

## Эвристики поиска дублей

Четыре, в порядке убывания уверенности: **`same-name`** (одно и то же имя у разных Id —
самый частый случай: следы второго импорта, у канона имя на иврите без `NameEn`, у дубля
то же имя и заполненный `NameEn`), `suffix` (мусорный хвост парсера), `swimmers`
(пересечение пловцов), `levenshtein` (опечатка). Первые две помечаются «уверенная».

⚠ `levenshtein` совпадающие имена **пропускает** (`na == nb → continue`) — до появления
`same-name` (2026-08-01) такие дубли находились только случайно, через общих пловцов.
Тогда их было 65 групп / 68 клубов / 7793 результата, все склеены.

## Правка клуба (фаза 7.3 op#2)

`Pages/Admin/Clubs/Edit.cshtml(.cs)`; репозиторий `IClubAdminRepository`
(`ClubAdminRepository`). Переименование (Name/NameEn) + флаг IsPseudo. Имя клуба
нигде не денормализовано (результаты ссылаются по ClubId), поэтому «каскад» — это
инвалидация кэша агрегатов после сохранения. Мутация пишется в аудит (`club.update`
со снимком before/after). Вход: поле «Клуб по Id» на тулбаре Index + клик по имени
клуба в таблице кандидатов (открывается в новой вкладке). Удаление/дедуп — через merge.

## Deep-link фильтры «здоровье данных» (T3b)

`?filter=dedup-sure|dedup-unsure` — как раньше. `?filter=no-swimmers|no-country` —
новая сворачиваемая секция «Качество данных» под кнопками merge, грузится лениво
через `GET /api/admin/clubs/quality?filter=…` (`IDataQualityService`, топ-200 + total),
предикаты те же, что в `DashboardStatusService`. Read-only, строка линкует на Edit.
