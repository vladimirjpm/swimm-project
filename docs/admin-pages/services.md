# /Admin/Services — сайты и кабинеты проекта

Файлы: `Pages/Admin/Services.cshtml`, `Pages/Admin/Services.cshtml.cs` (`ServicesModel`), содержимое —
`Pages/Admin/Shared/ServicesCatalog.cs`. Пункт сайдбара «Services» в разделе «Система». Запросов к
API и базе нет — страница статическая.

## Что показывает

Все внешние сайты, на которых держится SwimHub, сгруппированные: сайт, Azure, GitHub, домен/DNS/почта,
Google, источники данных. У каждого — зачем он Владу, ссылки (в новой вкладке), где взять доступ и
сколько стоит. Вверху — ссылка на [deploy.md](../deploy.md) («если сломалось»).

## Правила

- **Новый сервис** — запись в `ServicesCatalog.Groups`; разметку не трогать.
- **Паролей и ключей нет и не будет** — репозиторий публичный. В поле «Доступ» — только где взять:
  какой аккаунт, какая запись в менеджере паролей.
- **Ссылки общие** — без id подписки Azure и других идентификаторов аккаунта (портал сам откроет
  нужную подписку). Исключение — проект Google: его id уже есть в документации.
- На проде админки нет (В17) — страница видна в разработке и в ProdAdmin.
