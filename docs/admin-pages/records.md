# /Admin/Records — рекорды и нормативы

Файлы: `Pages/Admin/Records/Index.cshtml`; API: `/api/admin/records`,
`/api/admin/normative-standards` (`RecordsAdminController`), diff/apply —
`RecordDiffService`, сиды — `RecordsSeeder`.

Три вкладки: рекорды (ISR Masters и др., импорт с diff-подтверждением),
нормативные стандарты (система разрядов; ось Country — alpha-3, RUS/ISR,
"" = универсальный набор). Данные питают normative-попап и карточки рекордов
на публичном сайте.

## Качество справочника (2026-08-01)

Ошибки самих официальных файлов **не чиним** — наша копия обязана совпадать с
источником. Вместо правки — реестр `Sys_RecordIssues` (сущность `RecordIssue`) и
сверка с нашими протоколами `Sys_RecordVerifications` (`RecordQualityService`).
Вкладка **«Спорные записи»** (`?tab=issues`, она же цель дип-линка `?filter=issues`
с дашборда): фильтр по статусу, создание записи, правка причины/статуса/обоснования,
удаление. API — `/api/admin/record-issues` (GET/POST/PATCH/DELETE). В таблице рекордов
у каждой строки кнопка **⚑** — заводит претензию на эту ось с текущим временем; сам
рекорд при этом НЕ меняется. Если рекорд с тех пор сменился, в реестре у записи стоит
пометка «рекорд с тех пор сменился» (ключ реестра включает время).
Метрики и кнопка «Сверить с протоколами» — в блоке «Рекорды» на `/Admin`.

⚠ `Found = false` — не признак ошибки: у нас загружены протоколы не за все годы.
Полный разбор и реестр (первая запись RQ-1) — `docs/plans/records-quality-plan.md`.

## Кандидаты сторожа импорта (2026-09-15)

Статус **`candidate`** заводит не человек, а импорт рекордов (`RecordDiffService`, правила —
`RecordPlausibility`): неправдоподобное время из источника. Два правила:
`implausible-improvement` — мировой рекорд улучшен за раз больше чем на 3 %;
`faster-than-world-record` — рекорд страны / возраста / мастерса быстрее мирового той же
дисциплины. Живой повод — «мировой» 40.11 на 100 в/с ж 50 м в отчёте World Aquatics
(`docs/data-integrity.md` И-20).

- Сам рекорд записан **как в источнике** — не чиним.
- На сайте метки **нет**, пока запись не переведена в `open` (публичные выборки берут только
  `open` / `reported` / `accepted`). Правило плана: автомат только предлагает, статус ставит
  человек. Ошибка сторожа — `rejected`.
- Кандидаты стоят в списке первыми; с дашборда — метрика «Кандидаты в спорные» →
  `?tab=issues&status=candidate`.
- Повторный импорт того же значения претензию не пересоздаёт и снятую (`rejected`) не
  воскрешает: ключ реестра — 8 осей + время.
