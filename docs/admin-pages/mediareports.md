# /Admin/MediaReports — жалобы «Report» на фото и видео

Файлы: `Pages/Admin/MediaReports/Index.cshtml(.cs)`; сервис — `IMediaReportService` /
`MediaReportService`; правила — `Swimm.Application/Mapping/MediaReportRules.cs`. Решения —
Р62–Р64 в `docs/data-integrity.md`, устройство медиа — `docs/media-page.md` §9.

## Что делает

Очередь жалоб на пользовательские медиа (`Sys_UserMedia`). Одна карточка на медиа: ссылка на
само видео/фото, пловец (ссылка на сайт), автор (ссылка в /Admin/Users), куда опубликовано
(группа ↗, уровень, статус, `trusted`) и таблица жалоб — **кто пожаловался (email), причина,
текст «Other», статус, дата**. Имена и текст видит только админ сайта: тренер группы в табе
Admin видит лишь число жалоб и причины.

Вкладки: «Ждут решения · N» (есть открытые жалобы) и «Разобранные». Над очередью — текущий
порог (`MediaReportHideThreshold`, /Admin/Settings, по умолчанию 3).

## Решения

- **Оставить** — открытые жалобы → `kept`, `UserMedia.ModerationState` → null: медиа снова видно
  там, где было опубликовано. Для уже снятого медиа кнопка называется **«Вернуть»**: автор снова
  может публиковать, но отклонённые публикации не возвращаются.
- **Снять** (с подтверждением) — открытые жалобы → `removed`, все публикации медиа → `rejected`,
  `ModerationState = removed`: видно только автору, подать заново нельзя. Можно и до порога.

Каждое решение пишется в аудит: `media.report.keep` / `media.report.remove`.

## Грабли

- Порог — по ОТКРЫТЫМ жалобам: после «Оставить» старые жалобы не считаются, прятать снова
  начнут новые. Смена порога действует на новые жалобы — уже спрятанное не возвращает.
- Настройки в памяти: после рестарта порог снова 3.
- Спрятанное не видно на витринах НИКОМУ, включая админа сайта и тренера (иначе кажется, что
  прятание не сработало). Разбирать — здесь; ссылка на само видео — в карточке.
- Текст жалобы — пользовательский ввод: выводится только экранированным (`@r.Comment`), `Html.Raw`
  здесь нельзя.
