# myswimm-dashboard-check — дашборд прода: чиню сам что можно, остальное — Владу

Полный ранбук — **[docs/dashboard-check.md](../../../docs/dashboard-check.md)**. Прочитай его целиком
перед первым действием: там команды, SQL, таблица «сам / Владу» и формат отчёта. Здесь — только
порядок и жёсткие границы.

## Порядок

1. **Подготовка** (ранбук §0): worktree `C:/_Proj/swimm-dashcheck` на `origin/master`, сборка там,
   консоль против прода через `--environment ProdAdmin --contentRoot C:/_Proj/swimm-project/server/Swimm.API`.
   Основной чекаут не переключать — там работают соседние сессии.
2. **Сбор** (§1): `/version` и `/readyz`, `--check-data`, сводка реестра и открытые находки,
   службы, кандидаты смены клуба, жалобы, свежесть рекордов.
3. **Починка сам** (§2): только строки таблицы «сам», каждая — dry-run → прочитать план → запись.
   План неожиданный — не применять, перенести во «Владу».
4. **Повторный `--check-data`**, сравнить было → стало.
5. **Отчёт** (§4): «починил сам» с числами, «нужно твоё решение» списком с готовыми командами,
   «не смотрел». Строка в журнал прогонов в конце ранбука.

## Границы (не обсуждаются)

- Запуск скилла = просьба Влада писать в прод **только** для действий из таблицы §2 «сам».
- Никогда без «да» в чате: склейки пловцов/клубов, удаления пловцов и соревнований, `--repull`,
  Apply рекордов, «Принять как есть», пол пловца, `prod-sql.mjs apply`, миграции, деплой.
- Прод на другом коде, чем `origin/master` (сайт отстал), — пишущие команды не запускать,
  вынести «выкатить master» во «Владу».
- Чтение прода — `node server/db/prod-sql.mjs read`; пароли не читать и не печатать.
- По-русски, коротко; не предлагать push/PR/коммит в конце.
