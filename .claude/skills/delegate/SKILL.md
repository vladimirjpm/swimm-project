# /delegate — конвейер «Fable готовит и ревьюит, Sonnet исполняет»

Аргумент: краткое описание задачи (например «нормативы: фильтр country в API»).
Если аргумента нет — спроси, что делегируем.

## Шаг 1 — таск-документ

Напиши `docs/tasks/<slug>-sonnet.md`. Документ **самодостаточен**: агент стартует с нуля,
без контекста этой беседы. Обязательные разделы (см. образцы в docs/tasks/, свежий —
`normatives-country-sonnet.md`):

1. **Заголовок + контекст** — зачем, откуда взялась задача.
2. **Решения (зафиксированы, не пересматривать)** — все дизайн-выборы сделай СЕЙЧАС,
   в таске; исполнителю оставляй механику, не решения.
3. **Что уже готово (не переделывать)** — существующие швы, файлы, паттерны с путями.
4. **Шаги** — конкретно, с путями файлов и сигнатурами.
5. **Тесты (обязательно)** — какие кейсы, по какому образцу из Swimm.Tests.
6. **Проверка** — команды build/test/tsc + живой curl/страница, если применимо.
7. **Footguns** — build-lock от VS (обход: `--configuration Release`, API на :5079,
   клиент `client-5079` из launch.json), два DbContext, кэши, swimm_ro.
8. **Вне скоупа (не делать)** — явно отсечь соблазны.

Закоммить таск отдельным коммитом (`Docs: задание Sonnet — …`).

## Шаг 2 — запуск исполнителя

Запусти Agent tool:
- `subagent_type: "sonnet-implementer"` (модель Sonnet задана в определении агента);
- `prompt`: `Выполни задание docs/tasks/<slug>-sonnet.md` + 1-2 строки, если есть
  нюанс момента (например «Visual Studio сейчас держит :5078 — сразу работай в Release»);
- фон (по умолчанию) — можно продолжать другую работу;
- `isolation: "worktree"` — ТОЛЬКО если параллельно планируется править код в этой
  сессии; иначе без изоляции (в общем дереве проще ревьюить и коммитить).

## Шаг 3 — приёмка (не пропускать!)

Когда агент отчитается:
1. Прочитай отчёт; раздел «Отклонения» — с пристрастием.
2. Проревьюй дифф сам (`git diff`): соответствие таску, Clean Architecture,
   стиль, отсутствие лишнего.
3. Перепроверь независимо: `dotnet build` + `dotnet test` + `tsc --noEmit`;
   если менялось видимое поведение — проверь вживую в браузере.
4. Мелкие огрехи — поправь сам; крупное расхождение с таском — верни агенту
   через SendMessage с конкретными замечаниями (контекст у него сохранён).
5. Разложи результат на коммиты и отчитайся Владу: что сделано, что поправлено
   за Сонетом, что осталось.

## Правила

- Не делегируй: миграции схемы с неочевидными последствиями, auth/безопасность,
  задачи без ясной спецификации («поиграйся с дизайном»). Это делаем сами.
- Один таск = одна связная задача. Большое — режь на несколько тасков.
- Таск-документ остаётся в репо и после выполнения — это документация решений.
